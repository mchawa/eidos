= UI Component: Portal Living Specification Reader
:toc: left

== 1. Component Purpose & Reading Ergonomics
The Portal Living Specification Reader (`UIC-PORTAL-READER`) establishes the reading-friendly stage for long-form technical documentation across the Eidos Living Web Portal:
* **Expansive Stage & Optimal Measure**: Renders within an enlarged modal dialog (`max-w-[94vw] 2xl:max-w-[1550px] h-[95vh]`) with optimal line length (`max-w-4xl xl:max-w-5xl`) to prevent ocular fatigue while utilizing modern wide displays.
* **Typographic Hierarchy**: Distinct, readable type sizes based on `DS-CORE` tokens:
  - Title (H1): `26px`–`30px` bold with tracking-tight.
  - Section Headings (H2): `20px`–`24px` bold with top breathing room and hoverable anchor links.
  - Subsection Headings (H3): `18px` semibold with visual hierarchy.
  - Body Copy: `15.5px`–`16px` with relaxed `1.8` line-height.
  - Code Snippets: `13px` monospace with syntax styling and one-click copy.
* **Human-Centric Specification Header**: Renders human-readable document titles, clean category badges, plain `Valid` / `Needs Attention` health pills, humanized status badges, resolved parent domain and container title links with clean tooltips, and human-titled cross-reference links via `EntityLabelProvider`—omitting raw ID copy chips, raw file path pills, and raw YAML/JSON frontmatter inspectors from visible reader chrome.
* **High-Contrast Dark Theme**: Clean neutral zinc surfaces (`#121215`), elevated popovers (`#18181b`), readable muted foregrounds (`#a1a1aa`), and distinct borders (`#27272a`) ensuring effortless legibility comparable to light mode.

== 2. Dynamic Table of Contents (TOC) & On-This-Page Navigation
For multi-section specifications with two or more H2 headings:
* A sticky right-hand navigation rail renders the hierarchical section tree (`== ` and `=== `).
* Real-time scroll-spy tracks reading progress and highlights the current section.
* Clicking any outline entry smoothly scrolls the viewport to the target heading anchor.

== 3. Optimal Reading Ergonomics
To maximize cognitive focus and remove interface clutter, the reader eliminates redundant view-mode and font-scaling toggles in favor of carefully balanced defaults:
* **Always-Rendered Clean Prose**: Always presents the rendered specification document directly.
* **Locked Optimal Typography**: Standardizes on the ideal reading line-height and font size.
* **Section Permalinks**: Hovering over any section heading reveals an anchor link button for instant permalink copying.
* **Uncramped Embedded Inspector Reading (`DEC-PORTAL-UNCRAMPED-INSPECTOR-PROSE`)**: Inspector drawers hosting `AsciiDocRenderer` (such as `#c4InspectorDrawer` in `SCR-PORTAL-ARCHITECTURE`) must never trap specification prose inside fixed-height nested scroll containers (e.g., `max-h-[360px] overflow-y-auto`) or double-nested card frames; prose expands naturally across the scrollable `Sheet` height and drawer width (`measure="full"`) and exposes an **"Open in Full Reader"** action (`requestSpecNavigation(id, { mode: "reader" })`) to launch the full-stage `SpecReader` with sticky Table of Contents.

== 4. AsciiDoc Rendering (Asciidoctor.js)
Specification bodies are rendered through Asciidoctor.js (`@asciidoctor/core`, `safe: 'secure'`) instead of a hand-written parser, so the reader supports standard AsciiDoc blocks used by living specs:

* **Quote blocks** (`[quote, Attribution]`, as in `eidos/system.adoc`) with attribution lines.
* **Admonitions** (`NOTE:`, `[WARNING]` delimited blocks, ...) rendered as colored callout cards.
* **Callouts** (`<1>` markers in source blocks plus the matching callout list).
* **Definition lists** (`term:: definition`) and nested/ordered lists.
* **Multi-line tables** (`[cols=...]`, header rows, multi-paragraph cells) inside a horizontally scrollable wrapper.
* **Embedded Mermaid Diagrams** (`[mermaid]` and `[source,mermaid]` blocks across `----` and `....` fences, including nested lists, admonitions, examples, sidebars, `dlist` definitions, and `a|` table cells): Extracted at the Asciidoctor AST level and mounted **post-DOMPurify** into deterministic `.adoc-mermaid-slot` placeholders as interactive Mermaid v12 SVG diagram cards (`DocumentMermaidBlock`, `securityLevel: "strict"` and `sanitizeMermaidCode`). Each card renders an optional plain-text AsciiDoc `.Title` caption header (defaulting to `"Diagram"`), `View Source` / `View Diagram` and `Copy` controls, pan/zoom/fit/expand controls with non-scroll-trapping modifier-wheel zoom (`Ctrl`/`Cmd`+wheel so vertical prose scrolling is never hijacked), and reactive light/dark theme synchronization.
* **Cross references**: `xref:SPEC-ID[]`, `<<SPEC-ID>>`, and relative `link:path/spec.adoc[]` / `xref:path/spec.adoc[]` targets are resolved to in-portal spec navigation (the Catalog spec inspector) and never leave the single-page app; in-page `#anchor` links scroll smoothly.
* `include::` is explicitly unsupported in the browser (no filesystem) and is left as inert text in secure mode; no living spec currently uses it.

Passthrough HTML emitted by Asciidoctor is sanitized (no scripts, iframes, styles, `<svg>`, or event handlers), untrusted passthrough slot markers are stripped unconditionally, and heading ids and the sticky outline come from the same Asciidoctor parse, so `Table of Contents` anchors always match rendered headings. Mermaid, Asciidoctor.js, and the Geist fonts are embedded in the portal bundle (INV-PORTAL-AIR-GAPPED-BUNDLE).

== 5. Accessibility & Verification
* **WCAG Conformance**: Level AA (`aria-role: article`; embedded Mermaid diagram cards expose `role="figure"` with accessible `aria-label` captions, labeled zoom/expand toolbar controls, and a single `role="alert"` human-readable error notice `"Unable to render diagram."` paired with sanitized raw-source fallback on invalid or empty diagrams).
* **Keyboard Navigation**: Tab and Shift+Tab traverse section anchors, interactive code blocks, and embedded diagram controls (`View Source` / `View Diagram`, `Copy`, zoom, fit, reset, and expand); Enter navigates via sticky Table of Contents.
* **Automated Verification**: Exercised by `tests/test_portal.py::test_portal_reading_ergonomics` and `tests/test_portal.py::test_portal_document_mermaid_rendering`.
