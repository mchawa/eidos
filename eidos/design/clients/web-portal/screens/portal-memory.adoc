= Screen: Team Operational Memory View
:toc: left

== 1. View Purpose & Advisory Visibility
The **Team Operational Memory** View (`SCR-PORTAL-MEMORY`) surfaces shared engineering notes stored in Git (`eidos/memory/mem-*.adoc`) alongside deterministic, strictly non-blocking freshness and hygiene diagnostics (`memory_audit`) while honoring human-first presentation (`INV-PORTAL-HUMAN-READABLE-UI`):

* **Category & Freshness Filtering**: Filter notes by category (`Feedback`, `Project Context`, `Reference`) and freshness/lifecycle state (`Fresh`, `Needs Verification`, `Expired`, `History Unavailable`, `Promoted`, `Archived`) plus instant full-text search across titles, summaries, and resolved targets.
* **Non-Blocking Hygiene Highlights**: Highlights potential duplicate notes and overlaps with formal policies or verified rules without polluting blocking specification validation warnings (`validation.warnings`).
* **Resolved Entity Cross-Links**: Clicking any anchored container, component, domain, capability, or promoted specification chip navigates directly to the linked living specification; conversely, Architecture and Business drawers surface inline active team memories anchored to the inspected entity.
* **Scannable List, Full Operational Note Drawer & Reader Escalation**: Renders active and archived team memories in a clean, de-carded scannable list preserving `data-memory-card` anchors, inline freshness notices, and resolved target chips; clicking any note opens a detail drawer rendering sanitized borderless AsciiDoc (`AsciiDocRenderer`, DOMPurify `SANITIZE_DOM: true`) with one-click `"Open in Full Reader"` escalation into `SpecReader`.
* **Zero-Memory Onboarding Empty State**: When no team memories exist, renders a clean, minimal quickstart banner showing how to capture the repository's first team memory via `eidos memory add`.
