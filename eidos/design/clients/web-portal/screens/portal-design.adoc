= Screen: Design Systems & Experience View
:toc: left

== 1. View Purpose & Design Scope
The Design Systems View (`SCR-PORTAL-DESIGN`) connects product capabilities with the visual user experience using resolved human titles and humanized labels (eliminating raw ID prefixes, literal backticks, leading state colons, and raw filename stems):
* **Client Applications & Multi-Experience**: Interactive client switcher (`designClientSelect`) displaying human client titles, resolved container and design-system badges, and scoped screen and capability titles.
* **Empty State Resilience**: Gracefully handles repositories with zero configured design systems by displaying an informational banner and clean onboarding card without raw directory paths.
* **Interaction Flows & Full Screen Expansion**: Single-Client Flow and Cross-Client Flow journeys with humanized flow-type badges, dynamic Mermaid diagrams resolving participant client titles and screen titles, and a dedicated **Full Screen** expansion button (`data-flow-fullscreen`, `#flowFullscreenDialog`) opening a native top-layer `<dialog>` modal with full-viewport interactive Mermaid zoom/pan/fit and a toggleable Journey/Sequence Steps panel (plus toolbar full-screen expansion on every `MermaidDiagram`).
* **Design Systems Catalog**: Registered design systems, base inheritance, and brand overrides using resolved titles, `aria-pressed` selection state, and explicit `<label for="designClientSelect">` control association.
* **Design Tokens Studio & All Design Tokens**: Visual swatches for brand palettes, Dark Background / Light Background neutral surfaces, feedback colors, spacing scales, corner radii, and typography, paired with a searchable **All Design Tokens** explorer with humanized token paths and tooltips.
* **UI Components**: Component cards normalizing both string and `{ name, description }` states and variants with humanized category, variant, and state labels (e.g. `Loading`, `Populated`, `Default` without CSS colons), visible inline descriptions, and plain `Test Verified` indicators.
* **Screen States & Layout Slots**: Mermaid-powered state diagrams with humanized state names, resilient string/array/object `slots` formatting with humanized slot names and resolved component titles, and hydrated AsciiDoc specification reader drawers (`Inspect Screen Spec`).
