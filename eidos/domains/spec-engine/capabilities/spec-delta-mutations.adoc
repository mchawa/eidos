= Capability: SpecDelta Semantic Mutation Engine
:toc: left

== Intent
Replaces traditional essay-style RFCs with declarative, machine-executable mutations. When a feature is added, changed, or removed, a `SpecDelta` specifies the precise mutations and impacted invariants. Upon PR merge, the mutations are applied to update the living baseline documents automatically.

== Key Responsibilities
* **Orthogonal Composable Scope (`mutations[].operation` + `target` + `parent`)**: Establishes composable `mutations[].operation` (`add` | `modify` | `remove` | `deprecate`), prefix-resolved `mutations[].target` (determining the target entity kind across all 14 Eidos prefixes), and optional `mutations[].parent` (while maintaining backwards compatibility with legacy `mutations[].action` and `mutations[].target_*` keys via `normalize_delta_mutation`) as the single source of truth for SpecDelta scope and `x-eidos-ref` cross-reference validation, while 0-hop `affects` and k-hop `blast_radius` (including `invariants_to_enforce`) are derived dynamically from the living specification graph.
* **Cross-Ref Collision-Free Delta ID Generation (`generate_collision_free_delta_id`)**: Scans local and remote Git refs (`refs/heads/*` and `refs/remotes/*` via `git for-each-ref` and `git ls-tree`) for both `auto` and explicit `DLT-YYYY-NNN` IDs, supports optional `[DELTA_ID]` and `--slug` / `-s` CLI flags on `eidos delta create`, and fast-paths cached `status: applied` SpecDeltas in `spec_validation_cache`.
* **Default-Verified Application & Safe Transactional Mutation Execution (`eidos delta apply [--execute] [--verify/--no-verify]`)**: Enforces mutation verification by default (`verify=True` unless `--no-verify` is explicitly supplied), performs copy-on-write transactional snapshotting of targeted living specifications before executing mutations, handles all composable `(operation, target_prefix)` pairs and legacy 44 schema `mutations[].action` values (explicitly rejecting unsupported operations/actions), infers language-appropriate file extensions from container `runtime` when scaffolding inline components (`_infer_container_code_extension`), verifies target specification `type:` before unlinking on `remove` / `remove_*` mutations, applies strictly `expect`-driven (`body`/`frontmatter`) modifications without appending raw `details` prose or overwriting component responsibilities/invariant rules, validates all mutated specifications and the `status: applied` SpecDelta via `SpecValidator` prior to committing to disk, and rolls back all disk changes on any verification or validation failure (`INV-MUTATION-REVERSIBILITY`).
* **Modification-Evidence Verification (`eidos delta verify`)**: Verifies `modify` (`modify_*`, `extend_*`, and `patch_*`) mutations only on positive evidence of change to the targeted entity (a satisfied closed-schema declarative `expect:` post-condition supporting structured `body.contains`, `body.not_contains`, and typed `frontmatter.*` assertions with list-subset matching and `failure_reason` diagnostics, plus a canonical content digest differing from the recorded `vcs.base_commit` / Git-history or SQLite baseline via `_resolve_git_baseline_sha`), with prefix-aware target extraction, component-entry digest granularity for inline `CMP-*` targets, and parent/sub-target membership treated strictly as a precondition (`INV-DELTA-VERIFY-MODIFICATION-EVIDENCE`).
