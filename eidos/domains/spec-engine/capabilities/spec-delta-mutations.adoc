= Capability: SpecDelta Semantic Mutation Engine
:toc: left

== Job To Be Done (JTBD)
Define, review, and apply explicit composable mutations (`add`, `modify`, `remove`, `deprecate`) to features and invariants without leaving stale documentation.

== Intent
Replaces traditional essay-style RFCs with declarative, machine-verifiable mutations. When a feature is added, changed, or removed, a `SpecDelta` specifies the precise composable mutations and impacted invariants. Upon PR merge, the mutations are verified against the living specification catalog and the SpecDelta is transitioned to `status: applied`.

== Key Responsibilities
* **Orthogonal Composable Scope (`mutations[].operation` + `target`)**: Establishes composable `mutations[].operation` (`add` | `modify` | `remove` | `deprecate`) and prefix-resolved `mutations[].target` (determining the target entity kind across all 14 Eidos prefixes) as the single source of truth for SpecDelta scope and `x-eidos-ref` cross-reference validation, while 0-hop `affects` and k-hop `blast_radius` (including `invariants_to_enforce`) are derived dynamically from the living specification graph.
* **Standalone Blueprint Creation & Collision-Free Delta IDs (`create_delta` & `generate_collision_free_delta_id`)**: Scans local `eidos/deltas/` and `eidos/deltas/archive/` `.adoc` files without Git subprocesses and always derives a mandatory title `<SLUG>` and engine-computed `<4HEX>` hash suffix (`DLT-YYYY-NNN-<SLUG>-<4HEX>`) with unambiguous prefix resolution in `find_spec_by_id_or_path`, auto-detects `vcs.branch` and `vcs.base_commit` from Git `HEAD`, supports `[DELTA_ID]`, `--kind`, and `--slug` / `-s` on `eidos delta create`, enforces SpecDelta-exclusive deletion via `delete_delta`, and tracks the 5 canonical `delta_status` states (`proposed`, `in_review`, `approved`, `applied`, `rejected`).
* **Default-Verified Application (`eidos delta apply [--verify/--no-verify]`)**: Enforces declarative mutation verification by default (`verify=True` unless `--no-verify` is explicitly supplied), verifies all composable `(operation, target_prefix)` pairs (explicitly rejecting unsupported operations), and validates the updated `status: applied` SpecDelta via `SpecValidator` prior to committing to disk (`INV-MUTATION-REVERSIBILITY`).
* **Modification-Evidence Verification (`eidos delta verify`)**: Verifies `modify` mutations only on positive evidence of change to the targeted entity (a satisfied closed-schema declarative `expect:` post-condition supporting structured `body.contains`, `body.not_contains`, and typed `frontmatter.*` assertions with nested dot-path key resolution across dicts and lists of dicts, leaf-key prose substring matching, list-subset matching, and `failure_reason` diagnostics, plus a canonical content digest differing from the recorded `vcs.base_commit` / Git-history baseline via `_resolve_git_baseline_sha` with memoized Git revision and blob resolution), with prefix-aware target extraction (`INV-DELTA-VERIFY-MODIFICATION-EVIDENCE`).
* **Subdirectory Archive Partitioning & Slimming (`eidos delta archive [--keep-recent 15]`)**: Retains all active SpecDeltas (`proposed`, `in_review`, `approved`) and the most recent `keep_recent` (default `15`) terminal SpecDeltas (`applied`, `rejected`) in `eidos/deltas/`, while moving older terminal SpecDeltas into `eidos/deltas/archive/` as slimmed, schema-valid `.adoc` files with stripped `mutations[].expect` scaffolding and Git-resolved changelog provenance (`INV-DELTA-EXPLORATION-ARCHIVE-LEDGER`).
* **Index-Driven Spec-Scoped Deletion Auditing (`eidos delta audit`)**: Pre-filters governed candidate files via the SQLite FTS5 `file_tokens_fts` inverted token table in `eidos/.cache/index.db`, resolves historical `delta/mutation` and `product/exploration` statuses in $O(1)$ from `entities`, and classifies leaks by `indexed_files.doc_type` and container `source_path` ownership (`INV-DELTA-DELETION-AUDIT`).
