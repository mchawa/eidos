= Capability: SpecDelta Semantic Mutation Engine
:toc: left

== Intent
Replaces traditional essay-style RFCs with declarative, machine-verifiable mutations. When a feature is added, changed, or removed, a `SpecDelta` specifies the precise composable mutations and impacted invariants. Upon PR merge, the mutations are verified against the living specification catalog and the SpecDelta is transitioned to `status: applied`.

== Key Responsibilities
* **Orthogonal Composable Scope (`mutations[].operation` + `target` + `parent`)**: Establishes composable `mutations[].operation` (`add` | `modify` | `remove` | `deprecate`), prefix-resolved `mutations[].target` (determining the target entity kind across all 14 Eidos prefixes), and optional `mutations[].parent` as the single source of truth for SpecDelta scope and `x-eidos-ref` cross-reference validation, while 0-hop `affects` and k-hop `blast_radius` (including `invariants_to_enforce`) are derived dynamically from the living specification graph.
* **Cross-Ref Collision-Free Delta ID Generation (`generate_collision_free_delta_id`)**: Scans local and remote Git refs (`refs/heads/*` and `refs/remotes/*` via `git for-each-ref` and `git ls-tree`) for both `auto` and explicit `DLT-YYYY-NNN` IDs, supports optional `[DELTA_ID]` and `--slug` / `-s` CLI flags on `eidos delta create`, and fast-paths cached `status: applied` SpecDeltas in `spec_validation_cache`.
* **Default-Verified Application (`eidos delta apply [--verify/--no-verify]`)**: Enforces declarative mutation verification by default (`verify=True` unless `--no-verify` is explicitly supplied), verifies all composable `(operation, target_prefix)` pairs (explicitly rejecting unsupported operations), and validates the updated `status: applied` SpecDelta via `SpecValidator` prior to committing to disk (`INV-MUTATION-REVERSIBILITY`).
* **Modification-Evidence Verification (`eidos delta verify`)**: Verifies `modify` mutations only on positive evidence of change to the targeted entity (a satisfied closed-schema declarative `expect:` post-condition supporting structured `body.contains`, `body.not_contains`, and typed `frontmatter.*` assertions with list-subset matching and `failure_reason` diagnostics, plus a canonical content digest differing from the recorded `vcs.base_commit` / Git-history or SQLite baseline via `_resolve_git_baseline_sha`), with prefix-aware target extraction, component-entry digest granularity for inline `CMP-*` targets, and parent/sub-target membership treated strictly as a precondition (`INV-DELTA-VERIFY-MODIFICATION-EVIDENCE`).
