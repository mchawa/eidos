= Capability: SpecDelta Semantic Mutation Engine
:toc: left

== Intent
Replaces traditional essay-style RFCs with declarative, machine-executable mutations. When a feature is added, changed, or removed, a `SpecDelta` specifies the precise mutations and impacted invariants. Upon PR merge, the mutations are applied to update the living baseline documents automatically.

== Key Responsibilities
* **Single Source of Truth Scope (`mutations[].target_*`)**: Establishes `mutations[].target_*` as the single source of truth for SpecDelta scope and x-eidos-ref cross-reference validation (enforcing catalog existence on `modify_*`/`extend_*`/`patch_*`/`deprecate_*` actions and prefix/type integrity across all actions), while 0-hop `affects` and k-hop `blast_radius` (including `invariants_to_enforce`) are derived dynamically from the living specification graph.
* **Cross-Ref Collision-Free Delta ID Generation (`generate_collision_free_delta_id`)**: Scans local and remote Git refs (`refs/heads/*` and `refs/remotes/*` via `git for-each-ref` and `git ls-tree`) for both `auto` and explicit `DLT-YYYY-NNN` IDs, supports optional `[DELTA_ID]` and `--slug` / `-s` CLI flags on `eidos delta create`, and fast-paths cached `status: applied` SpecDeltas in `spec_validation_cache`.
* **Transactional Mutation Execution & Pre-Commit Validation (`eidos delta apply --execute`)**: Performs copy-on-write transactional snapshotting of targeted living specifications before executing mutations, handles all 44 schema `mutations[].action` values (explicitly rejecting unsupported actions), verifies target specification `type:` before unlinking on `remove_*` mutations, applies structured (`body`/`frontmatter`) `expect` post-conditions and substantive non-comment `details` updates, validates all mutated specifications and the `status: applied` SpecDelta via `SpecValidator` prior to committing to disk, and rolls back all disk changes on any verification or validation failure (`INV-MUTATION-REVERSIBILITY`).
* **Modification-Evidence Verification (`eidos delta verify`)**: Verifies `modify_*`, `extend_*`, and `patch_*` mutations only on positive evidence of change to the targeted entity (a satisfied closed-schema declarative `expect:` post-condition supporting structured `body.contains`, `body.not_contains`, and typed `frontmatter.*` assertions with list-subset matching and `failure_reason` diagnostics, plus a canonical content digest differing from the recorded `vcs.base_commit` / Git-history or SQLite baseline via `_resolve_git_baseline_sha`), with action-aware target extraction, component-entry digest granularity for inline `CMP-*` targets, and parent/sub-target membership treated strictly as a precondition (`INV-DELTA-VERIFY-MODIFICATION-EVIDENCE`).
