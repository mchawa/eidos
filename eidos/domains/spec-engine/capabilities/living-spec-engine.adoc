= Capability: Living Baseline Specification Engine
:toc: left

== Job To Be Done (JTBD)
Maintain an accurate, non-drifting representation of what the software product currently does across both business and technical dimensions.

== Intent
Traditional product requirements documents (PRDs) quickly become obsolete. This capability ensures that the `eidos/` directory is treated as living code: every document has an explicit type and JSON/YAML schema, is validated continuously across `CMP-SPEC-VALIDATOR`, `CMP-CONTRACT-PARITY-VALIDATOR`, and `CMP-ARCHITECTURE-BOUNDARY-VALIDATOR` while preserving disjoint, acyclic component boundaries (`INV-CORE-MODULAR-COMPONENT-COHESION`), and forms an in-memory knowledge graph that AI agents and developer tools can query to understand the system state.

Through an embedded SQLite Knowledge Graph (`eidos/.cache/index.db`), Eidos bridges human-readable AsciiDoc specifications with sub-millisecond relational queries, full-text lexical search (FTS5 BM25), and zero-drift incremental indexing.

== Key Responsibilities
* **Living Specification Parsing, Blueprint Scaffolding, Schema Introspection, Brownfield Discovery (`INV-BROWNFIELD-DETERMINISTIC-DISCOVERY`, `INV-BROWNFIELD-REST-CONTROLLER-DISCOVERY`), Turnkey CI Templates (`INV-INIT-CI-WORKFLOW-TEMPLATES`) & Typed `FrontmatterModel`**: Robust extraction of YAML frontmatter (including trailing `---` markers and structured `UnicodeDecodeError` diagnostics) combined with AsciiDoc technical specifications, catalog-aware blueprint scaffolding (`eidos spec create <TYPE> <ID> --title <TITLE> [--client <CLIENT>] [--path <PATH>]`) across all 15 declarative specification & discovery blueprint types (`system`, `architecture`, `domain`, `capability`, `policy`, `persona`, `exploration`, `container`, `component`, `contract`, `design-system`, `ui-component`, `screen`, `client`, `flow`), dynamic v1 schema introspection (`eidos spec schema [TYPE] [--json]` via `get_spec_schema_info`), deterministic zero-AI polyglot brownfield blueprint discovery (`eidos spec discover [--path PATH] [--json]` via `discover_repository_blueprint`), opt-in turnkey CI workflow scaffolding (`eidos init --ci github|gitlab`), parent-directory-first entity type inference, and Pydantic `FrontmatterModel` (`SpecDocument.model`) normalization across parser, validator, catalog, and indexing pipelines.
