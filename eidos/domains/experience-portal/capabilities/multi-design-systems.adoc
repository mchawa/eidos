= Capability: Multi-Design Systems, W3C Tokens & Client Surface Management
:toc: left

== Job To Be Done (JTBD)
Govern brand tokens, multi-client application targets, UI component contracts, and interaction flows as first-class living specifications synchronized with code.

== Intent
Visual design systems, component state machines, and client runtimes frequently suffer from token drift and undocumented edge cases. This capability elevates frontend design into a first-class living specification pillar, enabling multi-client applications (`CLT-*`), canonical UI component contracts (`UIC-*`), screen state machines (`SCR-*`), and interaction flows (`FLOW-*`) directly inside Git.

== Key Responsibilities
* Cataloging base and branded design systems (`DS-*`) with `extends` inheritance chains, repository-contained `tokens.manifest` path verification (`is_relative_to`), and interactive recursive W3C DTCG token tree inspection.
* Mapping client targets (`web`, `mobile-ios`, `mobile-android`, `desktop`, `tui`, `cli`, `multi-platform`) to their bound design systems, C4 containers, and client-owned screens (`eidos/design/clients/<client>/screens/<screen>.adoc`, `INV-DESIGN-SCREEN-CLIENT-OWNERSHIP`).
* Formalizing multi-step user interaction flows with visual state-transition diagrams.
