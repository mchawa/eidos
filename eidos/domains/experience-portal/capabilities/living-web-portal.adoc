= Capability: Interactive Living Web Portal & Visual Documentation Engine
:toc: left

== Job To Be Done (JTBD)
Explore, search, and visually inspect living C4 architecture models, multi-client screens, and SpecDelta lifecycles without opening an IDE or compiling external frontend bundles.

== Intent
Technical specifications and architecture models are often trapped in raw text files or separate wikis. This capability provides a local, zero-dependency embedded HTTP server (`eidos portal serve`) and static site builder (`eidos portal build`) that turns living AsciiDoc files into an interactive single-page application.

== Key Responsibilities
* Real-time inspection and clickable hierarchical exploration of C4 Level 1 (Context), Level 2 (Containers), and Level 3 (Component Whitebox) models using client-side Mermaid rendering (`securityLevel: "strict"`), an in-place **full-page** zoomed diagram stage (`z-[45]`, up to `400%` zoom), interactive component-and-**connections** SVG highlighting (`c4Highlight.ts`), direct C4 SVG node Blast Radius simulation, and boundary interface contract (`CTR-*`) inspection.
* Slide-over component inspection drawer with uncramped full-height **Full Specification** prose for both containers and focused internal components plus **"Open in Full Reader"** escalation into `SpecReader`, lazy local `specs/<id>.json` body loading (with `--single-file` offline archive support), DOMPurify `SANITIZE_DOM` AsciiDoc rendering, and shareable `window.location.hash` (`#/...`) deep linking revealing module responsibilities, source paths, bound contracts, and catalog specifications.
* Same-origin loopback `Host` header isolation and real-time Server-Sent Events (`GET /api/events`) streaming live workspace and uncommitted drift (`/api/drift`) updates across `eidos/`, `src/`, and `tests/`.
* Interactive SpecDelta Kanban dashboard and Chronological Timeline tracking proposed, in-review, and applied mutations.
* Full-text fuzzy search (`⌘K`), real-time category filtering, and inline validation diagnostics (including non-blocking amber advisory validation `warnings` badges and collapsible diagnostics lists) across all catalog entities.
* **Team Operational Memory View & Inline Entity Cross-Links (`SCR-PORTAL-MEMORY`, `INV-PORTAL-TEAM-MEMORY-SURFACE`)**: Surfaces Git-native team memories (`agent/memory`, `MEM-*`) with category/freshness filters, non-blocking `memory_audit` hygiene highlights (separate from `validation.warnings`), zero-memory onboarding guidance, `HomeView` memory health summary, and inline active memory cross-links inside C4 container/component and Domain/Capability inspection drawers.
* **Interactive Embedded AsciiDoc Mermaid Diagram Rendering (`INV-PORTAL-DOCUMENT-MERMAID-RENDERING`)**: Automatically renders embedded AsciiDoc Mermaid (`[mermaid]` and `[source,mermaid]`) diagram blocks as interactive, theme-reactive Mermaid v12 SVG cards post-DOMPurify across all 8 portal views sharing `AsciiDocRenderer` (`UIC-PORTAL-READER`), with caption headers, `View Source` / `Copy` controls, non-scroll-trapping modifier-wheel zoom, and human-readable raw-source error fallbacks under `securityLevel: "strict"`.
* **Human-First, Slug-Free Presentation (`INV-PORTAL-HUMAN-READABLE-UI`)**: Renders human-readable titles, humanized statuses/types/states, plain-language copy, and clean Mermaid diagram labels across every view, navigation chrome, command palette, specification reader, and diagram while keeping canonical IDs strictly internal for routing, DOM/Mermaid click binding, and search indexing.
