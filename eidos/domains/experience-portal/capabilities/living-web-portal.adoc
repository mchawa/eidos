= Capability: Interactive Living Web Portal & Visual Documentation Engine
:toc: left

== Job To Be Done (JTBD)
Explore, search, and visually inspect living C4 architecture models, multi-client screens, and SpecDelta lifecycles without opening an IDE or compiling external frontend bundles.

== Intent
Technical specifications and architecture models are often trapped in raw text files or separate wikis. This capability provides a local, zero-dependency embedded HTTP server (`eidos portal serve`) and static site builder (`eidos portal build`) that turns living AsciiDoc files into an interactive single-page application.

== Key Responsibilities
* Real-time inspection and clickable hierarchical exploration of C4 Level 1 (Context), Level 2 (Containers), and Level 3 (Component Whitebox) models using client-side Mermaid rendering (`securityLevel: "strict"`), direct C4 SVG node Blast Radius simulation, and boundary interface contract (`CTR-*`) inspection.
* Slide-over component inspection drawer, lazy local `specs/<id>.json` body loading (with `--single-file` offline archive support), DOMPurify `SANITIZE_DOM` AsciiDoc rendering, and shareable `window.location.hash` (`#/...`) deep linking revealing module responsibilities, source paths, bound contracts, and catalog specifications.
* Same-origin loopback `Host` header isolation and real-time Server-Sent Events (`GET /api/events`) streaming live workspace and uncommitted drift (`/api/drift`) updates across `eidos/`, `src/`, and `tests/`.
* Interactive SpecDelta Kanban dashboard and Chronological Timeline tracking proposed, in-review, and applied mutations.
* Full-text fuzzy search (`⌘K`), real-time schema filtering, and inline validation diagnostics across all catalog entities.
