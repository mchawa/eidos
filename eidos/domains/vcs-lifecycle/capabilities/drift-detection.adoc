= Capability: Git-Native Spec-to-Code Drift Detection
:toc: left

== Job To Be Done (JTBD)
Detect and reconcile structural code-to-spec drift continuously across local working trees and Git commit ranges without manual documentation maintenance.

== Intent
Ensures that source code and living specifications never diverge via a deterministic drift detection and reconciliation gate. Through local Git diff analysis, decorator-aware AST structural symbol comparison, embedded knowledge graph lookups, and automated CI/CD gating, Eidos continuously verifies that structural code modifications are paired with living specification updates, preserving system documentation integrity with zero manual overhead.

By leveraging the SQLite Knowledge Graph (`eidos/.cache/index.db`), drift detection maps code diffs directly to architectural components, reuses canonical `CMP-GRAPH-STORAGE` cache helpers (`get_cached_spec_document`, `load_test_binding_cache`, `save_test_binding_cache`) without redundant inline DDL, and traverses 1-hop relational neighborhoods to recommend exact specification targets.

== Key Responsibilities
* **Git Diff Inspection**: Inspecting working trees, staged changes, and branch heads for unmapped architectural modifications via direct canonical `eidos.vcs.diff` and `eidos.vcs.structural` submodule signatures (`merge_base=resolved_mb`) without runtime `sys.modules` or `inspect.signature` introspection shims.
* **Decorator-Aware AST Structural Diffing**: Capturing enclosing `@decorator` and `#[attribute]` lines in `CodeSymbol.line_start` and prefixing normalized decorator/attribute annotations onto `CodeSymbol.signature` in `AstGrepIndexer` (`SgRoot`) across all 17 supported languages so CLI route, lifecycle, and visibility decorator changes are detected by `diff_public_symbols`.
* **Graph-Powered Reverse Symbol Resolution**: Resolving modified source code file paths to internal C4 components (`CMP-*`) and owning container IDs (`CNT-*`) in sub-millisecond SQLite queries rather than linear disk crawls.
* **1-Hop Neighborhood Resolution**: Querying the knowledge graph during `eidos drift` to discover bound interface contracts (`CTR-*`), domain capabilities (`CAP-*`), and parent containers affected by code changes.
* **Single Source of Truth Enforcement**: Gating CI/CD pipelines via `eidos drift` to guarantee that no pull request merges with un-synchronized specifications (`POL-001`).
* **Diff-Aware & Boundary-Aware Spec Coverage**: Rejecting "touch-to-appease" spec edits (blank lines, `//` comments, re-wrapping) as coverage for new source files and new public symbols, enforcing strict symbol/file anchoring (`is_anchored`) for unclaimed files and package/contract boundary exports while allowing substantive owning/1-hop spec updates to cover module-internal helper functions, and reporting rejected edits in `trivially_covered_files`.
* **Direct Mode Frictionless Co-evolution**: Enabling developers and autonomous agents to write code first and instantly reconcile specifications in the same commit.
