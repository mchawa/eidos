= Policy: Minimum 90% Per-File Statement Test Coverage
:toc: left

== Rationale

High aggregate repository coverage can mask poorly tested modules when large, heavily tested files offset low-coverage CLI entrypoints, parser edge cases, or VCS utilities. Enforcing a strict **>90% statement coverage floor per source file** across `src/eidos/` guarantees that every subsystem—CLI commands, living specification parser/validator, SQLite knowledge graph, SpecDelta lifecycle, Git drift detector, web portal, and agent plugin manager—is thoroughly exercised by automated regression tests.

== Enforcement Rules

1. **Per-File Statement Coverage Floor (>90.0%)**: Across `src/eidos/`, every Python module (excluding generated `src/eidos/_version.py` and frontend packaging scripts under `src/eidos/portal/frontend/`) must maintain strictly greater than `90.0%` statement coverage (`percent_covered > 90.0` per file in `coverage.json` from `pytest --cov=src/eidos --cov-report=json:coverage.json`).
2. **Declarative Coverage Configuration**: `pyproject.toml` must declare `[tool.coverage.run]` (`source = ["src/eidos"]`, `omit = ["src/eidos/_version.py", "src/eidos/portal/frontend/*"]`) and `[tool.coverage.report]` (`fail_under = 90`).
3. **Automated Invariant & CI Verification**: Verified per file via `coverage.json` in `tests/test_validator.py::test_pol_005_statement_test_coverage` (`INV-POL-005-STATEMENT-TEST-COVERAGE`) and `.github/workflows/ci.yml`.
