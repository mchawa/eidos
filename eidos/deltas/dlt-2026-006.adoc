= SpecDelta: Solution Architecture Synchronization with Multi-Design Systems, MCP Contract, and Lifecycle Scaffolding
:toc: left

== Problem Statement
The living architecture specifications (`ARCH-EIDOS-001` and `CMP-EIDOS-ENGINE`) had not been reconciled with several major recent evolutions in the codebase:
1. The stdio Model Context Protocol (MCP) server lacked an authoritative interface contract document (`CTR-EIDOS-MCP`) and was missing from `CMP-EIDOS-ENGINE` contracts and C4 internal components.
2. The Multi-Design System engine, W3C Design Tokens generation, and PluginValidator building blocks were unmapped in `CMP-EIDOS-ENGINE`.
3. The global C4 Context model and Arc42 cross-cutting concepts did not document MCP client connections, W3C token standards, or self-contained lifecycle view isolation.

== Proposed Specification Changes
1. Author `CTR-EIDOS-MCP` in `eidos/architecture/contracts/mcp.adoc` documenting all 10 callable MCP tools, protocol handshake, and schemas.
2. Update `CMP-EIDOS-ENGINE` in `eidos/architecture/components/engine.adoc`:
   - Declare provided contracts: `CTR-EIDOS-CLI` and `CTR-EIDOS-MCP`.
   - Add internal C4 modules: `McpServer`, `DesignEngine`, `PluginValidator`.
   - Update external service dependencies with JSON-RPC 2.0 Stdio Host.
3. Update `ARCH-EIDOS-001` in `eidos/architecture/system-architecture.adoc`:
   - Add AI IDEs & MCP Clients to C4 Context external systems and Mermaid diagram.
   - Expand Arc42 Solution Strategy and Cross-Cutting Concepts with multi-design systems, W3C tokens, and flat delta lifecycle isolation.
