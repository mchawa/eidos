= SpecDelta: Modularize Core and CLI God Modules into 1-to-1 C4 Component Modules
:toc: left

== Problem Statement

* `eidos/architecture/containers/core.adoc` declares `CMP-LIFECYCLE-SCAFFOLDER`, `CMP-DESIGN-ENGINE`, and `CMP-REPO-INITIALIZER` as distinct components, yet all three point to the same 2,039-line `src/eidos/core/scaffolder.py`. That file also houses an undeclared SpecDelta engine (`verify_delta_mutations`, `execute_delta_mutations`, `apply_delta`, baseline snapshots).
* `eidos/architecture/containers/cli.adoc` declares 11 components (`CMP-CLI-APP` through `CMP-CLI-DOCTOR-HOOKS`), yet all 11 point to the same 2,636-line `src/eidos/cli/main.py`.
* Because of this, `eidos context`, `eidos drift`, and blast-radius queries cannot tell these components apart: every change looks like a change to all of them.

== Architectural Mutations

Pure code motion: no behavior changes, CLI command tree unchanged, `CTR-EIDOS-CLI` unchanged.

[cols="2,3", options="header"]
|===
| Component | Module(s)
| `CMP-LIFECYCLE-SCAFFOLDER` | `src/eidos/core/lifecycle/scaffolder.py` (+ compat re-exports), `src/eidos/core/lifecycle/catalog.py`
| `CMP-DESIGN-ENGINE` | `src/eidos/core/lifecycle/design_engine.py`
| `CMP-REPO-INITIALIZER` | `src/eidos/core/lifecycle/initializer.py`
| `CMP-DELTA-ENGINE` _(new)_ | `src/eidos/core/lifecycle/delta_engine.py`
| `CMP-CLI-APP` | `src/eidos/cli/main.py`, `src/eidos/cli/_shared.py`
| `CMP-CLI-SPEC-COMMANDS` | `src/eidos/cli/spec_commands.py`
| `CMP-CLI-DELTA-COMMANDS` | `src/eidos/cli/delta_commands.py`
| `CMP-CLI-PLUGIN-COMMANDS` | `src/eidos/cli/plugin_commands.py`
| `CMP-CLI-DRIFT-COMMANDS` | `src/eidos/cli/drift_commands.py`
| `CMP-CLI-INIT-COMMAND` | `src/eidos/cli/init_command.py`
| `CMP-CLI-CONTEXT-COMMAND` | `src/eidos/cli/context_command.py`
| `CMP-CLI-INDEX-COMMANDS` | `src/eidos/cli/index_commands.py`
| `CMP-CLI-COMPONENT-COMMANDS` | `src/eidos/cli/component_commands.py`
| `CMP-CLI-PORTAL-COMMANDS` | `src/eidos/cli/portal_commands.py`
| `CMP-CLI-DOCTOR-HOOKS` | `src/eidos/cli/doctor_hook_commands.py`
|===

* **Dependency direction (module-level graph is acyclic):** `catalog.py` ← `delta_engine.py` ← {`initializer.py`, `scaffolder.py`}, `design_engine.py` ← `scaffolder.py`, and `catalog.py` ← `audit.py`. `scaffolder.py` re-exports from the others, and none of them imports `scaffolder.py` at module level. The single exception is a function-local `from eidos.core.lifecycle.scaffolder import create_spec` inside `execute_delta_mutations`: `create_spec` itself needs the view-sync and baseline helpers in `delta_engine.py`, so the call-time import is what keeps the module graph a DAG. `create_spec` delegates the design-layer branches to `design_engine.build_design_spec`. In the CLI, `_shared.py` ← every command module ← `main.py`; command modules expose `register(app: typer.Typer) -> None` and never import `main.py`. The only sibling import is `component_commands.py` → `spec_commands.components` (the `component list` command reuses it).
* **Compatibility:** `eidos = "eidos.cli.main:app"` and every name importable today from `eidos.core.lifecycle.scaffolder` and `eidos.cli.main` stay importable as the same objects. The re-exports are permanent (no deprecation planned).
* Update the `components` frontmatter and the AsciiDoc component tables in both `core.adoc` and `cli.adoc`.
