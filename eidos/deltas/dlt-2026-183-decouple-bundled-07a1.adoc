= SpecDelta: Decouple Bundled Agent Plugin Version from CLI Engine Releases
:toc: left

== Problem Statement
Previously, `get_bundled_plugin_version()` derived the bundled Agent Skills plugin version directly from `eidos.__version__`. Every CLI-only release (such as `v0.30.1`) therefore incremented `bundled_version` even when nothing under `assets/plugin_reference/` changed, forcing a manual `.agents/.eidos-manifest.json` release-bump commit in this repository and triggering blocking `OUTDATED` failures in `eidos doctor` across every downstream repository after `uv tool upgrade eidos-ai`.

== Proposed Specification Changes
* Introduce `assets/plugin_reference/VERSION` (plain-text SemVer 2.0.0 starting at `1.0.0`, respecting `DEC-PLUGIN-SKILLS-ONLY-ALL-TARGETS` without introducing a plugin bundle manifest) as the single source of truth for the bundled Agent Skills version.
* Record `DEC-PLUGIN-DECOUPLED-VERSION` on `CNT-EIDOS-PLUGIN`.
* Split version resolution in `CMP-PLUGIN-INSTALLER` (`src/eidos/plugin/version.py`):
  - `get_bundled_plugin_version(bundle_dir: Path | None = None) -> str` reads `assets/plugin_reference/VERSION` (`PLUGIN_VERSION_FILENAME`), falling back safely to `get_cli_release_semver()` only when `VERSION` is absent or unreadable.
  - `get_cli_release_semver() -> str` retains the PEP 440 / post-tag `.devN` -> base release SemVer resolution for `eidos.__version__`.
* Update `CMP-HOOK-MANAGER` (`src/eidos/plugin/hook_adapters.py`) so `uvx` hook pinning (`uvx --from eidos-ai==<ver> eidos hook`) calls `get_cli_release_semver()` rather than `get_bundled_plugin_version()`.
* Update `CMP-PLUGIN-VALIDATOR` (`src/eidos/plugin/validator.py`) so `validate_plugin_package()` reads and validates `<plugin_dir>/VERSION` directly when present (catching invalid SemVer in `VERSION` during `eidos plugin validate`).
* Bump `CAP-AGENT-ADAPTER` to `1.23.0` and extend `INV-PLUGIN-INSTALL-TRUTHFULNESS`.

== Implementation Plan
1. **Bundled Version Asset**: Create `assets/plugin_reference/VERSION` containing `1.0.0` (owned by `CNT-EIDOS-PLUGIN`).
2. **Decoupled Version Resolution**: Split `get_cli_release_semver()` and `get_bundled_plugin_version()` in `src/eidos/plugin/version.py` (`CMP-PLUGIN-INSTALLER`), update `_resolve_hook_command()` in `src/eidos/plugin/hook_adapters.py` (`CMP-HOOK-MANAGER`), and validate `<plugin_dir>/VERSION` in `src/eidos/plugin/validator.py` (`CMP-PLUGIN-VALIDATOR`).
3. **CLI Label & Docs**: Update the `Bundled Version` label in `src/eidos/cli/plugin_commands.py` (body-only; no spec mutation) and refresh sample outputs in `docs/guides/agent-plugin.md` (body-only; no spec mutation).
4. **Tests & Invariant Binding**: Update `tests/test_plugin.py` (`test_normalize_to_semver_and_bundled_version_sync`, `test_installer_truthful_version_comments_symlinks_and_uninstall`, and `uvx` hook pinning tests) to cover `INV-PLUGIN-INSTALL-TRUTHFULNESS` and `>90%` per-file / diff-line coverage (`POL-STATEMENT-TEST-COVERAGE`).
5. **Living Spec Co-Evolution & Plugin Sync**: Update `CNT-EIDOS-PLUGIN`, `CMP-PLUGIN-INSTALLER`, `CMP-PLUGIN-VALIDATOR`, `CMP-HOOK-MANAGER`, `CAP-AGENT-ADAPTER`, and `MEM-RUN-EIDOS-PLUGIN-UPDATE-AFTER-6E84`, run `uv run eidos plugin update antigravity` to stamp `.agents/.eidos-manifest.json` to `1.0.0`, and verify via `eidos delta verify`, `eidos delta apply`, and `eidos drift --uncommitted --json`.
