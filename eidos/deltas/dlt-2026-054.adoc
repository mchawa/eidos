= SpecDelta: Portal Data Engine Synchronization, Full C4 Target Schema Coverage, and UI Navigation Polish
:toc: left

== Problem Statement

A thorough audit of the Eidos Living Web Portal revealed several accumulated schema desynchronizations and UI rendering gaps:

1. **SpecDelta Mutations Fallback**: 64% of mutations across the 53 SpecDeltas rendered as `"Target Specification"` because `DeltasView.tsx` only inspected `m.target_component || m.target_capability || m.target_domain || m.target_screen`, ignoring `target_container`, `target_architecture`, `target_contract`, `target_policy`, `target_persona`, `target_invariant_id`, `target_design_system`, `target_ui_component`, `target_client`, `target_flow`, and `new_capability_id`. Declarative `expect:` post-conditions were unrendered.
2. **Blast Radius & `affects:` Extraction**: `generator.py` omitted `affects:`, and `DeltasView.tsx` checked non-standard keys (`impact_level`, `domains`, `components`) while `delta.schema.yaml` specifies `impacted_containers`, `impacted_components`, `impacted_personas`, `impacted_design_systems`, `impacted_screens`, and `invariants_to_enforce`.
3. **C4 Promoted Components Conflation**: `generator.py` treated standalone `tech/component` specs as C4 Level 2 containers instead of attaching them to their parent container's Level 3 internal components whitebox. `CatalogView.tsx` omitted `tech/component` from `SPEC_CATEGORIES.architecture.types`.
4. **Decisions (`DEC-*`) and Invariants Missing**: Embedded architectural decisions on system, architecture, and container specs were omitted from the portal data model. Component-level invariants (`INV-*`) declared in containers or components were omitted from the governance invariants table.
5. **Container Subtext & AsciiDoc Inspector**: Container cards fell back to `"Core system container"` because `generator.py` never populated `responsibility` or `summary`. Container descriptions in the inspector were rendered in plain text rather than `AsciiDocRenderer`.
6. **Spotlight Search & Drilldown Disconnects**: `CMD+K` spotlight selection switched tabs but failed to select or focus the specific item. `onNavigateDelta` from Explorations did not select the target delta. `DesignView.tsx` duplicated client-specific flows in the Omnichannel panel.
7. **AsciiDoc Table Corruption**: Regex pipes in `dlt-2026-042.adoc` broke AsciiDoc table parsing, and Markdown `[text](...)` links were embedded in AsciiDoc specs.

== Proposed Specification Changes

1. **Portal Generator (`src/eidos/portal/generator.py`)**:
   * Extract container `responsibility` and `summary` from frontmatter or the `== Architectural Boundary` body section.
   * Attach promoted `tech/component` specs to their parent container's Level 3 `internal_components` by resolving `ref:` / `spec_path` / `id` stubs in-place rather than leaving unresolved stubs or treating them as top-level containers.
   * Extract embedded decisions (`decisions`) from system, architecture, container, and promoted component documents.
   * Extract container-level and component-level invariants (`invariants`) from containers and components into the global invariants list.
   * Normalize top-level `findings`, `recommendation`, and `resulting_deltas` on `product/exploration` specs into `decision` and top-level fields.
   * Extract `affects:` (`containers`, `components`, `capabilities`, `contracts`, `domains`, `policies`) and preserve full `blast_radius:` on SpecDeltas.
   * Extract `technical_mapping.containers` on domains and `technical.containers` on capabilities.
2. **Frontend Views (`src/eidos/portal/frontend/src/`)**:
   * `types.ts`: Update `SpecDelta`, `SpecComponent`, `SpecCapability`, `SpecDomain`, `SpecExploration`, `CommandItem` interfaces.
   * `DeltasView.tsx`: Resolve all mutation target keys (`target_container`, `target_architecture`, `target_contract`, `target_policy`, etc.), render `expect:` assertions, format plural `affects` labels (`Capabilities:`, `Policies:`), display `blast_radius.impacted_design_systems`, and support re-focusing a delta via selection nonce.
   * `ArchitectureView.tsx`: Display container responsibility subtext, render living spec body via `AsciiDocRenderer`, display `data.decisions` and component-level `invariants`/`decisions` in the C4 Inspector drawer, and support opening/re-opening by initial container ID and nonce.
   * `BusinessView.tsx`: Render `technical.containers` and `technical_mapping.containers`, add a Governance Invariants (`INV-*`) section and detail drawer, and support focusing items selected via `CMD+K`.
   * `ExplorationsView.tsx`: Render `resulting_deltas` (clickable to navigate to `DeltasView`), `findings`, and `recommendation`, and support focusing items selected via `CMD+K`.
   * `DesignView.tsx`: Fix omnichannel flows panel to render `omnichannelFlows` instead of `flows`.
   * `CatalogView.tsx`: Add `tech/component` to `SPEC_CATEGORIES.architecture.types` and add the `arch-components` (`Components (C4 L3)`) subgroup.
   * `App.tsx`: Deduplicate `commandItems` across specialized categories and generic specs, include `rejected` deltas, and connect `handleCommandSelect` and `onNavigateDelta` with selection nonces and clear callbacks.
3. **Living Specs & Documentation**:
   * Fix table cell pipe escaping in `dlt-2026-042.adoc`.
   * Convert markdown links to AsciiDoc syntax in `dlt-2026-034.adoc`, `dlt-2026-035.adoc`, `dlt-2026-039.adoc`, `dlt-2026-042.adoc`.
   * Reconcile runtime view links in `ARCH-EIDOS-001`.
   * Register `portal-explorations.adoc` in `CAP-EXP-001`.
   * Update `docs/guides/living-portal.md`.
