= SpecDelta: Scalable Portal UX: Scope Lens, Full-Page C4 Stage, and Progressive Hierarchy
:toc: left

== Problem Statement
When a repository scales to dozens of C4 containers (`CNT-*`) and hundreds of components (`CMP-*`), capabilities (`CAP-*`), invariants (`INV-*`), decisions (`DEC-*`), and historical SpecDeltas (`DLT-*`), the Eidos Living Web Portal experience becomes visually noisy and disorienting:

1. **No Global Scope Filtering**: Every tab (`Home`, `Architecture`, `Business`, `Deltas`, `Catalog`) renders 100% of the repository simultaneously with no way to focus the portal on a specific Bounded Context (`DOM-*`) or Container (`CNT-*`).
2. **Cramped C4 Viewport**: The C4 diagram card in `ArchitectureView` is constrained to a `580px` (`800px` expanded) inline card surrounded by headers, legends, and page chrome, which feels cramped when exploring large Level 2 Container topologies or Level 3 Component whiteboxes.
3. **Endless Vertical Card Walls**:
   * `ArchitectureView` stacks all Containers, then all Contracts (`CTR-*`), then all Architectural Decisions (`DEC-*`) in ungrouped 3-column grids at the bottom of the page.
   * `BusinessView` embeds every bound `CAP-*` vertically inside each Domain card, creating uneven multi-thousand-pixel cards followed by a flat list of all invariants.
4. **Catalog Tree-Grid Overload & Flat `CMP-*` Bucket**: `CatalogView` expands all categories and all subgroups on mount, places all `CMP-*` components into a single flat `Components (C4 L3)` subgroup instead of nesting them under their owning `CNT-*` container, and mixes historical applied/archived deltas with active specifications.
5. **Empty Kanban Columns in `DeltasView`**: When all or most deltas are `applied` or `archived`, the 6-column Kanban board shows 3–4 empty dashed columns alongside overflowing historical columns.
6. **Context-Losing Cross-Reference Jumps & Unstructured `⌘K`**: Clicking an entity badge inside an inspector drawer switches the background tab and replaces the drawer with no `← Back` history button, and `⌘K` displays a flat list of 50 items without category grouping or filter pills.
7. **Redundant Double-Work in Backend Data Synthesis & Live Serving (`CMP-PORTAL-GENERATOR`, `CMP-PORTAL-SERVER`)**:
   * `get_portal_data()` runs `SpecValidator.validate_directory()` before `arch_idx._ensure_synced()`, and `EidosPortalHandler._get_cached_validation()` runs a second independent `SpecValidator.validate_directory()` pass even when `_get_cached_portal_data()` has already computed `data["validation"]`.
   * Live server mode (`/api/data`) serializes every specification's AsciiDoc `body` twice (once in `data.specs` and again in `data.components`, `data.domains`, `data.capabilities`, `data.deltas`) because `_deduplicate_portal_payload()` was only wired into `build_static_portal()`, and re-serializes `orjson.dumps()` on every HTTP request.
   * `get_portal_data()` runs `compute_delta_impact()` multi-hop graph queries for every historical archived/applied SpecDelta on every refresh.

== Proposed Specification Changes

=== 1. Global Scope Lens (`UIC-PORTAL-SHELL`, `App.tsx`)
* Add a persistent **Scope Lens** selector in the sticky top header bar allowing users to filter the portal by:
  * **All System** (default)
  * **Bounded Domain (`DOM-*`)**
  * **C4 Container (`CNT-*`)**
* Synchronize the active scope across `HomeView`, `ArchitectureView`, `BusinessView`, `DeltasView`, and `CatalogView` (with a clear active-scope pill and one-click reset).

=== 2. Dedicated Almost-Full-Page C4 Canvas Mode (`SCR-PORTAL-ARCHITECTURE`, `ArchitectureView.tsx`)
* Add an **"Enlarge C4 Canvas (Full Page)"** control (`fixed inset-3 z-50` / `~96vw × 94vh` elevated stage with backdrop blur) to `ArchitectureView` (and reusable via `MermaidDiagram`):
  * Provides maximum screen real estate for C4 Level 1, Level 2, and Level 3 diagrams without leaving the portal context.
  * Retains the full C4 toolbar inside the top bar of the full-page stage: Level 1/2/3 switcher, breadcrumbs, Level 3 container selector dropdown, Tier legend, Blast Radius simulator selector, zoom/pan/auto-fit controls, and `ESC` / close button.
  * Clicking any container or component node inside the full-page canvas drills down or opens the C4 Inspector Drawer directly over the full-page stage.

=== 3. Segmented Sub-Views & Bounded Domain Cards (`SCR-PORTAL-ARCHITECTURE`, `SCR-PORTAL-BUSINESS`)
* **`ArchitectureView` Sub-Navigation Tabs**: Replace the long vertical stack below the C4 diagram with clean segmented sub-views:
  1. **Topology & Blast Radius**: Interactive C4 Explorer and structured Blast Radius Simulator (grouped by `1-Hop Direct` vs. `2-Hop Transitive` and entity category).
  2. **Containers (`CNT-*`)**: Grouped by Architectural Tier or Domain with instant filter search.
  3. **Interface Contracts (`CTR-*`)**: Searchable contract cards with provider/consumer badges.
  4. **Decisions Ledger (`DEC-*`)**: Searchable architectural decisions grouped by owning System / Container / Domain.
* **`BusinessView` Bounded Cards & Grouped Invariants**:
  * Cap inline capabilities displayed inside each Domain card to 4 items with a `+N more capabilities →` button that opens the Domain inspector or expands the card in place.
  * Group the `Invariants (INV-*)` section by owning Domain, Policy, or Container with quick filter pills (`All`, `Policy`, `Capability`, `Architecture`).
* **`DesignView` Split: Design System vs. Screens & Flows (`SCR-PORTAL-DESIGN`)**:
  * Remove the combined `"Full Overview"` (`activeTab = "all"`) dump that stacks tokens, clients, UI components, screen state machines, and flow diagrams on one long page.
  * Split `SCR-PORTAL-DESIGN` into two distinct primary workspaces:
    1. **Design Systems & UI Components (`DS-*`, W3C Tokens, `UIC-*`)**: Focused exclusively on design system selection (`DS-*`), W3C DTCG token swatches/scales/tree (`tokens.json`), and reusable UI Component contracts (`UIC-*`).
    2. **Screens & Flows (`CLT-*`, `SCR-*`, `FLOW-*`)**: Focused exclusively on Client Surfaces (`CLT-*`), Screen Architectures & State Machine diagrams (`SCR-*`), and Client/Omnichannel Interaction Flows (`FLOW-*`).

=== 4. True C4 Container Nesting & Progressive Collapse in `CatalogView` (`SCR-PORTAL-CATALOG`)
* **Container-to-Component Nesting**: Under `Architecture & Technology`, make each `CNT-*` Container a collapsible Level 2 subgroup (`parentSpec: container`) containing its child `CMP-*` (Level 3 Components) and provided `CTR-*` (Contracts), matching how `DOM-*` nests `CAP-*`.
* **Progressive Disclosure**: Default Level 2 subgroups to collapsed when the repository exceeds 40 specifications (keeping Level 1 pillars visible with aggregate counts and validity badges), while still auto-expanding matching branches during search.
* **Historical Spec Toggle**: Hide archived/applied `DLT-*` and archived `EXP-*` specs from the default Catalog view behind a `"Show Historical / Archived (N)"` toggle chip in the toolbar.

=== 5. Active-First `DeltasView` (`SCR-PORTAL-DELTAS`)
* Hide `Archived` and `Rejected` columns from the default Kanban board behind a `"Show Archived & Rejected"` toggle chip.
* Auto-default `viewLayout` to `"timeline"` (Chronological Changelog) when there are zero active (`proposed`, `in_review`, `approved`) deltas, while preserving one-click switching back to `"kanban"`.

=== 6. In-Drawer Navigation History (`← Back`) & Grouped `⌘K` Palette (`UIC-PORTAL-SHELL`, `UIC-PORTAL-READER`)
* **Inspector Breadcrumb Trail**: Track an inspection history stack when a user clicks an `xref:` or entity badge inside `SpecReader` or entity inspector drawers, rendering a `← Back to <PREV-ID>` button and breadcrumb trail in the drawer header instead of abruptly losing context.
* **Grouped `⌘K` Command Dialog**: Group results by category (`Containers & Components`, `Domains & Capabilities`, `Contracts`, `Decisions`, `Invariants`, `Policies`, `Deltas`), add quick category filter chips at the top of the dialog, and surface recently inspected entities when the search query is empty.

=== 7. Single-Pass Backend Synthesis & Deduplicated Live Caching (`CMP-PORTAL-GENERATOR`, `CMP-PORTAL-SERVER`, `CTR-EIDOS-PORTAL`)
* **Single-Pass Sync & Validation Reuse**: Ensure `arch_idx._ensure_synced()` runs before validation in `get_portal_data()` so warm SQLite spec cache rows are shared, and make `EidosPortalHandler._get_cached_validation()` reuse `_get_cached_portal_data()["validation"]` instead of running `SpecValidator.validate_directory()` a second time.
* **Batch SpecDelta Impact Lookup Memoization**: Cache/reuse the graph topology lookup context and memoize normalized mutation target tuples across the `raw_deltas` loop in `get_portal_data()` so all active and historical/archived SpecDeltas retain complete `affects` and `blast_radius` dictionaries (`containers`, `impacted_containers`, `invariants_to_enforce`) without repeating full-table SQLite scans per delta.
* **Deduplicated & Pre-Serialized Live `/api/data` Payload**: Apply `_deduplicate_portal_payload()` to `/api/data` in `EidosPortalHandler` (matching static builds where `App.tsx` runs `hydratePortalData()`) and cache the serialized JSON bytes alongside the mtime snapshot so spec bodies are never serialized twice.
