decisions:
  - id: DEC-CLI-BLUEPRINT-SPEC-CREATE
    title: Scope eidos spec and eidos delta Strictly to Disjoint Blueprint Lifecycles and Uniform CLI Flags
    decision: "Enforce a 100% disjoint boundary between 'eidos spec' (create, list, show, delete across the 15 declarative specification & discovery blueprints, including exploration EXP-* and excluding/rejecting delta/mutation DLT-*) and 'eidos delta' (create, list, status, verify, audit, apply, delete, changelog exclusively for SpecDeltas), simplify 'eidos spec create <TYPE> <ID> --title <TITLE> [--path <PATH>]' and 'eidos delta create [ID] --title <TITLE> [--kind <KIND>] [--slug] [--path <PATH>]' (auto-detecting Git branch), remove redundant/deprecated CLI flags (--with-plugin, --repo-root, duplicate --target, standalone 'eidos version'), and standardize '--json' across all JSON-capable commands including 'eidos context' and 'eidos index repo-map'."
    rationale: "Keeping exploration (EXP-*) under 'eidos spec' preserves a clean conceptual split: 'eidos spec' manages declarative specifications and discovery blueprints, whereas 'eidos delta' manages executable architectural mutations with verification/audit/apply/changelog machinery. Eliminating 16 type-specific flags on 'spec create', 2 redundant flags on 'delta create', duplicate argument+option bindings on 'plugin', and inconsistent '--format json' flags reduces CLI surface area and ensures authors and AI agents start from clean, minimal, schema-valid blueprints."
    rejected_alternatives:
      - option: Retain the 16 type-specific CLI flags on eidos spec create and --motivation / --branch on eidos delta create
        reason_rejected: Clutters CLI help and injects opinionated boilerplate that must be manually deleted when authoring specifications.
      - option: Allow both eidos spec (create/list/show/delete) and eidos delta (create/list/delete) to operate on SpecDeltas (DLT-*)
        reason_rejected: Violates the single canonical command path principle by maintaining duplicate CRUD entrypoints for SpecDeltas.
      - option: Move exploration (EXP-*) out of eidos spec or into its own top-level command group
        reason_rejected: "Explorations are pure declarative blueprints (create/list/show/delete) with no special execution engine, making them a natural fit for eidos spec."
      - option: Retain --format markdown|json on eidos context and eidos index repo-map
        reason_rejected: Creates a two-flag inconsistency where 12 commands use --json and 2 commands require --format json.
