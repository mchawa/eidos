decisions:
  - id: DEC-SCHEMA-PROSE-IN-BODY-AND-AST-EDGES
    title: Keep YAML Frontmatter Strictly for Machine-Indexed Metadata and Graph Edges while Moving Prose to AsciiDoc and Deriving Schema and Component Dependencies Automatically
    decision: "Remove top-level schema (always deriving schema deterministically from type via TYPE_TO_SCHEMA_NAME) and narrative prose blocks (business_identity, technical_profile, boundaries, ubiquitous_language, business.jtbd, business.pricing_tiers, goals, pain_points, interaction_modes, exploration hypothesis/questions_to_answer/spikes_to_run/exit_criteria/decision.learnings, architecture topology_style/solution_strategy/cross_cutting_concepts/deployment_view/c4_containers, and quality_attributes) from YAML frontmatter into the AsciiDoc body, make contract specification_file optional, generalize external_references to an open string map, unify UI component verification on standard invariants, remove manual component interfaces in favor of AstGrepIndexer.extract_imports, and relax SpecDelta target/operation/expect.frontmatter restrictions."
    rationale: "YAML frontmatter should only encode machine-validated identifiers, lifecycle statuses, file/test bindings, and semantic cross-references (x-eidos-ref). Because every specification declares a 1:1 'type' mapped in TYPE_TO_SCHEMA_NAME, declaring 'schema' in frontmatter is 100% redundant. Similarly, long-form prose in YAML duplicates the AsciiDoc body and forces placeholder boilerplate during scaffolding, while manual component interface lists duplicate relationships that the polyglot AST indexer can derive deterministically from source code imports."
    rejected_alternatives:
      - option: Retain explicit or optional schema field in YAML frontmatter
        reason_rejected: "Every Eidos specification has a canonical 1:1 mapping from type to schema in TYPE_TO_SCHEMA_NAME; keeping schema in frontmatter is pure boilerplate and risks type/schema mismatch."
      - option: Retain required narrative fields in YAML frontmatter with placeholder strings
        reason_rejected: Forces authors and scaffolders to duplicate prose across both YAML frontmatter and AsciiDoc sections.
      - option: Retain manual interfaces.provides and interfaces.consumes in component YAML frontmatter
        reason_rejected: Duplicates symbol and import graphs that AstGrepIndexer and _CodeOwnershipResolver can extract directly from source_path.
