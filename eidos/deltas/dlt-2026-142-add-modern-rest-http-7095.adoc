= SpecDelta: Add Modern REST HTTP Contract Parity and Authorization Attribute Verification
:toc: left

== Problem Statement
`ContractParityValidator` currently enforces bidirectional parity only for `openapi`/`rest_openapi`, `protobuf`/`grpc_proto`, `graphql`, `json_schema`, `python_protocol`, and `cli_args`. Modern HTTP/REST contracts (`protocol: rest_http` or `http_json`) implemented directly in code—such as ASP.NET Core controllers (`[Route]`, `[HttpGet|Post|Put|Patch|Delete]`) and Minimal APIs (`MapGet`/`MapPost`/...)—silently bypass parity verification in `eidos validate`, allowing omitted endpoints and drifted `[Authorize]` / `[AllowAnonymous]` annotations to pass undetected.

**Explicit Scope Boundary (No Legacy Technologies)**: This SpecDelta targets **modern** REST HTTP frameworks only (ASP.NET Core controllers & Minimal APIs plus modern polyglot REST frameworks already parsed by `ast_http.py`). Legacy SOAP/WCF (`soap_wcf`, `[ServiceContract]`/`[OperationContract]`, `.svc`, `.wsdl`, `.asmx`) and legacy .NET Framework ASP.NET Web API 2 / WebForms (`[RoutePrefix]`, `[AcceptVerbs]`, `IHttpHandler`, `.aspx`) are intentionally excluded.

== Proposed Specification Changes
* **`CMP-HTTP-TOPOLOGY-LINKER` (`src/eidos/core/index/ast_http.py`, `src/eidos/core/index/http_linker.py`)**: Fix ASP.NET Core route extraction (`[action]` token substitution, leading `/` and `~/` root overrides, full action attribute-block scanning for `[Route(...)]` above or below `[Http*]`), extract effective ASP.NET Core authorization attributes (`[Authorize(...)]` including `Roles`/`Policy`, `[AllowAnonymous]`, Minimal API `MapGroup`/`Map*` `.RequireAuthorization(...)` / `.AllowAnonymous()`), and link `protocol: rest_http` contract route tables in `_extract_contract_http_routes`.
* **`CMP-CONTRACT-PARITY-VALIDATOR` (`src/eidos/core/spec/contract_parity.py`)**: Add `_verify_rest_http_contract` for `rest_http` and `http_json` supporting single-file, directory, and glob/brace-glob `specification_file` targets, checking bidirectional `(METHOD, normalized_path)` parity (skipping reverse phantom-route scans when 0 framework endpoints are extracted so custom/stdlib servers such as `BaseHTTPRequestHandler` do not false-positive) and opt-in contradiction-only `[Authorize]` / `[Authorize(Roles/Policy=...)]` / `[AllowAnonymous]` parity when explicitly documented on a route entry (100% deterministic per `POL-004-ZERO-AI-CALL-DEPENDENCY`).
* **`CMP-SPEC-VALIDATOR` (`src/eidos/core/spec/validator.py`)**: Preserve directory and multi-file glob/brace-glob `specification_file` patterns when dispatching `rest_http` / `http_json` parity verification.
* **`CNT-EIDOS-CORE` (`assets/schemas/v1/tech/contract.schema.yaml`, `eidos/architecture/containers/core.adoc`)**: Document directory/glob `specification_file` support and record `DEC-CORE-MODERN-REST-PARITY-ONLY` (`graduated_from: DLT-2026-142-ADD-MODERN-REST-HTTP-7095`, documenting modern ASP.NET Core + polyglot REST parity and recording legacy SOAP/WCF and .NET Framework Web API 2 / WebForms as `rejected_alternatives`).
* **`CMP-DOCS-CORE-CONCEPTS`, `CMP-DOCS-USER-GUIDES` & `CAP-PROD-001`**: Synchronize `docs/concepts/how-eidos-works.md` and `docs/guides/cli.md` (`INV-DOCS-SYNCHRONIZATION`) and add `INV-CONTRACT-REST-HTTP-PARITY` in `eidos/domains/spec-engine/capabilities/living-spec-engine.adoc`.
