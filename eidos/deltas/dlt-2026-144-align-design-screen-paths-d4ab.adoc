= SpecDelta: Enforce Client-Scoped design/screen Paths and Ownership, Add --client to spec create, and Align Modern Contract Protocols
:toc: left

== Problem Statement
Three schema, scaffolder, skill-documentation, and design-validation discrepancies currently exist across Eidos:

1. **`design/screen` path contradiction**: `eidos-spec/SKILL.md`, `docs/concepts/design.md`, and Eidos's own portal specs place screens under `eidos/design/clients/<app>/screens/<screen>.adoc`, yet `eidos spec create screen` (`design_engine.py`) scaffolds into flat `eidos/design/screens/<screen>.adoc` and `eidos validate` does not enforce client-scoped screen placement.
2. **Orphaned active screens pass silently**: `validate_design_systems()` validates only `design/system` token manifests and `extends` cycles; active `SCR-*` specs not claimed by any `design/client` (`CLT-*.screens`) pass `eidos validate` silently and render with `client: "N/A"` in the Living Web Portal.
3. **`tech/contract` `protocol` drift and `protobuf`/`grpc_proto` divergence**: `assets/schemas/v1/tech/contract.schema.yaml` omits modern aliases already handled by the runtime (`grpc_proto`, `rest_openapi`, `http_json`, plus `rest_http`), and `ContractParityValidator._verify_grpc_proto_contract` verifies `.proto` top-level `message`/`enum` symbols only for `protobuf` while skipping them for `grpc_proto`. (Legacy protocols such as `soap_wcf` are intentionally excluded.)

== Proposed Specification Changes
* **`CMP-CLI-SPEC-COMMANDS` (`src/eidos/cli/spec_commands.py`), `CMP-LIFECYCLE-SCAFFOLDER` (`src/eidos/core/lifecycle/scaffolder.py`), `CMP-DESIGN-ENGINE` (`src/eidos/core/lifecycle/design_engine.py`), `CTR-EIDOS-CLI`, `CMP-DOCS-USER-GUIDES`**: Add `--client` (`-c`) to `eidos spec create` (required with no silent default when creating a `screen` / `design/screen`), resolving a `CLT-*` ID, client `.adoc` path, or client slug to scaffold strictly into `eidos/design/clients/<client-slug>/screens/<screen>.adoc`.
* **`CMP-SPEC-VALIDATOR` (`src/eidos/core/spec/validator.py`, `src/eidos/core/spec/design_validation.py`)**: Enforce blocking validation errors when (a) a `design/screen` (`SCR-*`) spec resides outside `eidos/design/clients/<app>/screens/<screen>.adoc`, or (b) a `status: active` `design/screen` (`SCR-*`) is not referenced in `screens:` of at least one `design/client` (`CLT-*`, resolving both `SCR-*` IDs and relative `.adoc` paths; `draft`/`planned`/`deprecated`/`retired` exempt).
* **`CMP-CONTRACT-PARITY-VALIDATOR` (`src/eidos/core/spec/contract_parity.py`), `CNT-EIDOS-CORE` (`assets/schemas/v1/tech/contract.schema.yaml`), `CNT-EIDOS-PLUGIN` (`assets/plugin_reference/skills/eidos-spec/SKILL.md`), `CMP-DOCS-CORE-CONCEPTS` (`docs/concepts/schema-glossary.md`)**: Make `protobuf` and `grpc_proto` identical aliases in `_verify_grpc_proto_contract` and align modern protocol documentation across schema, skill, and docs (retaining `pattern: \S`, strictly within `INV-PLUGIN-SKILL-SIZE-CEILING` `eidos-spec <= 2250` words and `INV-DOCS-SYNCHRONIZATION`, with zero legacy `soap_wcf` support).
* **`CAP-EXP-002` & `CAP-PROD-001`**: Add `INV-DESIGN-SCREEN-CLIENT-OWNERSHIP` and `INV-CONTRACT-PROTOCOL-SCHEMA-SYNC`.

== Implementation Plan
