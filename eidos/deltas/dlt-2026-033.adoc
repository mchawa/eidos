= SpecDelta: Normalize PreToolUse and PostToolUse Hook Payloads Across AI Agent Harnesses
:toc: left

== Problem Statement

In `src/eidos/plugin/hooks.py` (`handle_lint_pre_tool_use`, lines 51–103), the `PreToolUse` linter only inspects `tool_name in ("write_to_file", "replace_file_content")` and reads `TargetFile`, `CodeContent`, `TargetContent`, and `ReplacementContent`. While those match Google Antigravity's tool schema, Claude Code sends `tool_name in ("Write", "Edit", "MultiEdit")` with `tool_input.file_path`, `tool_input.content`, `tool_input.old_string`, and `tool_input.new_string` (and `PostToolUse` payloads also pass file paths in `tool_input` when `EIDOS_TARGET_FILE` is not set in the environment). Consequently, `PreToolUse` and `PostToolUse` specification linting is silently bypassed on non-Antigravity harnesses.

== Architectural & Behavioral Mutations

1. **Harness-Agnostic Tool Input Normalizer (`_extract_tool_edit_request`)**:
   * Normalize `tool_name` and `tool_input` / `tool_Args` across all supported coding agents:
     - **Antigravity**: `write_to_file`, `replace_file_content`, `multi_replace_file_content` (`TargetFile`, `CodeContent`, `TargetContent`, `ReplacementContent`, `ReplacementChunks`).
     - **Claude Code / Cursor / OpenCode / Cline**: `Write`, `Edit`, `MultiEdit`, `create_file`, `edit_file`, `str_replace_editor` (`file_path`, `path`, `target_file`, `content`, `file_text`, `old_string`, `new_string`, `old_str`, `new_str`, `edits`).
2. **`PostToolUse` Stdin Fallback**:
   * When `EIDOS_TARGET_FILE` is not set in environment variables during `PostToolUse`, extract `file_path` / `TargetFile` from the stdin JSON payload so single-file `.adoc` validation works identically across all harnesses.

== Verification Criteria

* Passing simulated Antigravity (`write_to_file` / `replace_file_content`), Claude Code (`Write` / `Edit` / `MultiEdit`), and Cursor stdin JSON payloads with invalid `.adoc` YAML frontmatter to `eidos hook lint --event PreToolUse` returns a blocking decision in all cases.
* Unit tests in `tests/test_plugin.py` cover all supported agent harness payload formats.
