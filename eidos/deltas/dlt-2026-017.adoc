= SpecDelta: SpecDelta Deletion and Deprecation Audit Engine (eidos delta audit)
:toc: left

== Problem Statement
When a capability, container, contract, policy, or domain is deprecated or removed via a SpecDelta (such as `DLT-2026-016` retiring the MCP server), human developers and autonomous AI agents often leave lingering references in active specifications, code generators, documentation, or contracts.

A naive grep fails because many references are legitimate:
1. Past applied SpecDeltas must preserve historical accuracy.
2. Regression tests must verify that deleted files or endpoints are *not* created (`assert not ...`).
3. Uninstallation routines must clean up legacy files from workstations.
4. User guides need to explain *why* an architectural shift took place.

== Proposed Architecture & Solution
Introduce `eidos delta audit <delta-id>`:
1. **Graph Integrity Check**: Traverses the SQLite `ArchitecturalIndex` to verify zero dangling edges in active living specs.
2. **Semantic Reference Classifier**: Scans the workspace and categorizes references into:
   - **Exempt / Approved**: Applied historical deltas, negative test assertions, cleanup functions, and declared tombstones.
   - **Unacknowledged Leaks**: Active living specs, active code generators, CLI app contracts, and user guides.
3. **Structured & Agent-Friendly Output**:
   - Rich terminal table highlighting risk tiers.
   - Strict exit code (`--strict`) for automated PR checks.
   - Machine-readable JSON output (`--json`) enabling autonomous agents to self-heal without human prompting.
