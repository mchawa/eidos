= SpecDelta: Expand Canonical Contract Protocols with Polyglot Interface, WSDL, Avro, SQL DDL, tRPC, WebSocket, MCP, Polyglot CLI, OpenAPI 3.1 Webhooks, and Bidirectional JSON Schema Parity
:toc: left

== Problem Statement
`assets/schemas/v1/tech/contract.schema.yaml` currently defines a 10-value canonical `protocol` enum (`openapi`, `rest_http`, `protobuf`, `graphql`, `asyncapi`, `json_schema`, `json_rpc_stdio`, `python_protocol`, `cli_args`, and `other`), while three existing verifiers have narrow scope limitations:

* **Polyglot library/SDK interfaces (`code_interface`)**: `python_protocol` only verifies Python `Protocol`/`ABC` classes, leaving TypeScript `.d.ts`/`export interface`, C# `public interface`, Go `type ... interface`, Rust `pub trait`, and Java/Kotlin `interface` contracts unchecked.
* **WSDL SOAP services (`wsdl`)**: Enterprise SOAP services that commit standard WSDL 1.1/2.0 XML files (`.wsdl`) lack deterministic operation parity even though stdlib `xml.etree.ElementTree` parses `.wsdl` cleanly with zero external dependencies.
* **Event & data schemas (`avro`, `sql_ddl`)**: Kafka/Schema Registry `.avsc`/`.avdl` schemas and SQL/Prisma database contracts (`.sql`, `.prisma`) have no static parity verifier.
* **Modern RPC, real-time & AI agent protocols (`trpc`, `websocket`, `mcp`)**: TypeScript tRPC routers, real-time SignalR/NestJS/Socket.IO hubs, and transport-agnostic MCP servers (including Streamable HTTP/SSE plus `resources` and `prompts` beyond `json_rpc_stdio` tools) lack dedicated canonical verifiers.
* **Python-only `cli_args` parity**: `ContractParityValidator._verify_contract_protocol` currently skips any `cli_args` contract whose `specification_file` is not a single `.py` file, leaving Go (`cobra`), Rust (`clap`), Node/TS (`commander`/`yargs`), and C# (`System.CommandLine`) CLIs unverified.
* **OpenAPI 3.1 `webhooks` blind spot**: `_verify_rest_openapi_contract` currently inspects only `data.get("paths")` and returns early when `paths` is absent, missing OpenAPI 3.1 top-level `webhooks:` outbound event contracts.
* **Forward-only, top-level-only `json_schema` parity**: `_verify_json_schema_contract` currently inspects only top-level `properties`/`required` (returning early on `$defs`-only shared definition schemas) and performs no reverse check for phantom properties removed from the schema.

== Proposed Specification Changes

=== 1. Canonical 17-Value Protocol Enum & Decision Amendment (`CNT-EIDOS-CORE`)
* Expand `assets/schemas/v1/tech/contract.schema.yaml` `properties.protocol.enum` to 17 canonical values:
  `openapi`, `rest_http`, `protobuf`, `graphql`, `asyncapi`, `json_schema`, `json_rpc_stdio`, `python_protocol`, `cli_args`, `code_interface`, `wsdl`, `avro`, `sql_ddl`, `trpc`, `websocket`, `mcp`, `other`.
* Preserve the Draft 2020-12 `if/then/else` constraint requiring non-empty `custom_protocol` strictly when `protocol == "other"` and forbidding it on all 16 standard enum values.
* Record `DEC-CORE-EXTENDED-CONTRACT-PROTOCOLS` in `eidos/architecture/containers/core.adoc` (`graduated_from: DLT-2026-166-EXPAND-CANONICAL-5F92`), documenting:
  * **Decision**: Add 7 statically verifiable canonical protocols (`code_interface`, `wsdl`, `avro`, `sql_ddl`, `trpc`, `websocket`, `mcp`) plus polyglot `cli_args` verification decomposed across two focused leaf modules (`src/eidos/core/spec/schema_contract_parity.py` for schema/IDL formats and `src/eidos/core/spec/source_contract_parity.py` for source-backed protocols) under `CMP-CONTRACT-PARITY-VALIDATOR`, extend `_verify_rest_openapi_contract` for OpenAPI 3.1 `webhooks`, extend `_verify_json_schema_contract` for `$defs`/`definitions` and recursive bare-identifier reverse phantom-property parity, and generalize multi-target (`file | dir | glob`) resolution in `CMP-SPEC-VALIDATOR`. Amend `DEC-CORE-MODERN-REST-PARITY-ONLY` solely to allow stdlib XML `.wsdl` 1.1/2.0 parsing under dedicated `protocol: wsdl` while continuing to exclude legacy code-first `.asmx`/WebForms/Web API 2 from `rest_http` and `wsdl`.
  * **Rejected alternatives**: (1) Folding all 7 protocols into `protocol: other` with `custom_protocol` heuristics (re-introduces silent typo bypasses rejected in `DEC-CORE-CANONICAL-CONTRACT-PROTOCOL-ENUM`); (2) Concentrating all 8 new verifiers in a single ~1,300-line catch-all module (undermines `INV-CORE-MODULAR-COMPONENT-COHESION` and complicates per-file coverage maintenance under `POL-005`); (3) Replacing `python_protocol` or `json_rpc_stdio` with breaking renames (breaks existing living specs); (4) Adding third-party XML/SQL/Avro parser dependencies (violates zero-bloat deterministic stdlib parsing under `POL-004`).

=== 2. Static Bidirectional Parity Verifiers (`CMP-CONTRACT-PARITY-VALIDATOR`, `CMP-SPEC-VALIDATOR`)
Decompose new parity verifiers into two cohesive leaf modules under `CMP-CONTRACT-PARITY-VALIDATOR.source_path` (preserving acyclic modular cohesion per `INV-CORE-MODULAR-COMPONENT-COHESION` and keeping `ContractParityValidator._CONTRACT_PROTOCOL_VERIFIERS` in `contract_parity.py` as the single dispatch facade). All verifiers strip AsciiDoc comments (`_strip_asciidoc_comments`), scope reverse phantom checks to interface sections (`_iter_contract_interface_sections`) respecting contrastive cues (`_CONTRAST_CUE_RE`), and apply zero-symbol fallbacks on source-backed protocols to prevent false positives on custom frameworks:

==== Schema & IDL Verifiers (`src/eidos/core/spec/schema_contract_parity.py`)
* **`wsdl`** *(single `.wsdl` file)*: Parses WSDL 1.1 (`<service>`, `<portType>/<operation>`) and WSDL 2.0 (`<service>`, `<interface>/<operation>`) XML via stdlib `xml.etree.ElementTree` (rejecting disallowed `<!DOCTYPE`/`<!ENTITY` declarations and >5 MiB payloads before parsing; namespace-stripped; emits malformed-XML error on `ET.ParseError`). Verifies forward parity of services/operations and reverse parity of documented `` `operation <Name>` `` / `` `service <Name>` `` tokens and `Operation`-column table rows.
* **`avro`** *(single `.avsc` or `.avdl` file)*: Parses `.avsc` JSON (`record`, `enum`, `fixed`, `error`, top-level `name`, and `fields[].name`; emits malformed-JSON error on parse failure) and `.avdl` IDL (`protocol`, `record`, `enum`, `fixed`, `error`, and RPC message declarations). Verifies forward presence and reverse parity of backticked `` `record|enum|fixed|error|message <Name>` `` tokens and schema tables.
* **`sql_ddl`** *(file, directory, or glob/brace-glob via shared `collect_protocol_source_files`)*: Parses `.sql` DDL (`CREATE [OR REPLACE] [TEMP|TEMPORARY|MATERIALIZED] TABLE|VIEW|FUNCTION|PROCEDURE [IF NOT EXISTS] <name>`, comment-stripped) and `.prisma` schemas (`model`, `enum`, `view`). Verifies forward presence of object names and reverse parity of backticked `` `table|view|function|procedure|model|enum <Name>` `` tokens and object tables.

==== Source-Backed Protocol Verifiers (`src/eidos/core/spec/source_contract_parity.py`)
All multi-target source-backed verifiers share `collect_protocol_source_files` (safely expanding files, directories with `STANDARD_EXCLUDED_DIRS` + test pruning, and `list[Path]` globs without calling `.read_text()` on directories):
* **`code_interface`** *(file, directory, or glob/brace-glob)*: Extracts exported/public interface/trait names and public method names across TypeScript (`.ts`, `.tsx`, `.d.ts`, `.mts`, `.cts`: `export interface`, `export type`), C# (`.cs`: `public interface`), Go (`.go`: `type <Name> interface`), Rust (`.rs`: `pub trait`), and Java/Kotlin (`.java`, `.kt`, `.kts`: `interface`). Verifies forward presence of interfaces/methods and reverse parity for documented interface/method signatures.
* **`trpc`** *(file, directory, or glob/brace-glob)*: Statically scans TypeScript router definitions (`.ts`, `.tsx`, `.mts`, `.cts`) for `router({ ... })` / `createTRPCRouter({ ... })` procedure keys bound to `.query(...)`, `.mutation(...)`, or `.subscription(...)`. Verifies forward presence and reverse parity of backticked `` `query|mutation|subscription <name>` `` tokens and `Procedure`-column tables.
* **`websocket`** *(file, directory, or glob/brace-glob)*: Extracts real-time hub/event names across ASP.NET Core SignalR `Hub` / `Hub<T>` public methods (plus opt-in contradiction-only `[Authorize]`/`[AllowAnonymous]` parity reusing `_parse_doc_auth_expectation`), NestJS `@SubscribeMessage("...")` handlers, and Socket.IO / WS `socket.on("...")` / `io.emit("...")` events. Verifies forward presence and reverse parity of documented `` `event|hub|message <name>` `` tokens and `Event`/`Method`-column tables.
* **`mcp`** *(file, directory, or glob/brace-glob)*: Transport-agnostic (stdio + Streamable HTTP / SSE) Model Context Protocol verifier parsing JSON/YAML MCP manifests (`tools`, `resources`, `prompts`) and Python/TypeScript MCP server sources via shared `extract_mcp_symbols_from_text` (`@mcp.tool`/`@mcp.resource`/`@mcp.prompt`, `.tool()`/`.resource()`/`.prompt()`, `registerTool`/`registerResource`/`registerPrompt`, `add_tool`/`add_resource`/`add_prompt`). Verifies forward presence and reverse parity across tools, resources, and prompts while preserving backward compatibility for `json_rpc_stdio`.
* **Polyglot `cli_args`** *(file, directory, or glob/brace-glob)*:
  * **Safe dispatch**: When `spec_file` is a single `.py` file (`isinstance(spec_file, Path) and spec_file.is_file() and spec_file.suffix == ".py"`), dispatch directly to existing `verify_cli_contract_commands` (`cli_contract_parity.py`). When `spec_file` is a directory, `list[Path]`, or non-`.py` file, collect supported CLI source files via `collect_protocol_source_files` (never calling `.read_text()` on a directory), routing `.py` entrypoint files to `verify_cli_contract_commands` safely and `.go` (`cobra`: `cobra.Command{Use: "..."}` and flag bindings), `.rs` (`clap`: `#[derive(Subcommand)]` variants, `Command::new("...")`, `#[arg(long...)]`), `.ts`/`.js` (`commander`/`yargs`: `.command("...")`, `.option(...)`), and `.cs` (`System.CommandLine`: `new Command("...")`, `new Option<...>("...")`) files to the polyglot CLI parity verifier (forward + reverse with zero-command fallback).

==== Hardening Existing Verifiers (`src/eidos/core/spec/contract_parity.py`) & Multi-Target Dispatch (`CMP-SPEC-VALIDATOR`)
* **OpenAPI 3.1 `webhooks`** *(extending `_verify_rest_openapi_contract`)*: Inspects top-level `data.get("webhooks")` alongside `data.get("paths")` (supporting webhook-only OpenAPI 3.1 documents without `paths`), verifying forward presence of every webhook key and reverse parity of documented `` `webhook <name>` `` tokens and `Webhook`-column tables.
* **Bidirectional `json_schema` + `$defs`/`definitions`** *(extending `_verify_json_schema_contract`)*:
  * **Forward parity**: Verifies required top-level `properties` when top-level `properties` are declared, and enforces forward presence of `$defs` / `definitions` names when top-level `properties` is absent (definitions-only library schemas, avoiding false positives on internal `$defs` helper types in root-object schemas).
  * **Reverse parity**: Scans interface sections (`_iter_contract_interface_sections`) for `Property`/`Field`/`Definition`-column table rows and explicit `` `property|field|def <name>` `` tokens (respecting `_CONTRAST_CUE_RE`), matching strictly bare identifiers (`^[A-Za-z_$][A-Za-z0-9_$-]*$` — skipping dotted/bracketed paths like `user.email`, `items[].id`, and multi-word prose) against the full recursive union of top-level `properties`, `$defs`/`definitions` names, and nested sub-schema `properties` (`properties.*.properties`, `items.properties`, `$defs.*.properties`) so optional or nested documented fields never false-positive while deleted fields are caught as phantom drift.
