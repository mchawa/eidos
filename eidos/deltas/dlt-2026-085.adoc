= SpecDelta: Eliminate Hand-Authored affects and blast_radius from SpecDelta Schema in Favor of Graph-Derived Scope and Impact
:toc: left

== Problem Statement

In `assets/schemas/v1/delta/delta.schema.yaml`, a SpecDelta (`DLT-*`) currently defines three overlapping entity-reference sections in YAML frontmatter: `mutations[].target_*`, `affects`, and `blast_radius`. Inspecting the 80+ SpecDeltas and the engine implementation reveals four architectural problems:

1. **Three-Way Boilerplate Duplication (DRY Violation)**:
   Authors copy-paste the exact same container, component, contract, and capability IDs three times in every SpecDelta: once in `mutations[].target_*`, again in `affects.*`, and a third time in `blast_radius.impacted_*`.

2. **Redundancy with the SQLite Knowledge Graph**:
   Parent relationships (e.g., `CMP-*` -> `CNT-*` via `part_of`, `CAP-*` -> `DOM-*` via `realizes`, and `CAP-*` -> `CNT-*`/`CMP-*` via `implements`) are already persisted in the SQLite knowledge graph (`src/eidos/core/index/sync.py`). Furthermore, `_collect_1hop_spec_targets` in `src/eidos/vcs/structural.py` already expands modified code files across their 1-hop graph neighborhood during `eidos drift`.

3. **Static Hand-Authored `blast_radius` Goes Stale and Is Unenforced**:
   Although `delta.schema.yaml` describes `blast_radius` as `"Automated or computed impact analysis across personas, architecture components, and invariants"`, it is authored manually in YAML. Neither `delta_engine.py` nor `drift.py` reads `blast_radius.invariants_to_enforce` (since `drift.py` already verifies all invariants globally via `extract_invariants_and_verify`).

4. **`blast_radius` Weakens the Planned Mode Drift Gate (`drift.py`)**:
   In `src/eidos/vcs/drift.py` (lines 326–341), `detect_drift` adds `blast_radius.impacted_containers` and `impacted_components` into `declared_delta_targets`. Listing a downstream container in `blast_radius` therefore whitelists direct source-code modifications to that container even when no mutation in `mutations[]` authorizes changing it.

== Proposed Specification Changes

1. **Single Source of Truth in `delta.schema.yaml` & `SpecValidator` (`CMP-SPEC-VALIDATOR`)**:
   * Remove `affects` and `blast_radius` from `assets/schemas/v1/delta/delta.schema.yaml` (so `additionalProperties: false` rejects hand-authored `affects` and `blast_radius` blocks) and strip them from existing `eidos/deltas/dlt-*.adoc` files and bundled skills (`assets/plugin_reference/skills/`).
   * Attach `x-eidos-ref` metadata (`target_types`, `prefixes`, `entity_label`) directly to `mutations[].target_*` fields (`target_domain`, `target_capability`, `target_container`, `target_component`, `target_architecture`, `target_contract`, `target_policy`, `target_persona`, `target_design_system`, `target_screen`, `target_ui_component`, `target_client`, `target_flow`).
   * Update `SpecValidator` (`src/eidos/core/spec/validator.py`) so prefix and target-type rules are enforced on all `mutations[].target_*` references, while catalog existence is enforced whenever `mutations[].action` is a modification/deprecation action (`modify_*`, `extend_*`, `patch_*`, `deprecate_*`) on non-applied deltas.

2. **Strict Mutation-Scoped Drift Authorization (`CMP-DRIFT-DETECTOR`)**:
   * Update `detect_drift` in `src/eidos/vcs/drift.py` to populate `declared_delta_targets` strictly from `mutations[].target_*` on active SpecDeltas, relying on `_collect_1hop_spec_targets` for 1-hop container/component/capability/contract ownership resolution.

3. **Graph-Derived `affects` and `blast_radius` in Portal Generator (`CMP-PORTAL-GENERATOR`)**:
   * Update `generate_portal_data` in `src/eidos/portal/generator.py` to compute `affects` (categorized 0-hop target entities and their owning containers/domains) and `blast_radius` (1..2-hop impacted containers, components, screens, design systems, personas, and bound `INV-*` invariants) dynamically from `mutations[].target_*` and the architectural graph, preserving the frontend data contract for `DeltasView.tsx` without manual YAML authoring.

4. **Update `CAP-PROD-002` & Bundled Skills**:
   * Update `eidos/domains/spec-engine/capabilities/spec-delta-mutations.adoc` and bundled skills (`eidos-plan/SKILL.md`, `eidos/SKILL.md`) to reflect that SpecDeltas declare `mutations` as the single source of truth while `affects` and `blast_radius` are computed automatically from the knowledge graph.
