= SpecDelta: Default-Verified SpecDelta Application, Safe Deterministic Mutation Execution, and Single-Pass `os.scandir` Index Dirty Checking
:toc: left

== Problem Statement

A deep review of the SpecDelta lifecycle engine (`CNT-EIDOS-CORE` / `CNT-EIDOS-CLI`) and knowledge-graph synchronization pipeline (`CNT-EIDOS-INDEX`) identified two operational and performance weaknesses (Review Points **2.2** and **6.4**):

1. **Point 2.2 — `eidos delta apply` Defaults to `verify=False` & Fragile `--execute` Mutation Behavior**:
   * **Unverified Status Transitions by Default**: Both `delta_apply_cmd` (`src/eidos/cli/delta_commands.py`, lines 367–388) and `apply_delta` (`src/eidos/core/lifecycle/delta_engine.py`, lines 2166–2248) default `verify: bool = False`. Running `eidos delta apply DLT-YYYY-NNN` without `-v` / `--verify` flips `status: proposed` to `status: applied` on disk without running `verify_delta_mutations` to confirm that the declared `mutations:` were actually fulfilled in the living specification catalog.
   * **Destructive / Naive Text Mutation in `execute_delta_mutations` (`--execute`)**:
     ** In `_apply_expect_or_details_to_spec` (`src/eidos/core/lifecycle/delta_engine.py`, lines 1674–1713), when a `modify` mutation has no `expect` block (only `details`), `--execute` appends the raw `details` string onto the bottom of the target `.adoc` file (`updated = f"{updated.rstrip()}\n\n{details}\n"`).
     ** In `execute_delta_mutations` (`src/eidos/core/lifecycle/delta_engine.py`, lines 2055–2060 and 2093–2097), running `--execute` on a `modify` inline component or `patch_invariant` mutation without `expect.frontmatter` either overwrites the inline component's entire `responsibility` field (`updated_comp["responsibility"] = details`) / invariant's `rule` field (`item["rule"] = details`) when `expect` is omitted, or leaves the inline component / invariant dictionary unchanged when `expect` contains only `body.contains` (causing `verify_delta_mutations` to fail because `_inline_component_digest` and `_invariant_digest` hash only the entity's frontmatter dictionary).
     ** When scaffolding a new inline component via `add` / `add_component` (`delta_engine.py`, lines 1834–1842), `--execute` hardcodes a `.py` extension (`"source_path": f"{pkg_base}/{comp_slug}.py"`) even when the parent `CNT-*` container's `runtime` is TypeScript, Go, Rust, Java, Kotlin, C#, Ruby, PHP, Swift, or C++.
     ** Additionally, `sync_delta_views` (`delta_engine.py`, line 206) still calls uncached `parse_spec_file(p)` in a loop across all delta files rather than using the shared `get_cached_spec_document(p)` helper introduced in `DLT-2026-086`.

2. **Point 6.4 — Duplicate `os.stat` Pass and Full `os.walk` Overhead in `check_index_dirty`**:
   * `check_index_dirty` (`src/eidos/core/index/sync.py`, lines 408–548) runs before almost every CLI command (`validate`, `drift`, `context`, `index`, `status`, `delta audit`, and the `Stop` hook).
   * Currently, Step 2 (`lines 499–508`) iterates over every non-`.adoc` path in `db_files` and calls `os.path.isfile(abs_tracked)` + `os.stat(abs_tracked)` on each file, and then Step 3 (`lines 517–536`) runs `os.walk(code_dir)` across all `top_code_dirs` (`src/`, `tests/`, `test/`, and container `package_path` directories), visiting every file a second time only to skip already-checked paths via `if rel_code in disk_files: continue`.
   * Furthermore, `os.walk()` combined with separate `os.stat()` calls issues redundant filesystem syscalls per file and directory compared to a single-pass `os.scandir()` traversal that uses `DirEntry.is_dir(follow_symlinks=False)` for directory pruning and `DirEntry.stat().st_mtime` for file inspection.

== Proposed Specification Changes

=== 1. Default-Verified `eidos delta apply` & Safe Deterministic `--execute` (`CMP-DELTA-ENGINE`, `CMP-CLI-DELTA-COMMANDS`, `CTR-EIDOS-CLI`, `CAP-PROD-002`, `INV-MUTATION-REVERSIBILITY`)

* **Default `verify: bool = True` in `apply_delta` and `eidos delta apply`**:
  ** Change `apply_delta(eidos_dir, delta_id_or_path, execute: bool = False, verify: bool = True)` in `src/eidos/core/lifecycle/delta_engine.py` so `verify` defaults to `True`.
  ** Change `delta_apply_cmd` in `src/eidos/cli/delta_commands.py` to expose `verify: bool = typer.Option(True, "--verify/--no-verify", "-v", help="Verify all mutations are satisfied in the living spec catalog before applying (enabled by default).")`.
  ** Update `eidos/architecture/contracts/cli.adoc` (`CTR-EIDOS-CLI`), `eidos/domains/spec-engine/capabilities/spec-delta-mutations.adoc` (`CAP-PROD-002` and `INV-MUTATION-REVERSIBILITY`), `tests/fixtures/cli_command_tree.json`, and CLI guides (`docs/guides/cli.md`, `docs/guides/agent-plugin.md`, `docs/concepts/specdeltas.md`) to document `eidos delta apply <id_or_path> [--execute] [--verify/--no-verify] [--json]`.
* **Harden `execute_delta_mutations` & `_apply_expect_or_details_to_spec`**:
  ** In `_apply_expect_or_details_to_spec` (`delta_engine.py`), apply structured `expect.frontmatter` mutations and explicit `expect.body.contains` blocks, returning `False` when `expect` is omitted or empty rather than appending free-form `details` prose onto the end of a specification body.
  ** In `execute_delta_mutations` (`delta_engine.py`), when modifying an inline `CMP-*` component (`modify_component`) or patching an `INV-*` invariant (`patch_invariant`), require non-empty `expect.frontmatter` (`fm_exp`) so the target entity's frontmatter digest advances deterministically without overwriting `updated_comp["responsibility"] = details` or `item["rule"] = details`.
  ** Add a helper `_infer_container_code_extension(cnt_fm: dict[str, Any]) -> str` in `delta_engine.py` that inspects existing component `source_path` suffixes and the container's `runtime` string (mapping TypeScript $\rightarrow$ `.ts`, JavaScript $\rightarrow$ `.js`, Go $\rightarrow$ `.go`, Rust $\rightarrow$ `.rs`, Java $\rightarrow$ `.java`, Kotlin $\rightarrow$ `.kt`, C#/.NET $\rightarrow$ `.cs`, Ruby $\rightarrow$ `.rb`, PHP $\rightarrow$ `.php`, Swift $\rightarrow$ `.swift`, C++ $\rightarrow$ `.cpp`, C $\rightarrow$ `.c`, defaulting to `.py`) when scaffolding a new inline component's default `source_path`.
  ** In `sync_delta_views` (`delta_engine.py`), replace `parse_spec_file(p)` with `get_cached_spec_document(p)` so symlink view synchronization reuses the shared in-memory/SQLite document cache.
  ** Update both the frontmatter `responsibility` and C4 Level 3 table row for `CMP-DELTA-ENGINE` in `eidos/architecture/containers/core.adoc` (`CNT-EIDOS-CORE`), and update legacy `details`-only `--execute` unit tests in `tests/test_delta_engine.py` to declare structured `expect:` blocks (or pass `verify=False` when testing unverified apply).

=== 2. Single-Pass `os.scandir` Dirty Checking in `check_index_dirty` (`CMP-INCREMENTAL-SYNC-ENGINE`, `CAP-PROD-001`)

* **Eliminate Duplicate `isfile` + `stat` on `top_code_dirs` Files with Strict Path-Boundary Filtering**:
  ** Build `top_code_dirs` before checking individual tracked files in `db_files`.
  ** Only run direct `os.stat()` checks on tracked files in `db_files` that are not covered by the `top_code_dirs` scan—specifically, skip pre-walk `os.path.isfile` + `os.stat` only when `abs_tracked` has an extension in `_CODE_EXTS`, starts with `code_dir + os.sep` for some existing `code_dir` in `top_code_dirs`, and has no relative path segment in `_EXCLUDED_CODE_DIRS` or starting with `"."`. All other tracked files in `db_files` (such as standalone root files or files outside `top_code_dirs`) continue to be checked directly, while files inside `top_code_dirs` are checked once during the directory scan.
* **Single-Pass Recursive `os.scandir` Traversal**:
  ** Replace the `os.walk()` + `os.stat()` loops over `index.eidos_dir` and `top_code_dirs` in `check_index_dirty` (`src/eidos/core/index/sync.py`) with a fast recursive `os.scandir()` traversal, pruning excluded/dot directories in-place via `entry.is_dir(follow_symlinks=False)` and reading `entry.stat().st_mtime` (`follow_symlinks=True`) directly from each matching `os.DirEntry`.

3. `uv run pytest` passes across all unit and integration suites (including `test_cli_command_tree_unchanged` and `test_documentation_and_schemas_in_sync`), with regression tests verifying:
   * `eidos delta apply` and `apply_delta` reject unfulfilled mutations by default (`verify=True`) unless `--no-verify` (`verify=False`) is explicitly passed.
   * `execute_delta_mutations` and `_apply_expect_or_details_to_spec` require explicit `expect:` blocks on `modify`/`patch` mutations, never clobber existing component responsibilities or invariant rules with `details`, never append raw `details` prose onto AsciiDoc bodies, and infer language-appropriate file extensions from container `runtime` when scaffolding inline components.
   * `check_index_dirty` accurately detects added, modified, mtime-touched, and deleted spec/code/test files (including sibling-prefix directories outside `top_code_dirs`) in a single `os.scandir` pass.
