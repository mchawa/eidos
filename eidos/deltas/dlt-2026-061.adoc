= SpecDelta: Filter Unapplied Deltas, Deduplicate Unreleased Commits, and Batch Git Tag Ancestry Queries in ChangelogGenerator
:toc: left

== Problem Statement

`ChangelogGenerator` (`CMP-CHANGELOG-GENERATOR` in `src/eidos/core/lifecycle/changelog.py`) has three bugs that violate `INV-DELTA-CHANGELOG-GENERATION`:

1. **Unapplied (`proposed` / `draft` / `in_review` / `approved` / `rejected`) Deltas Leak Into `CHANGELOG.md` (`get_applied_deltas`, lines 107-168)**:
   * Despite the method name `get_applied_deltas` and the `CNT-EIDOS-CORE` specification stating `"Compiles applied SpecDeltas"`, `get_applied_deltas` reads `status = fm.get("status", "proposed")` at line 129 and appends **every** `dlt-*.adoc` file in `eidos/deltas/` without checking `status == "applied"`.
   * As a result, `proposed`, `draft`, `in_review`, `approved`, and `rejected` SpecDeltas are rendered directly into `## [Unreleased]` and tagged release sections of `CHANGELOG.md`.
2. **Missing SpecDelta Deduplication in `Unreleased` Commit Section (`generate_changelog`, lines 219-227)**:
   * In tagged release sections (line 277), `_add_commit_to_section(sec, msg, existing_deltas=rel_deltas)` suppresses Git commits that already reference a `DLT-*` listed in that section. In `Unreleased` (line 225), `self._add_commit_to_section(sec_unreleased, msg)` is called *without* `existing_deltas=unreleased_deltas`, duplicating every unreleased delta commit alongside its SpecDelta entry.
3. **$O(D \times T)$ Git Subprocess Storm (`get_applied_deltas` & `_resolve_delta_release`, lines 141-184)**:
   * `get_applied_deltas` spawns a separate `git log -1 --format=%H -- <file>` subprocess for every delta file ($D$ subprocesses).
   * `_resolve_delta_release` then spawns `git merge-base --is-ancestor <commit> <tag>` for every `(delta, tag)` combination ($D \times T$ subprocesses). With 100 deltas and 20 tags, `eidos delta changelog` spawns up to 2,100 `git` subprocesses.

== Proposed Specification Changes

1. **Strict `status == "applied"` Filtering & Unreleased Commit Deduplication (`src/eidos/core/lifecycle/changelog.py`)**:
   * In `ChangelogGenerator.get_applied_deltas`, skip any SpecDelta whose normalized `frontmatter.get("status")` is not `"applied"`.
   * In `generate_changelog`, pass `existing_deltas=unreleased_deltas` to `self._add_commit_to_section(sec_unreleased, msg, existing_deltas=unreleased_deltas)`.
2. **Batched Git Commit & Tag Ancestry Resolution**:
   * Resolve the latest commit SHA for all `eidos/deltas/dlt-*.adoc` files in a single `git log --name-only --format="COMMIT:%H" -- eidos/deltas/` pass.
   * Resolve tag containment across all tags in a single batched pass (e.g., `git rev-list <tag>` commit set per tag or `git tag --contains`) instead of spawning `git merge-base --is-ancestor` inside a nested loop.
