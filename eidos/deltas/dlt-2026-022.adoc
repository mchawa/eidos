= SpecDelta: Automated Living Architecture Changelog Generation Engine
:toc: left

== Problem Statement
Maintaining release notes and changelogs manually is error-prone, noisy, and rapidly drifts from true system architecture. In Eidos, every significant architecture and feature evolution is already codified in living SpecDeltas (`DLT-*`) and git tags. A dedicated changelog engine bridges Git release history with living specs automatically.

== Architecture & Behavioral Mutations
1. **`ChangelogGenerator` (`src/eidos/core/changelog.py`)**:
   - Inspects Git tags (`v*`) and their commit timestamps.
   - Collects applied SpecDeltas (`DLT-*`) from `eidos/deltas/`.
   - Uses `git merge-base --is-ancestor` to deterministically map each SpecDelta to the earliest release tag containing it, or places it in `[Unreleased]` if not yet released.
   - Categorizes mutations into Keep a Changelog sections (`Added`, `Changed`, `Fixed`, `Deprecated`, `Removed`).
   - Links entries directly to living specification documents and SpecDeltas.
2. **CLI Integration (`src/eidos/cli/main.py`)**:
   - `eidos delta changelog [--output PATH] [--unreleased/--no-unreleased] [--docs/--no-docs]`
   - `eidos changelog` (top-level shortcut under `PANEL_SPECS`).
3. **Docs Synchronization**:
   - Symlinks or copies to `docs/changelog.md` and registers `{ "Changelog" = "changelog.md" }` in `zensical.toml`.
