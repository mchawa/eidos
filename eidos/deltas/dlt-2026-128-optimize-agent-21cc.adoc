= SpecDelta: Add Opt-In Native Stop Lifecycle Hooks (--hooks), Doctor Hook Health Diagnostics, and Stateless 1-Turn Continuation Across Hook-Capable Agent Targets
:toc: left

== Problem Statement

Eidos's agent integration relies on two pillars working together:

1. **Progressive-Disclosure Skills & `AGENTS.md`**: The 4 Eidos skills (`eidos`, `eidos-spec`, `eidos-plan`, `eidos-ops`) and the canonical root `AGENTS.md` block across all 9 supported coding assistants (`antigravity`, `claude`, `cursor`, `aider`, `cline`, `kilocode`, `open-code`, `codex`, `copilot`).
2. **The Stateless `Stop` / `TaskComplete` Lifecycle Hook (`eidos hook`)**: Runs `detect_drift(uncommitted=True)` at the end of an agent turn to surface specification validation errors, broken invariant test bindings, and spec-to-code drift across the 6 coding clients that natively support CLI `Stop` / `TaskComplete` hooks (`antigravity`, `claude`, `cursor`, `cline`, `copilot`, `codex`).

Currently:

1. **Unconditional Hook Installation & Missing Opt-In Control**: `eidos plugin install` previously installed `Stop` hooks unconditionally for Antigravity and Claude Code without a `--hooks` opt-in flag, and `eidos doctor` could not tell whether a missing hook was intentionally omitted or accidentally broken.
2. **Missing Native `Stop` / `TaskComplete` Hook Wiring for `cursor`, `cline`, `copilot`, and `codex`**: Under `agent-plugins.org v1.0.0`, lifecycle hooks are not part of the portable core specification. Each of those four clients loads its completion hook from its own native project hook file:
   * **Cursor (`cursor`)**: `.cursor/hooks.json` (`version: 1`, `hooks.stop` array with `loop_limit: 1`).
   * **Cline (`cline`)**: `.clinerules/hooks/TaskComplete` (executable `0o755` POSIX shell trampoline invoking `exec eidos hook` or `exec uvx --from eidos-ai==<ver> eidos hook`).
   * **GitHub Copilot (`copilot`)**: `.github/hooks/hooks.json` (`version: 1`, `hooks.agentStop` array with `type: "command"`, `bash`, `powershell`, `timeoutSec`).
   * **OpenAI Codex (`codex`)**: `.codex/hooks.json` (`hooks.Stop` array with `hooks: [{"type": "command", "command": "...", "timeout": 30}]`).
3. **Incompatible `Stop` Hook `stdout` Wire Schemas**: Returning `{"decision": "allow", "systemMessage": "..."}` only works in Claude Code—OpenAI Codex rejects `"decision": "allow"` under `StopCommandOutputWire`, while Antigravity (`Stop`), Cursor (`stop`), Cline (`TaskComplete`), and GitHub Copilot (`agentStop`) ignore `systemMessage` and instead require their native continuation payload (`{"decision": "continue", "reason": "..."}` in Antigravity, `{"followup_message": "..."}` in Cursor, `{"cancel": true, "contextModification": "...", "errorMessage": "..."}` in Cline, and `{"decision": "block", "reason": "..."}` in Claude Code, Codex, and Copilot) gated by each client's built-in in-memory retry counter (`executionNum`, `loop_count`, `hookName`, `stop_hook_active`).

=== 2. Opt-In `--hooks` Flag on `install`, State Preservation on `update`, and `eidos doctor` Hook Health (`CMP-PLUGIN-INSTALLER`, `CMP-CLI-PLUGIN-COMMANDS`, `CMP-CLI-DOCTOR-HOOKS`)

1. **Opt-In `--hooks` CLI Flag on `eidos plugin install`**:
   * `eidos plugin install <target> [--hooks]` defaults to `hooks=False` (no `--no-hooks` flag). By default, Eidos installs only the target's plugin/skills bundle and `AGENTS.md` block without installing any `Stop` hook (and removes any previously installed Eidos `Stop` hook for that target). Only when `--hooks` (`hooks=True`) is explicitly passed does Eidos install and wire the target's native `Stop` / `TaskComplete` hook.
   * `eidos plugin update <target>` does **not** accept `--hooks`; it reads each target's recorded `hooks` setting from `.eidos-manifest.json` (via `_resolve_saved_hook_preference()`) and refreshes the current installed state.
2. **Manifest Hook Intent Tracking (`.eidos-manifest.json`)**:
   * `.agents/plugins/eidos/.eidos-manifest.json`, `.claude/.eidos-manifest.json`, `.agents/.eidos-manifest.json`, and `.aider/.eidos-manifest.json` record `"targets": {"<target>": {"hooks": <bool>, "launcher": "<launcher>"}}` alongside `"version"` and `"files"`.
   * For `antigravity`, `.agents/plugins/eidos/hooks.json` is copied only when `hooks=True` and omitted/removed when `hooks=False` (unless `antigravity` remains installed with `hooks=True`).
3. **Target-Aware Hook Health in `check_plugin_version_status()` and `eidos doctor`**:
   * `check_plugin_version_status()` inspects each installed target's recorded `hooks` intent and verifies its native hook file:
     - **Installed without `--hooks` (`hooks: false`, default) or non-hook target**: `status: "disabled"`, `ok: true` (`eidos doctor` recognizes the hook is intentionally not installed and displays `PASS` with `(hooks: disabled)`).
     - **Installed with `--hooks` (`hooks: true`) and valid**: `status: "active"`, `ok: true` (`eidos doctor` displays `PASS` with `(hooks: active)`).
     - **Installed with `--hooks` (`hooks: true`) and missing/corrupted**: `status: "missing" | "invalid" | "corrupted"`, `ok: false` (`eidos doctor` displays `FAIL`, sets `checks.agent_plugin.ok = false`, `checks.agent_plugin.status = "hook_error"`, `hooks_ok = false`, and exits `1` with target-specific diagnostics in `hook_errors`).

=== 3. Stateless Client-Aware 1-Turn `Stop` / `TaskComplete` Hook Continuation (`CMP-HOOK-RUNNER`)

Update `src/eidos/plugin/hooks.py` to support all 6 hook-capable clients natively without writing any disk state files:

1. **Workspace Root Detection (`find_workspace_root`)**:
   * Check `"workspacePaths"` (Antigravity), `"workspace_roots"` (Cursor), and `"workspaceRoots"` (Cline) list fields in addition to `"cwd"`, `"workspaceRoot"`, and `"workspace_root"`.
2. **Client Detection & In-Memory 1-Turn Continuation Guard (`handle_stop_hook`)**:
   * Detect the calling client and its per-turn in-memory retry state directly from `payload`:
     - **Cursor** (`"loop_count"` or `"workspace_roots"` in `payload` or `payload.get("hook_event_name") == "stop"`):
       * Clean, retry, or non-completed stop (`payload.get("loop_count", 0) > 0` or `payload.get("status", "completed") != "completed"`): return `{}`.
       * First completed stop with drift/validation issues: return `{"followup_message": msg}`.
     - **Cline** (`"clineVersion"` or `"hookName"` or `"workspaceRoots"` in `payload`):
       * Clean, retry, or non-`TaskComplete` hook (`payload.get("hookName", "TaskComplete") != "TaskComplete"` or `bool(payload.get("stop_hook_active"))`): return `{"cancel": False}`.
       * `TaskComplete` with drift/validation issues: return `{"cancel": True, "contextModification": msg, "errorMessage": msg}`.
     - **Claude Code, OpenAI Codex, and GitHub Copilot** (`"stop_hook_active"` in `payload` or `"cwd"` in `payload` or `"sessionId"` in `payload`):
       * Clean or retry stop (`bool(payload.get("stop_hook_active"))`): return `{}`.
       * First stop with drift/validation issues: return `{"decision": "block", "reason": msg}`.
     - **Antigravity** (default / `"executionNum"` or `"workspacePaths"` or `"terminationReason"` in `payload`):
       * Clean or retry/non-normal stop (`payload.get("executionNum", 1) > 1` or `payload.get("terminationReason", "NO_TOOL_CALL") not in ("", "NO_TOOL_CALL")`): return `{"decision": "allow"}`.
       * First stop with drift/validation issues: return `{"decision": "continue", "reason": msg}`.
