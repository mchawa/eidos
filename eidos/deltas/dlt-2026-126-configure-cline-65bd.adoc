= SpecDelta: Configure Cline Installation to Use Shared .agents/skills Without Unused Plugin Bundle or Hooks
:toc: left
:icons: font
:sectnums:

== Problem Statement

The current `eidos plugin install cline` target (`PluginInstallTarget.CLINE` in `src/eidos/plugin/installer.py`) writes an unused plugin bundle, a non-functional `hooks.json`, and a harness-isolated `.cline/skills/` directory:

1. **Unloaded `.cline/plugins/eidos/` Bundle and `hooks.json`**:
   * `TARGET_ADAPTERS[PluginInstallTarget.CLINE]` sets both `plugin_subdir=".cline/plugins/eidos"` and `skills_subdir=".cline/skills"`.
   * Because `TargetAdapter.install()` passes `include_skills=(self.skills_subdir is None)`, `_copy_plugin_tree()` copies only `plugin.json` (an `agent-plugins.org v1.0.0` manifest with `com.google.antigravity`) and `hooks.json` (`{"eidos-drift-gate": {"Stop": [...]}}`) into `.cline/plugins/eidos/`, stripping `skills/`.
   * Cline does **not** load `agent-plugins.org` `plugin.json` or `hooks.json` files (Cline SDK plugins require an npm/TypeScript package declaring `"cline": {"plugins": [...]}` in `package.json` and exporting an `@cline/sdk` `AgentPlugin`).
   * Furthermore, because `.eidos-manifest.json` is written inside `.cline/plugins/eidos/`, the 4 skills installed under `.cline/skills/` lie outside `target_dir` and are omitted from the manifest.
2. **Incompatible Hook Semantics in Cline (`.clinerules/hooks/`)**:
   * Cline (v3.36+) discovers hooks only as extensionless executable scripts (`chmod +x`, macOS/Linux only; unsupported on Windows) inside `.clinerules/hooks/<EventName>` (disabled by default in VS Code unless the user manually toggles *Enable Hooks*), with a different JSON stdin/stdout protocol (`workspaceRoots` + `hookName` on stdin; `{"cancel": bool, "contextModification": str}` on stdout).
   * Neither of Cline's completion-related hook events maps cleanly to Eidos's stateless `Stop` gate (`DEC-PLUGIN-STOP-SCOPED-DRIFT-GATE`, `DEC-PLUGIN-STATELESS-SINGLE-STOP-HOOK`, `INV-HOOK-CLI-NATIVE`):
     ** `TaskComplete` is a post-completion observation hook that fires *after* `attempt_completion` has already finalized the task, so it cannot feed a drift warning back into the active agent turn before completion.
     ** `PreToolUse` has no declarative tool-name matcher in Cline's hook discovery, so installing `.clinerules/hooks/PreToolUse` would spawn a subprocess on **every single tool call** (`read_file`, `write_to_file`, `execute_command`, etc.), violating `DEC-PLUGIN-STOP-SCOPED-DRIFT-GATE` and colliding with any user-authored `.clinerules/hooks/PreToolUse` script.
3. **Unnecessary `.cline/skills/` Duplication vs. Shared `.agents/skills/`**:
   * Both **Cline** and **Kilo Code** natively discover project-scoped Agent Skills in the cross-agent `.agents/skills/<skill>/SKILL.md` directory alongside the root `AGENTS.md` instruction file.
   * Writing into `.cline/skills/` creates an extra top-level `.cline/` dot-directory and duplicates skill files for repositories using Cline, Kilo Code, or other `.agents/skills/`-compatible harnesses.

== Proposed Specification Changes

* **Update `CMP-PLUGIN-INSTALLER` (`src/eidos/plugin/installer.py`, `src/eidos/plugin/version.py`, `eidos/architecture/components/plugin-installer.adoc`)**:
  1. **Shared `.agents/skills/` Layout (`DEC-PLUGIN-CLINE-AGENTS-SKILLS`)**:
     - Configure `TARGET_ADAPTERS[PluginInstallTarget.CLINE]` as a skills + `AGENTS.md` target (matching `PluginInstallTarget.CURSOR`):
       * `plugin_subdir=None` (do not create `.cline/plugins/eidos/` or copy `plugin.json` / `hooks.json`)
       * `skills_subdir=".agents/skills"`
       * `install_destination_subdir=".agents/skills"`
       * `uninstall_destination_subdir=".agents/skills"`
       * `prune_dirs=(".agents",)` (prunes `.agents/` on uninstall only when empty, preserving `.agents/plugins/eidos` if installed)
     - Project `targets=cline:.agents/skills` into the canonical root `AGENTS.md` managed block (`- \`.agents/skills/<skill>/SKILL.md\``).
     - **No Backward Compatibility or Legacy Cleanup**: No migration or cleanup is performed for `.cline/plugins/eidos/` or `.cline/skills/` directories written by earlier releases; fresh-install correctness is the only requirement.
  2. **Clean Up Dead Fallback Paths in `src/eidos/plugin/version.py`**:
     - Remove the unused `root / ".cline" / "plugins" / "eidos" / "plugin.json"` and `root / ".cline" / "skills" / "eidos" / "plugin.json"` fallback entries from `_resolve_installed_plugin_manifest()`.
* **Update `CNT-EIDOS-PLUGIN` (`eidos/architecture/containers/plugin.adoc`)**:
  - Record `DEC-PLUGIN-CLINE-AGENTS-SKILLS` in frontmatter (phrased without literal tombstone tokens `.cline/plugins` / `.cline/skills` so `eidos delta audit --strict` remains zero-leak on active specs):
    * *Decision*: Configure `PluginInstallTarget.CLINE` to install the 4 Eidos skills into the shared `.agents/skills/<skill>/SKILL.md` directory (natively discovered by both Cline and Kilo Code) and project the canonical root `AGENTS.md` block, without creating Cline-specific `plugins/eidos/` or `skills/` subdirectories under `.cline/` or `.clinerules/hooks/` scripts, and without migrating or cleaning up legacy `.cline/` directories.
    * *Rationale*: Cline and Kilo Code both natively discover Agent Skills under `.agents/skills/` and load project instructions from root `AGENTS.md`, providing cross-harness compatibility with zero dot-directory bloat. Meanwhile, Cline ignores `agent-plugins.org` `plugin.json`/`hooks.json` manifests, and Cline's file-based `.clinerules/hooks/` system lacks a pre-completion `Stop` hook (offering only post-completion `TaskComplete` or every-tool `PreToolUse` shell scripts).
    * *Rejected alternatives*:
      1. *Keep Cline-specific `plugins/eidos/` (`plugin.json` + `hooks.json`) and `skills/` subdirectories under `.cline/`*: Cline does not load `agent-plugins.org` manifests or `hooks.json`, and a dedicated `.cline/` skills directory duplicates skill files instead of sharing `.agents/skills/` with Kilo Code.
      2. *Install an executable `.clinerules/hooks/TaskComplete` script*: `TaskComplete` in Cline fires after `attempt_completion` has already ended the task (observation-only), requires a shell wrapper script (`INV-HOOK-CLI-NATIVE`), is unsupported on Windows, and requires manual opt-in in Cline VS Code settings.
      3. *Install an executable `.clinerules/hooks/PreToolUse` script filtering `attempt_completion`*: Cline has no declarative tool-name matcher in hook discovery and executes `PreToolUse` on every tool call (`read_file`, `write_to_file`, `execute_command`), violating `DEC-PLUGIN-STOP-SCOPED-DRIFT-GATE` and `DEC-PLUGIN-STATELESS-SINGLE-STOP-HOOK` and colliding with user-authored `PreToolUse` scripts.
      4. *Migrate or clean up legacy `.cline/` subdirectories on install/uninstall*: Backward compatibility is not a goal; fresh-install correctness is the only requirement.
  - Update `== Internal Structure & Key Mechanisms` in `eidos/architecture/containers/plugin.adoc` to replace `.cline/skills/` with `.agents/skills/`.
* **Update `CTR-EIDOS-CLI` (`eidos/architecture/contracts/cli.adoc`) & `CAP-AGENT-001` (`eidos/domains/agent-intelligence/capabilities/agent-adapter.adoc`)**:
  - Update `eidos plugin install` in `CTR-EIDOS-CLI` to reference `.agents/skills/` instead of `.cline/skills/`.
  - Bump `CAP-AGENT-001` to `1.11.1` and document shared `.agents/skills/` support for Cline and Kilo Code.
* **Update `CMP-DOCS-USER-GUIDES` & `CMP-DOCS-CORE-CONCEPTS` (`docs/guides/agent-plugin.md`, `docs/concepts/how-eidos-works.md`, `eidos/architecture/components/docs-user-guides.adoc`, `eidos/architecture/components/docs-core-concepts.adoc`)**:
  - Update the target table and `=== "Cline"` section in `docs/guides/agent-plugin.md` to document `.agents/skills/` (shared by Cline and Kilo Code) and root `AGENTS.md`, and update the `Stateless Stop Lifecycle Hook` section so Cline, Cursor, and Codex are not listed as `hooks.json` consumers.
  - Update `docs/concepts/how-eidos-works.md` (`§3.5`) and `eidos/architecture/components/docs-core-concepts.adoc` to replace `.cline/` with `.agents/skills/`.
