= SpecDelta: Decorator-Aware AST Symbol Signatures and AST-Backed Polyglot Test-Binding Verification
:toc: left

== Problem Statement

A deep audit of the polyglot AST symbol indexer (`CNT-EIDOS-INDEX`), specification validator (`CNT-EIDOS-CORE`), and structural drift detector (`CNT-EIDOS-VCS`) uncovered two accuracy gaps in AST symbol and test-binding analysis (Review Points **4.1** and **3.2**):

1. **Point 4.1 — `AstGrepIndexer` and `FallbackIndexer` Omit `@decorator` / Attribute Lines from `CodeSymbol.line_start` and `CodeSymbol.signature`**:
   * In `AstGrepIndexer.extract_symbols` (`src/eidos/core/index/ast_indexer.py`, lines 284–340 and 366–443), `line_start` is computed from `m.range().start.line + 1` (the `def` or `class` keyword node) without checking whether `m.parent()` is a `decorated_definition` (unlike `list_test_functions` at lines 502–506, which explicitly checks `if parent and parent.kind() in ("decorated_definition",):`).
   * Similarly, in `FallbackIndexer.extract_symbols` (`ast_indexer.py`, lines 641–653 and 747–791), `line_start` uses `node.lineno` rather than `min(d.lineno for d in node.decorator_list)`, and `_python_node_signature(node)` formats only `class Name(Bases)` or `def name(args) -> ret`, omitting `node.decorator_list`.
   * Consequently, adding, removing, or modifying decorators on public classes, functions, or methods (such as `@app.command("...")`, `@staticmethod`, `@classmethod`, `@property`, `@dataclass`, route decorators, or auth/permission decorators) leaves `CodeSymbol.line_start` and `CodeSymbol.signature` unchanged, making decorator-only structural changes invisible to `diff_public_symbols` and `eidos drift`.

2. **Point 3.2 — Raw Regex Fallback in `SpecValidator._test_symbol_exists` & Missing Parameterized / Subtest Constructs in Polyglot Test Indexing**:
   * **Raw Word-Boundary Regex on Non-Python Test Files**: In `SpecValidator._test_symbol_exists` (`src/eidos/core/spec/validator.py`, lines 948–975), Python `.py` files are parsed with `ast.parse`, but every non-Python test file (`.ts`, `.tsx`, `.js`, `.go`, `.rs`, `.java`, `.kt`, etc.) falls through to `return bool(re.search(rf"\b{re.escape(leaf_sym)}\b", source))`. If a deleted test's name is mentioned inside a `//` or `/* ... */` comment or an unrelated string literal, `eidos validate` falsely reports the `test_binding` as valid!
   * **Missing Polyglot Test Runner Constructs in `ast_indexer.py`**:
     ** **TypeScript / JavaScript**: `AstGrepIndexer.list_test_functions` and `extract_test_bindings` (`ast_indexer.py`, lines 473–488 and 573–592) only match `call_expression` nodes where `fn_ident.text() in ("it", "test", "describe")`. They miss chained/member test calls used across Vitest, Jest, Playwright, and Deno: `test.each(...)('name', ...)`, `it.each(...)('name', ...)`, `describe.each(...)('name', ...)`, `test.concurrent('name', ...)`, and `Deno.test('name', ...)` / `Deno.test({ name: '...' }, ...)`.
     ** **Go**: Only top-level `func TestXxx(t *testing.T)` declarations are indexed (`lines 489–490`); table-driven subtests invoked via `t.Run("subtest_name", func(t *testing.T) { ... })` cannot be targeted or resolved as `TestParent/subtest_name` or `subtest_name`.
     ** **Rust**: `is_test` (`lines 512–518` and `617–624`) only checks `"#[test]" in full_text`, missing standard async and parameterized Rust test attributes such as `#[tokio::test]`, `#[rstest]`, `#[test_case(...)]`, and `#[async_std::test]`.

== Proposed Specification Changes

=== 1. Decorator-Inclusive `CodeSymbol.line_start` & `CodeSymbol.signature` (`CMP-AST-SYMBOL-INDEXER`, `CAP-VCS-001`)

* **`AstGrepIndexer.extract_symbols` (`src/eidos/core/index/ast_indexer.py`)**:
  ** When extracting class/struct/interface nodes and function/method nodes, inspect `m.parent()` for `decorated_definition` (and preceding `@decorator` / `#[...]` attribute siblings/lines). Set `line_start` to the first decorator line (`prng.start.line + 1`) and include normalized `@decorator` prefixes in `CodeSymbol.signature` (while preserving `export ` prefixing and `_evaluate_symbol_visibility` / `_evaluate_boundary_export` semantics).
* **`FallbackIndexer.extract_symbols` (`src/eidos/core/index/ast_indexer.py`)**:
  ** In Python `ast` extraction (`lines 641–653` and `746–792`), set `line_start = min((d.lineno for d in node.decorator_list), default=node.lineno)` and prefix `@<unparsed_decorator>` onto `_python_node_signature(node)` so `AstGrepIndexer` and `FallbackIndexer` produce consistent decorator-aware `line_start` coordinates and signatures.

=== 2. Expanded Polyglot Test Extraction & AST-Backed `SpecValidator._test_symbol_exists` (`CMP-AST-SYMBOL-INDEXER`, `CMP-SPEC-VALIDATOR`, `CAP-PROD-001`)

* **Expand Polyglot Test Extraction in `AstGrepIndexer` and `FallbackIndexer` (`src/eidos/core/index/ast_indexer.py`)**:
  ** **TS/JS**: Recognize `test.each(...)("...")`, `it.each(...)("...")`, `describe.each(...)("...")`, `test.concurrent("...")`, `it.concurrent("...")`, and `Deno.test("...", ...)` / `Deno.test({ name: "..." }, ...)` in both `AstGrepIndexer` and `FallbackIndexer`.
  ** **Go**: Extract `t.Run("<subtest>", ...)` subtest calls inside `Test*` functions, recording both the qualified `<TestFunc>/<subtest>` key and `<subtest>` key in `list_test_functions` and `extract_test_bindings`.
  ** **Rust**: Recognize `#[tokio::test]`, `#[rstest]`, `#[test_case]`, and `#[async_std::test]` attributes (including module-qualified forms like `#[tokio::test(flavor = ...)]`) alongside `#[test]`.
* **AST-Backed `SpecValidator._test_symbol_exists` (`src/eidos/core/spec/validator.py`)**:
  ** Route `SpecValidator._test_symbol_exists(test_file, symbol_parts)` through `get_ast_indexer().list_test_functions(test_file, source)` and `get_ast_indexer().extract_symbols(test_file, source)` for all supported polyglot test files (checking qualified `::` / `/` keys as well as leaf symbol names), falling back to comment-stripped identifier matching only for file extensions not handled by the AST indexer.
