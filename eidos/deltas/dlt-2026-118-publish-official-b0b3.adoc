= SpecDelta: Publish Official Eidos Dev Container Feature to GHCR
:toc: left
:icons: font
:sectnums:

== Problem Statement

Adopting Eidos inside containerized development environments (VS Code Dev Containers, GitHub Codespaces, DevPod, or JetBrains Gateway) currently requires users to write custom `postCreateCommand` shell scripts to install `uv`, provision a compatible Python interpreter (`3.11`–`3.14` when using `[semantic]`), and run `uv tool install eidos-ai`.

Publishing an official, OCI-compliant **Dev Container Feature** (`ghcr.io/mchawa/eidos/eidos`) allows any repository to declaratively add Eidos in `.devcontainer/devcontainer.json`:

[source,json]
----
{
  "features": {
    "ghcr.io/mchawa/eidos/eidos:1": {
      "version": "latest",
      "semantic": true,
      "pythonVersion": "3.14"
    }
  }
}
----

== Proposed Specification Changes

1. **Dev Container Feature Definition (`devcontainer-features/src/eidos/`)**:
   * `devcontainer-feature.json`: Declares Feature ID `eidos`, semantic version `1.0.0`, options (`version`, `semantic`, `pythonVersion`), recommended VS Code extensions (`asciidoctor.asciidoctor-vscode`, `redhat.vscode-yaml`), and `installsAfter` ordering (`common-utils`, `git`, `python`, `astral.sh-uv`).
   * `install.sh`: Executes as `root` during container build, detects the host package manager (`apt-get`, `apk`, `dnf`, `microdnf`, `yum`) to ensure `curl`, `ca-certificates`, and `git` are present, ensures `uv` is installed, validates/clamps `PYTHONVERSION` to `3.14` when `SEMANTIC="true"` and `PYTHONVERSION` is `>= 3.15` (since `onnxruntime` wheels require Python `3.11`–`3.14`), installs `eidos-ai` (or `eidos-ai[semantic]`) with `uv tool install --no-cache` into system-wide locations (`UV_TOOL_BIN_DIR=/usr/local/bin`, `UV_TOOL_DIR=/usr/local/share/uv/tools`, `UV_PYTHON_INSTALL_DIR=/usr/local/share/uv/python`), and applies `chmod -R a+rX` so any non-root `remoteUser` can invoke `eidos` directly without bloating the OCI image layer.
   * `devcontainer-features/test/eidos/`: Automated `devcontainer features test` scenarios (`test.sh`, `with_semantic.sh`, and `scenarios.json`) verifying default installation and `[semantic]` extra provisioning.
   * Exclude `"/devcontainer-features"` and `"/.devcontainer"` from `[tool.hatch.build.targets.sdist].exclude` in `pyproject.toml` so the PyPI source distribution remains isolated from Dev Container Feature artifacts.
2. **CI/CD Publishing Pipeline (`.github/workflows/ci.yml`)**:
   * Add a `publish-devcontainer-feature` job using `devcontainers/action@v1` (`publish-features: "true"`, `base-path-to-features: "./devcontainer-features/src"`) sequenced after validation, test, site build, and PyPI release (`needs: [validate, test, build-site, publish-to-pypi]` with `if: always() && ...`) and granted `permissions: { contents: write, packages: write }` to publish `ghcr.io/mchawa/eidos/eidos`.
3. **Architecture & System Specifications (`ARCH-EIDOS-001`, `SYS-EIDOS-001`)**:
   * Record `DEC-ARCH-DEVCONTAINER-FEATURE` (`graduated_from: DLT-2026-118-PUBLISH-OFFICIAL-B0B3`) and document the OCI Dev Container Feature distribution channel in `eidos/architecture/system-architecture.adoc` (Section 7: Deployment View) and `eidos/system.adoc`.
4. **Documentation & Onboarding (`CMP-DOCS-GETTING-STARTED`, `CNT-EIDOS-DOCS`)**:
   * Document the `ghcr.io/mchawa/eidos/eidos` Dev Container Feature and its configuration options (`version`, `semantic`, `pythonVersion`) in `docs/getting-started/installation.md`, `README.md`, and `eidos/architecture/components/docs-getting-started.adoc`.
5. **Capability & Invariant Governance (`CAP-PROD-001`, `INV-DEVCONTAINER-FEATURE-CONFORMANCE`)**:
   * Bump `CAP-PROD-001` to `1.9.0` and add `INV-DEVCONTAINER-FEATURE-CONFORMANCE` bound to `tests/test_devcontainer_feature.py::test_devcontainer_feature_manifest_and_installer_conformance`:
     _"The OCI Dev Container Feature under devcontainer-features/src/eidos/ must maintain a schema-valid devcontainer-feature.json (exposing version, semantic, and pythonVersion options), an executable syntax-valid install.sh provisioning eidos-ai system-wide via uv with multi-distro prerequisite checks and Python <3.15 semantic guardrails, automated test scenarios under devcontainer-features/test/eidos/, sdist exclusion in pyproject.toml, and GHCR release automation in .github/workflows/ci.yml."_
