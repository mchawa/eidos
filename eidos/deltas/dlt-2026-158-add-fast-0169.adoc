= SpecDelta: Add Fast In-Process QuickJS Mermaid Diagram Syntax Validation to SpecValidator
:toc: left

== Problem Statement
Living specifications in `eidos/` routinely embed `[mermaid]` and `[source,mermaid]` AsciiDoc diagram blocks (`C4Context`, `sequenceDiagram`, `flowchart`, `stateDiagram-v2`, `classDiagram`, `erDiagram`), yet `SpecValidator` (`eidos validate` and `eidos drift`) currently ignores diagram bodies completely. Broken Mermaid syntax therefore slips past local validation and CI gates undetected.

Existing off-the-shelf validation approaches conflict with Eidos's zero-Node, zero-browser, offline (`POL-004`), and sub-second execution constraints:
* **`mermaid-cli` (`mmdc`) / Puppeteer / Playwright** launches Headless Chromium (~1–3s startup + hundreds of MB RAM).
* **`mermaid-py`** delegates to the external `mermaid.ink` HTTP API (violating offline/private-repo operation).
* **`mermaid-parser-py`** requires host Node.js + `pythonmonkey` and hooks deprecated `mermaidAPI` internals.
* **`mermaidx`** pulls in a C++ SVG rasterizer (`novasvg`) and runs full layout + SVG generation (~100–180 ms/diagram) instead of parse-only syntax validation.
* **Pure-Python regex / third-party Tree-sitter or Rust grammars** diverge from Mermaid's Jison grammars—especially for `C4Context` and flowchart label syntax—creating false positives on valid specs.

Empirical benchmarking on Eidos's real specs proved that calling `mermaid.parse()` directly inside **`quickjs-ng`** (2.4 MiB wheel, zero Node.js, zero Chromium, zero `novasvg`) validates each diagram in **~7–18 ms** (~8–10× faster than full SVG rendering) after a **~106 ms** bytecode-cached VM boot, and drops to **0 ms** on warm runs when backed by a SHA-256 cache in `eidos/.cache/index.db`.

== Proposed Specification Changes
* **`CMP-MERMAID-VALIDATOR` (new standalone component under `CNT-EIDOS-CORE`, `src/eidos/core/spec/mermaid_validator.py`)**:
  * **AsciiDoc Extraction (`extract_mermaid_blocks(body: str)`)**: Extract `[mermaid]` / `[mermaid, ...]` and `[source,mermaid]` / `[source, mermaid, ...]` AsciiDoc blocks delimited by matched `----` or `....` fences (`>=4` identical characters), ignoring AsciiDoc comment blocks (`//// ... ////`) and single-line comments (`// [mermaid]`), rejecting empty/whitespace-only diagram blocks with an explicit error, and recording 1-based body line numbers. Resolve exact 1-based `.adoc` file line offsets **lazily only on validation failure** by inspecting `doc.file_path` (falling back to body-relative line numbers when `doc.file_path` is unreadable or in-memory), avoiding both happy-path disk reads and any changes to `SpecDocument` (`CMP-DOMAIN-MODELS`) or `CMP-SPEC-PARSER`.
  * **Thread-Safe, Bounded QuickJS Execution (`validate_mermaid_blocks(...)`)**: Execute `mermaid.parse(code)` in `securityLevel: 'strict'` inside a lazily initialized, **thread-safe** dedicated single-worker thread (protecting concurrent callers such as `eidos portal serve` from non-thread-safe `quickjs.Context` access) with explicit worker thread stack sizing, QuickJS memory/stack limits (`set_memory_limit`, `set_max_stack_size`), and a bounded per-diagram execution timeout (`set_time_limit`) against the pinned standalone asset `assets/mermaid/mermaid.min.js.gz` (MIT-licensed `mermaid@12.x` `dist/mermaid.min.js`, ~1.50 MiB gzipped, completely independent of `CNT-EIDOS-PORTAL` and `assets/portal/`, preserving `ARCH-EIDOS-001` `core` denies `presentation` and `INV-CORE-MODULAR-COMPONENT-COHESION` acyclicity `CMP-SPEC-VALIDATOR -> CMP-MERMAID-VALIDATOR -> CMP-ASSET-LOCATOR`).
  * **Version-Pinned Caching & Bytecode Acceleration**: Derive canonical `engine_version` from the pinned Mermaid version + SHA-256 digest of `assets/mermaid/mermaid.min.js.gz` (and QuickJS version) for `mermaid_validation_cache` keys and atomic QuickJS bytecode caching (`eidos/.cache/mermaid_parser.<digest12>.qjsbc`, best-effort and gitignored under `eidos/.cache/`).
  * **Zero-Dependency Fallback**: When `quickjs` is unavailable (e.g., pre-release Python 3.15 without `quickjs-ng` wheels), degrade cleanly under a distinct `engine_version` (`"structural-v1"`) to a conservative pure-Python structural validator (non-empty block, recognized Mermaid header after comments/directives, valid `%%{...}%%` JSON directive, balanced `subgraph`/`end`, sequence `alt`/`opt`/`loop`/`par`/`critical`/`rect`/`end`, and quote/brace checks).
* **`CMP-ASSET-LOCATOR` (`src/eidos/core/workspace/assets.py`), `CNT-EIDOS-CORE` & `ARCH-EIDOS-001`**:
  * Ship the standalone `assets/mermaid/mermaid.min.js.gz` asset owned by `CNT-EIDOS-CORE` (automatically packaged by existing `pyproject.toml` `assets` force-include), add `get_mermaid_bundle_path() -> Path`, update `CNT-EIDOS-CORE` `runtime` + `source_path` and `ARCH-EIDOS-001` Source Path table, and record `DEC-CORE-IN-PROCESS-QUICKJS-MERMAID-VALIDATION`.
* **`CMP-GRAPH-STORAGE` (`src/eidos/core/index/storage.py`) & `CNT-EIDOS-INDEX`**:
  * Bump `SCHEMA_VERSION` from `"2.21.0"` to `"2.22.0"` (14 tables) adding stateless `mermaid_validation_cache (diagram_sha256 TEXT PRIMARY KEY, engine_version TEXT NOT NULL, is_valid INTEGER NOT NULL, error_message TEXT NOT NULL)`.
  * Export opportunistic non-blocking `load_mermaid_validation_cache(db_path, engine_version)` (`allow_ddl=False`) and `save_mermaid_validation_cache(db_path, rows)` (`_advisory_db_lock(..., non_blocking=True)`), matching `public_surface_cache` WAL safety (`DEC-INDEX-STRICT-FRESHNESS-LOCK-DIAGNOSTICS`).
* **`CMP-SPEC-VALIDATOR` (`src/eidos/core/spec/validator.py`)**:
  * Add `check_mermaid: bool = True` to `SpecValidator.validate_document(self, doc: SpecDocument, root_dir: Path | None = None, *, check_mermaid: bool = True) -> list[str]`.
  * Pass `check_mermaid=False` from `SpecValidator.validate_directory()` so `spec_validation_cache` stores strictly YAML/JSON schema verdicts, then run a single post-load batch `CMP-MERMAID-VALIDATOR` pass over loaded documents (skipping historical `status: applied` and `status: rejected` SpecDeltas, matching `fast_pathed_applied_deltas`), hydrating/flushing `mermaid_validation_cache` once per pass so unchanged diagrams never import `quickjs` or boot the VM (0 ms warm overhead), and emitting failures as blocking repo-relative `ValidationReport.schema_errors` entries (e.g., `Mermaid syntax error in [mermaid] block at line <N>: <parser message>`).
* **`CTR-EIDOS-CLI` (`1.8.0`), `CMP-DOCS-USER-GUIDES`, `CMP-DOCS-CORE-CONCEPTS` & `CAP-PROD-001` (`1.18.0`)**:
  * Synchronize `eidos validate` and `eidos index status` (`SCHEMA_VERSION` `2.22.0`) documentation in `eidos/architecture/contracts/cli.adoc`, `docs/guides/cli.md`, `docs/concepts/architectural-index.md`, and `CAP-PROD-001` (`INV-DOCS-SYNCHRONIZATION`), register `CMP-MERMAID-VALIDATOR`, and bind `INV-MERMAID-SPEC-VALIDATION` to `tests/test_mermaid_validator.py::test_mermaid_spec_validation_and_cache_lifecycle`.
