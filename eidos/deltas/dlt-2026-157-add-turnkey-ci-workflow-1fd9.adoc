= SpecDelta: Add Turnkey CI Workflow Templates to eidos init
:toc: left

== Problem Statement
While `eidos init` bootstraps the 12-directory `eidos/` skeleton and `eidos plugin install --hooks` wires local AI agent stop hooks, teams adopting Eidos still have to write GitHub Actions or GitLab CI YAML by hand (including `fetch-depth: 0` for 3-dot merge-base diffs, `uvx --from eidos-ai eidos drift`, and `$GITHUB_STEP_SUMMARY` Markdown output).

== Proposed Specification Changes
* **`CMP-REPO-INITIALIZER` (`src/eidos/core/lifecycle/initializer.py`)**: Add optional `ci: str | None = None` (`"github"` or `"gitlab"`, raising `ValueError` on unsupported providers) to `init_repository`, scaffolding `.github/workflows/eidos-drift.yml` (full-history checkout, `uvx --from eidos-ai eidos validate` + `eidos drift --base origin/${{ github.base_ref }} --markdown "$GITHUB_STEP_SUMMARY"`) or `.gitlab-ci.eidos.yml` (includeable merge-request gate template) non-destructively (preserving existing files unless `force=True`) and keeping templates 100% project-agnostic (`INV-ENGINE-GENERICITY`).
* **`CMP-CLI-INIT-COMMAND` (`src/eidos/cli/init_command.py`), `CTR-EIDOS-CLI` & `CMP-DOCS-USER-GUIDES`**: Expose `--ci` on `eidos init`, update `tests/fixtures/cli_command_tree.json` and `docs/guides/cli.md`.
* **`CAP-PROD-001`**: Add and bind `INV-INIT-CI-WORKFLOW-TEMPLATES`.

== Implementation Plan
1. **CI Template Generation (`CMP-REPO-INITIALIZER`)**: Add validated YAML templates and non-destructive write logic in `src/eidos/core/lifecycle/initializer.py` (`CNT-EIDOS-CORE` covered via `CMP-REPO-INITIALIZER`).
2. **CLI Option & Contract (`CMP-CLI-INIT-COMMAND`, `CTR-EIDOS-CLI`, `CMP-DOCS-USER-GUIDES`)**: Wire `--ci` in `src/eidos/cli/init_command.py` (`CNT-EIDOS-CLI` covered via `CMP-CLI-INIT-COMMAND` and `CTR-EIDOS-CLI`), update `tests/fixtures/cli_command_tree.json` and `docs/guides/cli.md`.
3. **Living Specs, Tests & Coverage (`POL-005-STATEMENT-TEST-COVERAGE`)**: Update all declared specs and add `tests/test_scaffolder.py::test_init_repository_ci_workflow_templates` verifying valid YAML parsing for both GitHub and GitLab templates, non-destructive preservation without `--force`, rejection of invalid `--ci` values, and `>90.0%` coverage.
4. **Verification**: Run `pytest`, `eidos delta verify DLT-2026-157 --json`, `eidos delta apply DLT-2026-157`, and `eidos drift --uncommitted --json`.
