= SpecDelta: Composable SpecDelta Mutation Schema (operation + target) and Stop-Scoped Drift Hook Execution
:toc: left

== Problem Statement

An architectural and agent-UX review of Eidos identified two sources of schema bloat, token overhead, and multi-turn agent friction (Section 7, sub-points 7.1 and 7.2):

1. **7.1 — Combinatorial SpecDelta Action & Target Taxonomy (`delta.schema.yaml`, `delta_engine.py`)**:
   * `assets/schemas/v1/delta/delta.schema.yaml` defines **44 distinct verb-noun enum values** under `mutations[].action` (`add_domain`, `modify_domain`, `remove_domain`, `add_capability`, `extend_capability`, `modify_capability`, `deprecate_capability`, `remove_capability`, `add_flow`, `modify_flow`, `remove_flow`, etc.) and **15 separate type-specific target properties** (`target_domain`, `target_capability`, `new_capability_id`, `target_container`, `target_component`, `target_architecture`, `target_contract`, `target_policy`, `target_persona`, `target_invariant_id`, `target_design_system`, `target_screen`, `target_ui_component`, `target_client`, `target_flow`).
   * Because every Eidos entity ID already carries a mandatory, unambiguous prefix (`DOM-*`, `CAP-*`, `CNT-*`, `CMP-*`, `ARCH-*`, `CTR-*`, `POL-*`, `PER-*`, `INV-*`, `DS-*`, `SCR-*`, `UIC-*`, `CLT-*`, `FLOW-*`), encoding the entity type in **three places** (`action: modify_screen`, `target_screen: SCR-HOME`, and the `SCR-` prefix itself) forces agents to memorize a 44-action matrix (`eidos-plan/SKILL.md`) and bloats `delta_engine.py`, `validator.py`, `models.py`, `audit.py`, `changelog.py`, `sync.py`, `drift.py`, and `generator.py` with repetitive action/target dispatch tables.

2. **7.2 — Noisy Per-Turn `PostInvocation` Drift Hook (`hooks.json`, `hooks.py`)**:
   * In `assets/plugin_reference/hooks.json` (lines 27–33 and 43–49) and `src/eidos/plugin/hooks.py` (`handle_drift_post_invocation` and `handle_lint_post_invocation`), Eidos runs `detect_drift(..., uncommitted=True)` and directory validation after **every single agent turn** (`PostInvocation`) and injects `[Eidos Sync Notice] Uncommitted code changes detected...` into the agent's context via `injectSteps`.
   * During standard multi-step software engineering tasks (Turn 1: edit source code -> Turn 2: run pytest -> Turn 3: fix edge case -> Turn 4: update living specs), running a full repository `detect_drift` pass and injecting drift warnings after every intermediate turn wastes tokens, adds per-turn latency, and distracts the agent mid-implementation.
   * Full spec-to-code drift gating belongs at task completion (**`Stop`**, which already implements TTL/session-scoped Block-Once fingerprinting in `eidos/.cache/stop-gate.json`), while intermediate turns only need fast single-file `.adoc` schema linting on `PreToolUse` / `PostToolUse`.

== Proposed Specification Changes

=== 1. Composable SpecDelta Mutation Schema (`CMP-DELTA-ENGINE`, `CMP-SPEC-VALIDATOR`, `CMP-DOMAIN-MODELS`, `CMP-DELTA-AUDITOR`, `CMP-CHANGELOG-GENERATOR`, `CMP-INCREMENTAL-SYNC-ENGINE`, `CMP-DRIFT-DETECTOR`, `CMP-PORTAL-GENERATOR`, `CAP-PROD-002`)

* **Orthogonal `operation` + `target` + `parent` Schema in `delta.schema.yaml`**:
  ** Support a composable mutation representation in `assets/schemas/v1/delta/delta.schema.yaml` using `anyOf: [{required: [operation, target]}, {required: [action]}]` so composable mutations and all historical `action`/`target_*` SpecDeltas validate cleanly:
     ```yaml
     mutations:
       - operation: modify # add | modify | remove | deprecate
         target: CMP-DELTA-ENGINE
         parent: CNT-EIDOS-CORE # optional parent scope for inline CMP-*, CAP-*, SCR-*, UIC-*; required for INV-*
         details: "..."
         expect:
           frontmatter:
             responsibility: "..."
     ```
  ** In composable mode (`operation` + `target`), require `target` to match the canonical prefixed entity ID pattern `^(DOM|CAP|PER|POL|INV|ARCH|CNT|CMP|CTR|DS|UIC|SCR|CLT|FLOW)-[A-Z0-9_-]+$` (and optional `parent` to match `^(DOM|CAP|POL|CNT|CMP|DS|CLT)-[A-Z0-9_-]+$`), inferring the target entity type deterministically from the ID prefix (`CMP-` -> `tech/component`, `CAP-` -> `product/capability`, `INV-` -> `invariant`, etc.) in `SpecValidator` (`src/eidos/core/spec/validator.py`). For `INV-*` targets, require `parent` (or legacy `target_capability` / `target_policy` / `target_container` / `target_component`) to identify the owning specification.
  ** Normalize both composable (`operation`, `target`, `parent`) and legacy verb-noun (`action`, `target_<type>`, `new_capability_id`) entries into canonical `(operation, entity_type, target_id, parent_id)` tuples inside a single shared normalizer in `delta_engine.py` (mapping `extend_capability` and `patch_policy`/`patch_invariant` to `operation == "modify"`), and consume it across `verify_delta_mutations`, `execute_delta_mutations`, `DeltaMutationModel` (`models.py`), `DeltaAuditor` (`audit.py`), `ChangelogGenerator` (`changelog.py`), `sync_index` (`sync.py`), `detect_drift` (`drift.py`), and `PortalGenerator` (`generator.py`).
  ** Record `DEC-CORE-COMPOSABLE-DELTA-MUTATIONS` under `decisions:` in `eidos/architecture/containers/core.adoc` (`graduated_from: DLT-2026-087`) and update `assets/plugin_reference/skills/eidos-plan/SKILL.md` to teach the concise `operation` + `target` syntax.

=== 2. Stop-Scoped Drift Gate Execution (`CMP-HOOK-RUNNER`, `CMP-HOOK-MANAGER`, `CMP-CLI-DOCTOR-HOOKS`, `CTR-EIDOS-CLI`, `CAP-AGENT-001`)

* **Remove `PostInvocation` from `assets/plugin_reference/hooks.json` & `hooks.py`**:
  ** Remove the `PostInvocation` hook bindings from `assets/plugin_reference/hooks.json` (and installed plugin targets via `eidos plugin update`), keeping:
     *** `eidos-doc-linter` on `PreToolUse` (fast markdown/ADR path guard), `PostToolUse` (fast single-file `.adoc` frontmatter & schema lint on the edited file), and `Stop` (final specification validation gate).
     *** `eidos-drift-gate` exclusively on `Stop` (`eidos hook drift --event Stop`), where full spec-to-code drift detection runs once when the agent attempts to conclude its task, protected by Block-Once fingerprinting in `eidos/.cache/stop-gate.json`.
  ** Retire `handle_drift_post_invocation`, `handle_lint_post_invocation`, and the `PostInvocation`-only `hook-state.json` working-tree digest short-circuit helpers from `src/eidos/plugin/hooks.py` (making `--event PostInvocation` a clean no-op `{"decision": "allow"}` for backwards compatibility with any un-updated external hook configs).
  ** Record `DEC-PLUGIN-STOP-SCOPED-DRIFT-GATE` under `decisions:` in `eidos/architecture/containers/plugin.adoc` (`graduated_from: DLT-2026-087`), and update `src/eidos/cli/doctor_hook_commands.py`, `CTR-EIDOS-CLI` (`eidos/architecture/contracts/cli.adoc`), `CAP-AGENT-001`, and `INV-HOOK-FAIL-LOUD` (`eidos/domains/agent-intelligence/capabilities/agent-adapter.adoc`).
