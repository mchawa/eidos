= SpecDelta: Diff-Aware Specification Coverage for Structural Code Additions
:toc: left

NOTE: Split from the original DLT-2026-034 (index enrichment). This delta is independent of DLT-2026-034 and can land in either order.

== Problem Statement

[`_is_covered_by_changed_specs()`](file:///home/MTS/marwan.chawa/WS/eidos/src/eidos/vcs/drift.py#L800) only checks whether a changed spec *path* falls inside the 1-hop neighbourhood of a structurally changed code file. It never looks at what changed in that spec. Adding a blank line or an AsciiDoc `// comment` to `container.adoc` silences drift for a brand-new module or public class that the spec never mentions.

[`detect_drift()`](file:///home/MTS/marwan.chawa/WS/eidos/src/eidos/vcs/drift.py#L895) already has the data needed to detect the case: `_get_file_versions()` returns `old = None` for added files, and [`has_structural_changes()`](file:///home/MTS/marwan.chawa/WS/eidos/src/eidos/core/ast_indexer.py#L801) already computes added public symbols using `_is_public_symbol()`. That information just isn't exposed in structured form.

== Architectural & Behavioral Mutations

=== 1. Structured public-symbol diff (CMP-AST-SYMBOL-INDEXER)
* `diff_public_symbols()` returns `added`, `removed` and `changed` lists of `(kind, parent, name)`. It uses the same indexer selection and `_is_public_symbol()` rules as today (Python: no leading `_`, plus `__init__`/`__call__`; other languages: the existing per-indexer public filter).
* `has_structural_changes()` is reimplemented on top of it with identical output.

=== 2. When the stricter rule applies (CMP-DRIFT-DETECTOR)
A structurally changed code file `cf` has **structural additions** when:

* it was added (`old is None and new is not None`), or
* `diff_public_symbols(old, new, cf).added` is non-empty.

For such files the stricter coverage rule below applies. In all other cases the existing rule is unchanged: signature changes, removals, deletions and design-token/UI-contract changes are still covered by any change to a 1-hop spec. Planned Mode coverage through an active delta that declares the target (`covered_by_delta`) is also unchanged and is checked first.

=== 2a. Moves and renames (content-based, no VCS rename detection)
The changed-file list keeps both sides of a rename (`--no-renames`). Eidos then pairs each added file with a deleted file of the same change set and extension when their whitespace-normalized contents are identical, or when the deleted file had public symbols that all still exist in the added file. A paired file is not a new file: only public symbols absent from its source count as additions, so a pure move keeps the classic coverage rule.

=== 3. Substantive spec diff (deterministic)
`_SpecDiffInspector.is_substantive(spec)` uses `_get_file_versions()` for the spec, in the same mode as the code diff (`--uncommitted` or `base...head`), and caches the result per spec for the run.

* A new spec (`old is None`) or a deleted spec is substantive.
* Otherwise, both versions are normalized and compared:
  . compare the frontmatter as parsed YAML data (YAML comments and formatting are ignored; `#` inside block strings is content; invalid YAML falls back to whitespace-normalized text);
  . in the body, drop AsciiDoc single-line comments (`//`, but not `///` text) and `////` comment blocks, *except* inside verbatim blocks (`----` listing, `....` literal, `++++` passthrough) whose lines, e.g. `// ...` in code samples, are content;
  . collapse every whitespace run, including line breaks, to one space and strip.
* The diff is substantive iff the normalized old and new texts differ. Pure re-indentation, re-wrapping, blank lines and comment edits are therefore all trivial.
* If the two versions are identical in git (synthetic or mocked diffs, as already handled for code at L919–923), the spec is treated as substantive to preserve current behavior.

=== 4. Anchor requirement for new unclaimed files
If an added `cf` is not matched by any `source_path` or `owned_path` declared in the owner's spec at the base revision (i.e. it is owned only through a `package_path` prefix), at least one substantive owner-spec diff must also be **anchored**. `_SpecDiffInspector.is_anchored()` returns true if either:

* the `components`, `source_path`, `owned_path` or `package_path` frontmatter keys differ between the parsed old and new frontmatter, or
* a normalized added line (or changed frontmatter value) contains the file's repo-relative path, its file name *with* extension, or the qualified name of one of its added public symbols (`Class.method` for methods). A bare stem is not enough: generic words such as "utils" must not anchor `utils.py`.

=== 5. Reporting
* Files whose only coverage was rejected are appended to `uncovered_components` / `uncovered_direct_components` as today, so `drift_detected` becomes true. They are also recorded in `DriftCheckResult.trivially_covered_files` with `rule: "trivial_spec_diff" | "missing_anchor"`, the triggering `additions` (e.g. `added class 'Foo'`, `added file 'src/x.py'`) and the rejected `spec_files`.
* A new summary/remediation line is added: `Trivial Spec Edit: <n> structural addition(s) are only covered by whitespace/comment-only spec edits — document <additions> in <spec>.`

=== 6. Living specification updates
* [drift-detection.adoc](file:///home/MTS/marwan.chawa/WS/eidos/eidos/domains/vcs-lifecycle/capabilities/drift-detection.adoc): add `INV-DRIFT-DIFF-AWARE-COVERAGE`, a "Diff-Aware Spec Coverage" responsibility, and `version: "1.3.0"`.
* [vcs.adoc](file:///home/MTS/marwan.chawa/WS/eidos/eidos/architecture/containers/vcs.adoc): extend the `CMP-DRIFT-DETECTOR` responsibility with diff-aware coverage of structural additions.
* [cli.adoc contract](file:///home/MTS/marwan.chawa/WS/eidos/eidos/architecture/contracts/cli.adoc): document `trivially_covered_files` in `eidos drift --json`.

== Out of Scope
* Requiring substantive spec edits for signature changes, removals or deletions (possible follow-up once false-positive rates are known).
* Semantic or NLP judgement of prose quality. Only the normalized-content and anchor checks above are enforced.
