= SpecDelta: Polyglot AST Symbol Indexing, AI Code Graph, and Granular Invariant Traceability via ast-grep
:toc: left
:icons: font

== 1. Problem Statement & Motivation

In Eidos, the boundary between **C4 Level 3 (Components)** and **C4 Level 4 (Code & AST)** currently exhibits two fundamental architectural limitations:

1. **Governance & Drift Coarseness:**
   * **Coarse Reverse Symbol Mapping:** `symbol_mappings` in `.eidos/cache/index.db` only stores file paths and manual interface signatures from spec YAML frontmatter (`interfaces.provides`). It does not dynamically index classes, methods, or routes from actual source code.
   * **Naive Invariant Test Scans:** In `src/eidos/vcs/drift.py`, invariant test coverage checks read whole test files and evaluate `if iid in content`. This substring check cannot identify *which specific test function* exercises an invariant, and is susceptible to false positives from comments or variable names.
   * **Coarse Drift Alerts:** `eidos drift` detects file modifications via `git diff --name-only`. An internal private helper refactoring is treated identically to a breaking public API signature change.

2. **AI Agent Context Inefficiency (The Code Intelligence Gap):**
   * AI coding agents (Antigravity, Cursor, Claude Code, Copilot) frequently suffer from either **context bloat** (stuffing thousands of lines of raw code into prompts) or **hallucinated symbol names** (guessing method signatures because no structural index exists).
   * Plain text `grep` is noisy (matching comments, imports, strings), while vector embeddings are fuzzy and non-deterministic (unable to answer exact structural questions like *"what methods are declared on class X?"*).
   * Eidos currently indexes living specifications (`.adoc`) into SQLite, but leaves source code unindexed in relational tables.

Following feasibility research in `EXP-2026-005`, `ast-grep` (`ast-grep-py`) was proven to deliver sub-10ms polyglot AST parsing across Python, TypeScript, Go, Rust, and Java within a single pre-compiled 5MB wheel, while Python standard library `ast` provides a zero-dependency fallback.

== 2. Architectural Design & Deliverables

=== 2.1 The Two-Tiered AST Indexing Engine (`ast_indexer.py`)

A new component `CMP-AST-SYMBOL-INDEXER` is introduced under `src/eidos/core/ast_indexer.py`:

```
┌────────────────────────────────────────────────────────┐
│             Polyglot Source Code & Tests               │
│         (Python, TypeScript, Rust, Go, Java)           │
└───────────────────────────┬────────────────────────────┘
                            │
               ast-grep-py Installed?
              /                      \
        [YES]                         [NO] (Fallback)
          ▼                             ▼
┌───────────────────────────┐ ┌───────────────────────────┐
│      AstGrepIndexer       │ │      FallbackIndexer      │
│ ├── Single ~5MB Rust wheel│ │ ├── Python stdlib `ast`   │
│ ├── Python, TS, Rust, Go  │ │ └── Polyglot regex lexer  │
│ └── Sub-10ms per 1k lines │ └── Zero external wheels    │
└─────────────┬─────────────┘ └─────────────┬─────────────┘
              │                             │
              └──────────────┬──────────────┘
                             ▼
┌────────────────────────────────────────────────────────┐
│       Embedded SQLite Knowledge Graph (.eidos/cache)    │
│  ├── symbol_mappings (classes, functions, endpoints)   │
│  ├── edges ((test_fn) -> asserts -> (INV-*))           │
│  └── entities (C4 Level 3 & Level 4 linked)            │
└───────────────┬────────────────────────┬───────────────┘
                │                        │
       Architectural Governance     AI Code Intelligence
         - eidos drift (AST diff)     - eidos index repo-map
         - Invariant traceability     - eidos index find-symbol
         - Zero-drift verification    - Surgical context slicing
```

=== 2.2 The AI Code Graph & Structural Repo Map Engine

The embedded SQLite knowledge graph (`.eidos/cache/index.db`) becomes a unified **Architectural & Code Graph**:

1. **Compressed Structural Repo Map (`eidos index repo-map`)**:
   Generates a token-budgeted outline of classes, public methods, function signatures, and file coordinates:
   ```text
   src/eidos/core/graph_index.py [CNT-EIDOS-INDEX]
     ├── class ArchitecturalIndex
     │     ├── def get_tiered_context_slice(component_id, tier) -> TieredContextSlice
     │     ├── def get_repo_map(max_tokens=1500) -> str
     │     └── def find_symbol(name) -> list[SymbolMatch]
     └── class TieredContextSlice
           ├── def to_dict() -> dict
           └── def to_markdown() -> str
   ```
   * **Token Compression:** Achieves **>= 85% token reduction** compared to raw file loading (~800 tokens vs. ~40,000 tokens for 20 modules).
   * **Hallucination Prevention:** Agents inspect exact signatures and parameters before editing code.

2. **Sub-Millisecond Symbol Discovery (`eidos index find-symbol <name>`)**:
   Provides machine-readable (`--json`) lookup of symbol declarations, file paths, line ranges, docstrings, and owning C4 components:
   ```bash
   eidos index find-symbol TieredContextSlice --json
   ```

3. **Full Vertical Grounding (The Unified Semantic Stack)**:
   Connects the entire hierarchy in a single relational query:
   ```text
   Level 1: System Vision      (SYS-EIDOS-001)
      │
   Level 2: Container          (CNT-EIDOS-INDEX)
      │
   Level 3: Component Spec     (CMP-TIERED-CONTEXT-COMPRESSOR)
      │
   Level 4: AST Code Symbol    (def get_tiered_context_slice in graph_index.py#L850)
      │
   Testing: Test Function      (tests/test_context.py::test_tiered_context_slice)
      │
   Policy:  Governing Invariant (INV-INDEX-AI-REPO-MAP-BUDGET)
   ```

=== 2.3 Optional Packaging (`pyproject.toml`)

In strict compliance with `POL-004-ZERO-AI-CALL-DEPENDENCY`:
* Base installation (`pip install eidos-ai`) remains 100% lightweight and zero-dependency for AST parsing.
* Optional extra enables AST acceleration:
  ```toml
  [project.optional-dependencies]
  ast = [
      "ast-grep-py>=0.50.0",
  ]
  ```

=== 2.4 Incremental Sync & Invariant Traceability

1. **Incremental Indexing (`graph_index.py`)**:
   During `eidos index sync` (and automatic dirty refreshes), `CMP-AST-SYMBOL-INDEXER` extracts symbols for modified code files and persists them to `symbol_mappings`.
2. **Granular Test Mapping (`drift.py`)**:
   Test file analysis queries function-level nodes (`def test_*`, `it(...)`, `func Test*`, `#[test] fn`) and maps enclosed invariant references (`INV-*`, `POL-*`) to specific test function identifiers.

== 3. Invariants & Acceptance Criteria

1. **`INV-INDEX-OPTIONAL-AST-FALLBACK`**:
   The entire test suite (`pytest`) must pass 100% with zero failures or deprecation warnings both with and without `ast-grep-py` installed in the environment.
2. **`INV-INDEX-POLYGLOT-SYMBOL-PRECISION`**:
   When `ast-grep-py` is installed, `symbol_mappings` must resolve exact function and class names across Python and TypeScript, with query latency under 10ms for 1,000 lines.
3. **`INV-INDEX-AI-REPO-MAP-BUDGET`**:
   The generated AI repo map must compress codebase structure by >= 85% compared to raw file loading and execute in <15ms across 50+ source files.
4. **`POL-004-ZERO-AI-CALL-DEPENDENCY`**:
   Zero LLM or AI model APIs invoked during any AST extraction, repo map generation, or indexing operation.
