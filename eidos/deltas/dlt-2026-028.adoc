= SpecDelta: Scoped 1-Hop Graph Neighborhood and AST Structural Drift Detection
:toc: left

== Problem Statement

Previously, `detect_drift()` evaluated `base_direct_drift = code_changed and not specs_changed and not has_deltas`. This had two major flaws:
1. Editing a single line inside the body of an existing function (a bugfix, typo fix, or internal refactor) triggered drift and forced unnecessary specification edits.
2. Modifying 10 files in Component A while touching an unrelated spec for Component B silenced drift across the entire repository.

== Architectural & Behavioral Mutations

1. **AST Structural Change Filtering (`has_structural_changes`)**:
   * Compare AST symbols (`class`, `function`, `method`, `interface`, `struct`, `enum`, `type`) and their header signatures between the Git base blob and current file content.
   * **Structural changes** (file added/deleted, or public symbol added, removed, renamed, or signature modified) require specification synchronization.
   * **Body-only changes** (edits strictly inside existing function/method bodies or private `_` helpers) pass cleanly without requiring spec churn.
2. **Scoped 1-Hop Graph Neighborhood Verification**:
   * Each file with a structural change is mapped to its owning `CNT-*` / `CMP-*` / `CLT-*` / `DS-*` entities in the SQLite Knowledge Graph.
   * Drift is satisfied only if the owning specification or a 1-hop linked neighbor (`CAP-*`, `CTR-*`, parent `CNT-*`, `CLT-*`, `DS-*`) is updated in the same diff (or declared in an active SpecDelta).
