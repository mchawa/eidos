= SpecDelta: Harden Plugin Dev Versioning, Uniform Symlink Safety, Config Clarity, and Centrality-Ranked Repo Map
:toc: left

== Problem Statement
Six operational rough edges surfaced during live dogfooding of `v0.29.0`:
1. **Editable `.devN` Version Mismatch**: `_parse_git_describe_version()` resolves post-tag dev commits to `X.Y.(Z+1).devN` (e.g., `0.29.1.dev1`), and `get_bundled_plugin_version()` strips `.dev1` into an unreleased `"0.29.1"`, causing `eidos doctor` to falsely fail (`healthy: false`, `outdated`) on every dev commit and `eidos plugin update` to write unreleased versions into `.eidos-manifest.json`.
2. **Eidos-Only Canonical Symlink Special-Case**: `_is_canonical_skills_symlink()` in `installer.py` and `skills.is_symlink()` fallbacks in `version.py` and `doctor_hook_commands.py` existed solely for Eidos's former self-hosted `.agents/skills` symlink (now replaced with real installed files) and broke when running globally installed wheel binaries.
3. **Missing Trailing Newline on `.eidos-manifest.json`**: `installer.py` serialized `.eidos-manifest.json` without a trailing `\n`, creating `No newline at end of file` diff noise for repositories committing `.agents/.eidos-manifest.json`.
4. **Ambiguous `workspace.tests.exclude` Documentation**: Users setting `workspace.tests.exclude` on non-test scripts under `tests/` were surprised when files reclassified to unowned `code/source`, reducing `source_ownership` instead of being excluded via `workspace.exclude`.
5. **Missing Onboarding `.gitignore` & `eidos config init` Cross-References**: `docs/guides/agent-plugin.md` omitted `eidos config init` from its agent CLI table and lacked `.gitignore` guidance for tracking `.agents/skills/` and `.agents/.eidos-manifest.json`.
6. **Alphabetical `repo-map` Truncation**: `BaseAstIndexer.generate_repo_map()` and `generate_repo_map_from_db()` truncated strictly in alphabetical path order, dropping core architectural hubs whenever earlier-alphabetical modules were added.

== Proposed Specification Changes
* **`CMP-PLUGIN-INSTALLER`, `CNT-EIDOS-PLUGIN`, `CAP-AGENT-ADAPTER` (`1.21.0`), `INV-PLUGIN-INSTALL-TRUTHFULNESS`**:
  * Remove `_is_canonical_skills_symlink()` and all `skills.is_symlink()` detection fallbacks so every symlinked skill destination is refused uniformly while preserving per-target fault isolation across `install all` / `update all`.
  * Resolve PEP 440 post-tag dev versions (`X.Y.Z.devN` with `Z > 0`) in `get_bundled_plugin_version()` to their base released SemVer `X.Y.(Z-1)` (and pre-release `.devN` tags like `0.29.0-rc.1.dev2` or `0.29.0.dev1` without fabricating an unreleased final version), so `eidos doctor` checks skill SHA-256 parity cleanly across editable dev commits.
  * Append a trailing `\n` whenever `.eidos-manifest.json` is written.
* **`CMP-AST-SYMBOL-INDEXER`, `CMP-FTS-QUERY-ENGINE`, `CAP-AST-CODE-GRAPH` (`1.12.0`), `INV-INDEX-AI-REPO-MAP-BUDGET`**:
  * Extend `BaseAstIndexer.generate_repo_map(symbols_by_file, max_tokens=1500, file_weights=None)` to rank modules by architectural centrality (`file_weights`) plus public API surface richness (`classes * 3 + public_funcs + public_methods`, gating centrality weights on non-zero public surface) with deterministic alphabetical tie-breaking, keeping the canonical truncation marker.
  * Compute incoming `code_couplings` file-level (`provenance = 'ast_import'`) and entity-level fan-in weights in `generate_repo_map_from_db()` (gracefully degrading when `code_couplings` is absent) and pass them as `file_weights` (`CNT-EIDOS-INDEX` covered via `CMP-AST-SYMBOL-INDEXER` and `CMP-FTS-QUERY-ENGINE`).
* **`CMP-DOCS-USER-GUIDES`**:
  * Clarify `workspace.tests.exclude` vs `workspace.exclude` in `docs/guides/cli.md` (`CNT-EIDOS-DOCS` covered via `CMP-DOCS-USER-GUIDES`), add `eidos config init` to the CLI table in `docs/guides/agent-plugin.md`, and document `.gitignore` best practices for committing `.agents/skills/` and `.agents/.eidos-manifest.json`.
