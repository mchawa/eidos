= SpecDelta: Accurate Non-Code Invariant/Delta/Validation Drift Diagnostics in Hooks & CLI and Push-Aware CI Drift Base Resolution
:toc: left

== Problem Statement

`CMP-HOOK-RUNNER` (`src/eidos/plugin/hooks.py`), `CMP-DRIFT-DETECTOR` (`src/eidos/vcs/report.py`), `CMP-CLI-DRIFT-COMMANDS` (`src/eidos/cli/drift_commands.py`), and `.github/workflows/ci.yml` have three defects:

1. **Misleading `"0 code file(s) were modified"` Diagnostics on Non-Code Drift (`src/eidos/plugin/hooks.py`, lines 455-462 & 592-600; `src/eidos/vcs/report.py`, lines 135-145; `src/eidos/cli/drift_commands.py`, lines 116-122)**:
   * When `report.drift_detected` is `True` solely because of a broken `INV-*` test binding (`tests/` edit or spec edit) or an unverified active `DLT-*` mutation while `len(report.code_files) == 0`:
     - `handle_drift_stop` and `execute_drift_hook` emit `"0 code file(s) were modified without corresponding updates to eidos/ specifications."` and omit `unverified_delta_mutations` from the failure message.
     - `generate_remediation_prompt` emits `"Modified Source Code Files (causing drift):\n(none)"`.
     - `drift_commands.py` prints `"DRIFT DETECTED: Code modified without corresponding spec updates!"`.
2. **Standalone `eidos hook drift` Ignores Spec Validation Errors (`src/eidos/plugin/hooks.py`, line 588)**:
   * `execute_drift_hook` checks `if report.drift_detected:` instead of `if not report.is_clean:` (`report.drift_detected or not report.validation_passed`), and `handle_drift_stop` omits `report.validation_errors` from the Stop-gate fingerprint and message.
3. **No-Op `eidos drift --base origin/main` on `push` Events in CI (`.github/workflows/ci.yml`, lines 72-73)**:
   * On `push` events to `main`, `origin/main` already points to `HEAD`, so `uv run eidos drift --base origin/main` evaluates `git diff origin/main...HEAD` (`HEAD...HEAD`, 0 changed files) instead of comparing against `${{ github.event.before }}`.

== Proposed Specification Changes

1. **Cause-Aware Drift Diagnostics in `hooks.py`, `report.py`, and `drift_commands.py`**:
   * Gate `execute_drift_hook` and `handle_drift_stop` on `not report.is_clean`, include `validation_errors` and `unverified_delta_mutations` in the fingerprint and message, and construct the summary headline from the active failure category (spec validation failure, broken invariant test bindings, unverified SpecDelta mutations, or unmapped code changes).
   * Update `generate_remediation_prompt` (`src/eidos/vcs/report.py`) and `drift` (`src/eidos/cli/drift_commands.py`) to describe non-code drift accurately when `report.code_files` is empty.
2. **Push-Aware Base Commit Resolution in `.github/workflows/ci.yml`**:
   * On `pull_request` events, use `origin/${{ github.base_ref || 'main' }}`; on `push` events with a valid non-zero `github.event.before` SHA, pass `--base ${{ github.event.before }}` to `eidos drift`.

== Verification Plan

* `uv run pytest tests/test_plugin.py tests/test_drift.py` — Verify `handle_drift_stop`, `execute_drift_hook`, `generate_remediation_prompt`, and `eidos drift` produce accurate messages when `code_files` is empty and invariant/delta/validation failures occur.
* `uv run eidos validate eidos && uv run eidos drift --uncommitted --json`
