= SpecDelta: Resolve Symbols, Source File Paths, and Spec Paths in Blast Radius Queries
:toc: left

== Problem Statement
Both `CTR-EIDOS-CLI` (`eidos/architecture/contracts/cli.adoc`) and `docs/guides/cli.md` specify that `eidos index blast-radius` accepts `SYMBOL_OR_PATH` (*"Container ID, component ID, contract ID, domain ID, symbol, or file path"*).

However, passing a source file path (e.g. `src/eidos/vcs/drift.py`), specification path (`eidos/architecture/containers/vcs.adoc`), or code symbol (`detect_drift`) fails with `Entity '<input>' not found in architectural graph.`:

1. **Direct join against `entities.id` without resolution**:
   * `index_blast_radius_cmd()` in `src/eidos/cli/index_commands.py` declares its argument as `entity_id: str` and passes the raw string directly to `idx.get_k_hop_neighborhood(entity_id, max_depth=depth)`.
   * `execute_k_hop_traversal()` in `src/eidos/core/index/query.py` seeds the recursive CTE `graph_walk` with `(entity_id, 0, entity_id)` and immediately runs `JOIN entities ent ON ent.id = gw.node_id`.
   * Because `entities.id` only stores canonical entity IDs (`CNT-*`, `CMP-*`, `CAP-*`, `CTR-*`, etc.) and never invokes `resolve_symbol_or_path_in_db()` or `indexed_files` lookup, any file path or symbol produces zero rows.
2. **CLI contract verifier ignores positional argument placeholders**:
   * `SpecValidator._verify_cli_contract_commands()` in `src/eidos/core/spec/validator.py` strips tokens starting with `<` or `[`, so it verified the subcommand name `blast-radius` while missing both positional argument count parity and placeholder-to-parameter/metavar alignment (such as `<symbol_or_path>` in `CTR-EIDOS-CLI` vs. `entity_id` in `index_commands.py`).

== Proposed Specification Changes
* **Update `CMP-GRAPH-TRAVERSAL-ENGINE` (`eidos/architecture/components/graph-traversal-engine.adoc`)**:
  - Add `resolve_blast_radius_targets(conn: sqlite3.Connection, symbol_or_path: str) -> list[str]` in `src/eidos/core/index/query.py`:
    1. Exact (case-insensitive) match against `entities.id`.
    2. Specification file path match against `indexed_files` (`doc_id`) and `entities.file_path` (normalizing leading `./`, backslashes, and `eidos/` prefixes, plus suffix path matching for relative spec subpaths).
    3. Source file path, `source_path` glob, `test_binding`, or AST code symbol resolution via `resolve_symbol_or_path_in_db(conn, symbol_or_path)`:
       * When exact AST/symbol matches (`m["symbol"] == clean`) exist among non-path symbol matches, prefer exact matches over `.method` / `::func` suffix fallbacks.
       * When one or more `tech/component` (`CMP-*`) matches resolve, filter to `tech/component` seeds so ancestor `tech/container` (`CNT-*`) matches and shared `specification_file` (`CTR-*`) contracts (e.g. `src/eidos/cli/main.py` on `CTR-EIDOS-CLI`) are reached naturally at `depth >= 1` rather than inflating the walk at `depth = 0`, while seeding all co-owning `CMP-*` entities at `depth = 0` (and preserving `CNT-*` or `CTR-*` seeds when no `CMP-*` match exists).
  - Update `execute_k_hop_traversal(conn, entity_id: str | Sequence[str], max_depth: int = 2)` to resolve string queries via `resolve_blast_radius_targets()`, seed `graph_walk` with all resolved target entity IDs at `depth = 0`, and return `[]` when no target resolves; reconcile `== Public Surface` signatures in `graph-traversal-engine.adoc` (`entity_id: str | Sequence[str]`, `target_id_or_path: str`, `query: str`).
* **Update `CMP-GRAPH-STORAGE` (`eidos/architecture/components/graph-storage.adoc`) & `CMP-CLI-INDEX-COMMANDS` (`eidos/architecture/components/cli-index-commands.adoc`)**:
  - Expose `resolve_blast_radius_targets()` on `ArchitecturalIndex` and accept `entity_id: str | Sequence[str]` on `ArchitecturalIndex.get_k_hop_neighborhood()` in `src/eidos/core/index/graph_index.py`.
  - Rename the CLI argument in `index_blast_radius_cmd()` (`src/eidos/cli/index_commands.py` and `tests/fixtures/cli_command_tree.json`) to `symbol_or_path` (`metavar="SYMBOL_OR_PATH"`), guard empty resolution via `"entity_id": resolved_ids[0] if resolved_ids else symbol_or_path`, include `"query"` and `"resolved_entities"` alongside `"entity_id"` in `--json` output, display resolved entity IDs in Rich terminal output when queried by path or symbol, and document `symbol_or_path` in `cli-index-commands.adoc`.
* **Update `CMP-SPEC-VALIDATOR` (`eidos/architecture/components/spec-validator.adoc`) & `CTR-EIDOS-CLI` (`eidos/architecture/contracts/cli.adoc`)**:
  - Extend `_verify_cli_contract_commands()` to strip bracketed `[--opt ...]` blocks and unbracketed `--opt <val>` option-value pairs before extracting positional `<arg>` (required) and `[arg]` (optional) placeholders across both top-level commands and subcommands, verifying positional argument count parity and placeholder-to-parameter/metavar alignment (matching `<placeholder>` / `[placeholder]` against explicit `metavar`, parameter name, or shared identifier sub-token/generic target aliases like `target` for `<id_or_path>`/`[TARGET]`, `doc_type` for `<type>`, `doc_id`/`delta_id` for `<id>`, and `plugin_path` for `[PATH]`).
  - Document `query` and `resolved_entities` in `CTR-EIDOS-CLI`.
* **Update `CAP-PROD-001` (`1.8.0`) & `INV-KNOWLEDGE-GRAPH-CATALOG` (`eidos/domains/spec-engine/capabilities/living-spec-engine.adoc`)**:
  - Bump `CAP-PROD-001` version to `1.8.0` and register `CMP-GRAPH-TRAVERSAL-ENGINE` and `CMP-FTS-QUERY-ENGINE` under `technical.components`.
  - Require `k`-hop blast-radius traversal to resolve canonical entity IDs, specification paths, source file paths, and AST symbols.

== Implementation Plan
1. **Target Resolution & Multi-Seed CTE (`src/eidos/core/index/query.py`, `src/eidos/core/index/graph_index.py`)**:
   * Implement `resolve_blast_radius_targets(conn, symbol_or_path)` combining case-insensitive `entities.id` lookup, `indexed_files` / `entities.file_path` spec path lookup, and `resolve_symbol_or_path_in_db()` source/symbol resolution (preferring exact symbol matches over suffix fallbacks and filtering to `CMP-*` seeds when `CMP-*` matches exist).
   * Update `execute_k_hop_traversal()` and `ArchitecturalIndex.get_k_hop_neighborhood()` to accept `entity_id: str | Sequence[str]`, seed `graph_walk` at `depth = 0` for all resolved IDs, and return `[]` when `resolved_ids` is empty.
2. **CLI Command & Output (`src/eidos/cli/index_commands.py`, `tests/fixtures/cli_command_tree.json`)**:
   * Rename `entity_id` parameter in `index_blast_radius_cmd()` to `symbol_or_path: str = typer.Argument(..., metavar="SYMBOL_OR_PATH", help=...)` and synchronize `tests/fixtures/cli_command_tree.json`.
   * Resolve `resolved_ids = idx.resolve_blast_radius_targets(symbol_or_path)` and pass `resolved_ids` to `idx.get_k_hop_neighborhood()`, returning `"entity_id": resolved_ids[0] if resolved_ids else symbol_or_path`, `"query": symbol_or_path`, and `"resolved_entities": resolved_ids` in `--json` mode.
3. **Validator, Specs & Tests (`src/eidos/core/spec/validator.py`, `eidos/`, `tests/test_graph_index.py`, `tests/test_validator.py`)**:

   * Update `CMP-GRAPH-TRAVERSAL-ENGINE`, `CMP-GRAPH-STORAGE`, `CMP-CLI-INDEX-COMMANDS`, `CMP-SPEC-VALIDATOR`, `CTR-EIDOS-CLI`, `CAP-PROD-001` (`1.8.0`), and `INV-KNOWLEDGE-GRAPH-CATALOG`.
   * Add unit and CLI tests in `tests/test_graph_index.py` and `tests/test_validator.py` verifying `eidos index blast-radius` with an entity ID (`CNT-EIDOS-VCS`), a source file path (`src/eidos/vcs/drift.py`), a spec file path (`eidos/architecture/containers/vcs.adoc`), and an AST symbol (`detect_drift`), plus CLI positional placeholder drift detection in `SpecValidator`, then run `eidos delta verify DLT-2026-114-RESOLVE-SYMBOLS-0327 --json`.
