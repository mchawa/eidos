= SpecDelta: Repo-Relative Path Normalization and Configurable Governance Checks Across Validator and Drift
:toc: left

== Problem Statement
1. **False-Positive `INV-COMPONENT-CENTRALIZATION-MANDATE` Under `~/src/...`**:
   - In `src/eidos/core/spec/validator.py:617-623`, `rel_parts = doc.file_path.parts` inspects the full `Path` (which is absolute when invoked from `portal/server.py:94` or when passed an absolute path) and triggers a violation whenever `"src" in rel_parts`. Any repository checked out inside `/home/<user>/src/...` or `/usr/src/...` fails validation on every `tech/component` document.
2. **Hardcoded `eidos/` Directory Name in Drift Classification**:
   - `classify_git_changes` (`src/eidos/vcs/drift.py:373-384`) and helper routines (`lines 962, 1066-1069, 2040`) hardcode `parts[0] == "eidos"`. Running `eidos drift --path specs` on a repository using a custom specification directory fails to classify modified `.adoc` files as `spec_files` or `delta_files`.
3. **Eidos-Specific Checks Hardcoded in Generic Validator**:
   - `_validate_cli_contract_parity` (`validator.py:725-783`) assumes a Python Typer CLI (`app = typer.Typer`), and `validator.py:19-37` maintains a manual prefix table duplicating `x-eidos-ref` metadata in the v1 YAML schemas.

== Proposed Specification & Engine Changes
1. **Repo-Relative Path Evaluation in `SpecValidator`**:
   - Compute `rel_parts = doc.file_path.resolve().relative_to(root_dir.resolve()).parts` before checking component directory placement so parent directories above the repository root never trigger false positives.
2. **Dynamic Spec Directory Prefix in `classify_git_changes`**:
   - Resolve `eidos_dir` relative to `repo_root` via `CMP-PROJECT-RESOLVER` and classify spec/delta changes against that relative prefix instead of hardcoded `"eidos"`.
3. **Schema-Driven Reference Prefixes & Scoped Contract Parity**:
   - Derive entity ID prefixes directly from `x-eidos-ref` schema declarations and run Typer AST parity checks only when the contract's `protocol: cli_args` binds to a Python Typer entrypoint.
