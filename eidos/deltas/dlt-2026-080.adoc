= SpecDelta: Cross-Ref Collision-Safe SpecDelta ID Resolution, Optional ID/Slug CLI Ergonomics, and Applied Delta Fast-Path Validation
:toc: left

== Problem Statement

1. **Explicit Delta IDs Bypass Collision Detection**:
   In `src/eidos/core/lifecycle/scaffolder.py` (`create_spec`), `generate_collision_free_delta_id` is only invoked when `raw_id.strip().lower() in ("", "auto", "auto-slug")`. When a user or agent passes an explicit ID (e.g. `eidos delta create DLT-2026-079 --title "..."`), `create_spec` bypasses `generate_collision_free_delta_id` completely and only checks whether the file exists in the local working tree. Furthermore, inside `generate_collision_free_delta_id` (`delta_engine.py:L523`), the collision check `if slug_suffix or (is_auto and base_id in existing_ids):` ignores `base_id in existing_ids` when `is_auto` is `False`, returning a colliding ID even when that ID already exists on `origin/main` or another branch.

2. **Incomplete Git Ref Discovery**:
   `generate_collision_free_delta_id` currently inspects only 5 hardcoded ref names (`HEAD`, `main`, `origin/main`, `master`, `origin/master`). SpecDeltas created on parallel local or remote feature branches (`refs/heads/*`, `refs/remotes/*`) are not scanned, risking sequential `DLT-YYYY-NNN` collisions when parallel branches merge.

3. **CLI Friction on `eidos delta create`**:
   `delta_create_cmd` in `src/eidos/cli/delta_commands.py` requires `delta_id` as a mandatory positional argument and does not expose `--slug`, encouraging users and agents to guess sequential IDs manually instead of using collision-free auto/slug generation.

4. **Unbounded `eidos/deltas/` Validation Overhead**:
   As applied SpecDeltas accumulate in `eidos/deltas/` (already 78+ files), `SpecValidator.validate_directory` re-evaluates all historical `status: applied` deltas on every run.

== Proposed Specification Changes

1. **Universal Collision Resolution Across All Git Refs (`CMP-DELTA-ENGINE`, `CMP-LIFECYCLE-SCAFFOLDER`)**:
   * Always route `canonical_key == "delta"` through `generate_collision_free_delta_id(eidos_dir, raw_id=raw_id, title=title, slug_suffix=slug_suffix)` in `create_spec`.
   * Expand Git ref scanning in `generate_collision_free_delta_id` to enumerate all local and remote branch refs (`refs/heads`, `refs/remotes`) via a batched `git ls-tree` / `git for-each-ref` inspection.
   * When an explicit `base_id` collides with an existing ID on any ref (or when `slug_suffix=True`), deterministically resolve the collision by advancing the sequence number or appending the title-derived slug/hash suffix.

2. **Optional `delta_id` & `--slug` Flag on `eidos delta create` (`CMP-CLI-DELTA-COMMANDS`, `CTR-EIDOS-CLI`)**:
   * Make `delta_id` optional in `eidos delta create [DELTA_ID]` (defaulting to `"auto"`).
   * Add `--slug` / `-s` to `eidos delta create` and `eidos spec create delta` to generate human-readable, branch-collision-proof IDs (`DLT-YYYY-NNN-<SLUG>`).

3. **Schema-Digest Keyed Fast-Path for Applied Deltas (`CMP-SPEC-VALIDATOR`)**:
   * Key `spec_validation_cache` entries for `status: applied` SpecDeltas against both the delta file's SHA-256 and the `delta.schema.yaml` SHA-256 digest so unchanged historical applied deltas skip redundant re-validation while still catching breaking schema changes immediately.
