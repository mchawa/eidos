= SpecDelta: Support Independent Sub-Project Eidos Directories in Monorepos
:toc: left

== Problem Statement
In a monorepo where a single `.git` directory sits at the repository root (`<git_root>/.git`) and individual packages or services maintain their own self-contained `eidos/` folders (e.g., `<git_root>/packages/billing/eidos/`, `<git_root>/services/auth/eidos/`), several core Eidos subsystems currently assume that `repo_root` (the parent of `eidos/`) is identical to the `.git` worktree root:

1. **Conflation of Sub-Project Root (`repo_root`) and Git Worktree Root (`git_root`) (`CMP-PROJECT-RESOLVER`)**:
   * `find_repo_root()` stops at `.git` or `eidos/` while walking up, which works when CWD is inside a sub-project with an existing `eidos/`, but `resolve_spec_and_repo_roots()` breaks early when encountering nested `package.json` / `pyproject.toml` markers before reaching the sub-project's `eidos/` root.
   * `get_tracked_files(repo_root)` and `is_generated_or_vendored(repo_root, rel_paths)` check `if (repo_root / ".git").exists():`, which is `False` for every sub-project `<git_root>/packages/<pkg>`, bypassing `git ls-files` (`.gitignore` filtering) and `.gitattributes` (`linguist-generated` / `linguist-vendored`) checks.
2. **Unscoped Git Diffs & Worktree-Relative Blob Paths in Drift Detection (`CMP-DRIFT-DETECTOR`)**:
   * `get_git_diff_files(repo_root)` runs `git diff --name-only` and `git status --porcelain -uall` with `cwd=repo_root`. Git always emits paths relative to `<git_root>` (e.g., `packages/billing/src/ledger.py` and `packages/auth/src/user.py`) rather than `repo_root` (`src/ledger.py`), causing:
     a. Changes in sibling sub-projects (`packages/auth/...`) or root files to bleed into `packages/billing`'s drift check as `unmapped_code_files`.
     b. Changes inside `packages/billing/src/...` and `packages/billing/eidos/...` to fail path matching against sub-project-relative `source_path: src/...` and `eidos/...` spec classifications.
   * `batch_read_git_blobs(repo_root, ...)` and `_get_files_versions_batch(repo_root, ...)` query `git cat-file --batch` with `<ref>:<rel_path>`. When `rel_path` is relative to the sub-project (`src/ledger.py`), `git cat-file --batch` looks for `<git_root>/src/ledger.py` instead of `<git_root>/packages/billing/src/ledger.py` and returns `missing`!
   * `collect_polyglot_test_files(repo_root)` and `_load_or_update_test_binding_cache(repo_root)` check `if (root / ".git").exists():`, which is `False` in sub-projects.
3. **SpecDelta Git Baseline & History Lookup Failure in Sub-Projects (`CMP-DELTA-ENGINE`)**:
   * `_resolve_git_repo_root(eidos_dir)` in `src/eidos/core/lifecycle/delta_engine.py` only inspects `(eidos_dir, eidos_dir.parent)` for `.git`. For `<git_root>/packages/billing/eidos` (depth >= 2), it returns `None`, so `eidos delta create` omits `vcs.branch` / `vcs.base_commit` and `eidos delta verify` cannot recover pre-delta baseline blobs from Git history.
4. **Inconsistent CLI Sub-Project Discovery (`CNT-EIDOS-CLI`, `CMP-HOOK-RUNNER`)**:
   * `eidos index *`, `eidos delta *`, and `eidos spec *` default `--path` to literal `Path("eidos")` instead of calling `resolve_cli_eidos_dir(path)`. Running those commands from a subdirectory inside a sub-project (e.g. `packages/billing/src/`) or passing `--path packages/billing` fails to locate `packages/billing/eidos`.
   * Running `eidos context -f packages/billing/src/ledger.py` without `--path` does not walk up from the target `--file` to discover the nearest owning `packages/billing/eidos` directory or normalize the `-f` path relative to `packages/billing`.
5. **Duplicate ONNX Model Downloads & Sub-Project Plugin/AGENTS.md Scattering (`CMP-SEMANTIC-EMBEDDING-ENGINE`, `CMP-REPO-INITIALIZER`, `CMP-PLUGIN-INSTALLER`)**:
   * `resolve_semantic_model_dir(eidos_dir)` in `src/eidos/core/index/semantic.py` hardcodes `(Path(eidos_dir).resolve() / ".cache" / "models" / "harrier-oss-v1-0.6b").resolve()`. In a monorepo with $N$ sub-project `eidos/` folders, running `eidos index semantic setup` duplicates 600MB–2.4GB of read-only Harrier-OSS-v1-0.6B ONNX weights $N$ times on disk and instantiates separate `_SESSION_CACHE` ONNX Runtime sessions in memory.
   * When centralizing the semantic model cache at `<git_root>/eidos/.cache/models/harrier-oss-v1-0.6b` in a monorepo that has not initialized a root `<git_root>/eidos/` project, `<git_root>/eidos/.gitignore` (and `<git_root>/eidos/.cache/.gitignore`) must be provisioned automatically so Git never sees untracked model binaries, and `find_repo_root`, `resolve_spec_and_repo_roots`, and `init_repository` must not mistake a cache-only `<git_root>/eidos/` directory for an already-initialized root specification catalog.
   * Similarly, `install_plugin`, `uninstall_plugin`, `update_plugin`, and `check_plugin_version_status` in `src/eidos/plugin/` currently resolve `root = (project_dir or Path.cwd()).resolve()`. Running `eidos plugin install` or `eidos doctor` from inside a sub-project would install or look for `.agents/plugins/eidos` and `AGENTS.md` inside the sub-project instead of always sharing the single monorepo root installation at `<git_root>`.

== Proposed Specification Changes

=== 1. Architectural Model: Independent Single-Scope Sub-Projects (`DEC-CORE-MONOREPO-ISOLATED-SUBPROJECTS`)
* **Isolated Sub-Projects**: Each `eidos/` directory in a monorepo is an independent, self-contained project whose `repo_root` (sub-project root) is `eidos_dir.parent`. Commands operate on one `eidos/` directory at a time.
* **Strictly Sub-Project-Relative Paths**: All `source_path`, `specification_file`, `test_binding`, and internal spec references inside `<subproject>/eidos/` are resolved strictly relative to `<subproject>/`.
* **Self-Contained Catalog & Portal**: Each `<subproject>/eidos/` validates only against its own specifications, maintains its own `<subproject>/eidos/.cache/index.db` (including its own `spec_embeddings` rows), and serves/builds its own standalone portal.
* **Shared Git-Root Semantic Model Cache (`<git_root>/eidos/.cache`)**: All sub-projects in a Git monorepo share a single Harrier ONNX model installation at `<git_root>/eidos/.cache/models/harrier-oss-v1-0.6b` with automatic `.gitignore` configuration (`<git_root>/eidos/.gitignore` and `<git_root>/eidos/.cache/.gitignore`).
* **Shared Git-Root Agent Plugin & `AGENTS.md` (`<git_root>`)**: The Eidos Agent Plugin (`.agents/plugins/eidos` and all harness targets) and `AGENTS.md` / `CLAUDE.md` are always installed, updated, uninstalled, and inspected at `<git_root>`, never in sub-projects.
* **Nested Sub-Project Boundary Exclusion**: If a parent directory also has an `eidos/` directory, nested directories that contain their own `eidos/` (i.e., independent child sub-projects) are excluded from the parent project's tracked files, index sync, test discovery, and drift detection.

=== 2. Project & Git Root Separation (`CMP-PROJECT-RESOLVER`, `src/eidos/core/workspace/project.py`)
* Introduce `find_git_root(start_dir: Path | None = None) -> Path | None` to locate the enclosing `.git` worktree root across all ancestor directories (or via `git rev-parse --show-toplevel`).
* Update `find_repo_root(start_dir)`:
  * Walk upward from `start_dir`: if an ancestor `<dir>` has a valid `<dir>/eidos` specification directory (`_has_eidos_markers(<dir>/eidos)`), return `<dir>` immediately (even before reaching `<git_root>/.git`), so any directory inside a sub-project resolves its nearest owning sub-project root.
* Update `resolve_spec_and_repo_roots(root_dir, doc_path)`:
  * Require `_has_eidos_markers(child)` when checking a candidate `eidos` directory so a cache-only `<git_root>/eidos/` directory (containing only `.cache/` and `.gitignore`) does not masquerade as an initialized specification root.
  * Do not stop upward search at intermediate `package.json` / `pyproject.toml` markers before checking ancestor `eidos/` directories; only stop at `.git` after checking whether the `.git` directory itself has a valid `eidos/`.
* Update `get_tracked_files(repo_root)` and `is_generated_or_vendored(repo_root, rel_paths)`:
  * Use `find_git_root(repo_root)` instead of `(repo_root / ".git").exists()`. Because `git ls-files` and `git check-attr --stdin` run with `cwd=repo_root`, Git natively accepts and returns paths relative to `repo_root`.
  * Exclude any nested child sub-project directories (child directories under `repo_root` that contain their own valid `eidos/` root) so independent sub-projects never pollute an enclosing project.

=== 3. Sub-Project-Scoped Git Diffs & Blob Extraction (`CMP-DRIFT-DETECTOR`, `src/eidos/vcs/`)
* **`get_git_diff_files(repo_root, ...)` (`src/eidos/vcs/diff.py`)**:
  * Resolve `git_root = find_git_root(repo_root)`. When `git_root` is an ancestor of `repo_root`, compute `rel_prefix = repo_root.relative_to(git_root)` (e.g., `packages/billing`).
  * Filter Git diff / status paths (`git diff`, `git diff --cached`, `git status --porcelain -uall`) to only files inside `rel_prefix/`, strip `rel_prefix/` so returned paths are strictly relative to `repo_root` (`src/ledger.py`, `eidos/system.adoc`), and exclude files belonging to any nested child sub-project under `repo_root`.
* **`batch_read_git_blobs(repo_root, object_specs)` & `_get_files_versions_batch` (`src/eidos/vcs/diff.py`)**:
  * When `git_root` is an ancestor of `repo_root`, prefix `rel_prefix/` onto each `rel_path` when querying `git cat-file --batch` (`<ref>:<rel_prefix>/<norm_rel>`), while mapping the returned dictionary keys back to the caller's `repo_root`-relative `(ref, norm_rel)` keys and reading working-tree files from `repo_root / norm_rel`.
* **Shallow Clone & Test Discovery (`src/eidos/vcs/diff.py`, `src/eidos/vcs/invariants.py`)**:
  * Check `(git_root / ".git" / "shallow").exists()` via `find_git_root(repo_root)` and use `find_git_root(repo_root) is not None` in `collect_polyglot_test_files` and `_load_or_update_test_binding_cache`.

=== 4. SpecDelta Git Baseline Resolution in Sub-Projects (`CMP-DELTA-ENGINE`, `src/eidos/core/lifecycle/delta_engine.py`)
* Update `_resolve_git_repo_root(eidos_dir)` to walk all parents `(eidos_dir.resolve(), *eidos_dir.resolve().parents)` for `.git` (or delegate to `find_git_root(eidos_dir)`).
* Because `_resolve_git_baseline_sha` already computes `rel_target = target_file.resolve().relative_to(repo_root)` and `rel_delta = delta_file.resolve().relative_to(repo_root)` against `_resolve_git_repo_root(eidos_dir)`, walking all ancestors automatically makes `git log -- <rel_delta>` and `git show <rev>:<rel_target>` resolve `<git_root>/packages/billing/eidos/...` accurately!

=== 5. Unified CLI, Plugin & Hook Resolution (`CNT-EIDOS-CLI`, `CMP-PLUGIN-INSTALLER`, `CMP-HOOK-RUNNER`)
* **`resolve_cli_eidos_dir(target_path, hint_files)` (`src/eidos/cli/_shared.py`)**:
  * When `target_path` is provided: if `(target_path / "eidos").is_dir()` and not `has_eidos_markers(target_path)`, return `target_path / "eidos"`; if `target_path` is a subdirectory inside a sub-project (and not itself an `eidos/` dir), walk up to the nearest owning `eidos/` via `find_repo_root(target_path) / "eidos"`.
  * When `target_path` is `None`: if `hint_files` (e.g., `eidos context -f packages/billing/src/ledger.py`) are provided, walk upward from the first existing hint file path to find its nearest owning `<subproject>/eidos` directory; otherwise walk upward from `Path.cwd()` via `find_repo_root()` to locate the nearest `<subproject>/eidos`.
* **Consistent CLI Option Resolution**:
  * Update `index_commands.py`, `delta_commands.py`, `spec_commands.py`, `drift_commands.py`, `context_command.py`, and `doctor_hook_commands.py` to resolve `--path` through `resolve_cli_eidos_dir(path)` and derive `repo_root = resolved_eidos.parent if resolved_eidos.name == "eidos" else find_repo_root(resolved_eidos)`.
  * In `context_cmd`, normalize `--file` (`-f`) paths that are passed relative to CWD (e.g. `packages/billing/src/ledger.py` when run from `<git_root>`) into sub-project-relative paths (`src/ledger.py`) so index file lookup matches seamlessly.
* **Git-Root-Only Agent Plugin & `AGENTS.md` (`CMP-PLUGIN-INSTALLER`, `CMP-CLI-DOCTOR-HOOKS`)**:
  * In `install_plugin`, `uninstall_plugin`, `update_plugin` (`src/eidos/plugin/installer.py`) and `_resolve_installed_plugin_manifest`, `get_installed_plugin_version`, `check_plugin_version_status` (`src/eidos/plugin/version.py`), resolve the target project root via `find_git_root(project_dir or Path.cwd()) or (project_dir or Path.cwd()).resolve()`, ensuring the plugin and `AGENTS.md` / `CLAUDE.md` always live at `<git_root>` and never inside a sub-project.
  * In `doctor_cmd` (`src/eidos/cli/doctor_hook_commands.py`), check plugin status at `find_git_root(repo_root) or repo_root`.
* **`HookRunner` (`src/eidos/plugin/hooks.py`)**:
  * Use `find_repo_root` on the hook workspace path so agent sessions working inside a sub-project run `detect_drift` against that sub-project's `repo_root` and `eidos_dir`.

=== 6. Shared Git-Root `eidos/.cache` Semantic Model & `.gitignore` Hygiene (`CMP-SEMANTIC-EMBEDDING-ENGINE`, `CMP-REPO-INITIALIZER`)
* **`resolve_semantic_model_dir(eidos_dir: Path) -> Path` (`src/eidos/core/index/semantic.py`)**:
  * Resolve `git_root = find_git_root(eidos_dir)`.
  * When `git_root` is found, always resolve the canonical model directory to `(git_root / "eidos" / ".cache" / "models" / "harrier-oss-v1-0.6b").resolve()` (with read fallback to `(Path(eidos_dir).resolve() / ".cache" / "models" / "harrier-oss-v1-0.6b").resolve()` if a model was already provisioned locally in that sub-project before the shared cache was populated).
