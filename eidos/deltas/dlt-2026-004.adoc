= SpecDelta: Repository Initialization Engine and eidos-init Agent Skill
:toc: left

== Problem Statement
Starting a new Eidos living specification repository or bootstrapping an existing project previously required manually creating directory hierarchies, AsciiDoc files, and YAML frontmatters conforming to strict schemas. Without an automated initialization command and guided agent skill, users and AI agents risked schema mismatch or incomplete governance setups.

== Proposed Specification Changes
1. Provide `eidos init [PATH]` CLI command with `--name`, `--title`, `--with-plugin`, and `--force` options.
2. Implement `init_repository()` in `src/eidos/core/scaffolder.py` generating:
   - Self-contained `eidos/.gitignore` (ignoring `deltas/by-status/`).
   - Schema-conforming `system.adoc` (`product/system`).
   - Baseline policies `POL-001-GIT-SOURCE-OF-TRUTH` and `POL-002-INVARIANT-TEST-ENFORCEMENT` (`product/policy`).
   - Default persona `personas/autonomous-agent.adoc` (`product/persona`).
   - Baseline system architecture `architecture/system-architecture.adoc` (`tech/architecture`).
   - Automatic execution of `SpecValidator.validate_directory()`.
   - Automatic project-scoped agent plugin installation into `.agents/plugins/eidos/`.
3. Provide `eidos_init_repo` tool in stdio MCP server (`src/eidos/mcp/server.py`).
4. Author specialized agent skill `skills/eidos-init/SKILL.md` in `assets/plugin_reference` and sync to `.agents/plugins/eidos`.
5. Update `CTR-EIDOS-CLI` contract with `eidos init` specifications.
