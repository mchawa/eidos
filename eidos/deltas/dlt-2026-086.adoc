= SpecDelta: Consolidate Overlapping SQLite & In-Memory Caches, Adopt Typed FrontmatterModel, and Remove VCS Test-Mock Introspection Shims
:toc: left

== Problem Statement

An architectural audit of `CNT-EIDOS-CORE`, `CNT-EIDOS-INDEX`, and `CNT-EIDOS-VCS` identified two internal maintainability and performance anti-patterns (excluding any file-splitting refactor):

1. **Three Overlapping Caching Layers & Underutilized Pydantic `FrontmatterModel`**:
   * Every `.adoc` specification file is currently stat'ed, hashed, parsed, and cached across **three separate mechanisms**:
     1. In-memory `_SPEC_CATALOG_CACHE` in `src/eidos/core/lifecycle/catalog.py` (`_build_spec_catalog` and `_build_spec_catalog_with_invariants`, lines 458–547, invoked by `load_spec_catalog` at lines 85–115), which independently walks `eidos/`, stats files, and calls `parse_spec_file`.
     2. SQLite `spec_validation_cache` in `src/eidos/core/spec/validator.py` (`SpecValidator.validate_directory`, lines 337–558), which executes two separate inline `CREATE TABLE IF NOT EXISTS spec_validation_cache` DDL blocks on read (lines 337–348) and write (lines 531–542), duplicating `storage.py`, and serializes `doc_json`.
     3. SQLite `indexed_files` + `entities` in `src/eidos/core/index/sync.py` (`check_index_dirty` and `sync_index`), plus `test_binding_cache` in `src/eidos/vcs/invariants.py` (`_load_or_update_test_binding_cache`, which also runs two redundant inline `CREATE TABLE IF NOT EXISTS test_binding_cache` DDL blocks on read at lines 129–141 and write at lines 259–271).
   * Furthermore, although `pydantic>=2.7.0` is a required dependency and `src/eidos/core/spec/models.py` defines `FrontmatterModel` (with `source_paths()`, `package_paths()`, `all_invariants()`, `all_decisions()`, and `_DictCompatibleModel` backwards compatibility) and `SpecDocument.model`, `parser.py`, `validator.py`, `catalog.py`, and `sync.py` manually unpack untyped `dict[str, Any]` frontmatter fields everywhere because nested models in `FrontmatterModel` currently fail with `pydantic.ValidationError` on incomplete/unvalidated dicts or legacy `c4_internal_components` keys.

2. **Production VCS Code Polluted by Unit-Test Monkeypatch Introspection**:
   * When `src/eidos/vcs/drift.py` was decomposed into `diff.py` and `structural.py`, existing unit tests in `tests/test_drift.py` continued monkeypatching private helpers on `eidos.vcs.drift` (sometimes with legacy call signatures omitting `merge_base`).
   * To accommodate those test mocks, production code in `diff.py`, `structural.py`, and `drift.py` was polluted with runtime reflection and `sys.modules` lookups:
     ** `src/eidos/vcs/structural.py` (lines 60–67): defines `_accepts_kwarg(fn, kwarg)` using `inspect.signature(fn)` at runtime.
     ** `src/eidos/vcs/structural.py` (lines 300–322): `_SpecDiffInspector.versions` looks up `sys.modules.get("eidos.vcs.drift")` to check if `_get_file_versions` was monkeypatched on `drift`, then calls `_accepts_kwarg(get_versions_fn, "merge_base")`.
     ** `src/eidos/vcs/diff.py` (lines 153–159 and 676–681): `_resolve_base_and_merge_base` and `classify_changed_files` look up `sys.modules.get("eidos.vcs.drift")` to check if `_resolve_base_ref`, `_resolve_merge_base`, or `is_generated_or_vendored` were monkeypatched on `drift`.
     ** `src/eidos/vcs/drift.py` (lines 177–195): `detect_drift` calls `_accepts_kwarg(_get_file_versions, "merge_base")` and `_accepts_kwarg(get_git_diff_files, "merge_base")` before every diff invocation.

== Proposed Specification Changes

=== 1. Consolidate SQLite & In-Memory Caching and Adopt Fault-Tolerant `FrontmatterModel` (`CMP-GRAPH-STORAGE`, `CMP-INCREMENTAL-SYNC-ENGINE`, `CMP-SPEC-PARSER`, `CMP-SPEC-VALIDATOR`, `CMP-LIFECYCLE-SCAFFOLDER`, `CMP-DOMAIN-MODELS`)

* **Single Authority for Cache DDL & Unified File-State Tracking (`storage.py`)**:
  ** Remove both inline `CREATE TABLE IF NOT EXISTS spec_validation_cache` statements from `src/eidos/core/spec/validator.py` (lines 337–348 and 531–542) and both `CREATE TABLE IF NOT EXISTS test_binding_cache` statements from `src/eidos/vcs/invariants.py` (lines 129–141 and 259–271); `ensure_cache_schema` in `src/eidos/core/index/storage.py` (`SCHEMA_VERSION = "2.4.0"`) is the sole authority for SQLite cache schema initialization.
  ** Provide shared file-state and parsed `SpecDocument` cache helpers in `storage.py` (backed by `spec_validation_cache` in `eidos/.cache/index.db` when the cache directory exists plus in-process `(resolved_path, mtime_ns, st_size)` memoization returning defensive copies) so `SpecValidator.validate_directory`, `_build_spec_catalog_with_invariants` / `load_spec_catalog` (`catalog.py`, preserving `copy.deepcopy` dict isolation and `deltas`/`by-status` filtering), and `sync_index` (`sync.py`) reuse parsed `SpecDocument` records without re-parsing the same `.adoc` files up to three times in a single CLI command or `detect_drift` run, and without leaking post-parse cross-reference errors into cached per-document schema error lists.
  ** Record `DEC-INDEX-UNIFIED-SPEC-CACHE` under `decisions:` in `eidos/architecture/containers/index.adoc` (`graduated_from: DLT-2026-086`) and synchronize `SCHEMA_VERSION` (`2.4.0`) references in `docs/concepts/architectural-index.md`, `docs/concepts/how-eidos-works.md`, `docs/guides/cli.md`, and `tests/test_graph_index.py`.
* **Fault-Tolerant `FrontmatterModel` Adoption (`models.py`, `parser.py`, `validator.py`, `catalog.py`, `sync.py`)**:
  ** Make nested models in `src/eidos/core/spec/models.py` (`RejectedAlternativeModel`, `DecisionModel`, `InvariantModel`, `InlineComponentModel`, `CapabilityTechnicalModel`, `DeltaMutationModel`, `FrontmatterModel`) fault-tolerant when coercing unvalidated or malformed YAML frontmatter (defaulting missing strings, coercing string shorthand invariants, normalizing legacy `c4_internal_components` into `components`, and exposing inline component invariant ownership pairs) so `SpecDocument.as_model()` / `doc.model` never raises `pydantic.ValidationError` on invalid specs under `SpecValidator`.
  ** Populate and use `doc.model` (`FrontmatterModel`) during `_parse_spec_content` (`parser.py`), `_build_spec_catalog_with_invariants` / `load_spec_catalog` (`catalog.py`), `SpecValidator` (`validator.py`), and `sync_index` (`sync.py`), replacing repetitive manual `frontmatter.get(...)` scalar/list normalization with `doc.model.source_paths()`, `doc.model.package_paths()`, `doc.model.all_invariants()`, and `doc.model.all_decisions()`.

=== 2. Remove Runtime Monkeypatch Introspection Shims from VCS (`CMP-DRIFT-DETECTOR`)

* **Eliminate `_accepts_kwarg` & `sys.modules["eidos.vcs.drift"]` Lookups**:
  ** Delete `_accepts_kwarg` from `src/eidos/vcs/structural.py` (and its import/usage in `src/eidos/vcs/drift.py`).
  ** Delete `sys.modules.get("eidos.vcs.drift")` indirection from `_resolve_base_and_merge_base` and `classify_changed_files` in `src/eidos/vcs/diff.py` and from `_SpecDiffInspector.versions` in `src/eidos/vcs/structural.py`.
  ** Invoke `_resolve_base_ref`, `_resolve_merge_base`, `is_generated_or_vendored`, `get_git_diff_files`, and `_get_file_versions` directly with their canonical keyword arguments (`merge_base=resolved_mb`), resolving shared diff helpers through `eidos.vcs.diff` module attributes across `drift.py` and `structural.py`.
* **Align Unit Tests (`tests/test_drift.py`)**:
  ** Update all test monkeypatches in `tests/test_drift.py` that patch `_resolve_base_ref`, `_resolve_merge_base`, `_get_file_versions`, `get_git_diff_files`, or `is_generated_or_vendored` to patch the canonical target and accept `merge_base: str | None = None` (or `**kwargs`).
