= SpecDelta: Unify Agent Plugin Targets Around .agents/plugins/eidos and .agents/skills, Add Kilo Code Target, and Require Explicit Target Without --dest
:toc: left
:icons: font
:sectnums:

== Problem Statement

Across Eidos's supported AI coding harnesses, `TARGET_ADAPTERS` in `src/eidos/plugin/installer.py` and `src/eidos/cli/plugin_commands.py` previously maintained bespoke per-client dot-directories that conflicted with the `agent-plugins.org v1.0.0` specification (`https://agent-plugins.org/compatible-clients`) and the `agentskills.io` `.agents/skills/` standard, lacked a dedicated `kilocode` install target, and exposed a redundant `project` target and `--dest` (`dest_path`) override:

1. **Fragmented & Broken Bundles for `agent-plugins.org` Compatible Clients (`cursor`, `copilot`, `codex`)**:
   * According to `agent-plugins.org/compatible-clients` and the `agent-plugins.org v1.0.0` specification, **Google Antigravity**, **Cursor**, **GitHub Copilot**, and **OpenAI Codex** all support the portable `agent-plugins.org v1.0.0` package format (`.agents/plugins/eidos/` containing `plugin.json` + `skills/`).
   * Instead of pointing `cursor`, `copilot`, and `codex` to the canonical `.agents/plugins/eidos/` bundle:
     ** `PluginInstallTarget.COPILOT` wrote a split layout (`.github/plugin/` + `.github/skills/` + `.github/copilot/settings.json`). Because `TargetAdapter.install()` sets `include_skills=(self.skills_subdir is None)`, `.github/plugin/` omitted `skills/` (leaving `"skills": "skills"` in `.github/plugin/plugin.json` dangling) and copied Antigravity's `hooks.json` into `.github/plugin/hooks.json` (which violates Copilot's `"version": 1` hook schema).
     ** `PluginInstallTarget.CODEX` generated a bespoke `.codex/plugin.json` and `.codex/skills/` outside `.agents/plugins/eidos/`.
     ** `PluginInstallTarget.CURSOR` installed skills into `.cursor/skills/` instead of sharing `.agents/plugins/eidos/`.
2. **Unloaded Plugin Bundle in OpenCode (`open-code`) & Missing Dedicated `kilocode` Target**:
   * **OpenCode** is **not** an `agent-plugins.org` client; its `.opencode/plugins/` directory loads only TypeScript/JavaScript modules (`index.ts`). Writing `plugin.json` and `hooks.json` into `.opencode/plugins/eidos/` produced dead files that OpenCode never loads, while `.opencode/skills/` duplicated the cross-agent `.agents/skills/` directory that OpenCode natively scans.
   * **Kilo Code** natively discovers skills in `.agents/skills/<skill>/SKILL.md` and reads root `AGENTS.md`, but lacked its own first-class `PluginInstallTarget.KILOCODE = "kilocode"` CLI target (`eidos plugin install kilocode`).
3. **Redundant Generic `project` Target and Custom `--dest` (`dest_path`) Override**:
   * Once `antigravity`, `cursor`, `copilot`, and `codex` all install into `.agents/plugins/eidos/`, the unnamed `PluginInstallTarget.PROJECT = "project"` target is redundant with explicit client targets and `all`, and its implicit default on `eidos plugin install` / `uninstall` / `update` obscures which coding harness is being configured.
   * Similarly, the `--dest` / `-d` (`dest_path`) custom destination flag and `_relative_skills_dir` (`custom:<dest>/skills`) add bespoke branching across `install_plugin`, `uninstall_plugin`, `update_plugin`, and `version.py` that is unnecessary when every supported client maps to a well-defined canonical repository directory.

== Proposed Specification Changes

* **Update `CMP-PLUGIN-INSTALLER` (`src/eidos/plugin/installer.py`, `src/eidos/plugin/version.py`, `eidos/architecture/components/plugin-installer.adoc`) & `CMP-CLI-PLUGIN-COMMANDS` (`src/eidos/cli/plugin_commands.py`, `eidos/architecture/components/cli-plugin-commands.adoc`)**:
  1. **Unified `.agents/plugins/eidos/` Adapter for `agent-plugins.org` Clients (`DEC-PLUGIN-UNIFIED-AGENTS-LAYOUT`)**:
     - Configure `PluginInstallTarget.ANTIGRAVITY`, `PluginInstallTarget.CURSOR`, `PluginInstallTarget.COPILOT`, and `PluginInstallTarget.CODEX` via `_make_project_adapter(target, name)` to install the canonical `agent-plugins.org v1.0.0` bundle into `.agents/plugins/eidos/` and project `targets=<target>:.agents/plugins/eidos/skills` into the root `AGENTS.md` block.
     - Remove the bespoke Copilot and Codex manifest/settings helpers from `src/eidos/plugin/installer.py`: `_ensure_copilot_plugin_manifest`, `_update_project_copilot_settings`, `_remove_project_copilot_settings`, `_ensure_codex_plugin_manifest`, `_codex_pre_manifest_hook`, `_copilot_pre_manifest_hook`, `_copilot_post_install_hook`, and `_copilot_extra_uninstall`.
  2. **Unified `.agents/skills/` Adapter for Agent Skills Clients (`cline`, `kilocode`, `open-code`)**:
     - Add `PluginInstallTarget.KILOCODE = "kilocode"` to `PluginInstallTarget` and include it in `PluginInstallTarget.ALL` and the CLI help strings of `eidos plugin install`, `eidos plugin uninstall`, and `eidos plugin update`.
     - Configure `PluginInstallTarget.CLINE`, `PluginInstallTarget.KILOCODE`, and `PluginInstallTarget.OPEN_CODE` via `_make_agents_skills_adapter(target, name, label)` (`plugin_subdir=None`, `skills_subdir=".agents/skills"`, `install_destination_subdir=".agents/skills"`, `uninstall_destination_subdir=".agents/skills"`, `prune_dirs=(".agents",)`), installing the 4 Eidos skills into `.agents/skills/<skill>/SKILL.md` and projecting `targets=<target>:.agents/skills` into root `AGENTS.md`.
  3. **Retain Specialized Adapters for `claude` and `aider`**:
     - `PluginInstallTarget.CLAUDE`: `.claude/skills/`, `.claude/settings.json` (`hooks.Stop`), root `CLAUDE.md` (`@AGENTS.md`), and root `AGENTS.md`.
     - `PluginInstallTarget.AIDER`: `.aider/skills/`, `.aider.conf.yml` (`read: [AGENTS.md]`), and root `AGENTS.md`.
  4. **Remove `PluginInstallTarget.PROJECT` and Custom `--dest` (`dest_path`), Requiring `<target>` Always**:
     - Remove `PROJECT = "project"` from `PluginInstallTarget` and `TARGET_ADAPTERS` so only the 9 client targets (`antigravity`, `claude`, `cursor`, `aider`, `cline`, `kilocode`, `open-code`, `codex`, `copilot`) plus `all` exist.
     - Require `target: PluginInstallTarget` as a mandatory positional argument on `eidos plugin install <target>`, `eidos plugin uninstall <target>`, and `eidos plugin update <target>` (as well as `install_plugin`, `uninstall_plugin`, and `update_plugin`).
     - Remove the `--dest` / `-d` option from `plugin_install`, `plugin_uninstall`, `plugin_update`, and `plugin_version` in `src/eidos/cli/plugin_commands.py`, remove `dest_path: Path | None = None` and `_relative_skills_dir` from `src/eidos/plugin/installer.py`, and remove `dest_path: Path | None = None` from `_resolve_installed_plugin_manifest`, `get_installed_plugin_version`, and `check_plugin_version_status` in `src/eidos/plugin/version.py`.
  5. **Clean Up Dead Fallback Paths & Resolve All 4 Canonical Manifests in `src/eidos/plugin/version.py`**:
     - Replace the retired `.github/plugin/plugin.json`, `.codex/plugin.json`, `.opencode/plugins/eidos/plugin.json`, and `.claude/plugins/eidos/plugin.json` fallback entries in `_resolve_installed_plugin_manifest()` with the active manifest locations across all four canonical layouts (`.agents/plugins/eidos/plugin.json` / `.agents/plugins/eidos/.eidos-manifest.json`, `.claude/.eidos-manifest.json`, `.agents/.eidos-manifest.json`, and `.aider/.eidos-manifest.json`).
     - Update user-facing CLI hint strings in `src/eidos/cli/plugin_commands.py`, `src/eidos/cli/init_command.py`, `src/eidos/cli/doctor_hook_commands.py`, and `src/eidos/plugin/managed_block.py` to include `<target>` (e.g. `eidos plugin install <target>` / `eidos plugin update <target>`).
  6. **No Backward Compatibility or Legacy Cleanup**:
     - No migration or uninstall cleanup is performed for legacy per-client directories written by earlier releases; fresh-install correctness is the only requirement.
