= SpecDelta: Bidirectional Contract Parity Verification and Multi-Framework CLI Contract Extraction
:toc: left

== Problem Statement

1. **One-Way Contract Verification (Code -> Spec Only)**:
   In `src/eidos/core/spec/validator.py`, `_CONTRACT_PROTOCOL_VERIFIERS` (`_verify_cli_contract_commands`, `_verify_python_protocol_contract`, `_verify_rest_openapi_contract`, `_verify_grpc_proto_contract`, `_verify_graphql_contract`) only verify that operations discovered in `specification_file` appear in the `CTR-*` specification body. When an API route, gRPC method, GraphQL field, or CLI command is **removed or renamed** in code, phantom entries left behind in the `CTR-*` specification table/body are never flagged by `eidos validate`.

2. **Typer-Bound CLI Extraction & Sub-App Resolution**:
   `_verify_cli_contract_commands` is tightly coupled to top-level Python `typer` patterns and immediate sibling `.register(app)` calls. It does not recursively verify sub-commands mounted on sub-typers (`app.add_typer(sub_app, name="...")`) or extract commands from standard `click` (`@click.command`, `@group.command`) and `argparse` (`add_subparsers` / `add_parser`) entrypoints.

== Proposed Specification Changes

1. **Bidirectional Contract Parity (`CMP-SPEC-VALIDATOR`)**:
   * Extract declared contract operations from structured AsciiDoc tables and backtick-delimited command/route declarations in `CTR-*` bodies (e.g., `eidos <subcommand>` rows in `cli_args`, HTTP path patterns `/api/...` in `rest_openapi`, `rpc <Name>` in `grpc_proto`, and field signatures in `graphql`).
   * Report a contract drift error in `report.broken_references` whenever a `CTR-*` specification documents an operation/route/subcommand that no longer exists in the bound `specification_file`.

2. **Recursive Sub-App & Multi-Framework CLI AST Extraction (`CMP-SPEC-VALIDATOR`)**:
   * Recursively resolve mounted `add_typer(sub_app, name="...")` sub-applications to verify documented subcommand trees (e.g., `eidos delta create`, `eidos index search`).
   * Add AST extraction support for `click` (`@click.command`, `@<group>.command`) and `argparse` (`add_parser("...")`) so non-Typer Python CLIs receive deterministic contract parity verification.

== Verification Plan

* Add unit tests in `tests/test_validator.py` verifying that:
  ** Deleting a CLI command, OpenAPI route, Protobuf RPC, or GraphQL operation from `specification_file` while leaving it documented in `CTR-*` triggers a `Contract drift` error in `SpecValidator`.
  ** Click and `argparse` CLI entrypoints and nested Typer sub-apps are extracted and verified accurately.
