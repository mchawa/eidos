= SpecDelta: Publish Official Eidos Node.js CLI Launcher Package to npm
:toc: left
:icons: font
:sectnums:

== Problem Statement

Frontend, full-stack, and polyglot teams working in Node.js/TypeScript repositories frequently standardize on `npx` / `npm` / `pnpm` for CLI tooling and agent hooks rather than installing standalone Python tool managers (`uv` or `pipx`) manually.

Publishing an official, lightweight **Node.js CLI launcher package** (`eidos-ai` on npm) enables developers and AI coding agents to run Eidos directly via `npx eidos-ai` or install it globally via `npm install -g eidos-ai` without pre-installing Python or `uv`, while avoiding the `+300–800ms` `/tmp` extraction penalty of `PyInstaller --onefile` binaries and the `+40–80ms` per-call resolution overhead of invoking `uvx` on every command.

== Proposed Specification Changes

1. **Node.js CLI Launcher Package (`npm/eidos-ai/`)**:
   * `npm/eidos-ai/package.json`: Declares package `eidos-ai`, ESM `"type": "module"`, `"engines": { "node": ">=18.0.0" }`, and dual `"bin"` entries (`"eidos": "./bin/eidos.mjs"` and `"eidos-ai": "./bin/eidos.mjs"`) so both `npx eidos-ai <cmd>` and `npm install -g eidos-ai && eidos <cmd>` work seamlessly.
   * `npm/eidos-ai/bin/eidos.mjs`: Zero-dependency Node.js launcher that:
     1. Resolves a deterministic versioned cache environment (`~/.cache/eidos/envs/<version>-<mode>` or `EIDOS_CACHE_DIR` / `XDG_CACHE_HOME` / `LOCALAPPDATA` on Windows).
     2. **Fast Path (Warm Run, `~15–20ms` Node overhead)**: If both the completion marker (`.eidos-ready`) and the provisioned `bin/eidos` (or `Scripts/eidos.exe` on Windows) binary exist inside the cached virtual environment, spawns `eidos` directly via `child_process.spawn` with `stdio: "inherit"` and signal forwarding (`SIGINT`, `SIGTERM`, `SIGHUP`)—bypassing `uv`/`uvx` completely on warm invocations.
     3. **Atomic Cold Bootstrap Path**: If the cached environment or `.eidos-ready` marker does not yet exist, locates `uv` via `EIDOS_UV_BIN` or `PATH` (or auto-downloads the standalone `uv` binary for the current OS/arch into `~/.cache/eidos/bin`), provisions an isolated virtual environment (`uv venv --python <3.12|3.14>`), installs `eidos-ai==<version>` (or `eidos-ai[semantic]==<version>` with Python `3.14` clamping when `EIDOS_SEMANTIC=1`/`true`/`yes`) with `uv pip install --compile-bytecode`, writes `.eidos-ready` only after installation succeeds, and then executes `eidos`.
   * Exclude `"/npm"` from `[tool.hatch.build.targets.sdist].exclude` in `pyproject.toml` so the PyPI source distribution remains isolated from npm wrapper artifacts.
2. **CI/CD Publishing Pipeline (`.github/workflows/ci.yml`)**:
   * Add a `publish-to-npm` job sequenced after `validate`, `test`, `build-site`, and `publish-to-pypi` (`needs: [validate, test, build-site, publish-to-pypi]`) on release tags (`refs/tags/v*.*.*`) that stamps `npm/eidos-ai/package.json` with the tag version (`${GITHUB_REF_NAME#v}`), copies `README.md` and `LICENSE`, and publishes to npm with provenance (`npm publish --provenance --access public`).
3. **Architecture & System Specifications (`ARCH-EIDOS-001`, `SYS-EIDOS-001`)**:
   * Record `DEC-ARCH-NPM-CLI-LAUNCHER` (`graduated_from: DLT-2026-119-PUBLISH-OFFICIAL-9237`) and document the npm distribution channel (`npx eidos-ai` / `npm install -g eidos-ai`) in `eidos/architecture/system-architecture.adoc` (Section 7: Deployment View) and `eidos/system.adoc`.
4. **Documentation & Onboarding (`CMP-DOCS-GETTING-STARTED`, `CNT-EIDOS-DOCS`)**:
   * Document `npx eidos-ai` and `npm install -g eidos-ai` (including `EIDOS_SEMANTIC=1`) in `docs/getting-started/installation.md`, `README.md`, `eidos/architecture/components/docs-getting-started.adoc`, and `eidos/architecture/containers/docs.adoc`.
5. **Capability & Invariant Governance (`CAP-PROD-001`, `INV-NPM-CLI-CONFORMANCE`)**:
   * Bump `CAP-PROD-001` to `1.10.0` and add `INV-NPM-CLI-CONFORMANCE` bound to `tests/test_npm_cli.py::test_npm_cli_package_and_launcher_conformance`:
     _"The npm CLI launcher package under npm/eidos-ai/ must maintain a valid package.json exposing both eidos and eidos-ai bin entrypoints, a syntax-valid Node.js launcher (bin/eidos.mjs) that provisions a versioned uv virtual environment with --compile-bytecode (clamping Python to 3.14 when EIDOS_SEMANTIC is enabled) and executes the cached eidos binary directly on warm runs, sdist exclusion in pyproject.toml, and npm release automation in .github/workflows/ci.yml."_
