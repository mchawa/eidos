= SpecDelta: Working-Tree Digest Short-Circuit in Agent Hooks and Mtime-Cached Portal HTTP Server
:toc: left

== Problem Statement

1. **Redundant Full Drift & Validation Runs in `PostInvocation` Hooks (`src/eidos/plugin/hooks.py`, lines 250-280, 372-411)**:
   * `handle_lint_post_invocation` and `handle_drift_post_invocation` run `SpecValidator.validate_directory` and `detect_drift` after every single agent invocation, even when the working tree and `HEAD` commit are completely unchanged since the previous clean invocation.
2. **Uncached Full Spec Re-Parsing on Every Portal HTTP Request (`src/eidos/portal/server.py`, lines 32-48)**:
   * `EidosPortalHandler.do_GET` calls `get_portal_data(self.eidos_dir)` and `SpecValidator().validate_directory(self.eidos_dir)` synchronously from scratch on every `/api/data`, `/api/overview`, and `/api/validate` request.

== Proposed Specification Changes

1. **Fast Working-Tree Digest Short-Circuit in `CMP-HOOK-RUNNER` (`src/eidos/plugin/hooks.py`)**:
   * Compute a fast working-tree digest from `git rev-parse HEAD`, `git status --porcelain -z`, and `(mtime_ns, size)` of dirty files.
   * Persist the last clean digest in `eidos/.cache/hook-state.json` and return `{"injectSteps": []}` in `<5ms` from `handle_lint_post_invocation` and `handle_drift_post_invocation` when the digest matches.
2. **Mtime-Keyed Response Caching in `CMP-PORTAL-SERVER` (`src/eidos/portal/server.py`)**:
   * Cache `get_portal_data` and `validate_directory` payloads in `EidosPortalHandler` keyed by the max `(mtime_ns, size, count)` snapshot of `eidos_dir`, recomputing only when a specification or token file changes on disk.
