= SpecDelta: Transactional SpecDelta Execution, Complete Action Coverage, and Git-Backed Baseline SHAs
:toc: left

== Problem Statement
`CMP-DELTA-ENGINE` (`src/eidos/core/lifecycle/delta_engine.py`) previously violated `INV-MUTATION-REVERSIBILITY` across four failure modes:

1. **Non-Atomic Writes & Missing Rollback**: `execute_delta_mutations` wrote, scaffolded, and `unlink()`ed specification files one mutation at a time directly on disk. If subsequent verification failed or post-apply validation failed, partial edits and deletions remained on disk and `status: applied` was written before `validate_document` checked the resulting file.
2. **Silent No-Op on Unsupported Actions**: While `assets/schemas/v1/delta/delta.schema.yaml` enumerates 44 `mutations[].action` values, `execute_delta_mutations` implemented only ~13. The remaining actions fell into a catch-all `else:` branch that returned `success: True`.
3. **Unchecked Deletions**: `remove_component` and `remove_container` called `unlink()` on whichever document matched `target_id` without verifying its `type:` (e.g., `remove_component` passed a `CAP-*` ID deleted the capability file).
4. **Ephemeral Baseline SHAs**: `_check_or_record_baseline_sha` stored baseline hashes only in the gitignored `eidos/.cache/index.db`. On fresh clones, CI runners, or parallel branches where the SQLite cache is absent, the first check recorded the current SHA as the baseline instead of consulting Git history.

== Proposed Specification & Engine Changes
1. **Transactional Staging & Pre-Commit Validation**:
   - Snapshot all existing specification files and directories prior to executing mutations (`_MutationTransaction`).
   - Validate all mutated baseline specifications and the updated SpecDelta document (`status: applied`) via `SpecValidator` *before* committing `status: applied` to disk; restore original file snapshots on any error.
2. **Strict Action Coverage & Type-Safe Deletions**:
   - Implement deterministic handlers for all 44 schema actions (`add_*`, `remove_*`, `deprecate_*`, `modify_*`, `extend_*`, `patch_*`) and explicitly reject unsupported actions (`UNSUPPORTED_ACTION` / `False`).
   - Verify that the resolved specification's `type:` matches the `remove_*` action before unlinking any file.
3. **Git-Backed Baseline Digest Fallback**:
   - When `delta_baselines` in `eidos/.cache/index.db` has no recorded baseline for a target, `_resolve_git_baseline_sha` inspects Git history (`<delta_intro_commit>~1` or `HEAD`) to recover the true pre-delta baseline digest without polluting `delta.schema.yaml`.
