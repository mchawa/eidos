== Problem Statement

Reviewing `assets/schemas/v1/`, `CNT-EIDOS-CLI`, and `POL-005-STATEMENT-TEST-COVERAGE` identified three architectural and governance gaps:

1. **Permissive Blank Strings, Empty `code_paths` & Missing `"cli"` Client Platform in `assets/schemas/v1/`**:
   * Blank or whitespace-only strings (`title: ""`, `rule: "   "`, `motivation: ""`) and empty path arrays (`source_path: []` or `source_path: ""` in `assets/schemas/v1/common/defs.yaml:112-118`) pass all 16 v1 schemas because `minLength: 1` / `pattern: "\\S"` and `minItems: 1` are omitted.
   * `assets/schemas/v1/design/client.schema.yaml:3` states `"Defines a client application surface (web, mobile, desktop, CLI)..."`, yet its closed `platform` enum (`L32-39`) lists only `["web", "mobile-ios", "mobile-android", "desktop", "tui", "multi-platform"]`, rejecting `"cli"`.
2. **No CLI Command to Inspect SpecDeltas (`eidos delta show` Missing)**:
   * `eidos spec show <DLT-ID>` (`src/eidos/cli/spec_commands.py`) intentionally rejects `delta/mutation` documents to keep `eidos spec` and `eidos delta` disjoint, but `eidos delta` (`src/eidos/cli/delta_commands.py`) exposes no `show` subcommand—forcing coding agents to fall back to raw filesystem reads.
3. **Policy vs. Enforcement Drift on `POL-005-STATEMENT-TEST-COVERAGE`**:
   * `eidos/policies/pol-005-statement-test-coverage.adoc:15-24` explicitly mandates **`>90%` statement coverage on every individual Python source file** under `src/eidos/`, yet `pyproject.toml` (`fail_under = 90`), `.github/workflows/ci.yml`, and `tests/test_validator.py::test_pol_005_statement_test_coverage` (`L3854-4301`) check only **aggregate** statement coverage, allowing individual modules to fall below `90%` while larger high-coverage modules subsidize the repository average.

== Proposed Specification Changes

* **Strict Non-Empty v1 Schemas & `"cli"` Client Platform (`CNT-EIDOS-CORE`, `CAP-PROD-001`, `CAP-EXP-002`, `CMP-DOCS-CORE-CONCEPTS`)**:
  1. Introduce `$defs/non_empty_string` (`type: string`, `minLength: 1`, `pattern: "\\S"`) and update `$defs/code_paths` (`minLength: 1`, `pattern: "\\S"`, array `minItems: 1`) in `assets/schemas/v1/common/defs.yaml`, applying non-empty constraints across required string/list fields (`title`, `rule`, `motivation`, `decision`, `rationale`, `manifest`, `specification_file`, `route`, `action`, `outcome`, `owners`, `archetypes`) in all 16 v1 schemas.
  2. Add `"cli"` to `properties.platform.enum` in `assets/schemas/v1/design/client.schema.yaml` and synchronize `docs/concepts/schema-glossary.md`.
* **First-Class `eidos delta show` Subcommand (`CMP-CLI-DELTA-COMMANDS`, `CMP-CLI-SPEC-COMMANDS`, `CTR-EIDOS-CLI`, `CAP-PROD-002`, `CMP-DOCS-USER-GUIDES`)**:
  1. Add `eidos delta show <delta_id> [--json] [--path <path>]` to `src/eidos/cli/delta_commands.py` resolving active (`eidos/deltas/`) and archived (`eidos/deltas/archive/`) SpecDeltas via `find_spec_by_id_or_path` and outputting structured frontmatter, composable `mutations`, and AsciiDoc body in Rich or `orjson` `--json` format.
  2. Update `spec_show_cmd` in `src/eidos/cli/spec_commands.py` to direct `DLT-*` queries specifically to `eidos delta show <ID>`, update `assets/plugin_reference/skills/eidos-plan/SKILL.md` (within `INV-PLUGIN-SKILL-SIZE-CEILING` and `INV-PLUGIN-SKILL-CLI-PARITY`, covered via `CNT-EIDOS-PLUGIN` `(body-only optional command hint if needed)`), and synchronize `docs/guides/cli.md` + `tests/fixtures/cli_command_tree.json`.
* **True Per-File `>90%` Statement Coverage Gate (`POL-005-STATEMENT-TEST-COVERAGE`, `INV-POL-005-STATEMENT-TEST-COVERAGE`)**:
  1. Update `tests/test_validator.py::test_pol_005_statement_test_coverage` and `.github/workflows/ci.yml` (`--cov=src/eidos --cov-report=json`) to inspect `files[path]["summary"]["percent_covered"]` for every non-trivial `.py` module under `src/eidos/` (excluding generated `_version.py`) and fail with an explicit table of offending files whenever any file has `percent_covered <= 90.0`, adding targeted unit tests for any module currently below `90.0%`.
