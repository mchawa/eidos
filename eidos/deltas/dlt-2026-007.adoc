= SpecDelta: Architectural Decomposition of Monolithic Engine into C4 Level 2 Containers
:toc: left

== Problem Statement
Previously, Eidos maintained a single monolithic component manifest (`CMP-EIDOS-ENGINE`) representing all codebase sub-systems. This conflated human CLI interaction, autonomous agent MCP daemons, foundational specification/validation libraries, and agent plugin extensions into one undifferentiated monolith, obscuring real architectural boundaries and dependency directions.

== Proposed Specification Changes
1. Decompose `CMP-EIDOS-ENGINE` into 4 dedicated C4 Level 2 containers:
   - `CMP-EIDOS-CORE` (`src/eidos/core`): Core living spec parser, validator, scaffolder, multi-design system engine, and delta lifecycle manager.
   - `CMP-EIDOS-CLI` (`src/eidos/cli`): User-facing Typer CLI application providing `CTR-EIDOS-CLI`.
   - `CMP-EIDOS-MCP` (`src/eidos/mcp`): Autonomous agent stdio JSON-RPC 2.0 daemon providing `CTR-EIDOS-MCP`.
   - `CMP-EIDOS-PLUGIN` (`src/eidos/plugin`): Agent plugin package installer and validator conforming to `agent-plugins.org v1.0.0`.
2. Retire legacy `eidos/architecture/components/engine.adoc`.
3. Update contract bindings:
   - `CTR-EIDOS-CLI`: Owned by `CMP-EIDOS-CLI`.
   - `CTR-EIDOS-MCP`: Owned by `CMP-EIDOS-MCP`.
4. Update `ARCH-EIDOS-001` (`eidos/architecture/system-architecture.adoc`) to declare all 4 containers in `c4_containers` and Section 5 topology table.
5. Update tests and CLI defaults to reference the decomposed component identifiers.
