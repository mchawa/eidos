= SpecDelta: Harmonize and Canonicalize All v1 Specification Schemas Without Legacy Aliases
:toc: left

== Problem Statement

Across the 16 Eidos v1 YAML schemas (`assets/schemas/v1/`) and shared definitions (`assets/schemas/v1/common/defs.yaml`), identical architectural concepts evolved with divergent property names, duplicate intra-schema aliases, redundant relationship blocks, bidirectional design couplings, inconsistent `status` enums, fragmented sub-object shapes, and copy-pasted `x-eidos-ref` blocks. Maintaining these inconsistencies forces fallback chains across `FrontmatterModel`, `SpecParser`, `SpecValidator`, `LifecycleScaffolder`, `IndexSyncEngine`, `DeltaEngine`, and `PortalGenerator`:

1. **Divergent Display Heading (`title` vs `name`)**:
   * 12 schemas require `title`, while 4 schemas (`product/domain`, `product/persona`, `tech/container`, `tech/component`) require `name` and reject `title` (`additionalProperties: false`).
   * Inline `container.components[]` and `architecture.c4_containers[]` also use `name` instead of `title`.
2. **Divergent Domain Binding (`domain` vs `parent_domain` vs `domain_binding`)**:
   * `product/capability` uses `domain` (plus a legacy `parent_domain` alias), whereas `tech/container`, `tech/container.components[]`, and `tech/component` use `domain_binding`.
3. **Divergent Container Ownership (`container` vs `owning_container` vs `owning_component` vs `container_ref` vs `component_ref`)**:
   * `tech/component` and `design/client` use `container`.
   * `tech/contract` uses `anyOf: [required: [owning_container], required: [owning_component]]` even though `INV-INTERFACE-BOUNDARY-GOVERNANCE` forbids `CMP-*` from owning boundary contracts.
   * `tech/architecture.c4_containers[]` uses `container_ref` and legacy `component_ref`.
   * `tech/component.container` uses `pattern: "^CNT-[A-Z0-9_-]+$"` (forbidding `.adoc` paths), whereas all other container references allow `^(CNT-[A-Z0-9_-]+|.*\.adoc)$`.
4. **Divergent Code Path Binding (`package_path` vs `source_path`)**:
   * `tech/container` and `tech/architecture.c4_containers[]` use `package_path`, whereas `tech/component`, `tech/container.components[]`, and `delta.schema.yaml` (`expect.frontmatter.source_path`) use `source_path`.
5. **Redundant Relationship Blocks (`domain.technical_mapping`, `container.dependencies`, `contract.consumers`, `capability.technical.contracts` sub-object, `container.components` pointer stubs)**:
   * `product/domain.schema.yaml` defines `technical_mapping: { containers, components, dependencies }` even though `CNT-*` and `CAP-*` already declare `domain: DOM-*` and cross-domain links derive from contracts/components.
   * `tech/container.schema.yaml` defines `dependencies: { internal_containers, internal_components, external_services }` even though cross-container boundaries are captured through `contracts` (`provides` / `consumes`), in-process calls through component `interfaces.consumes`, and external systems in `architecture.c4_context.external_systems`.
   * `tech/contract.schema.yaml` defines `consumers: [CNT-* | CMP-*]` even though consumption is already declared via `contracts.consumes` on containers and capabilities.
   * `product/capability.schema.yaml` over-specifies `technical.contracts` as a nested object (`interfaces`, `provides`, `consumes`, `events_published`, `events_consumed`) instead of a clean flat reference list matching `technical.containers` and `technical.components`.
   * `tech/container.schema.yaml` mixes inline component definitions and `{ id, ref, title, responsibility }` pointer stubs inside `components[]`, duplicating fields from standalone `tech/component` files that already declare `container: CNT-*`.
6. **Intra-Schema, Policy & Design-Layer Bidirectional Redundancy**:
   * `product/policy.schema.yaml` defines top-level `rule: string`, `enforcement: { mechanism, severity }`, and `invariants: [{ id, rule, test_binding }]`, duplicating both the normative rule statement and the programmatic enforcement mechanism (`test_binding`).
   * `design/system.schema.yaml` defines `client_id`, `extends_system`, and `inheritance: { extends, override_mode }`, coupling a reusable design system to a single client.
   * `design/ui-component.schema.yaml` defines both `implements` and `implements_component`.
   * `design/client.schema.yaml`, `design/screen.schema.yaml`, and `design/flow.schema.yaml` maintain bidirectional reverse-links (`capabilities`, `client`, `clients`, `supported_design_systems`, `user_flows`) back to their consumers instead of acting as pure reusable definitions referenced from outside (`product/capability.experience` and `design/client`).
   * `tech/container.schema.yaml` defines `spec_path` on inline `components[]`, and `models.py`/`sync.py`/`generator.py` still check the legacy `c4_internal_components` key and `InvariantModel.verification`.
   * `tech/container.contracts` defines both `consumes` and `requires` for consumed `CTR-*` contracts.
7. **Fragmented `status` Enums, Duplicate Invariant Defs, Sub-Objects, and `x-eidos-ref` Boilerplate**:
   * Non-workflow living specs split across 3 different `status` enums (6-state, 8-state with `sunset`/`removed`, and 9-state with `accepted`/`sunset`/`removed`), and workflow schemas (`delta`, `exploration`) include unused `draft` and `planned` states alongside `proposed`.
   * `common/defs.yaml` duplicates `#/$defs/invariant` and `#/$defs/test_bound_invariant` with identical properties (`id`, `rule`, `test_binding`), and defines ad-hoc `component_or_symbol_ref` and `consumed_component_ref` instead of using `#/$defs/component_ref`.
   * `quality_attributes` in `tech/container` (`stateless`, `idempotent`, `concurrency_model`, `max_memory_mb: integer`) diverges from `tech/component` (`stateless`, `reentrant`, `concurrency_model`, `max_memory_mb: number`, `max_validation_latency_ms: number`).
   * `states` is `string[]` in `design/ui-component` but `{ name, description }[]` in `design/screen`.
   * `external_references` uses three different Figma keys (`figma_team_library`, `figma_node_url`, `figma_frame_url`) across `design/system`, `design/ui-component`, and `design/screen`.
   * `decisions` (`#/$defs/decision`) is missing from `product/persona` and all 5 `design/*` schemas.
   * `x-eidos-ref.entity_label` uses generic `"entity"` for `DS-*`, `UIC-*`, and inconsistent `"entity"` vs `"screen"` / `"client"` for `SCR-*` and `CLT-*`.

== Proposed Specification Changes

=== 1. Canonical Field Naming & Property Removals Across All 16 Schemas (Zero Legacy Shims)

[cols="1,2,2,2", options="header"]
|===
| Concept | Retired Fields / Blocks / Values | Canonical Field / Replacement | Affected Schemas
| Display Heading | `name` (top-level & `components[]` / `c4_containers[]`) | `title` | `product/domain`, `product/persona`, `tech/container`, `tech/component`, `tech/architecture`
| Domain Reference (`DOM-*`) | `domain_binding`, `parent_domain` | `domain` (`#/$defs/domain_ref`) | `product/capability`, `tech/container`, `tech/component`
