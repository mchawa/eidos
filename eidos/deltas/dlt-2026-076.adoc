= SpecDelta: Synchronize Bundled Agent Skills (eidos, eidos-spec, eidos-plan, eidos-ops) with v1 JSON Schemas and Canonical Design Paths
:toc: left

== Problem Statement

The bundled Agent Skills under `assets/plugin_reference/skills/` (`eidos-spec/SKILL.md`, `eidos-plan/SKILL.md`, `eidos-ops/SKILL.md`, and `eidos/SKILL.md`) contain YAML templates and field descriptions that contradict the v1 JSON Schemas (`additionalProperties: false`), causing specifications authored by AI coding agents following the skills to fail `eidos validate`:

1. **`EXP-*` (`product/exploration`) Template in `eidos-plan/SKILL.md` (lines 31-58)**:
   * Uses forbidden top-level keys `timebox`, `findings`, `recommendation`, and `resulting_deltas`, and formats `exit_criteria` as a YAML list instead of `exit_criteria: { max_duration, benchmark }` and `decision: { outcome, resulting_delta_id, learnings }` (`assets/schemas/v1/product/exploration.schema.yaml`).
2. **`DOM-*` (`product/domain`) Template in `eidos-spec/SKILL.md` (lines 54-70)**:
   * Omits required `boundaries: { responsibilities: [...] }` (`assets/schemas/v1/product/domain.schema.yaml`).
3. **`PER-*` (`product/persona`) Template in `eidos-spec/SKILL.md` (lines 117-129)**:
   * Uses `role:` instead of required `role_type:` and `frustrations:` instead of required `pain_points:` (`assets/schemas/v1/product/persona.schema.yaml`).
4. **Root `eidos/system.adoc` Type in `eidos-spec/SKILL.md` (line 137)**:
   * Documents `type: tech/system` instead of `type: product/system` (`assets/schemas/v1/product/system.schema.yaml`).
5. **Promoted Component Reference in `eidos-spec/SKILL.md` (lines 162 & 206)**:
   * Shows `- ref: "eidos/architecture/components/cmp-usage-ledger.adoc"` without `id: CMP-USAGE-LEDGER`, violating `required: [id, ref]` in `assets/schemas/v1/tech/container.schema.yaml` (lines 111-115).
6. **`CTR-*` (`tech/contract`) Template in `eidos-spec/SKILL.md` (lines 210-221) & Cross-References (line 301)**:
   * Uses `name:` instead of required `title:`, `provider:` instead of required `owning_container:`, and omits required `specification_file:` (`assets/schemas/v1/tech/contract.schema.yaml`).
7. **Design System & Client Paths and Field Names (`eidos-spec/SKILL.md`, lines 245-252; `eidos-ops/SKILL.md`, line 75; `eidos/SKILL.md`, line 211)**:
   * Document client/screen/flow paths as `eidos/clients/<app>/...` instead of `eidos/design/clients/<app>/...` and `eidos/design/flows/`.
   * Describe non-schema fields (`props`, `tokens_consumed`, `source_binding` on `UIC-*`; `web_spa`, `ios_native`, `cli_tui` platform values on `CLT-*`; `personas`, `ui_components`, `view_states` on `SCR-*`; `trigger`, `system_action`, `next_step`, `invariants` on `FLOW-*`) instead of the actual schema properties (`variants`, `states`, `accessibility`, `test_bindings` on `UIC-*`; `web`, `mobile-ios`, `mobile-android`, `desktop`, `tui`, `multi-platform` on `CLT-*`; `capabilities`, `supported_design_systems`, `slots`, `states`, `user_flows` on `SCR-*`; `flow_type`, `client`, `clients`, `capabilities`, `steps: [{step, title, screen, client, action, outcome}]` on `FLOW-*`).

== Proposed Specification Changes

1. **Update YAML Templates & Field Reference in `assets/plugin_reference/skills/`**:
   * Update `eidos-plan/SKILL.md`, `eidos-spec/SKILL.md`, `eidos-ops/SKILL.md`, and `eidos/SKILL.md` so every YAML snippet and field description validates cleanly against `assets/schemas/v1/**` and uses canonical `eidos/design/...` directory paths.
   * Synchronize the installed project skill copies under `.agents/plugins/eidos/skills/`.
2. **Add Automated Skill YAML Template Validation Test**:
   * Add a test in `tests/test_docs_sync.py` (or `tests/test_validator.py`) that extracts YAML frontmatter blocks from `assets/plugin_reference/skills/*/SKILL.md` and validates them against `SpecValidator` so skill templates can never drift from the v1 JSON Schemas again.

* `uv run eidos validate eidos && uv run eidos drift --uncommitted --json`
