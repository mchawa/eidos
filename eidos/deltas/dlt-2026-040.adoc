= SpecDelta: Require Modification Evidence in SpecDelta Verification
:toc: left

== Problem Statement

SHA-256 baselines and `expect:` post-conditions already exist in `verify_delta_mutations`, but four paths still report fulfilment without evidence:

. **mtime fallback**: baselines live in the gitignored `eidos/.cache/index.db` and are only recorded by `eidos delta create`. On a fresh clone, or for a hand-authored delta, verification falls back to `target.mtime > delta.mtime`. Observed: the original draft of DLT-2026-038 reported `CNT-EIDOS-CORE` and `CNT-EIDOS-CLI` as `MODIFIED` before any implementation work, because `core.adoc` / `cli.adoc` had been saved after the delta file.
. **Container-granular hashing**: `CMP-*` targets are hashed by their whole container file, so any edit to `core.adoc` (e.g. by DLT-2026-035 or DLT-2026-036) satisfies every component mutation in it.
. **Existence-only `patch_invariant`**: when `target_capability` and `target_invariant_id` are both set, the structural sub-target check returns `True` as soon as the invariant is listed in the capability.
. **Target precedence**: `_extract_mutation_target` reads `target_capability` before `target_invariant_id`, so `patch_invariant` mutations that set both resolve to the capability ID and report `MISSING` forever. DLT-2026-035 is affected today.

== Behavioral Mutations

Implemented in `src/eidos/core/lifecycle/delta_engine.py` (extracted by DLT-2026-038):

. `_extract_mutation_target` prefers `target_invariant_id` for `add_invariant` / `patch_invariant` / `remove_invariant`.
. The baseline order becomes: local SQLite snapshot → Git (target content at the commit that first added the delta file, via `git log --diff-filter=A --format=%H -1 -- <delta>`, or `HEAD` if the delta is uncommitted) → record a fresh baseline and report `UNMODIFIED`. The `st_mtime_ns` comparison is removed.
. `CMP-*` targets are digested from their own component entry (as invariants already are), not from the whole container file.
. The capability/invariant structural sub-target check becomes a precondition (`MISSING` if absent). It no longer counts as evidence of modification.
. No new status values. `eidos delta verify --json` keeps its output shape, so `CTR-EIDOS-CLI` is unchanged.

== Verification Criteria

* `tests/test_delta_engine.py::test_delta_verify_requires_modification_evidence` (INV-DELTA-VERIFY-MODIFICATION-EVIDENCE) covers:
** No local baseline, target container touched (newer mtime) but byte-identical to the Git baseline → `UNMODIFIED`.
** Editing a sibling component in the same container leaves the targeted `CMP-*` → `UNMODIFIED`.
** `patch_invariant` with `target_capability` + `target_invariant_id` resolves to the invariant, and stays `UNMODIFIED` until its rule or test binding changes.
** No Git repository and no local baseline → baseline recorded, `UNMODIFIED` (never mtime-based).
* `tests/test_delta_engine.py::test_delta_verify_declarative_expect_and_patch_invariant` and the rest of `tests/test_delta_engine.py` still pass.
* Re-running `eidos delta verify` on the open deltas (DLT-2026-034 … DLT-2026-041) after a fresh clone reports no `MODIFIED` status without a matching spec change.
* `eidos validate eidos && eidos drift --uncommitted` exits 0.
