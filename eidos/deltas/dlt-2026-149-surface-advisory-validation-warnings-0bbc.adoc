= SpecDelta: Surface Advisory Validation Warnings in Living Web Portal and Add Fail-On-Warnings Flag
:toc: left

== Problem Statement
`DLT-2026-143` added non-blocking `ValidationReport.warnings` to `eidos validate` and `eidos drift`, but two adoption gaps remain:
1. Architects inspecting architecture health through the Living Web Portal (`eidos portal serve` / `eidos portal build`) only see `schema_errors` and `broken_references`, not advisory `warnings`.
2. Teams maintaining zero warnings (including Eidos's own CI) have no opt-in CLI flag to fail CI when new advisory warnings are introduced while preserving non-blocking local defaults.

== Proposed Specification Changes
* **`CMP-PORTAL-GENERATOR` (`src/eidos/portal/generator.py`), `CMP-PORTAL-ASSETS` (`src/eidos/portal/frontend/src/`) & `CTR-EIDOS-PORTAL`**: Export `validation.warnings` in `get_portal_data` and `/api/validate` (server response body-only or `CMP-PORTAL-SERVER` if touched — verify during implementation), render a compact amber advisory warnings pill and collapsible list in `HomeView.tsx` / `App.tsx`, and rebuild the air-gapped `assets/portal/bundle.html.gz` bundle (`INV-PORTAL-AIR-GAPPED-BUNDLE`).
* **`CMP-CLI-SPEC-COMMANDS` (`src/eidos/cli/spec_commands.py`), `CMP-CLI-DRIFT-COMMANDS` (`src/eidos/cli/drift_commands.py`) & `CTR-EIDOS-CLI`**: Add `--fail-on-warnings` (default `False`) to both `eidos validate` and `eidos drift`, exiting with code `1` when warnings exist and `--fail-on-warnings` is passed (while keeping `is_clean` / default exit code `0` unchanged and respecting `--warn-only` on `eidos drift`).
* **`CMP-DOCS-USER-GUIDES`, `CAP-EXP-001` & `CAP-PROD-001`**: Synchronize `docs/guides/cli.md`, update `tests/fixtures/cli_command_tree.json`, and bind `INV-VALIDATION-WARNINGS-PORTAL-AND-CI-ESCALATION`.

== Implementation Plan
1. **Portal Data, Server & Frontend (`CMP-PORTAL-GENERATOR`, `CMP-PORTAL-SERVER`, `CMP-PORTAL-ASSETS`, `SCR-PORTAL-HOME`, `CTR-EIDOS-PORTAL`)**: Export `warnings` in `src/eidos/portal/generator.py` and `src/eidos/portal/server.py` (`CNT-EIDOS-PORTAL` covered via `CMP-PORTAL-GENERATOR`, `CMP-PORTAL-SERVER`, `CMP-PORTAL-ASSETS`, and `CTR-EIDOS-PORTAL`), add the amber advisory warnings UI in `src/eidos/portal/frontend/src/views/HomeView.tsx` and `src/eidos/portal/frontend/src/App.tsx`, update `eidos/design/clients/web-portal/screens/portal-home.adoc`, and run `build_assets.py` to rebuild `assets/portal/bundle.html.gz`.
2. **CLI Escalation Flag (`CMP-CLI-SPEC-COMMANDS`, `CMP-CLI-DRIFT-COMMANDS`, `CTR-EIDOS-CLI`)**: Add `--fail-on-warnings` in `src/eidos/cli/spec_commands.py` and `src/eidos/cli/drift_commands.py` (`CNT-EIDOS-CLI` covered via both components and `CTR-EIDOS-CLI`), and update `tests/fixtures/cli_command_tree.json`.
3. **Docs, Living Specs & Tests (`POL-005-STATEMENT-TEST-COVERAGE`, `INV-DOCS-SYNCHRONIZATION`)**: Update `docs/guides/cli.md`, all declared living specs, and add `tests/test_portal.py::test_validation_warnings_in_portal_and_cli_fail_on_warnings`.
4. **Verification**: Run `pytest`, `eidos delta verify DLT-2026-149 --json`, `eidos delta apply DLT-2026-149`, and `eidos drift --uncommitted --json`.
