== Problem Statement

`CMP-CLI-DOCTOR-HOOKS` (`src/eidos/cli/doctor_hook_commands.py`, lines 24-120) has two usability and diagnostic bugs in `eidos doctor`:

1. **Hardcoded `eidos_dir = repo_root / "eidos"` (line 45)**:
   * Unlike `eidos validate`, `eidos drift`, `eidos index`, and `eidos context`, `eidos doctor` does not accept `--path` / `-p` and always inspects `repo_root / "eidos"`.
2. **False-Negative Exit Code `1` Under `uv run` or Virtualenv Execution (lines 48-56 & 119)**:
   * `doctor_cmd` checks `shutil.which("eidos")` and sets `all_passed = False` (exiting with code `1`) if `eidos` is not on the global `PATH`—even when `eidos doctor` is actively running via `uv run eidos doctor` or `python -m eidos.cli.main doctor` inside a project virtual environment (`Path(sys.executable).parent / "eidos"`).

== Proposed Specification Changes

1. **Add `--path` / `-p` Option to `doctor_cmd` (`src/eidos/cli/doctor_hook_commands.py` & `eidos/contracts/ctr-eidos-cli.adoc`)**:
   * Accept `path: Path | None = typer.Option(None, "--path", "-p", ...)` and resolve `repo_root` via `find_repo_root`.
2. **Virtualenv-Aware CLI Binary Check (`src/eidos/cli/doctor_hook_commands.py`)**:
   * Check `shutil.which("eidos")` first, then fallback to `Path(sys.executable).parent / "eidos"` (or active module invocation), reporting a warning rather than failing `all_passed = False` when running inside an isolated environment without a global `PATH` binary.
