= SpecDelta: Add Optional Repository Configuration File (`eidos.yaml`)
:toc: left

== Problem Statement

Eidos currently relies on hardcoded heuristics, constants, and repeated CLI flags for repository-level engine and workflow behavior:

* **Discovery & File Classification**: Excluded directories (`STANDARD_EXCLUDED_DIRS`), polyglot test file heuristics (`is_polyglot_test_file`), nested sub-project discovery, and non-default spec directory paths (`eidos/`) require `.gitattributes` workarounds or repeating `--path` on every command.
* **Drift & Validation Policy**: Teams using `develop` / `trunk` branches, gradual brownfield shadow mode (`--warn-only`), strict body-only co-evolution (`--strict`), `--fail-on-warnings`, non-architectural ignore paths (`scripts/dev/**`, `benchmarks/**`), or granular validator check severities must duplicate CLI flags across local invocations, agent hooks, and CI templates.
* **Velocity-Dependent Thresholds & Ergonomics**: Team operational memory drift (`DEFAULT_MEMORY_COMMIT_DRIFT_THRESHOLD = 5`), context tier token budgets (`TIER_TOKEN_BUDGETS`), semantic model variant / air-gapped mirror URLs, archive retention (`keep_recent = 15`), plugin targets / hook behavior / PyPI update checks, and portal serve/build defaults vary per repository but cannot be committed in one canonical configuration file.

At the same time, introducing a configuration file must preserve Eidos's core constitutional boundaries: zero-config operation when `eidos.yaml` is absent, zero duplication of architectural/product truth (`POL-GIT-SOURCE-OF-TRUTH`, which stays exclusively in `eidos/*.adoc`), zero credentials or user-local secrets in Git, zero LLM/AI provider configuration (`POL-ZERO-AI-CALL-DEPENDENCY`), and strict preservation of the 17 canonical living specification schemas under `assets/schemas/v1/` (`INV-SPEC-VALIDATION`, `INV-DOCS-SYNCHRONIZATION`).

== Proposed Specification Changes

=== Canonical v1 `eidos.yaml` Schema, Env Contract & Architectural Boundary (`CNT-EIDOS-CORE`, `CMP-REPO-CONFIG`, `CMP-ASSET-LOCATOR`)

* **`assets/schemas/config/eidos-config.v1.schema.yaml`** (owned by `CNT-EIDOS-CORE`, isolated outside `assets/schemas/v1/` so the 17 living-spec schemas stay untouched and containing zero Eidos-self IDs/paths per `INV-ENGINE-GENERICITY`): Closed Draft 2020-12 JSON Schema (`additionalProperties: false` at root and every nested block, `version: const 1`) covering seven optional sections:
** `workspace`: `specs_dir` (default `"eidos"`, strictly relative child inside `repo_root`—rejecting `"."`, absolute paths, `..`, and symlinks), `exclude` (list of repo-relative glob patterns), `tests: { include, exclude }` (glob lists), `subprojects_exclude` (glob list for fixture/example directories containing mock `eidos/` folders).
** `drift`: `base_ref` (string, prepended ahead of `origin/main` fallback chain), `strict` (bool, default `false`), `warn_only` (bool, default `false`), `fail_on_warnings` (bool, default `false`), `ignore_paths` (glob list suppressing only `code_files`—never `spec_files`, `delta_files`, `memory_files`, `test_files`, or `onboarding_files`), `checks: { mermaid, import_boundaries, public_surface, contract_parity, deprecated_references }` (`error | warn | off`; zero-config defaults: `mermaid: error`, `import_boundaries: error`, `public_surface: error`, `contract_parity: error`, `deprecated_references: warn`).
** `context`: `default_tier` (`anchor | guardrails | deep`, default `"guardrails"`), `budgets: { anchor, guardrails, deep }` (positive ints, built-in defaults `300 / 1000 / 2500`), `repo_map_max_tokens` (positive int, default `1500`), `semantic: { enabled, variant, model_mirror_url }` (`enabled` default `true`, `variant` default `"quantized"`, `model_mirror_url` optional strictly `https://` or `http://` URL—rejecting `file://` and non-HTTP schemes).
** `memory`: `commit_drift_threshold` (positive int, default `5`), `tier_caps: { anchor, guardrails, deep }` (`[max_anchored, max_global]` non-negative int pairs), `default_expiry_days` (optional positive int; CLI `--expires none` opts out for a single permanent memory when configured).

** `plugin`: `targets` (list of the 9 concrete canonical `PluginInstallTarget` slugs—excluding `"all"` so `eidos doctor` advisories remain unambiguous), `launcher` (`eidos | uvx`, default `"eidos"`), `updates_check` (bool, default `true`), `hooks: { install, enabled, strict, fail_on_warnings, baseline_ttl_seconds }` (`install`: bool default `false` controlling `eidos plugin install --hooks` default; `enabled`: bool default `true` acting as runtime kill-switch in `CMP-HOOK-RUNNER`; `strict` and `fail_on_warnings`: nullable `bool | null` default `null` inheriting `drift.strict` / `drift.fail_on_warnings` unless explicitly overridden; `baseline_ttl_seconds`: positive number default `86400`).
