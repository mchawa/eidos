= SpecDelta: Enforce Implementation-Plan Blast-Radius Reconciliation, Glob Context Slicing, and 1-Hop Review Rules
:toc: left

== Problem Statement

When coding agents author a SpecDelta (`eidos/deltas/dlt-*.adoc`) and subsequently run a Staff Systems Architect Review (`eidos-plan` §3) prior to code implementation, reviews frequently fail with avoidable `[BLOCKER]` and `[WARNING]` findings:

[source,text]
----
[BLOCKER] Unauthorized Blast Radius Across N CNT-* Containers and M CMP-* Components:
mutations: only authorizes CNT-A, CNT-B, ARCH-001, and SYS-001.
However, == Implementation Plan Step 1 edits apps/*/docker/Dockerfile (owned by CNT-C..CNT-H)
and Step 2 modifies foo.py (CMP-FOO), bar.py (CMP-BAR), and router.py (CMP-ROUTER).
Editing those files without declaring their owning specs in mutations: will fail eidos drift --uncommitted.
----

Eight interacting engine and skill gaps cause these recurring authoring and review defects:

1. **Top-Down `mutations:` Authoring Without Bottom-Up `== Implementation Plan` Reconciliation**:
   * Agents populate `mutations:` in YAML frontmatter from the high-level prompt and only later draft concrete file paths in `== Implementation Plan` without slicing each planned file via `eidos context -f` to back-propagate missing 1-hop owners (`CNT-*`, `CMP-*`, `CTR-*`, `CAP-*`) and bound design specs (`DS-*`, `CLT-*`, `UIC-*`, `SCR-*`, `FLOW-*`) into `mutations:`.
   * While `status: proposed` and `0` source files are modified in Git, `eidos drift --uncommitted` exits `0` (`is_clean: true`), masking the mismatch until architectural review.
2. **Glob Blind Spot in `eidos context -f` (`CMP-TIERED-CONTEXT-COMPRESSOR`, `CMP-CLI-CONTEXT-COMMAND`)**:
   * Implementation plans frequently specify cross-container globs such as `apps/*/docker/Dockerfile`. Currently, `build_tiered_context_slice` (`src/eidos/core/index/context.py`) treats `--file` strings literally without glob expansion: unquoted globs shell-expand into extra positional arguments that fail Typer with exit code `2`, whereas quoted globs (`eidos context -f "apps/*/docker/Dockerfile"`) match zero `source_path` prefixes and silently return `components: []`—misleading agents into treating governed container files as unmapped files.
3. **`DEC-*`-Heavy Primary Containers Evicting 1-Hop Capability `INV-*` & `POL-*` Guardrails (`CMP-TIERED-CONTEXT-COMPRESSOR`)**:
   * In `TieredContextSlice._enforce_token_budget` (`src/eidos/core/index/context.py`), Stage 1a (`_compress_verbose_fields_in_place`) sets `_compact_prose = True`, which leaves full multi-paragraph `DEC-*` decisions uncompacted on `index_in_slice == 0`. On `DEC-*`-heavy containers (e.g., `CNT-EIDOS-PLUGIN` with 6 `DEC-*` records), Stage 1b and Stage 2 evict 11 of 12 capability invariants (hiding `INV-PLUGIN-SKILL-SIZE-CEILING` and `INV-PLUGIN-SKILL-CLI-PARITY`) and policies before Stage 3 sets `_compact_decisions = True` (which then drops primary `DEC-*` records altogether and collapses the slice to `~280` tokens under a `1,000` / `2,500` budget).
4. **The `SYS-*` / `ARCH-*` Umbrella Fallacy**:
   * Authoring agents add `SYS-*` and `ARCH-*` to `mutations:` assuming system-level specs authorize edits across all containers/components, whereas `_collect_1hop_spec_targets` (`src/eidos/vcs/structural.py`, line 507) explicitly strips system-level specs from `CNT-*`/`CMP-*` coverage (`SYS-*`/`ARCH-*` cover only *unmapped* repository files).
5. **Ambiguous 1-Hop & Design-Subgraph Rules in Reviewer Dimension 1 (`eidos-plan` §3)**:
   * `eidos-plan/SKILL.md` §3 Dimension 1 mentions *"1-hop ownership neighborhood"* without defining that `_collect_1hop_spec_targets` covers a `CMP-*` file when `mutations:` includes `CMP-*`, its parent `CNT-*`, or a bound 1-hop `CTR-*`/`CAP-*` (and `detect_drift` separately requires `DS-*`/`CLT-*`/`UIC-*`/`SCR-*`/`FLOW-*` on design token or `ui_contract` changes), causing reviewers to falsely flag child `CMP-*` files already covered by a parent `CNT-*`.
6. **The `eidos delta verify` `UNMODIFIED` Catch-22 on Body-Only & Non-Code Edits**:
   * Default `eidos drift` only requires spec coverage on `structural_code_files` (plus `body_only_code_files` under `--strict` only when `not classification.test_files`) and classifies `Dockerfile` under `other_files`, while `verify_delta_mutations` fails with `UNMODIFIED` whenever an `operation: modify` target's `.adoc` file has no Git diff. Demanding `mutations:` entries for unmodified specs traps agents between a review `[BLOCKER]` and an `UNMODIFIED` verification failure.
7. **Contradictory Canonical Template (`DLT-2026-015`) & Unbound Planned Tests**:
   * In `assets/plugin_reference/skills/eidos-plan/SKILL.md` (`DLT-2026-015`, lines 125–168), Step 2 says *"update `CTR-BILLING-API` and `CNT-BILLING-API` specifications"* while `CNT-BILLING-API` is absent from `mutations:`, `INV-BILL-WEBHOOK-SIG` omits `expect.frontmatter: { rule, test_binding }`, and `CAP-BILL-001` omits `technical.invariants.id` and `expect.body`—teaching agents by example to author non-compliant SpecDeltas.
8. **Unverified Planned CLI/Workspace Steps & Delayed 5-Dimension Review**:
   * Agents draft CLI commands and workspace file operations in `== Implementation Plan` without checking live CLI flags, snapshot fixtures, or workspace symlinks (e.g., `.agents/plugins/eidos -> ../../assets/plugin_reference`), and wait for the user to ask `"review it"` instead of running the §3 5-Dimension Review autonomously before presenting a SpecDelta.

== Proposed Specification Changes

=== 1. Glob File Slicing & Guardrail-Preserving Compaction (`CMP-TIERED-CONTEXT-COMPRESSOR`, `CMP-CLI-CONTEXT-COMMAND`, `CTR-EIDOS-CLI`, `CMP-DOCS-USER-GUIDES`, `CAP-AGENT-001`, `CAP-AGENT-002`)

1. **Deterministic `--file` Glob Expansion (`CMP-TIERED-CONTEXT-COMPRESSOR`, `CMP-CLI-CONTEXT-COMMAND`)**:
   * In `build_tiered_context_slice` (`src/eidos/core/index/context.py`), when any `--file` entry (after comma splitting) contains glob metacharacters (`*`, `?`, `[`):
     - Expand matching workspace files relative to `index.root` in deterministic sorted order (skipping excluded/cache directories such as `.git`, `.venv`, `node_modules`, `__pycache__`).
     - When a glob targets planned not-yet-created files (yielding zero existing leaf files, e.g., `"apps/*/docker/.dockerignore"`), expand matching existing parent directories under `index.root` and `fnmatch`-matched indexed `symbol_mappings` (`source_path`, `owned_path`, `inferred_path`) prefixes to synthesize candidate relative paths for `resolve_symbol_or_path_in_db`, returning an honest empty slice when neither existing paths nor indexed prefixes match.
   * In `context_cmd` (`src/eidos/cli/context_command.py`), split comma-separated `--file` (`-f`) values and preserve repo-root-relative globs when invoked from subdirectories (rebasing relative globs to `Path.cwd()` only when `Path.cwd()` matches files and `repo_root` does not), and update `--file` help text + `CTR-EIDOS-CLI` (`1.4.0`) + `docs/guides/cli.md` (`CMP-DOCS-USER-GUIDES`).
2. **Primary `DEC-*` Compaction Before 1-Hop `INV-*`/`POL-*` Eviction (`CMP-TIERED-CONTEXT-COMPRESSOR`)**:
   * In `TieredContextSlice._enforce_token_budget` (`src/eidos/core/index/context.py`), add a Stage 1a step (after `_compact_prose` and `_compact_metadata`, *before* Stage 1b `_pop_non_direct` evicts 1-hop `invariants`, `policies`, or `capabilities`) that compacts `index_in_slice == 0` `DEC-*` narratives into compact 1-line summaries (`compact=True` in `_project_decisions` and `format_decisions_markdown`), and retain compact `DEC-*` summaries on `index_in_slice == 0` in Stage 3 unless still over budget.
   * Record `DEC-CONTEXT-GLOB-AND-GUARDRAIL-RETENTION` on `CMP-TIERED-CONTEXT-COMPRESSOR`, bump `CAP-AGENT-001` to `1.14.0` (`INV-AGENT-CONTEXT-SLICING`), and bump `CAP-AGENT-002` to `1.3.0` (`INV-CONTEXT-TOKEN-COMPRESSION`).

1. **Bottom-Up `== Implementation Plan` Reconciliation (`eidos context -f "<path_or_glob>" --tier guardrails --json`)**:
   * After drafting `== Implementation Plan`, slice every planned file or **quoted** glob (`-f "apps/*/Dockerfile"` or comma-separated `-f a,b`—never unquoted shell globs).
   * Declare 1-hop owners (`CMP-*`, parent `CNT-*`, or bound `CTR-*`/`CAP-*`) for structural code or spec-documented runtime/boundary changes, plus bound `DS-*`/`CLT-*`/`UIC-*`/`SCR-*`/`FLOW-*` specs when mutating design tokens or `ui_contract` surfaces. `SYS-*` and `ARCH-*` cover only unmapped files, never `CNT-*`/`CMP-*` `source_path` files.

=== 4. Architectural Decisions (`DEC-CONTEXT-GLOB-AND-GUARDRAIL-RETENTION` & `DEC-PLUGIN-DELTA-BLAST-RADIUS-RECONCILIATION`)

* **`DEC-CONTEXT-GLOB-AND-GUARDRAIL-RETENTION` (on `CMP-TIERED-CONTEXT-COMPRESSOR`)**:
  * *Decision*: Expand `--file` glob patterns (`*`, `?`, `[`) deterministically in `build_tiered_context_slice` across both existing workspace files and planned paths under existing directories / indexed `source_path` prefixes, and compact primary-component (`index_in_slice == 0`) `DEC-*` prose to 1-line summaries in `_enforce_token_budget` Stage 1a before evicting 1-hop `INV-*` or `POL-*` guardrails.
  * *Rationale*: Makes `eidos context -f "apps/*/docker/Dockerfile"` resolve every owning container in `<5ms` even before planned files exist on disk, while preventing `DEC-*`-heavy containers (`CNT-EIDOS-PLUGIN`) from evicting critical capability invariants (`INV-PLUGIN-SKILL-SIZE-CEILING`) and dropping primary `DEC-*` summaries.
  * *Rejected Alternatives*:
    ** *Require agents to run shell `find`/`ls` before `eidos context -f`*: Rejected because it violates CLI-first discovery (`eidos/SKILL.md` §2.1) and fails on not-yet-created files in `proposed` SpecDeltas.
    ** *Require separate `eidos context -c <CAP-ID>` calls instead of fixing `_enforce_token_budget`*: Rejected because evicting 11 invariants to `280` tokens under a `1,000`/`2,500`-token budget violated `INV-CONTEXT-TOKEN-COMPRESSION`'s prose-before-guardrails contract.
* **`DEC-PLUGIN-DELTA-BLAST-RADIUS-RECONCILIATION` (on `CNT-EIDOS-PLUGIN`)**:
  * *Decision*: Enforce symmetric SpecDelta authoring and mandatory pre-presentation 5-Dimension self-review rules in `eidos-plan` and `eidos` skills (bottom-up quoted-glob/comma `eidos context -f` reconciliation, 1-hop + `design/*` coverage excluding `SYS-*`/`ARCH-*`, inline `(covered via parent CNT-*)` / `(body-only; no spec mutation)` annotations, `INV-*` pairing, live CLI/workspace verification, and compliant few-shot templates) while keeping post-implementation AST drift and baseline digest checks in `eidos drift` and `eidos delta verify`.
  * *Rejected Alternatives*:
    ** *Regex-parse file paths from `== Implementation Plan` prose in `SpecValidator`*: Rejected because free-form plan prose legitimately cites context/caller files, parent-covered files, and body-only/non-code files whose unmodified specs would fail `eidos delta verify` (`UNMODIFIED`).
    ** *Allow `SYS-*` or `ARCH-*` to wildcard-cover `CNT-*`/`CMP-*` code in `eidos drift`*: Rejected because bypassing container/component ownership defeats C4 boundary governance (`INV-DRIFT-DIFF-AWARE-COVERAGE`).
