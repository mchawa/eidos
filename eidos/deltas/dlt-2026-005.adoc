= SpecDelta: Multi-Design System Engine, W3C Tokens, and Product Capability Linkage
:toc: left

== Problem Statement
Complex multi-tenant and enterprise products frequently use multiple design systems for different clients or brands, while frontend implementations often suffer from split-brain disconnects between Figma/design tools, product specifications, and code. Furthermore, business capabilities lacked formal linking to user-facing screens and design systems.

== Proposed Specification Changes
1. Author formal JSON schemas for Design living specifications in `assets/schemas/v1/design/`:
   - `system.schema.yaml` (`design/system`): Multi-brand design systems with inheritance (`extends`), W3C Design Token manifests, and theme modes.
   - `ui-component.schema.yaml` (`design/ui-component`): Reusable UI widget contracts with variant matrices, interaction states, and accessibility invariants (WCAG, ARIA, keyboard navigation).
   - `screen.schema.yaml` (`design/screen`): Screen layout slots, routes, state machines (loading, empty, active, error), and supported design systems.
2. Update `assets/schemas/v1/product/capability.schema.yaml` to introduce the optional `experience` property, linking business capabilities (`CAP-*`) to screens, user flows, design systems, and UI components.
3. Update `assets/schemas/v1/delta/delta.schema.yaml` to support design mutation actions and blast radius impact tracking.
4. Update `src/eidos/core/validator.py`, `src/eidos/core/scaffolder.py`, and `src/eidos/cli/main.py` to scaffold and validate design specifications with W3C `tokens.json`.
5. Update stdio MCP server (`src/eidos/mcp/server.py`) to expose design specification scaffolding parameters in `eidos_create_spec`.
6. Author `eidos-design` skill in `assets/plugin_reference/skills/eidos-design/SKILL.md` and sync to `.agents/plugins/eidos/`.
