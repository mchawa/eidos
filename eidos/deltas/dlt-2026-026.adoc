= SpecDelta: 100% Generic Engine, Zero-Config Path Standardization, and Graph-Inferred Design Paths
:toc: left

== Problem Statement

The Eidos engine (`graph_index.py`, `drift.py`, `portal/generator.py`) and bundled plugin skills contained hardcoded Eidos-self assumptions (`CNT-EIDOS-PLUGIN`, `SYS-EIDOS-001`, `cnt-eidos-`, and author-specific `file:///home/MTS/marwan.chawa/...` links). In addition, `component.schema.yaml` defined both `package_path` and `source_path` for the same purpose, `capability.schema.yaml` conflated C4 containers and components under `technical.components`, and runtime caches created a second top-level `.eidos/` directory alongside `eidos/`.

== Architectural & Behavioral Mutations

1. **Zero Settings File & Consolidated `eidos/.cache/`**:
   * Living specifications reside in `eidos/`, and ephemeral runtime caches (`index.db` and `stop-gate.json`) reside in `eidos/.cache/` (gitignored via `eidos/.gitignore`).
2. **Standardized Path & C4 Hierarchy Properties**:
   * **Container (`tech/container`)**: Strictly uses `package_path` (`string` or `array of strings/globs`).
   * **Component (`tech/component`, standalone & inline)**: Strictly uses `source_path` (`string` or `array of strings/globs`). `package_path` is removed from `component.schema.yaml`.
   * **Capability (`product/capability`)**: Under `technical`, `containers` (`CNT-*`) is the primary required list, and `components` (`CMP-*`) is an optional sub-list.
   * **Design Client (`CLT-*`) & Design System (`DS-*`)**: Do not declare path properties; their code paths are inferred automatically via the knowledge graph (`DS-* <-> CLT-* -> CNT-*`).
3. **100% Generic Engine & Skills**:
   * All Eidos-specific hardcodings are removed from `src/eidos/` and `assets/plugin_reference/skills/*/SKILL.md`.
