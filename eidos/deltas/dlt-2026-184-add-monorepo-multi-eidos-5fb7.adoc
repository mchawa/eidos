= SpecDelta: Add Monorepo Multi-Eidos CLI Auto-Routing, Multi-Subproject Drift/Hook Evaluation, and Agent Guidance
:toc: left

== Problem Statement
In Git monorepos containing multiple independent `eidos/` directories (both sub-projects-only layouts such as `packages/api/eidos` + `packages/billing/eidos` and hybrid layouts with a root `eidos/` alongside sub-projects), `eidos plugin install` intentionally installs a single shared `AGENTS.md` and `.agents/skills/` at `<git_root>` (`DEC-CORE-MONOREPO-ISOLATED-SUBPROJECTS`). Consequently, coding agents execute CLI commands from `<git_root>`, triggering four failure modes:

1. Neither `assets/plugin_reference/agents-md/block.md` nor the bundled `SKILL.md` files mention monorepo sub-project scoping (`-p <subproject>/eidos` or running from `<subproject>`).
2. Only `eidos context -f` passes `hint_files` to `resolve_cli_eidos_dir()`; all other CLI commands default to `./eidos` at the top root (even creating a bogus empty `<git_root>/eidos/.cache/index.db` on `eidos index` queries when no root `eidos/` exists).
3. When a root `eidos/` exists alongside nested sub-projects, running `eidos drift --uncommitted` from the monorepo root ignores nested sub-project changes and emits a false-green `is_clean: true` result.
4. `eidos hook` (`CMP-HOOK-RUNNER`) only inspects `<workspace_root>/eidos` (and treats cache-only `<git_root>/eidos/` as initialized), silently skipping drift checks for modified nested sub-projects.

== Proposed Specification Changes
* **Shared Monorepo Workspace Resolution (`CMP-CLI-APP`)**: Add `discover_workspace_eidos_dirs`, `resolve_uncommitted_workspace_eidos_dirs`, and `require_cli_eidos_dir` to `src/eidos/cli/_shared.py`, and upgrade `resolve_cli_eidos_dir` hint resolution to strip glob suffixes and walk up to the nearest existing ancestor for planned paths.
* **Path-Hint & Diff-Aware CLI Commands (`CMP-CLI-CONTEXT-COMMAND`, `CMP-CLI-INDEX-COMMANDS`, `CMP-CLI-SPEC-COMMANDS`, `CMP-CLI-DELTA-COMMANDS`, `CMP-CLI-MEMORY-COMMANDS`, `CTR-EIDOS-CLI` `2.2.0`)**:
  - Auto-route path-shaped inputs (`eidos index blast-radius <path>`, `eidos memory add -f <path>`, `eidos spec show/delete <path>`, `eidos delta show/verify/apply/audit/delete <path>`, `eidos memory show/update/verify/archive/promote <path>`) to their owning sub-project with repo-relative normalization.
  - Auto-route `--uncommitted` / `--from-diff` to the single dirty sub-project (or fail closed listing all dirty sub-projects when ambiguous) and guard multi-subproject `-f` spans in `eidos context`.
  - Fail closed with `discovered_subprojects` hints via `require_cli_eidos_dir` when invoked at a monorepo root with no root `eidos/` (preventing empty `<git_root>/eidos/.cache/index.db` creation) and attach `nested_subprojects` hints on root `eidos index` queries when nested sub-projects exist.
* **Multi-Subproject `drift` & `validate` (`CMP-CLI-DRIFT-COMMANDS`, `CMP-CLI-SPEC-COMMANDS`)**: When invoked from a monorepo root without an explicit `--path` / `target_path`, discover root + nested `eidos/` directories, route `eidos drift` to the dirty project(s) (aggregating `monorepo_projects` when multiple projects have changes or when no root `eidos/` exists), and aggregate `eidos validate` across discovered `eidos/` projects.
* **Multi-Subproject Stop Hook (`CMP-HOOK-RUNNER`)**: Resolve root (only when `has_eidos_markers` is true) plus all nested sub-project `eidos/` roots in `src/eidos/plugin/hooks.py`, exclude nested sub-project paths from root baseline scoping, and aggregate drift failures across all modified sub-projects into a single 1-turn continuation response.
* **Agent Guidance & Plugin Bundle (`CNT-EIDOS-PLUGIN`, `CAP-AGENT-ADAPTER` `1.24.0`, `INV-MONOREPO-ROOT-CLI-AND-HOOK-ROUTING`, `CMP-DOCS-USER-GUIDES`)**: Add concise monorepo scoping guidance to `assets/plugin_reference/agents-md/block.md`, `eidos/SKILL.md`, `eidos-plan/SKILL.md`, and `eidos-memory/SKILL.md` (preserving `INV-PLUGIN-SKILL-SIZE-CEILING` and `INV-PLUGIN-SKILL-CLI-PARITY`), bump `assets/plugin_reference/VERSION` to `1.1.0`, update `.agents/skills/` and root `AGENTS.md`, and document monorepo root routing in `docs/guides/cli.md`.

== Implementation Plan
1. **Shared CLI Monorepo Primitives**: Update `src/eidos/cli/_shared.py` with ancestor-walking glob-safe `hint_files` resolution, `discover_workspace_eidos_dirs`, `resolve_uncommitted_workspace_eidos_dirs`, `resolve_git_diff_workspace_eidos_dirs`, and `require_cli_eidos_dir` (`CNT-EIDOS-CLI` covered via `CMP-CLI-APP`).
2. **CLI Command Auto-Routing & Multi-Subproject Aggregation**: Update `src/eidos/cli/context_command.py`, `src/eidos/cli/index_commands.py`, `src/eidos/cli/drift_commands.py`, `src/eidos/cli/spec_commands.py`, `src/eidos/cli/delta_commands.py`, and `src/eidos/cli/memory_commands.py` to adopt `require_cli_eidos_dir`, path/diff hint routing, and multi-subproject `drift`/`validate` evaluation (zero new CLI flags, keeping `tests/fixtures/cli_command_tree.json` unchanged).
3. **Multi-Subproject Stop Hook**: Update `src/eidos/plugin/hooks.py` to discover all valid `eidos/` roots (`has_eidos_markers` + `discover_nested_subproject_roots`), share a single worktree snapshot, isolate root baseline scoping from nested sub-projects, and aggregate per-subproject drift reports.
