= SpecDelta: Hierarchical C4 Level 2 Container Topology and Inter-Container Connection Architecture
:toc: left

== Problem Statement
The C4 Level 2 Container diagram generated by `CMP-PORTAL-GENERATOR` (`src/eidos/portal/generator.py`) previously rendered a flat list of container nodes. Every container drew a hardcoded single arrow to `CNT-EIDOS-CORE` with the generic label `In-Process Python API`.

This implementation had several critical architectural defects:
1. **Absence of Hierarchy & Layering**: Containers were scattered without architectural grouping or layering. Viewers could not perceive which containers serve as presentation entry points (CLI, Web Portal, Docs), which provide extensibility (Plugin Manager), which form the core domain specification engine (Core Engine), and which manage data persistence (Knowledge Graph SQLite index).
2. **Inaccurate and Incomplete Connections**: Actual dependencies declared in container manifests (`dependencies.internal_containers` and `contracts`) were ignored. For instance, `CNT-EIDOS-CLI` depends on `CNT-EIDOS-INDEX`, `CNT-EIDOS-PLUGIN`, `CNT-EIDOS-PORTAL`, and `CNT-EIDOS-CORE`, yet only a connection to `CORE` was shown. `CNT-EIDOS-PORTAL` depends on `CNT-EIDOS-INDEX` and `CNT-EIDOS-CORE`. `CNT-EIDOS-DOCS` consumes `CTR-EIDOS-PORTAL` from `CNT-EIDOS-PORTAL`, but was shown connecting directly to `CORE`.
3. **Missing System & External Boundaries**: C4 Level 2 canonical diagrams depict the System Boundary enclosing internal containers, with external actors (developers, agents, web browsers) and external backing services (Git filesystem, SQLite database, host IDEs) clearly demarcated.

== Strategic Architecture & Design Solutions

=== 1. Four-Tier Architectural Hierarchy
Containers are dynamically classified into 4 canonical architectural tiers:
* **Tier 1: Presentation & Interface Tier** (`tier_presentation`):
  - User-facing entrypoints: `CNT-EIDOS-CLI` (cli_app), `CNT-EIDOS-PORTAL` (web_app), `CNT-EIDOS-DOCS` (web_app).
* **Tier 2: Extensibility & Agent Integration Tier** (`tier_extensibility`):
  - Plugin orchestration and toolchains: `CNT-EIDOS-PLUGIN` (library / agent extension manager).
* **Tier 3: Core Domain & Living Specification Engine Tier** (`tier_core`):
  - Foundation specification logic: `CNT-EIDOS-CORE` (parser, validator, scaffolder, context slicer).
* **Tier 4: Knowledge Graph & Persistence Tier** (`tier_persistence`):
  - Relational storage and retrieval: `CNT-EIDOS-INDEX` (SQLite3, WAL, FTS5 BM25, recursive CTE).

=== 2. System Boundary & External Actors
* Internal containers reside within `subgraph SYS_BOUNDARY ["📦 System Boundary: Eidos Living Architecture Ecosystem (SYS-EIDOS-001)"]`.
* Upstream persona actors: `Developers & AI Agents` (connecting to CLI) and `Web Browsers` (connecting to Portal and Docs).
* Downstream storage and platform services: `Git VCS Repository`, `SQLite3 Database`, `Host IDEs & Agent Environments`, and `GitHub Pages`.

=== 3. Explicit Inter-Container Connections
The generator inspects each container's declared `dependencies.internal_containers` and `contracts`:
* `CNT-EIDOS-CLI` --> `CNT-EIDOS-CORE`: `|Executes Engine Commands|`
* `CNT-EIDOS-CLI` --> `CNT-EIDOS-INDEX`: `|Queries FTS5 & Graph Index|`
* `CNT-EIDOS-CLI` --> `CNT-EIDOS-PLUGIN`: `|Installs & Validates Plugins|`
* `CNT-EIDOS-CLI` --> `CNT-EIDOS-PORTAL`: `|Serves & Builds Static Site [CTR-EIDOS-PORTAL]|`
* `CNT-EIDOS-PORTAL` --> `CNT-EIDOS-CORE`: `|Extracts Specs & Validates Schemas|`
* `CNT-EIDOS-PORTAL` --> `CNT-EIDOS-INDEX`: `|Fetches Knowledge Graph & Stats|`
* `CNT-EIDOS-DOCS` --> `CNT-EIDOS-PORTAL`: `|Embeds & Links Portal [CTR-EIDOS-PORTAL]|`
* `CNT-EIDOS-PLUGIN` --> `CNT-EIDOS-CORE`: `|Resolves Schemas & Assets|`
* `CNT-EIDOS-INDEX` --> `CNT-EIDOS-CORE`: `|Indexes Spec AST & Frontmatters|`

=== 4. Living Web Portal UI Enhancements
* **Tier Legend**: Interactive legend bar in Level 2 view summarizing the 4 tiers and connection semantics.
* **Container Cards Matrix**: Displays the container's tier badge, domain binding, outgoing dependency count, and incoming dependent count.
* **Component Inspector Drawer**: Enriched with full dependency lists (internal containers, external services, and downstream dependents) with direct click navigation.
