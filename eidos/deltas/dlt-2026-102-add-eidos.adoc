= SpecDelta: Add eidos spec schema CLI introspection and frontmatter authoring guardrails
:toc: left

== Problem Statement
When authoring or updating living specifications (`.adoc`) and SpecDeltas (`DLT-*`), AI coding agents sometimes guess YAML frontmatter keys (such as placing `invariants:` at the top level of `CAP-*` instead of `technical.invariants`, adding `jtbd:` to YAML frontmatter, or misremembering closed sub-object keys on `decisions:` and `contracts:`) and only discover the error after `eidos validate` fails.

== Proposed Specification Changes
1. **Dynamic Schema Introspection (`CMP-LIFECYCLE-SCAFFOLDER` & `CMP-CLI-SPEC-COMMANDS`)**: Add `get_spec_schema_info(doc_type_key)` in `src/eidos/core/lifecycle/scaffolder.py` and `eidos spec schema [type] [--json]` in `src/eidos/cli/spec_commands.py` (`CTR-EIDOS-CLI`), loading all 16 v1 YAML schemas directly from `assets/schemas/v1/` (`SpecValidator()._schema_cache`), flattening `allOf` / `$ref` descriptors, and synthesizing schema-valid YAML frontmatter templates.
2. **Bundled Agent Skill Hardening (`CMP-PLUGIN-INSTALLER`)**: Update `assets/plugin_reference/skills/{eidos,eidos-spec,eidos-plan,eidos-ops}/SKILL.md` with `eidos spec schema` instructions, an explicit `additionalProperties: false` Frontmatter Guardrails & Common Pitfalls table, schema-validated `SYS-*` and `ARCH-*` YAML examples, and corrected `business.personas` / `business.policies` brownfield extraction guidance.
