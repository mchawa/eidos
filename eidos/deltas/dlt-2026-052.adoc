= SpecDelta: Fix Batched is_generated_or_vendored Invocation and Single-Pass Base Ref Resolution in Drift
:toc: left

== Problem Statement
1. **Broken String-to-List Call in `classify_changed_files` / `classify_git_changes` (`diff.py` / `drift.py:401`)**:
   - `is_generated_or_vendored(repo_root: Path, rel_paths: list[str]) -> set[str]` in `src/eidos/core/workspace/project.py:133` expects a `list[str]` and joins them with `"\0".join(rel_paths)`.
   - `classify_changed_files` (`classify_git_changes` in `src/eidos/vcs/diff.py` / `src/eidos/vcs/drift.py:401`) calls `is_generated_or_vendored(effective_root, str(rel_f))` inside the per-file loop, passing a `str` instead of `list[str]`.
   - Iterating over `str(rel_f)` splits the path into single characters (`"s\0r\0c\0..."`), causing `git check-attr` to never match any file, always returning an empty `set()` (`not set()` is always `True`), and spawning one `git check-attr` subprocess per file.
2. **Repeated `git rev-parse` Subprocesses per File (`diff.py` / `drift.py:1045-1056, 1594`)**:
   - `_get_file_versions` (`_git_show_text`) re-runs `git rev-parse --verify` across candidate base refs for every modified code and specification file instead of resolving the base commit once.

== Proposed Specification & Engine Changes
1. **Batched `is_generated_or_vendored` Filtering**:
   - Collect all candidate relative paths in `classify_changed_files` (`classify_git_changes`), call `vendored = is_generated_or_vendored(effective_root, candidate_paths)` once before the loop, and check `str(rel_f) not in vendored`.
   - Add a runtime guard in `is_generated_or_vendored` (`if isinstance(rel_paths, (str, Path)): rel_paths = [str(rel_paths)]`) to prevent accidental character iteration.
2. **Single-Pass Base Reference Resolution**:
   - Resolve the base Git commit and merge-base SHA once at the start of `detect_drift` via `_resolve_base_and_merge_base` and pass the resolved `merge_base` into `get_git_diff_files`, `_get_file_versions` (`_git_show_text`), and `_SpecDiffInspector`.
