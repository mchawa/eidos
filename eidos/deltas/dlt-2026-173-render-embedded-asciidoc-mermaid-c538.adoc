= SpecDelta: Render Embedded AsciiDoc Mermaid Diagrams in Living Web Portal
:toc: left

== Problem Statement
Living specifications under `eidos/` routinely author embedded Mermaid diagrams using standard AsciiDoc blocks (`[mermaid]` and `[source,mermaid]` delimited by `----` or `....` fences)—for example, `ARCH-EIDOS-001` (`eidos/architecture/system-architecture.adoc`, `C4Context`), `FLOW-CLI-SERVE-AND-BROWSE` (`eidos/design/flows/cli-serve-and-browse.adoc`, `sequenceDiagram`), and `FLOW-PORTAL-EXPLORATION` (`eidos/design/clients/web-portal/flows/spec-exploration.adoc`, `flowchart LR`). Since `DLT-2026-158` (`CMP-MERMAID-VALIDATOR`, `INV-MERMAID-SPEC-VALIDATION`), `eidos validate` and `eidos drift` validate every embedded Mermaid block via pinned Mermaid v12.1.0 `mermaid.parse()`.

However, when stakeholders inspect any specification document through `AsciiDocRenderer` (`UIC-PORTAL-READER`, shared across all 8 portal views: `SpecReader` / `CatalogView`, `ArchitectureView` `#c4InspectorDrawer` and Contract Sheet, `BusinessView`, `DeltasView`, `DesignView`, `ExplorationsView`, `MemoryView`, and `HomeView`-launched specs), embedded Mermaid blocks never render as diagrams for three technical reasons:

1. **Silent Style Stripping by `@asciidoctor/core` (`src/eidos/portal/frontend/src/lib/asciidoc.ts`)**: Without a diagram extension, `@asciidoctor/core` drops the unknown `[mermaid]` block style during HTML conversion—emitting an unmarked `<div class="listingblock"><pre>...</pre></div>` (for `----`) or `<div class="literalblock"><pre>...</pre></div>` (for `....`). Post-HTML DOM inspection therefore cannot distinguish `[mermaid]` blocks from ordinary untyped code blocks, while `[source,mermaid]` renders solely as a dark code snippet with a `MERMAID` copy bar.
2. **Strict Post-Conversion HTML Sanitization (`INV-PORTAL-XSS-AND-SERVER-ISOLATION`)**: `SANITIZE_CONFIG` in `asciidoc.ts` intentionally forbids `<svg>`, `<style>`, and `<button>` tags (`SANITIZE_DOM: true`, `idprefix: "spec-"`). Mermaid SVGs therefore cannot be emitted into Asciidoctor HTML prior to `DOMPurify.sanitize()`; they must be mounted **after** HTML sanitization through Mermaid v12 with `securityLevel: "strict"` and `sanitizeMermaidCode()`.
3. **Scroll-Trapping, Concurrency, Layout, and Theme Reactivity Gaps (`MermaidDiagram.tsx`, `ArchitectureView.tsx`, `mermaid.ts`)**: `MermaidDiagram` currently binds an unconditional non-passive `wheel` listener that hijacks page scrolling when nested inside prose documents, has unguarded negative zoom when `clientWidth <= 48`, exits silently on empty input, and unmounts `diagramRef` on error; `ArchitectureView.tsx` and `MermaidDiagram.tsx` invoke global `mermaid.initialize()` + `mermaid.render()` without a shared serialization queue or orphan `#d<id>` error cleanup; and `AsciiDocRenderer` receives no `darkMode` prop across `CatalogView`, `BusinessView`, `DeltasView`, `DesignView`, `ExplorationsView`, and `MemoryView`.

== Proposed Specification Changes

=== 1. Architectural Decision & Security Model (`CNT-EIDOS-PORTAL`)
Graduate `DEC-PORTAL-DOCUMENT-MERMAID-RENDERING` (`graduated_from: DLT-2026-173-RENDER-EMBEDDED-ASCIIDOC-MERMAID-C538`) into `eidos/architecture/containers/portal.adoc` (`decisions:` block and `== Internal Structure & Key Mechanisms`; avoid backticked `()` external API calls in prose so `PublicSurfaceValidator` emits zero advisory warnings):

* **Decision**: Detect `[mermaid]` and `[source,mermaid]` blocks directly on the `@asciidoctor/core` v4.1.1 AST inside `renderAsciiDoc()` using `doc.findBy(...)` plus explicit recursive traversal of `table.rows.{head,body,foot}` `cell.getInnerDocument()` inner documents (avoiding non-existent `getBodyRows` and `dlist.getBlocks()` tuple pitfalls), extract verbatim source via `block.getSource()` and plain-text captions via `textOf(String(block.getTitle()))` into `RenderedAsciiDoc.mermaidBlocks`, tag matched AST nodes with a CSPRNG per-parse nonced role so raw HTML passthroughs cannot spoof diagram slots, leave `DOMPurify.sanitize(..., SANITIZE_CONFIG)` (`SANITIZE_DOM: true`, `FORBID_TAGS` including `svg`/`style`/`button`) completely unchanged, strip untrusted `.adoc-mermaid-slot`/`[data-mermaid-index]`/`adoc-mermaid-*` markers unconditionally in `decorate()` and convert only nonce-matched blocks into deterministic `<div class="adoc-mermaid-slot" data-mermaid-index="N"></div>` placeholders, mount interactive `DocumentMermaidBlock` components post-sanitization via sibling React 19 `createPortal` calls outside `AsciiDocRenderer`'s `onClick={handleClick}` container, and route **both** embedded document diagrams and `ArchitectureView` C4 diagrams through one unified serialized, theme-reactive `renderMermaidSvg()` queue enforcing `securityLevel: "strict"` and `sanitizeMermaidCode()`.
* **Rationale**: Reading the Asciidoctor AST handles `[mermaid]` (`----` / `....`), `[source,mermaid]`, case variants, `.Title` captions, nested `dlist`/list/admonition/example/table blocks, comments (`////`), and `[source,asciidoc]` examples accurately while preserving verbatim Mermaid syntax (`<br/>`, `<<interface>>`, `<1>`, `&`) before HTML escaping; CSPRNG per-parse nonced roles keep `renderAsciiDoc()` HTML deterministic while blocking passthrough spoofing; sibling `createPortal` preserves valid DOM nesting at arbitrary depth without leaking synthetic clicks into `AsciiDocRenderer.handleClick`; and routing all portal Mermaid callers (`DocumentMermaidBlock`, `MermaidDiagram`, `ArchitectureView`) through one serialized queue eliminates multi-diagram and theme-toggle global config/DOM race conditions with zero new npm dependencies (within the `5 MiB` uncompressed / `2 MiB` gzip bundle budget; currently `4.58 MiB` uncompressed with `425.6 KiB` headroom and `1.28 MiB` gzipped).
* **Rejected Alternatives**:
  * *Post-HTML DOM scanning for `code[data-lang="mermaid"]`*: Silently misses all `[mermaid]` blocks (`ARCH-EIDOS-001`, `FLOW-CLI-SERVE-AND-BROWSE`, `FLOW-PORTAL-EXPLORATION`) because `@asciidoctor/core` strips the `[mermaid]` style from emitted HTML.
  * *Registering an Asciidoctor.js `Extensions` block/treeProcessor registry*: Introduces global extension registry state/lifecycle complexity and `safe: "secure"` coupling across parses without avoiding the post-DOMPurify mounting constraint.
  * *Pre-parse regex extraction on raw AsciiDoc strings*: Misfires on `[source,asciidoc]` documentation examples, `////` comment blocks, and `++++` passthroughs, and cannot cleanly preserve nested block structures.
  * *Relaxing `DOMPurify` `FORBID_TAGS` to allow `<svg>` / `<style>` before sanitization*: Weakens `INV-PORTAL-XSS-AND-SERVER-ISOLATION` and exposes raw-HTML SVG/XSS vectors from untrusted specification prose.
  * *Splitting sanitized HTML strings around placeholders instead of `ReactDOM.createPortal`*: Produces malformed HTML whenever a Mermaid block is nested inside an admonition, example block, sidebar, `dlist`, or `a|` table cell.

=== 2. Frontend Rendering Pipeline & Interactive Diagram Card (`CMP-PORTAL-ASSETS`)
* **AST Mermaid Extraction & Anti-Spoofing Slots (`src/eidos/portal/frontend/src/lib/asciidoc.ts`)**:
  * Export `AsciiDocMermaidBlock` (`{ index: number; code: string; title?: string }`) and extend `RenderedAsciiDoc` with `mermaidBlocks: AsciiDocMermaidBlock[]`.
  * Before `doc.convert()`, walk the Asciidoctor v4.1.1 AST via a recursive helper using `d.findBy(...)` (which natively traverses sections, `ulist`/`olist`, `dlist` `[terms, dd]` tuples, admonitions, example blocks, and sidebars without crashing on `dlist.getBlocks()` tuple items) and recursing into `table.rows.{head,body,foot}` `cell.getInnerDocument()` inner documents to find every `listing` or `literal` block where `style.toLowerCase() === "mermaid"` or (`style.toLowerCase() === "source"` and `language.toLowerCase() === "mermaid"`).
  * Capture verbatim `block.getSource()` and plain-text optional caption normalized via `textOf(String(block.getTitle()))` (stripping Asciidoctor HTML formatting/entities safely for JSX text rendering), and tag each matched block with a CSPRNG per-parse nonced role (`adoc-mermaid-m<nonce>-<index>`, using `crypto.getRandomValues` / `crypto.randomUUID` with safe fallback).
  * Keep `SANITIZE_CONFIG` (`FORBID_TAGS`, `FORBID_ATTR`, `SANITIZE_DOM: true`) and `ASCIIDOC_ATTRIBUTES` (`idprefix: "spec-"`) strictly unchanged.
  * In `decorate()`, unconditionally strip any untrusted `.adoc-mermaid-slot`, `[data-mermaid-index]`, and stray `adoc-mermaid-*` classes from passthrough HTML (even when `mermaidBlocks.length === 0`), skip `.adoc-code-bar` decoration on nonce-matched Mermaid blocks, and replace each nonce-matched block with a deterministic `<div class="adoc-mermaid-slot" data-mermaid-index="<index>"></div>` placeholder (leaving zero raw AsciiDoc/Mermaid markers outside `<pre>`/`<code>` for `INV-ASCIIDOC-ZERO-WARNING-HYGIENE`).
* **Unified Serialized Strict Mermaid Renderer (`src/eidos/portal/frontend/src/lib/mermaid.ts` & `ArchitectureView.tsx`)**:
  * Export `renderMermaidSvg(id: string, rawCode: string, dark: boolean): Promise<{ svg: string }>` backed by a single module-level promise queue so concurrent embedded document diagrams and `ArchitectureView` C4 diagrams never race on `mermaid.initialize()` or Mermaid v12 scratch DOM nodes.
  * Enforce `sanitizeMermaidCode(rawCode)` and `securityLevel: "strict"`, reject empty/whitespace-only sanitized input with an explicit error, track `lastInitializedDark` (re-initializing only when the theme changes and keeping `getConfiguredMermaid(dark)` synchronized with that tracked state for backward-compatible callers), allocate collision-safe monotonic SVG element IDs (`eidos-mermaid-<sanitized>-<seq>`), and remove any orphan `#d<uniqueId>` temporary error nodes left in `document.body` on parse/render failure.
  * Route `ArchitectureView.tsx`'s C4 diagram render call through `renderMermaidSvg("c4", safeSource || "graph TD\nSYS[System]", darkMode)` (preserving `#c4ActiveDiagram`, `#c4DiagramContainer`, `c4Highlight.ts`, and `data-c4-entity` hooks unchanged) while retaining existing `loadMermaid`, `sanitizeMermaidCode`, `buildMermaidConfig`, and `getConfiguredMermaid` exports.
* **Reactive Dark/Light Theme Hook (`src/eidos/portal/frontend/src/lib/theme.ts`)**:
  * Export SSR-safe `useDarkMode(explicitDarkMode?: boolean): boolean` reading `document.documentElement.classList.contains("dark")` and subscribing via `MutationObserver` (`attributes: true, attributeFilter: ["class"]`) when `explicitDarkMode` is omitted so toggling Light/Dark theme in `NavigationRail` automatically re-renders every visible embedded document diagram across all 8 portal views without prop-drilling.
* **Hardened `MermaidDiagram`, `DocumentMermaidBlock`, `AsciiDocRenderer`, & Scoped CSS (`MermaidDiagram.tsx`, `DocumentMermaidBlock.tsx`, `AsciiDocRenderer.tsx`, `theme.css`)**:
  * Harden `src/eidos/portal/frontend/src/components/ui/MermaidDiagram.tsx`:
    * Add `wheelZoom?: "always" | "modifier"` (default `"always"` for standalone views; `"modifier"` calls `e.preventDefault()` only on `e.ctrlKey || e.metaKey`, with `[wheelZoom]` in the wheel effect dependencies and updated hint text), `emptyBehavior?: "fallback" | "error"` (default `"fallback"`), `hideErrorFallback?: boolean`, and `onRenderError?: (message: string | null) => void`.
    * Guard `autoFit()` when `containerWidth <= 0 || containerHeight <= 0` (falling back to `zoom = 1.0, pan = { x: 0, y: 0 }`), clamp `optimalZoom` to `[0.35, 1.0]` (preventing negative/inverted SVGs in jsdom, narrow table cells, or opening `Sheet` animations), and parse `viewBox` with `split(/[\s,]+/)` + `Number.isFinite(...)`.
