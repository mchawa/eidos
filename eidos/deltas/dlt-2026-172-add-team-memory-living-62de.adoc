= SpecDelta: Add Team Memory Living Web Portal Surface (Phase 4)
:toc: left

== Problem Statement
Phases 1–3 of `EXP-2026-012` introduced Git-native team operational memory (`agent/memory`, `MEM-*`), unified SQLite indexing with `HEAD`-keyed freshness caching, secondary budgeted `eidos context` injection, and the `eidos memory` CLI + `eidos-memory` skill. Stakeholders browsing the Living Web Portal (`CLT-WEB-PORTAL`) still lack visual visibility into recorded team memories, freshness/staleness diagnostics, promotion history, and which architectural containers, components, domains, or capabilities carry operational notes.

== Proposed Specification Changes
1. **Portal Data & Static Export (`CMP-PORTAL-GENERATOR`, `CMP-PORTAL-BUILDER`, `CTR-EIDOS-PORTAL` `v1.2.0`)**:
   * Synthesize `memories[]` (reusing `CMP-MEMORY-ENGINE.list_memories` with normalized repo-relative paths and attached bodies) and `memory_audit` (via `audit_memories(use_semantic=False)`) in `get_portal_data()`, plus `overview.memories_count` and `overview.active_memories_count`.
   * Preserve strict isolation: stale, expired, unverifiable, or overlapping memories never mutate `validation.warnings`, `validation.warning_count`, or `validation.is_clean`.
   * Deduplicate `memories[].body` in `_deduplicate_portal_payload()` so chunked (`./specs/<MEM-ID>.json`) and `--single-file` static portals keep payloads compact.
2. **Living Web Portal UI (`SCR-PORTAL-MEMORY`, `CLT-WEB-PORTAL`, `CMP-PORTAL-ASSETS`, `CNT-EIDOS-PORTAL`)**:
   * Add `MemoryView.tsx` (`#/memory`), accessible filter pills (category, freshness/lifecycle, search), non-blocking audit highlights (duplicates & formal spec overlaps), resolved entity cross-links, sanitized AsciiDoc inspection modal (`AsciiDocRenderer`), and a clean zero-memory empty state.
   * Add `Team Memory` tab in `NavigationRail.tsx` (count badge shown only when `memoriesCount > 0`, amber indicator when stale/expired notes exist), Command Palette (`CMD+K`) indexing, `CatalogView.tsx` Team Memory category, `HomeView.tsx` Team Operational Memory health card, and `EntityMemoriesStrip.tsx` inline cross-links inside `ArchitectureView.tsx` (`#c4InspectorDrawer`) and `BusinessView.tsx` (Domain/Capability drawers).
   * Extend `presentation.ts` to recognize `MEM-*` and `agent/memory` and sanitize freshness reasons so `INV-PORTAL-HUMAN-READABLE-UI` holds across all views.
   * Record `DEC-PORTAL-MEMORY-AUDIT-AND-CROSSLINKS` on `CNT-EIDOS-PORTAL` and bind `INV-PORTAL-TEAM-MEMORY-SURFACE` on `CAP-EXP-001` (`v1.6.0`).
3. **Documentation & Air-Gapped Bundle (`CMP-DOCS-USER-GUIDES`, `assets/portal/bundle.html.gz`)**:
   * Rebuild `assets/portal/bundle.html.gz` (`pnpm build:assets`, verified via `build_assets.py --check`) and update `docs/guides/living-portal.md`.

== Implementation Plan
1. Update `src/eidos/portal/generator.py` and `src/eidos/portal/builder.py` to emit and deduplicate `memories[]` and `memory_audit`.
2. Implement `MemoryView.tsx`, `EntityMemoriesStrip.tsx`, and updates to `types.ts`, `presentation.ts`, `command.tsx`, `NavigationRail.tsx`, `App.tsx`, `HomeView.tsx`, `ArchitectureView.tsx`, `BusinessView.tsx`, and `CatalogView.tsx`; add Vitest tests and rebuild `assets/portal/bundle.html.gz`.
3. Co-evolve `SCR-PORTAL-MEMORY`, `CLT-WEB-PORTAL`, `CNT-EIDOS-PORTAL`, `CMP-PORTAL-GENERATOR`, `CMP-PORTAL-BUILDER`, `CMP-PORTAL-ASSETS`, `CTR-EIDOS-PORTAL`, `CAP-EXP-001`, `CAP-PROD-001`, `CMP-DOCS-USER-GUIDES`, `EXP-2026-012`, and `docs/guides/living-portal.md`.
4. Add `tests/test_portal.py::test_portal_team_memory_payload_crosslinks_and_empty_state` bound to `INV-PORTAL-TEAM-MEMORY-SURFACE`, verify `>90%` per-file coverage, run Vitest, `build_assets.py --check`, `eidos delta verify/apply/audit`, `eidos drift --uncommitted --json`, and full `pytest`.
