= SpecDelta: Simplify Eidos CLI Surface and Standardize Pure Blueprint Specification Scaffolding
:toc: left

== Problem Statement
Across the Eidos CLI (`src/eidos/cli/`), several commands accumulated redundant flags, overlapping responsibilities, and inconsistent option names:

1. **`eidos spec create` Bloat**: Exposed 20 parameters (16 type-specific flags), injected non-required opinionated YAML boilerplate, lacked support for `system` (`SYS-*`) and `architecture` (`ARCH-*`), and duplicated `eidos delta create`.
2. **Overlapping `spec` and `delta` Lifecycles**: Both `eidos spec` (`create`, `list`, `show`, `delete`) and `eidos delta` (`create`, `list`, `delete`) operated on `DLT-*` files, violating the single canonical command path principle.
3. **`eidos delta create` & `eidos delta status` Redundancies**: `delta create` required manual `--motivation` and `--branch` flags even though Git `HEAD` branch can be auto-detected alongside `base_commit`, while `delta status` still displayed retired `draft` and `planned` rows removed from `#/$defs/delta_status`.
4. **Legacy & Duplicate Flags Across Subcommands**:
   * `eidos init` retained an unused hidden `--with-plugin / --no-plugin` option.
   * `eidos spec component promote / inline` exposed `--repo-root` in addition to `--path`.
   * `eidos plugin install / uninstall / update` bound both a positional `[TARGET]` argument and a duplicate `--target / -t` option.
   * `eidos context` and `eidos index repo-map` used `--format json` instead of `--json`.
   * Root `eidos` exposed both `eidos --version` (`-V`) and a redundant `eidos version` subcommand.
   * 5 CLI modules duplicated `eidos_dir` marker resolution and defined no-op `register(app)` functions.

== Proposed Specification Changes

=== 1. 100% Disjoint `eidos spec` (15 Living Spec Types) vs. `eidos delta` (`DLT-*`) Boundary
* **Conceptual Split**:
  * `eidos spec` (`create`, `list`, `show`, `delete`, `component`) manages the **15 declarative specification & discovery blueprints** (`system`, `architecture`, `domain`, `capability`, `policy`, `persona`, `exploration`, `container`, `component`, `contract`, `design-system`, `ui-component`, `screen`, `client`, `flow`). `exploration` (`EXP-*`) remains in `eidos spec` because its lifecycle is pure blueprint authoring (`create`, `list`, `show`, `delete`).
  * `eidos delta` (`create`, `list`, `status`, `verify`, `audit`, `apply`, `delete`, `changelog`) exclusively manages **executable architectural mutations** (`DLT-*`).
* **`eidos spec create <TYPE> <ID> --title <TITLE> [--path <PATH>]`**:
  * Scaffolds minimal, schema-valid draft blueprints (`status: draft`, or `status: proposed` for `exploration`) across all **15 living specification types**.
  * Rejects `delta` / `mutation` with an error directing the caller to `eidos delta create`.
* **`eidos spec list [--type <TYPE>] [--status <STATUS>] [--domain <DOMAIN>] [--path <PATH>] [--json]`**:
  * Lists only the 15 living specification types (excluding `delta/mutation` documents from default output) and rejects `--type delta` / `--type delta/mutation` with an error directing the caller to `eidos delta list`.
* **`eidos spec show <ID> [--path <PATH>] [--json]`**:
  * Displays any of the 15 living specification types and rejects `delta/mutation` (`DLT-*`) documents with an error directing the caller to `eidos delta status <ID>` / `eidos delta verify <ID>`.
* **`eidos spec delete <ID_OR_PATH> [--path <PATH>] [--force]`**:
  * Deletes any of the 15 living specification types with cross-reference safety checks, and rejects `delta/mutation` (`DLT-*`) documents with an error directing the caller to `eidos delta delete`.
* **`eidos delta create [ID] --title <TITLE> [--kind <KIND>] [--slug] [--path <PATH>]`**:
  * Removes `--motivation / -m` and `--branch / -b` CLI options; auto-detects `vcs.branch` from Git (`HEAD`) alongside `vcs.base_commit` and scaffolds a clean `delta/mutation` blueprint.
* **`eidos delta delete <ID_OR_PATH> [--path <PATH>] [--force]`**:
  * Dedicated deletion command for `delta/mutation` (`DLT-*`) specifications via `delete_delta()`, rejecting non-delta specifications with an error directing the caller to `eidos spec delete`.
* **`eidos delta status [ID] [NEW_STATUS] [--path <PATH>] [--json]`**:
  * Displays and transitions only the 5 canonical `delta_status` states (`proposed`, `in_review`, `approved`, `applied`, `rejected`).
