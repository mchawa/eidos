= SpecDelta: Dynamic Clickable Hierarchical C4 Architecture Explorer (L1-L3)
:toc: left

== 1. Problem Statement
The current Technical Architecture view (`SCR-PORTAL-ARCHITECTURE`) in the Eidos Living Web Portal (`CMP-EIDOS-PORTAL`) displays two static, vertically stacked Mermaid diagrams:
1. **C4 Level 1: System Context Topology**
2. **C4 Level 2: Container Topology**

While these diagrams successfully render high-level boundaries, they suffer from three major architectural and usability limitations:
* **No Interactive Drill-Down**: The diagrams are static SVG images with basic zoom/pan buttons. Clicking on the system node in Level 1 does not drill down into Level 2 containers; clicking on a container in Level 2 does not drill down into its internal components.
* **Missing C4 Level 3 (Component Whitebox View)**: Although all component specifications (`CMP-*`) author comprehensive `c4_internal_components` metadata (internal module names, responsibilities, and source paths), this rich architectural data is only shown in a static tabular format at the bottom of the page, completely disconnected from the visual graph representation.
* **Lack of Contextual Inspection**: Developers and architects cannot click on a building block to inspect its direct contract bindings, active invariants, or source files in an integrated slide-over inspector.

== 2. Proposed Architecture & UX Design

=== 2.1 Three-Tier Hierarchical Zoom Model
Transform the Architecture view from stacked static cards into a unified, interactive **Hierarchical C4 Explorer**:
* **Level 1 (System Context)**: Shows personas, the root system (`SYS-EIDOS-001`), and external integrations. Clicking the primary system node zooms into Level 2.
* **Level 2 (Container Topology)**: Shows all monorepo containers (`CMP-EIDOS-CORE`, `CMP-EIDOS-CLI`, `CMP-EIDOS-PORTAL`, etc.) and inter-container protocols. Clicking any container zooms into Level 3 for that container.
* **Level 3 (Component Whitebox)**: Shows the internal building blocks of the selected container (`SpecParser`, `SpecValidator`, `LifecycleScaffolder`, etc.), their responsibilities, source paths, and contract boundaries. Clicking any internal component opens the Component Inspector Drawer.

=== 2.2 Navigation Controls & Affordances
* **Interactive Breadcrumbs**:
  `🌐 System Context (L1) › 📦 Containers (L2) › 🧱 CMP-EIDOS-CORE (L3)`
  Enables instant jumping to any ancestor level.
* **Level Switcher Tabs & Container Selector**:
  A segmented control allowing direct switching between `[L1 Context]`, `[L2 Containers]`, and `[L3 Components]`. When in Level 3, a container dropdown selector allows rapid switching between containers without navigating back up.
* **Level Up Button**:
  Quick-action button (`↑ Up to Containers` or `↑ Up to System Context`) positioned next to zoom controls.
* **Visual Click Affordance**:
  Clickable nodes display an interactive pointer cursor, hover highlight/glow, and badge indicators hinting that clicking reveals lower architectural levels.

=== 2.3 Slide-Over Component Inspector Drawer
Clicking a Level 3 component or clicking an "Inspect" action on a Level 2 container reveals a slide-over details drawer showing:
* **Module Metadata**: Name, owning container, container type, runtime, and source path (clickable file link).
* **Architectural Responsibility**: Clear description of the module's role in the architecture.
* **Connected Contracts**: Interface protocols provided or consumed by the module's container.
* **Governing Policies & Invariants**: Policies and invariants impacting the module.
* **Living Spec Link**: Direct link to jump to the full specification in the Living Specs Catalog (`SCR-PORTAL-CATALOG`).

== 3. Technical Implementation Plan

=== 3.1 Portal Data Generator (`src/eidos/portal/generator.py`)
1. Implement `_generate_c4_component_mermaid(component: dict[str, Any], all_components: list[dict[str, Any]]) -> str`:
   - Extracts `c4_internal_components` from the component manifest.
   - Generates a styled Mermaid flowchart detailing internal modules, source files, and dependencies to peer containers.
2. In `get_portal_data()`:
   - Generate Level 3 diagrams for every container in the catalog.
   - Store them in `data["diagrams"]["c4_components"]` keyed by container ID (e.g., `data["diagrams"]["c4_components"]["CMP-EIDOS-CORE"]`).

=== 3.2 Web Portal Assets & Interactive State Machine (`src/eidos/portal/assets.py`)
1. Refactor `#tab-architecture` layout:
   - Replace the two static stacked `.panel` divs with a unified C4 Explorer panel featuring:
     - Header with segmented level controls (`L1 Context`, `L2 Containers`, `L3 Components`) and Container selector dropdown.
     - Breadcrumb navigation bar with clickable trail.
     - Central Mermaid visualization viewport with zoom, pan, and level-up controls.
     - Slide-over Component Inspector drawer (`#c4InspectorDrawer`).
2. Implement Client-Side C4 Explorer State Machine:
   - State object tracking: `currentLevel` (1, 2, or 3), `selectedContainerId`, `selectedComponentId`.
   - Functions:
     - `setC4Level(level, containerId)`: Handles level transitions, breadcrumb updates, and diagram re-rendering.
     - `drillDownToContainer(containerId)`: Transitions from L2 to L3 for the specified container.
     - `openC4Inspector(containerId, componentName)`: Populates and opens the inspector drawer.
     - `closeC4Inspector()`: Dismisses the inspector drawer.
     - `attachC4DiagramClickHandlers()`: Post-processes rendered SVG to bind click handlers to Mermaid node elements (`SYS` -> L2, `CMP_*` -> L3, internal modules -> open inspector).
3. Theme Integration:
   - Ensure all interactive elements, hover states, and inspector drawers support both dark and light modes.

=== 3.3 Living Specification Updates
1. `eidos/design/clients/web-portal/screens/portal-architecture.adoc` (`SCR-PORTAL-ARCHITECTURE`):
   - Update `slots` to include `c4_explorer_viewport`, `c4_breadcrumbs`, `c4_level_controls`, and `c4_inspector_drawer`.
   - Update `states` to document `level_1_context`, `level_2_containers`, `level_3_components`, and `component_inspected`.
2. `eidos/domains/experience-portal/capabilities/living-web-portal.adoc` (`CAP-EXP-001`):
   - Update `INV-PORTAL-INTERACTIVE-C4` to enforce interactive clickable navigation across all three C4 levels.
3. `eidos/architecture/system-architecture.adoc` (`ARCH-EIDOS-001`):
   - Synchronize Arc42 Section 4 and Section 5 documentation with the interactive C4 Explorer.
