= SpecDelta: Formalize First-Principles C4 Architecture (L2 Containers & L3 Components)
:toc: left
:icons: font

== 1. Problem Statement & Motivation

In Simon Brown's canonical C4 model:
* **Level 1 (System Context)**: The overall software system, its human users/personas, and external third-party systems.
* **Level 2 (Containers)**: Separately deployable/runnable units that execute code or store data (services, libraries, CLI executables, SPAs, databases, daemons).
* **Level 3 (Components)**: Modular building blocks encapsulated behind an interface running **in-process within a single container**.
* **Level 4 (Code)**: Classes, interfaces, functions, AST, and schemas.

=== The Cognitive Dissonance in Eidos
Because Eidos originally modeled everything technical under `type: tech/component` with prefix `CMP-*`:
1. **L2 Deployables were labeled Components**: `CMP-EIDOS-CORE` (a library) and `CMP-EIDOS-CLI` (a CLI app) were stored in `eidos/architecture/components/` and assigned `CMP-*` IDs, confusing anyone familiar with C4 into thinking they were Level 3 components.
2. **L3 In-Process Modules had no identity**: The actual components (`SpecParser`, `SpecValidator`, etc.) were relegated to an unindexed YAML list (`c4_internal_components`) without standard IDs (`CMP-*`).
3. **Prefix Collision**: Contracts had `CTR-*`, but Containers and Components shared `CMP-*`.

Since the project is in early stages, we make a **clean, breaking refactoring** to align directly with first principles: zero ambiguity, zero legacy baggage.

== 2. Target Architectural Taxonomy

We introduce distinct entity prefixes and document types across all 4 C4 levels:

[cols="1,2,2,3,2", options="header"]
|===
| C4 Level | C4 Term | Eidos Document Type | Prefix / Location | Execution Boundary
| **L1** | **System Context** | `product/system` & `tech/architecture` | `SYS-*`, `ARCH-*` (`eidos/system.adoc`, `eidos/architecture/`) | System ecosystem
| **L2** | **Container** | `tech/container` | `CNT-*` (`eidos/architecture/containers/*.adoc`) | **Process / Deployable / Package**
| **L3** | **Component** | `c4_components` / `tech/component` | `CMP-*` (nested in container or in `components/`) | **In-Process / Memory space**
| **L4** | **Code** | Source Code & Schemas | `src/eidos/**/*.py`, `schemas/**/*.yaml` | Classes, functions, AST
|===

=== 2.1 Prefix Namespace Standardization
* **`SYS-*`**: Root Systems (e.g. `SYS-EIDOS-001`)
* **`ARCH-*`**: Global Architectures (e.g. `ARCH-EIDOS-001`)
* **`CNT-*`**: **C4 Containers** (e.g. `CNT-EIDOS-CORE`, `CNT-EIDOS-CLI`, `CNT-EIDOS-MCP`)
* **`CMP-*`**: **C4 Components** (e.g. `CMP-SPEC-PARSER`, `CMP-SPEC-VALIDATOR`)
* **`CTR-*`**: **Interface Contracts** (e.g. `CTR-EIDOS-CLI`, `CTR-EIDOS-MCP`)

== 3. Detailed Specification Changes

=== 3.1 New Schema: `schemas/v1/tech/container.schema.yaml`
Replaces `tech/component.schema.yaml` as the Level 2 deployable schema:
[source,yaml]
----
---
type: tech/container
schema: schemas/v1/tech/container.schema.yaml
id: CNT-EIDOS-CORE
name: "Eidos Living Specification & Design Core Engine"
container_type: library    # service | library | cli_app | frontend_spa | daemon | worker
runtime: "Python 3.12 / Hatchling / PyYAML / jsonschema"
package_path: "src/eidos/core"
domain_binding: DOM-SPEC-ENGINE

components:                # <-- C4 Level 3 Components (CMP-*)
  - id: CMP-SPEC-PARSER
    name: "SpecParser"
    responsibility: "Extracts YAML frontmatter metadata and body text from AsciiDoc documents."
    source_path: "src/eidos/core/parser.py"
  - id: CMP-SPEC-VALIDATOR
    name: "SpecValidator"
    responsibility: "Validates living specs against Draft 2020-12 schemas and checks cross-references."
    source_path: "src/eidos/core/validator.py"
  - id: CMP-LIFECYCLE-SCAFFOLDER
    name: "LifecycleScaffolder"
    responsibility: "Manages document lifecycle, template generation, and reference safety checks."
    source_path: "src/eidos/core/scaffolder.py"
  - id: CMP-CONTEXT-SLICER
    name: "ContextSlicer"
    responsibility: "Extracts compact, token-efficient architectural subgraph slices."
    source_path: "src/eidos/core/context.py"

dependencies:
  internal_containers: []
  external_services:
    - "Git CLI (local)"

contracts:
  provides: []
  consumes: []
----

=== 3.2 Directory Layout Refactoring
Rename `eidos/architecture/components/` to `eidos/architecture/containers/`:
```
eidos/architecture/
├── system-architecture.adoc          # ARCH-EIDOS-001 (L1 Context & L2 Containers)
├── contracts/                        # CTR-* (Interface Contracts)
│   ├── cli.adoc                      # CTR-EIDOS-CLI (owned by CNT-EIDOS-CLI)
│   ├── mcp.adoc                      # CTR-EIDOS-MCP (owned by CNT-EIDOS-MCP)
│   └── portal.adoc                   # CTR-EIDOS-PORTAL (owned by CNT-EIDOS-PORTAL)
└── containers/                       # CNT-* (C4 Level 2 Container Manifests)
    ├── core.adoc                     # CNT-EIDOS-CORE
    ├── cli.adoc                      # CNT-EIDOS-CLI
    ├── mcp.adoc                      # CNT-EIDOS-MCP
    ├── plugin.adoc                   # CNT-EIDOS-PLUGIN
    ├── portal.adoc                   # CNT-EIDOS-PORTAL
    ├── index.adoc                    # CNT-EIDOS-INDEX
    └── docs.adoc                     # CNT-EIDOS-DOCS
```

=== 3.3 Interface Contracts (`CTR-*`)
Update `tech/contract.schema.yaml` to specify:
* `owning_container`: Points to `CNT-*` (e.g. `CNT-EIDOS-CLI`).
* `owning_component`: Optional point to a specific `CMP-*` within that container.

=== 3.4 CLI Commands
* `eidos containers`: Lists all registered C4 Level 2 containers (`CNT-*`), their runtimes, container types, and package paths.
* `eidos components [container-id]`: Lists the C4 Level 3 in-process components (`CMP-*`) contained inside the specified container (or across all containers).

=== 3.5 Web Portal Dynamic C4 Explorer
The interactive C4 Explorer view now has crystal-clear semantics:
* **L1**: Renders `SYS-EIDOS-001` interacting with Actors and External Systems.
* Clicking into Eidos zooms into **L2 Containers**: Displays boxes for `CNT-EIDOS-CLI`, `CNT-EIDOS-CORE`, `CNT-EIDOS-MCP`, etc.
* Clicking on `CNT-EIDOS-CORE` zooms into **L3 Components**: Displays `CMP-SPEC-PARSER`, `CMP-SPEC-VALIDATOR`, `CMP-CONTEXT-SLICER`, etc.
* Clicking on any component opens the slide-over inspector displaying the exact `source_path` (L4 Code link).
