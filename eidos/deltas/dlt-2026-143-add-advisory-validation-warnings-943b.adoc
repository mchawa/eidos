= SpecDelta: Add Advisory Validation Warnings for Over-Scoped source_path Entries and Prose Symbol Drift
:toc: left

== Problem Statement
Two classes of living-spec drift currently pass `eidos validate` with zero signal:

1. **Unchecked `source_path` over-scoping**: `SpecValidator` only verifies that each `source_path` exists on disk, and `PublicSurfaceValidator` flattens all `source_paths()` into one symbol set. If a component lists an unrelated directory in `source_path` that contributes 0 symbols to `== Public Surface`, validation passes silently while `CMP-HTTP-TOPOLOGY-LINKER` and `CMP-INCREMENTAL-SYNC-ENGINE` attribute spurious `consumes_api` / `depends_on` edges to that component.
2. **No symbol verification outside `== Public Surface`**: `PublicSurfaceValidator` only inspects `== Public Surface` sections on active `CNT-*`/`CMP-*` specs; nonexistent code types/methods cited in other sections (`== Responsibility`, `== Internal Structure & Key Mechanisms`, `== Key Responsibilities & Collaborators`) go unnoticed.

At the same time, `ValidationReport` currently has no non-blocking `warnings` channel, and Eidos's own `CMP-*` specs legitimately include internal helper submodules in multi-entry `source_path` arrays (`DEC-ARCH-MODULAR-COMPONENT-COHESION`).

== Proposed Specification Changes
* **`CMP-DOMAIN-MODELS` (`src/eidos/core/spec/models.py`)**: Add `warnings: list[str]` to `ValidationReport` (non-blocking: `is_clean` remains `True` when only warnings exist).
* **`CMP-ARCHITECTURE-BOUNDARY-VALIDATOR` (`src/eidos/core/spec/surface_validator.py`) & `CMP-SPEC-VALIDATOR` (`src/eidos/core/spec/validator.py`)**:
  - Emit a warning when a multi-entry `CMP-*.source_path` includes a code-bearing **directory or standalone source file** (containing `>= 1` AST code file) contributing zero `== Public Surface` symbols with no intra-component import linkage to the rest of the component's `source_path` entries.
  - Emit a high-precision advisory warning for explicit code references (`PascalType.member`, `PascalType::member`, and explicit `func_name(...)` calls, skipping fenced code blocks, contrastive/deprecated clauses, entity IDs, file paths, and common builtins/stdlib calls — never flagging bare `PascalCase` product/framework words) in non-`== Public Surface` sections of active `CNT-*`/`CMP-*` specs that do not exist in the repository's AST symbol catalog (100% deterministic per `POL-004-ZERO-AI-CALL-DEPENDENCY`).
* **`CMP-DRIFT-DETECTOR` (`src/eidos/vcs/drift.py`, `src/eidos/vcs/report.py`) & `CMP-CLI-DRIFT-COMMANDS` (`src/eidos/cli/drift_commands.py`)**: Expose non-blocking `validation_warnings` on `DriftCheckResult`, Markdown drift summaries, and `eidos drift [--json]` terminal/JSON output (preserving exit code `0` when `is_clean` is `True`).
* **`CMP-CLI-SPEC-COMMANDS` (`src/eidos/cli/spec_commands.py`), `CTR-EIDOS-CLI`, `CMP-DOCS-USER-GUIDES` (`docs/guides/cli.md`)**: Surface `warnings` in `eidos validate` rich output and `--json` payload (preserving exit code `0` on warnings-only runs) and document `validation_warnings` in `eidos drift`.
* **`CNT-EIDOS-CORE` & `CAP-PROD-001`**: Record `DEC-CORE-ADVISORY-VALIDATION-WARNINGS` (`graduated_from: DLT-2026-143-ADD-ADVISORY-VALIDATION-WARNINGS-943B`, documenting the non-blocking `ValidationReport.warnings` channel and rejecting blocking hard-errors on zero-contribution internal helper files and noisy bare-`PascalCase` prose matching) and add `INV-VALIDATION-ADVISORY-WARNINGS`.
