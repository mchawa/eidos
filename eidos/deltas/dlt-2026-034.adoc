= SpecDelta: Persistent AST Symbol Locations and Recursive Multi-Package Code Indexing
:toc: left

NOTE: Split from the original DLT-2026-034. The diff-aware specification coverage gate now lives in DLT-2026-039.

== Problem Statement

1. **Discarded symbol coordinates.** `ASTIndexer.extract_symbols()` yields `CodeSymbol(file_path, line_start, line_end, signature, parent_symbol)`, but every sync path in [`ArchitecturalIndex`](file:///home/MTS/marwan.chawa/WS/eidos/src/eidos/core/graph_index.py) only writes `(symbol, entity_id, kind)` into `symbol_mappings`. As a result:
   * [`find_symbol()`](file:///home/MTS/marwan.chawa/WS/eidos/src/eidos/core/graph_index.py#L1444) can only report the owning *spec* (`file_path` = spec path), never the defining source file/line.
   * [`get_repo_map()`](file:///home/MTS/marwan.chawa/WS/eidos/src/eidos/core/graph_index.py#L1479) re-reads and re-parses every `source_path` file on every call.
   * Deleted or edited source files leave stale AST rows behind (deletion only removes the `source_path` row).
2. **Secondary package paths not dirty-tracked.** `entities.package_path` stores only `pkg_list[0]`, and `is_dirty()` reads that column. `is_dirty()` always walks `src/`, `tests/`, `test/`, so the gap is limited to secondary package directories *outside* those roots (e.g. `frontend/`, `packages/*`).
3. **Non-recursive, gated package indexing.** Package directories are indexed only `if not all_modules` and with non-recursive `glob()`. Any container declaring a single inline component never indexes its unclaimed files or subdirectories.

== Architectural & Behavioral Mutations

=== 1. `code_symbols` table (CMP-GRAPH-STORAGE)
[source,sql]
----
CREATE TABLE IF NOT EXISTS code_symbols (
    id            INTEGER PRIMARY KEY,
    file_path     TEXT    NOT NULL,             -- repo-relative source path
    symbol        TEXT    NOT NULL,
    kind          TEXT    NOT NULL,             -- class | function | method | interface | ...
    parent_symbol TEXT    NOT NULL DEFAULT '',
    line_start    INTEGER NOT NULL,
    line_end      INTEGER NOT NULL,
    signature     TEXT    NOT NULL DEFAULT '',
    entity_id     TEXT    NOT NULL,             -- owning CNT-* (same attribution as symbol_mappings today)
    component_id  TEXT    NOT NULL DEFAULT '',  -- CMP-* when claimed by an explicit component source_path
    UNIQUE (file_path, kind, parent_symbol, symbol, line_start)
);
CREATE INDEX IF NOT EXISTS idx_code_symbols_symbol ON code_symbols(symbol);
CREATE INDEX IF NOT EXISTS idx_code_symbols_file   ON code_symbols(file_path);
----
* Files declared by several entities (e.g. two containers' components pointing at one module) keep a row set per declaring entity, so every declarer keeps its symbol mappings and `find-symbol` locations; `is_primary = 1` marks the resolved primary owner and is the only row set rendered by `repo-map`. Dropping a declaration prunes only that entity's rows.
* `symbol_mappings` schema and its ~35 positional inserts are **unchanged**. `resolve_symbol_or_path()`, drift mapping and the `inferred_path` post-pass keep working without modification.
* `code_symbols` is written with explicit column lists only.

=== 2. Cache schema versioning (CMP-GRAPH-STORAGE)
* Persist `metadata.schema_version`. On connect, if it is missing or differs from `ArchitecturalIndex.SCHEMA_VERSION` (bumped `1.0.0` → `2.1.0`), drop all tables and rebuild. This is safe because `index.db` is a derived cache.
* Coordination: DLT-2026-035 also adds tables to `index.db`. Whichever delta lands second bumps `SCHEMA_VERSION` again and reuses this mechanism.

=== 3. Invalidation (CMP-INCREMENTAL-SYNC-ENGINE)
* Whenever a code file is (re)indexed: `DELETE FROM code_symbols WHERE file_path = ?`, then insert fresh rows.
* When a code file is deleted: delete its `code_symbols` rows, and remove the matching AST rows (`class`/`function`/`method`/`interface`) from `symbol_mappings` only when no remaining `code_symbols` row for the same `(symbol, entity_id, kind)` exists.

=== 4. Queries
* **`find_symbol()`:** each match gains `location: {file, line_start, line_end, signature, parent_symbol}` (one match per definition), or `location: null` for non-AST matches (paths, test bindings, component refs). The existing keys, including `file_path` (spec path), are unchanged.
* **`get_repo_map()`:** builds `symbols_by_file` from `code_symbols` (`ORDER BY file_path, line_start`) as `CodeSymbol` instances and calls `generate_repo_map()` unchanged. It makes zero `extract_symbols()` calls and zero source reads when the index is warm.

=== 5. Multi-package tracking and recursive ownership (CMP-INCREMENTAL-SYNC-ENGINE)
* `is_dirty()` and the incremental owner fallback (currently `? LIKE entities.package_path || '%'`) read **all** entries from `symbol_mappings WHERE kind = 'package_path'`. `entities.package_path` keeps the first entry for display and FTS only.
* Per-spec sync only records `package_path` / `source_path` / `owned_path` declarations; it never indexes source files itself. A **global ownership post-pass** indexes every candidate file exactly once per sync (it runs only on forced syncs or when specifications were added, modified or deleted: code-only syncs index just the dirty files, so ownership cannot change without a spec change) then walks every package directory recursively. The walk uses `os.walk` with the same `excluded_dirs` pruning and test-file exclusion as `is_dirty()`, and assigns each unindexed code file an owner using this precedence:
  . exact component `source_path` match in **any** container (sets `component_id`);
  . highest `match_path_pattern()` score over `owned_path` globs;
  . longest `package_path` prefix across all entries of all containers.
* The result does not depend on the order specs are processed. Example: `src/eidos/core/graph_index.py` stays with `CNT-EIDOS-INDEX` (rule 1) even though it lies under `CNT-EIDOS-CORE`'s `src/eidos/core`.
