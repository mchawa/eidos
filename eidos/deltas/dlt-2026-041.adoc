= SpecDelta: Air-Gapped Portal Bundle with Embedded Mermaid, Fonts, and Asciidoctor.js Rendering
:toc: left

== Problem Statement

* `src/eidos/portal/frontend/index.html` loads Mermaid v10 from `cdn.jsdelivr.net` and fonts from `fonts.googleapis.com` / `fonts.gstatic.com`, while `package.json` already declares `mermaid ^12`. C4 diagrams therefore break in air-gapped environments, contradicting the CAP-EXP-001 promise of browsing "without compiling external frontend bundles" and the zero-fetch offline intent of `builder.py`.
* `AsciiDocRenderer.tsx` is a ~690-line line-by-line regex parser that fails on standard AsciiDoc blocks such as `[quote]` (used in `eidos/system.adoc`), definition lists, callouts, and complex tables.
* No invariant forbids remote subresources, so nothing caught the regression. `INV-PORTAL-ZERO-NODE-DEP` only covers the Node.js runtime.

== Architectural Mutations

* Drop all remote `<script>` / `<link>` tags from `index.html`; import `mermaid` from npm at the version pinned in `pnpm-lock.yaml`.
* Embed Geist and Geist Mono (latin woff2 subsets via `@fontsource`). `tokens.json` font stacks are unchanged; `Inter` / `JetBrains Mono` fall through to system fonts.
* Replace the regex renderer with `@asciidoctor/core` (`safe: 'secure'`), mapping `xref:` targets to in-portal spec navigation and keeping the INV-PORTAL-READING-ERGONOMICS typography.
* Keep the single-file Vite build (EXP-2026-003). `server.py` and `builder.py` keep consuming `PORTAL_HTML_TEMPLATE` unchanged, so `CTR-EIDOS-PORTAL` stays stable.
* `include::` is out of scope: a browser has no filesystem to resolve it, and no living spec currently uses it.

== Design Decisions

* **Asciidoctor.js over a hand-written AST parser:** it is the reference implementation's JS port and gives standards compliance without maintaining a parser. Cost: about 1 MB minified added to the bundle.
* **Inline bundling over separately served assets:** it keeps the server/builder contract and offline `file://` static sites working. Cost: the bundle grows from ~0.5 MB to a few MB. This is capped by an explicit size budget (see Verification Criteria) and should be revisited if the budget is exceeded.
* **New invariant instead of patching `INV-PORTAL-ZERO-NODE-DEP`:** "no Node.js at runtime" and "no remote subresources" are separate properties. Overloading the existing ID would silently change its meaning for EXP-2026-003 and applied deltas.

== Verification Criteria

* `tests/test_portal.py::test_portal_bundle_has_no_remote_subresources` (INV-PORTAL-AIR-GAPPED-BUNDLE): no `http(s)://` URL appears in any `src=`, `href=`, `@import`, or `url(...)` of `PORTAL_HTML_TEMPLATE`, ignoring XML namespace URIs and inert string literals such as React error links.
* `tests/test_portal.py::test_portal_bundle_size_budget`: `PORTAL_HTML_TEMPLATE` ≤ 5 MiB uncompressed.
* Frontend Vitest suite (build-time only, so INV-PORTAL-ZERO-NODE-DEP still holds): the renderer converts every `eidos/**/*.adoc` body with no raw-source fallback, and every Mermaid source emitted by `generator.py` for this repository passes `mermaid.parse()` with the bundled version.
* Existing `tests/test_portal.py` invariant tests (INV-PORTAL-INTERACTIVE-C4, INV-PORTAL-READING-ERGONOMICS, INV-PORTAL-C4-CONTAINER-HIERARCHY) pass.
* `eidos validate eidos && eidos drift --uncommitted` exits 0.
