= SpecDelta: Comprehensive PHP Language Support
:toc: left

== Problem Statement
PHP is already registered in the unified AST indexer, but registration does not
mean complete architectural support. Current extraction handles named class-like
declarations, functions, methods, basic imports and conventionally named tests.
The assessment preceding this proposal demonstrated the following gaps:

* Namespace changes are absent from public symbol identity; repeated short class
  names can collide and lose method ownership.
* Line-range ownership can misassociate declarations sharing a source line.
* Public magic methods and underscore-prefixed public methods are incorrectly
  treated as private.
* Public property types, constant values, enum cases and trait composition
  changes can escape structural API comparison.
* PHPUnit attribute/PHPDoc tests and Pest closures are not reliably discoverable
  for invariant bindings.

These are false-confidence risks for agents using PHP repo maps, dependency
graphs, Public Surface validation and spec-to-code drift enforcement.

== Scope and Compatibility

Comprehensive means *static architectural support*, not a PHP interpreter,
compiler, whole-program type checker or general-purpose PHP static analyzer.
The proposed syntax matrix targets PHP 7.4 through 8.5 source constructs relevant
to declarations, dependencies and tests. These are source-compatibility targets,
not a recommendation to deploy end-of-life PHP runtimes.

Grammar support must be established with fixtures against the installed
`ast-grep-py` parser. Cover typed properties (7.4); attributes, union types and
constructor promotion (8.0); enums, readonly properties and intersection types
(8.1); readonly classes and DNF types (8.2); typed class constants (8.3); property
hooks and asymmetric property visibility (8.4); and representative 8.5 syntax,
including expressions inside bodies and defaults that must not corrupt adjacent
declarations. Upgrade the existing parser dependency only if required and proven
compatible with the other supported languages. A grammar gap blocks the affected
coverage claim and completion of this delta; silently returning no symbols is not
evidence of support.

Keep existing CLI commands and JSON field shapes. Qualified identities are the
canonical PHP lookup and comparison keys; short names remain search aliases, not
an excuse to merge declarations. Preserve an existing short test binding only
when it resolves uniquely; ambiguous bindings require explicit qualification
and an actionable diagnostic. Non-PHP identity and binding behavior must remain
unchanged. Rebuild derived caches through the existing schema-version mechanism.

== Proposed Specification Changes

=== Symbol Identity, Ownership and Declaration Surfaces

* Track bracketed/unbracketed namespaces, the global namespace, multiple
  namespaces per file and namespace-relative names. Canonical examples are
  `App\Service\InvoiceService` and
  `App\Service\InvoiceService::issueInvoice`.
* Derive lexical parents from AST ancestry or exact source spans, not shared
  short names or line-only containment. Cover class/interface/trait/enum members,
  anonymous classes, nested declarations and multiple declarations on one line.
  Anonymous/local declarations must not become fabricated named public exports.
* Index functions, methods, classes, interfaces, traits, enums, properties,
  promoted properties, namespace/class constants and enum cases. Retain trait
  identity even if the common symbol-kind model uses an interface-like category.
* Follow PHP visibility, including default public methods, public `__construct`,
  `__invoke` and `_publicApi`. Index non-public members for navigation without
  marking them public. Protected members form a subclass API; private members
  do not form the externally visible surface. Model property read/write
  visibility separately where asymmetric visibility is present.
* Build deterministic declaration-level fingerprints for parameters, names
  relevant to named arguments, reference/variadic markers, defaults, nullable/
  union/intersection/DNF types, return types, modifiers, property hooks,
  inheritance, implemented interfaces, interface/abstract member requirements,
  trait `use`/`insteadof`/`as` adaptations, constant values and enum backing/cases.
  Include effective promoted properties and public trait adaptations. Changes
  to inherited/trait-provided API must remain attributable to their declaration
  and visible to dependency/blast-radius traversal, not require a PHP runtime.
* Attach PHPDoc and attributes to the correct declaration, including intervening
  comments and multiple attribute groups. Retain declaration metadata in
  deterministic summaries, but do not claim PHPDoc type inference. Formatting,
  ordinary prose-only PHPDoc edits and implementation-body edits must not create
  false API-signature changes.

=== Imports and Dependency Graphs

* Extract class, function and constant imports, aliases, grouped/mixed imports,
  fully qualified and namespace-relative references, plus `extends`,
  `implements` and trait composition references. Keep namespace import `use`
  distinct from closure captures and trait `use`.
* Resolve literal `include`, `include_once`, `require` and `require_once`,
  including statically evaluable `__DIR__`/`__FILE__` concatenation. Parse
  declarative Composer `autoload`/`autoload-dev` PSR-4, PSR-0, classmap and files
  mappings to connect local indexed files, with deterministic longest-prefix
  matching and declared component/container ownership.
* Read metadata only: never execute PHP, Composer commands, plugins, generated
  autoloaders or included files. Respect repository boundaries and existing
  source discovery/exclusion rules; do not scan dependencies merely because a
  mapping points into `vendor`. Dynamic includes, runtime aliases and external
  packages remain unresolved rather than generating guessed dependency edges.
* Changes to Composer mappings must invalidate affected dependency edges even
  if PHP source hashes have not changed. Cache rebuild and incremental sync must
  remove stale namespace identities, moved/deleted symbols and assertion edges.

=== PHPUnit, Pest and Invariant Traceability

* Discover PHPUnit public `test*` methods, `#[Test]` attributes (short, imported,
  aliased and fully qualified PHPUnit names), and legacy PHPDoc `@test` methods.
  Do not classify arbitrary attributes with the same short name as PHPUnit.
* Discover Pest `test` and `it` calls with literal titles and closure/arrow
  callbacks, including nested `describe` scopes and statically declared datasets.
  Calls inside strings/comments, hooks, providers and suite-only declarations
  must not become tests. Dynamic/generated titles remain outside guaranteed
  resolution and must not be accepted as an unrelated literal binding.
* Canonical bindings are `tests/PaymentTest.php::App\Tests\PaymentTest::testPay`
  for PHPUnit and `tests/PaymentTest.php::payments::captures payment` for
  `describe('payments', ...)` containing `it('captures payment', ...)`.
  A top-level Pest test uses `file.php::literal title`; use the literal title
  without injecting Pest's display-only `it ` prefix. Dataset instances bind to
  their declaration, not runtime-expanded names. Reject duplicate canonical
  identities within a file; never silently select the first matching test.
* Associate INV/POL tokens with the owning test's callback, directly attached
  comments/PHPDoc or title, not neighboring tests or suite-only comments.
  Retain existing unambiguous legacy binding aliases.
* Reject explicit statically disabled bindings, including Pest `skip`/`todo` and
  unconditional PHPUnit `markTestSkipped()`/`markTestIncomplete()` calls. Detect
  enclosing static suite disablement. Do not pretend to evaluate conditional runtime
  skips, environment requirements, dataset generation or framework execution.
* Use one shared discovery/identity implementation for indexing, validator and
  drift. Eidos checks static bidirectional traceability only; native CI remains
  responsible for executing tests and judging assertions.

=== Architectural Decisions and Specification Ownership

Keep implementation in the existing index, core-validation and VCS components;
no new container, component, CLI operation or PHP runtime dependency is proposed.
Declare the eight invariants above in their owning capabilities only when their
tests exist, each with the exact `test_binding` and an INV-ID reference in the
bound test. Existing personas, domain vocabulary and policies remain applicable;
there is no new user workflow, policy or UI contract.

Record `DEC-INDEX-PHP-STATIC-SEMANTICS` under `CNT-EIDOS-INDEX.decisions` during
implementation: extend the unified AST pipeline and static metadata resolution.
Reject regex-only declaration parsing because it loses lexical ownership, and
reject invoking PHP/Composer or adding a full semantic analyzer because it
executes untrusted project code or expands Eidos beyond architectural analysis.
Document the precise grammar/framework matrix and limitations in the owning
living specs and the existing user-facing language/binding documentation.
