= SpecDelta: Manifest-Tracked Plugin Uninstall, Non-Destructive Force Semantics, and Version-Pinned Hook Runner
:toc: left

== Problem Statement
`CMP-PLUGIN-INSTALLER` (`src/eidos/plugin/installer.py`) currently exhibits four safety and reproducibility flaws:

1. **Destructive Directory Removal on Uninstall**: `uninstall_plugin` (`installer.py:1335-1360`) calls `shutil.rmtree(root / ".codex")` for the `codex` target and `shutil.rmtree(root / ".github" / "plugin")` for `copilot`, destroying any non-Eidos configuration the user stored in those directories. Similarly, `uninstall_plugin --dest <dir>` (`lines 1062-1066`) runs `shutil.rmtree` on the entire `--dest` path.
2. **Ignored `force` Parameter & Unconditional Overwrites**: `install_plugin` (`line 837`) defaults `force: bool = True`, never reads `force` inside helper functions (`lines 107, 169`), and unconditionally overwrites `.aider.conventions.md` (`line 545`) and `.codex/rules.md` (`line 998`).
3. **Symlink Traversal at Destination**: `shutil.copy2` (`lines 139, 194`) follows destination symlinks without checking `dest.is_symlink()`.
4. **Unpinned `uvx` Hook Execution**: `_rewrite_hook_command_for_target_root` (`line 161`) rewrites hook commands to `uvx --from eidos-ai eidos ...` without pinning the installed package version, causing hook invocations to pull unpinned releases from PyPI.

== Proposed Specification & Engine Changes
1. **Manifest-Tracked Install & Uninstall**:
   - Write an installation manifest (`.eidos-manifest.json` storing relative paths and SHA-256 digests of installed files) during `eidos plugin install`.
   - On `eidos plugin uninstall`, delete only files recorded in the manifest (and prune empty Eidos-created subdirectories), never calling `shutil.rmtree` on shared parent directories (`.codex/`, `.github/plugin/`, or `--dest`).
2. **Safe Overwrite & Symlink Guards**:
   - Default `force=False` and require `--force` (or append/merge safely with backup) before overwriting pre-existing user files (`.aider.conventions.md`, `.codex/rules.md`).
   - Refuse to write through destination symlinks.
3. **Version-Pinned `uvx` Fallback**:
   - Pin `uvx --from eidos-ai==<version> eidos ...` using the active Eidos package version from `eidos.plugin.version`.
