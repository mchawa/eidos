= SpecDelta: Project-Agnostic Living Web Portal Views & C4 Context Diagram, Complete Portal & Design Subgraph Extraction, Modal TOC Scroll-Spy, and Frontend SPA Component Mapping
:toc: left

== Problem Statement

`CNT-EIDOS-PORTAL` (`src/eidos/portal/generator.py`, `src/eidos/portal/frontend/src/**`, `eidos/architecture/containers/portal.adoc`) and `CMP-DRIFT-DETECTOR` (`src/eidos/vcs/structural.py`) have four groups of defects:

1. **Hardcoded Eidos External Systems, Repository Paths & Entity IDs in Portal Generator and Frontend Views (`INV-ENGINE-GENERICITY` / `INV-FOREIGN-REPO-E2E` Violation)**:
   * `generator.py` (`_generate_c4_context_mermaid`, lines 621-652): Hardcodes `EXT_GIT["Git Repository & CI/CD..."]` and `EXT_IDE["AI IDEs & Coding Agents: Antigravity, Cursor, Claude Code"]` for **every project** instead of reading `c4_context.external_systems` from `system-architecture.adoc` or `system.adoc`.
   * `CatalogView.tsx` (lines 229-255): Groups design specs via hardcoded `s.path.includes("systems/core")` and `s.path.includes("web-portal")`. Any foreign repository using its own design system slug (e.g. `design/systems/acme/`) or client slug (e.g. `design/clients/mobile-app/`) has all its design specs dumped into a flat ungrouped list.
   * `DesignView.tsx` (lines 48-51 & 718): Hardcodes `"DS-CORE"` as the base design system ID and `"Core Systems (DS-CORE)"` in the UI badge instead of resolving the root design system (`!s.extends`) dynamically.
   * `ArchitectureView.tsx` (lines 233 & 267): Hardcodes `"Eidos"` and `"Complete Eidos Architecture"` instead of reading `data.system?.title`.
2. **Incomplete `get_portal_data` & `_generate_c4_component_mermaid` (`src/eidos/portal/generator.py`) and `_collect_design_subgraph` (`src/eidos/vcs/structural.py`)**:
   * `generator.py` (line 45): Only checks `elif doc_type == "product/system":`, ignoring `arch/system` (`eidos init --lite`).
   * `generator.py` (lines 244-256 & 330-355): Omits `product/policy` from `INV-*` invariant extraction and omits `product/domain`, `product/capability`, and `product/policy` from `DEC-*` decision extraction.
   * `generator.py` (lines 507-524): Hardcodes `design/systems/<slug>/tokens.json` instead of resolving `tokens.manifest` relative to `doc.file_path.parent`, and only reads `inheritance.extends` while ignoring top-level `extends_system`.
   * `generator.py` (lines 1140-1142): Calls `dep.upper().replace("-", "_")` on items of `dependencies.internal_containers` in `_generate_c4_component_mermaid`, crashing with `AttributeError` when an item is a dict (`{"id": "CNT-..."}`), unlike `_generate_c4_container_mermaid` (line 974) which handles dicts safely.
   * `structural.py` (`_collect_design_subgraph`, lines 524-566): Only reads top-level `extends_system` (missing `inheritance.extends`), singular `client` on `design/flow` (missing `clients: [...]` on `cross_client` flows), and singular `design_system` on `design/screen` (missing `supported_design_systems: [...]`).
3. **Portal Frontend UI Bugs in `SpecReader.tsx`, `HomeView.tsx`, and `DesignView.tsx`**:
   * `SpecReader.tsx` (lines 49-74): Attaches the TOC scroll-spy listener only to `document.getElementById("main-scroll")` (`<main>`), which does not scroll when `SpecReader` is opened inside the slide-over modal `Sheet` (`overflow-y-auto`).
   * `HomeView.tsx` (lines 36-44 & 164-175): Labels `inReviewCount + appliedCount` as `"Active SpecDeltas"` with subtitle `"${appliedCount} applied · ${proposedCount} proposed"`, contradicting `DeltasView.tsx` and excluding `proposed` deltas from the primary active count.
   * `DesignView.tsx` (lines 100-106): Filters flows strictly by `f.client === activeClient.id`, hiding `cross_client` flows (`FLOW-CLI-SERVE`) that have `client: ""` and `flow_type: "cross_client"`.
4. **Unmapped `src/eidos/portal/frontend/src` in `CNT-EIDOS-PORTAL` (`eidos/architecture/containers/portal.adoc`, lines 15-35)**:
   * No C4 Level 3 `CMP-*` component in `portal.adoc` includes `src/eidos/portal/frontend/src` in `source_path`.

== Proposed Specification Changes

1. **Data-Driven C4 Context Diagram & Project-Agnostic Frontend Views (`generator.py`, `CatalogView.tsx`, `DesignView.tsx`, `ArchitectureView.tsx`)**:
   * Pass `external_systems` from `system-architecture.adoc` (`c4_context.external_systems`) and `system.adoc` into `_generate_c4_context_mermaid`, omitting hardcoded `EXT_GIT` / `EXT_IDE` nodes when not declared in the project's specifications.
   * Group design systems and clients dynamically by path segments (`design/systems/<slug>/...` and `design/clients/<slug>/...`), resolve the base design system dynamically (`systems.find(s => !s.extends) ?? systems[0]`), and derive system titles from `data.system?.title`.
2. **Complete `get_portal_data` & `_collect_design_subgraph` (`src/eidos/portal/generator.py`, `src/eidos/vcs/structural.py`)**:
   * Support `arch/system`, extract `DEC-*` and `INV-*` across all owning spec types, resolve `tokens.manifest` relative to `doc.file_path.parent`, read `extends_system` and `inheritance.extends` in both `generator.py` and `structural.py`, traverse `clients[]` and `supported_design_systems[]` in `_collect_design_subgraph`, and normalize dict dependencies in `_generate_c4_component_mermaid`.
3. **Fix Modal TOC Scroll-Spy, Active Delta Metrics, Cross-Client Flow Rendering, and SPA Component Ownership**:
   * Resolve the nearest scrollable ancestor in `SpecReader.tsx` before falling back to `#main-scroll`, report in-flight vs applied deltas accurately in `HomeView.tsx`, render `cross_client` flows in `DesignView.tsx`, rebuild `assets/portal/bundle.html.gz`, and add `src/eidos/portal/frontend/src` to `CMP-PORTAL-ASSETS` `source_path` in `eidos/architecture/containers/portal.adoc`.
