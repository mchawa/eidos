= SpecDelta: Eliminate Unnecessary Index Lock Contention While Preserving Strict Freshness and Lock-Wait Diagnostics
:toc: left

== Problem Statement
Running `eidos drift`, `eidos doctor`, and `eidos validate` concurrently stalls silently on `eidos/.cache/index.db.lock` with no user feedback:

1. Opportunistic cache persistence (`save_spec_validation_cache` hitting SQLite's 10s `timeout=10.0` and `save_test_binding_cache` acquiring blocking `_advisory_db_lock`) introduces unnecessary contention even though callers already hold fresh disk-parsed results in memory.
2. Commands that legitimately must wait for a fresh synchronized graph (`sync_index`, dirty `evaluate_import_boundaries`, or initial schema DDL) block silently on `fcntl.flock(fd, LOCK_EX)` with no `stderr` lock-wait diagnostic identifying the lockfile and holder PID.

**Strict Freshness Guarantee**: Eidos must **never** return stale validation, boundary, or graph results by reading an outdated WAL snapshot while a dirty sync is still in progress. Because OS advisory locks (`fcntl.flock` / `msvcrt`) are automatically released by the kernel on process exit or crash, waiting cleanly with clear `stderr` holder-PID diagnostics avoids both stale verdicts and false timeouts during legitimate large-repo cold syncs.

== Proposed Specification Changes
* **`CMP-GRAPH-STORAGE` (`src/eidos/core/index/storage.py`, `src/eidos/core/index/graph_index.py`)**:
  - Record lock-holder metadata (PID + timestamp) in `index.db.lock` and emit a `sys.stderr` contention notice in `_advisory_db_lock` before kernel-blocking wait.
  - Make `save_spec_validation_cache` and `save_test_binding_cache` non-blocking (`non_blocking=True` + short SQLite timeout), skipping persistence cleanly when contended (zero staleness risk because live disk parsing already ran and subsequent runs always verify `(mtime_ns, sha256)`).
  - Allow `load_spec_validation_cache` / `load_test_binding_cache` to fall back cleanly to live disk parsing via `open_cache_connection(..., allow_ddl=False)` if `index.db` is missing or mid-DDL (100% fresh, never blocks).
* **`CMP-INCREMENTAL-SYNC-ENGINE` (`src/eidos/core/index/sync.py`)**: Emit a clear `sys.stderr` lock-wait notice (naming `index.db.lock` and holder PID, keeping `--json` stdout clean) when `sync_index` encounters contention, wait cleanly via kernel flock, and retain the post-lock `is_dirty()` re-check so waiting callers immediately reuse the newly committed fresh graph without duplicate indexing.
* **`CMP-ARCHITECTURE-BOUNDARY-VALIDATOR` (`src/eidos/core/spec/boundary_validator.py`) & `CMP-SPEC-VALIDATOR` (`src/eidos/core/spec/validator.py`)**: Guarantee strict freshness on `evaluate_import_boundaries` (never reading stale WAL snapshots when dirty) while eliminating unnecessary cache-write lock contention in `validate_directory`.
* **`CNT-EIDOS-INDEX` & `CAP-AGENT-002`**: Record `DEC-INDEX-STRICT-FRESHNESS-LOCK-DIAGNOSTICS` (`graduated_from: DLT-2026-141-ELIMINATE-EXCLUSIVE-INDEX-LOCK-53FD`, explicitly rejecting stale WAL snapshot reads, premature short timeouts, and lock removal) and add `INV-INDEX-FRESHNESS-AND-LOCK-DIAGNOSTICS`.

== Implementation Plan
1. **Holder-Aware Lock Wait & Non-Blocking Opportunistic Caches (`CMP-GRAPH-STORAGE`)**: Update `_advisory_db_lock` (holder PID metadata, `sys.stderr` wait notice before kernel-blocking wait, preserving thread re-entrancy and `INV-INDEX-SYNC-CLI-CONTROLS`), make `save_spec_validation_cache` and `save_test_binding_cache` non-blocking, and allow `load_*_cache` to fall back to live disk parsing when the DB is missing or mid-DDL (`src/eidos/core/index/storage.py`; `src/eidos/vcs/invariants.py` benefits via `save_test_binding_cache` with body-only; no spec mutation).
2. **Sync Contention Diagnostics (`CMP-INCREMENTAL-SYNC-ENGINE`)**: Update `sync_index` in `src/eidos/core/index/sync.py` to report the lockfile path and holder PID on `sys.stderr` when `contended` is true, wait cleanly until the writer finishes, and re-check `is_dirty()` after acquisition for strict freshness with zero redundant indexing.
3. **Strict-Freshness Boundary Evaluation & Validator (`CMP-ARCHITECTURE-BOUNDARY-VALIDATOR`, `CMP-SPEC-VALIDATOR`)**: Keep `evaluate_import_boundaries` (`src/eidos/core/spec/boundary_validator.py`) strictly fresh via `sync_index` (no stale WAL fallback) while `validate_directory` (`src/eidos/core/spec/validator.py`; `src/eidos/cli/spec_commands.py` and `src/eidos/cli/doctor_hook_commands.py` benefit via `CMP-SPEC-VALIDATOR` with no CLI changes) avoids cache-write stalls.
4. **Living Specs, Tests & Coverage (`POL-005-STATEMENT-TEST-COVERAGE`)**: Update `CMP-GRAPH-STORAGE`, `CMP-INCREMENTAL-SYNC-ENGINE`, `CMP-ARCHITECTURE-BOUNDARY-VALIDATOR`, `CMP-SPEC-VALIDATOR`, `CNT-EIDOS-INDEX` (`DEC-INDEX-STRICT-FRESHNESS-LOCK-DIAGNOSTICS`), and `CAP-AGENT-002` (`INV-INDEX-FRESHNESS-AND-LOCK-DIAGNOSTICS`). Add `tests/test_index_lock_contention.py::test_nonblocking_caches_strict_freshness_and_lock_wait_diagnostics` verifying: (a) opportunistic cache loads/writes never block on contended `index.db.lock` while returning fresh disk-validated results, (b) clean `validate` and `index status` do not block on `index.db.lock`, and (c) dirty `evaluate_import_boundaries` / `sync_index` waits until the writer releases, emits a `stderr` notice with holder PID without corrupting `--json` stdout, and detects the newly introduced violation with zero staleness, while maintaining `>90.0%` per-file statement coverage.
