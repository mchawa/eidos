= SpecDelta: Add Global Root -p/--path Option and Optional --design-system Flag on spec create
:toc: left

== Problem Statement
1. Coding agents operating in monorepos frequently pass `-p <subproject>/eidos` *before* subcommands (e.g. `eidos -p packages/api/eidos index status` or `eidos -p packages/api/eidos validate`), which previously failed because `-p` / `--path` was only registered per subcommand (and `validate` only accepted a positional argument).
2. `eidos spec create ui-component` and `eidos spec create client` always auto-selected the first `DS-*` design system in the catalog without an optional `--design-system` / `-d` flag to target a specific design system when a repository defines multiple design systems.

== Proposed Specification Changes
* **Global Root `-p` / `--path` (`CMP-CLI-APP`, `CMP-CLI-INIT-COMMAND`, `CMP-CLI-DOCTOR-HOOKS`, `CMP-CLI-PLUGIN-COMMANDS`, `CTR-EIDOS-CLI` `2.3.0`, `INV-MONOREPO-ROOT-CLI-AND-HOOK-ROUTING`)**: Register `--path` / `-p` on the root Typer callback (`main()`), propagate it via `get_global_cli_path()` in `src/eidos/cli/_shared.py` to every subcommand (including `plugin` via `_resolve_plugin_project_dir`, normalizing trailing `eidos/` to avoid split-brain), preserve explicit subcommand `--path`/`--project-dir`/positional `PATH` precedence, and regenerate `tests/fixtures/cli_command_tree.json`.
* **Optional `--design-system` / `-d` on `eidos spec create` (`CMP-CLI-SPEC-COMMANDS`, `CMP-LIFECYCLE-SCAFFOLDER`, `CMP-DESIGN-ENGINE`, `CAP-LIVING-SPEC-ENGINE`, `INV-SPEC-CREATE-DESIGN-SYSTEM-FLAG`, `CTR-EIDOS-CLI` `2.3.0`)**: Accept optional `--design-system` / `-d <DS-ID|path|slug>` on `eidos spec create`, sanitize and validate the slug and `DS-*` ID before directory creation in `build_design_spec` (preventing path traversal and orphan directories), and preserve automatic first-`DS-*` resolution when omitted.
* **User Documentation (`CMP-DOCS-USER-GUIDES`)**: Document both options in `docs/guides/cli.md` (with `src/eidos/cli/context_command.py` subproject-relative glob preservation as a body-only fix; no spec mutation).

== Implementation Plan
1. Add global `--path`/`-p` to `src/eidos/cli/main.py` and `get_global_cli_path()` / subcommand precedence to `src/eidos/cli/_shared.py`, plus fallbacks in `src/eidos/cli/init_command.py`, `src/eidos/cli/doctor_hook_commands.py`, `src/eidos/cli/plugin_commands.py`, and `src/eidos/cli/spec_commands.py` (plus subproject-relative glob preservation in `src/eidos/cli/context_command.py` — body-only; no spec mutation).
2. Add optional `--design-system` / `-d` to `src/eidos/cli/spec_commands.py`, `design_system: str | None = None` to `src/eidos/core/lifecycle/scaffolder.py`, and `_resolve_and_validate_design_system` to `src/eidos/core/lifecycle/design_engine.py`.
3. Regenerate `tests/fixtures/cli_command_tree.json`, update `docs/guides/cli.md`, co-evolve all affected living specs, add tests in `tests/test_monorepo_subprojects.py`, `tests/test_cli_json.py`, `tests/test_plugin.py`, and `tests/test_docs_sync.py`, and verify via `pytest`, `ruff`, `eidos delta verify`, `eidos delta apply`, and `eidos drift`.
