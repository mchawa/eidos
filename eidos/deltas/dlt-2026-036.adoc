= SpecDelta: Structured Architectural Decisions and Trade-Off Records Embedded in Living Specifications
:toc: left

== Problem Statement

Eidos strictly prohibits standalone Architecture Decision Records (`NO ADRs`) because chronological ADR folders inevitably rot into write-only graveyards detached from the components they govern. However, pure current-state specifications (`tech/container`, `tech/component`, `system/root`) lack a structured place to record **negative architectural knowledge**—specifically *why* a design was chosen and *which alternatives were evaluated and rejected*. Without this in-place context, developers and AI coding agents repeatedly propose designs (e.g., external vector databases, runtime LLM calls, co-located `src/` specs) that were already rejected for sound architectural reasons.

== Architectural & Behavioral Mutations

1. **In-Place `decisions` Schema Block (`system.schema.yaml`, `container.schema.yaml`, `component.schema.yaml`)**:
   * Introduce an optional `decisions` array in `system/root`, `tech/container`, and `tech/component` frontmatter:
     ```yaml
     decisions:
       - id: DEC-INDEX-SQLITE-WAL
         title: "Use Embedded SQLite WAL + FTS5 Instead of External Vector DB"
         decision: "Store the architectural knowledge graph and lexical index in local SQLite3 with WAL mode and FTS5 BM25."
         rationale: "Guarantees zero external runtime dependencies (Python stdlib), sub-2ms local queries, and 100% deterministic offline operation under POL-004."
         rejected_alternatives:
           - option: "ChromaDB / LanceDB Vector Store"
             reason_rejected: "Requires embedding model weights or external API calls, violating POL-004 and bloating installation size."
         graduated_from: EXP-2026-001
     ```
2. **Semantic Cross-Reference Validation (`validator.py`)**:
   * Enforce unique `DEC-*` IDs across the catalog.
   * When `graduated_from` is specified (`EXP-*` or `DLT-*`), validate that the referenced exploration or SpecDelta ID exists in the catalog.
3. **Knowledge Graph & Context Slicing Integration (`graph_index.py`, `context.py`)**:
   * Index `decisions[].title`, `decision`, `rationale`, and `rejected_alternatives` into `specs_fts` for `eidos index search`.
   * Surface owning container/component `decisions` (including rejected alternatives) in `eidos context` slices so AI coding agents respect historical trade-offs automatically.

== Verification Criteria

* Adding a `decisions:` block to `eidos/system.adoc` and `eidos/architecture/containers/index.adoc` passes `eidos validate eidos`.
* Referencing a non-existent `graduated_from: EXP-9999-999` triggers a `broken_references` error in `SpecValidator`.
* Running `eidos context --component CNT-EIDOS-INDEX --format json` includes the container's `decisions` and `rejected_alternatives` in the returned context slice.
