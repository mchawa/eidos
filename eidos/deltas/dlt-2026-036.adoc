= SpecDelta: Structured Architectural Decisions and Trade-Off Records Embedded in Living Specifications
:toc: left

== Problem Statement

Eidos strictly prohibits standalone Architecture Decision Records (`NO ADRs`) because chronological ADR folders inevitably rot into write-only graveyards detached from the components they govern. However, pure current-state specifications (`product/system`, `tech/architecture`, `tech/container`, `tech/component`) lack a structured place to record **negative architectural knowledge**—specifically *why* a design was chosen and *which alternatives were evaluated and rejected*. Without this in-place context, developers and AI coding agents repeatedly propose designs (e.g., external vector databases, runtime LLM calls, co-located `src/` specs) that were already rejected for sound architectural reasons.

== Architectural & Behavioral Mutations

=== 1. In-Place `decisions` Schema Block (`product/system.schema.yaml`, `tech/architecture.schema.yaml`, `tech/container.schema.yaml`, `tech/component.schema.yaml`)
* Introduce an optional `decisions` array in `product/system`, `tech/architecture`, `tech/container` (top-level and inline `components[]`), and `tech/component` frontmatter:
[source,yaml]
----
decisions:
  - id: DEC-INDEX-SQLITE-WAL
    title: "Use Embedded SQLite WAL + FTS5 Instead of External Vector DB"
    decision: "Store the architectural knowledge graph and lexical index in local SQLite3 with WAL mode and FTS5 BM25."
    rationale: "Guarantees zero external runtime dependencies (Python stdlib), sub-2ms local queries, and 100% deterministic offline operation under POL-004."
    rejected_alternatives:
      - option: "ChromaDB / LanceDB Vector Store"
        reason_rejected: "Requires embedding model weights or external API calls, violating POL-004 and bloating installation size."
    graduated_from: EXP-2026-001
----

=== 2. Semantic Cross-Reference Validation (`CMP-SPEC-VALIDATOR` in `src/eidos/core/spec/validator.py`)
* Enforce unique `DEC-*` IDs across the specification catalog in `_validate_cross_references()` and register `"DEC-"` in `ENTITY_ID_PREFIXES`.
* Validate `graduated_from` (`EXP-*` or `DLT-*`) via `x-eidos-ref` (`target_types: [product/exploration, delta/mutation]`, `prefixes: [EXP-, DLT-]`) in `_validate_schema_references()`.

=== 3. Knowledge Graph & Tiered Context Slicing (`CMP-TIERED-CONTEXT-COMPRESSOR` in `src/eidos/core/index/graph_index.py`, `CMP-CONTEXT-SLICER` in `src/eidos/core/workspace/context.py`)
* Index `decisions[].id`, `title`, `decision`, `rationale`, and `rejected_alternatives` into `specs_fts` for `eidos index search`.
* Surface owning container/component `decisions` in `eidos context` slices while respecting `CAP-AGENT-001` token budgets:
  ** `anchor` tier (~1,500 tokens): compact `DEC-*` summary (`title`, `decision`, and rejected option names).
  ** `guardrails` (~3,500 tokens) and `deep` (~8,000 tokens) tiers: full `rationale` and `rejected_alternatives` (`option` + `reason_rejected`).

== Verification Criteria

* Adding a `decisions:` block to `eidos/system.adoc`, `eidos/architecture/system-architecture.adoc`, and `eidos/architecture/containers/index.adoc` passes `eidos validate eidos`.
* Duplicate `DEC-*` IDs or referencing a non-existent `graduated_from: EXP-9999-999` triggers a `broken_references` error in `SpecValidator`.
* Running `eidos context --component CNT-EIDOS-INDEX --format json` includes the container's `decisions` and `rejected_alternatives` in the returned context slice, and Markdown rendering formats them according to the requested tier.
* `eidos validate eidos && eidos drift --uncommitted` exits 0.
