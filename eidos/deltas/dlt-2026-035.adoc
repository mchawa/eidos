= SpecDelta: Incremental SQLite Caching for Specification Validation and Static Invariant Verification
:toc: left

== Problem Statement

Every time `eidos drift` or `eidos hook drift` (`PostInvocation` and `Stop` hooks) runs, `detect_drift()` (`src/eidos/vcs/drift.py`) performs two full $O(N)$ repository crawls from scratch:

1. `SpecValidator.validate_directory(eidos_dir)` (`src/eidos/core/spec/validator.py`) parses every `.adoc` file in `eidos/` and runs Draft 2020-12 JSON Schema validation against YAML schemas on disk.
2. `extract_invariants_and_verify()` and `detect_orphan_invariants()` (`src/eidos/vcs/drift.py`) crawl all test files (`tests/**/*test*.py`, `*.spec.ts`, `*_test.go`, etc.) via `collect_polyglot_test_files()`, eagerly read every test file from disk, and run `ASTIndexer.list_test_functions()` + `extract_test_bindings()` on every file.

In repositories with hundreds of specifications and thousands of test files, running this uncached on every agent turn (`PostInvocation`) introduces multi-second latency.

== Architectural & Behavioral Mutations

=== 1. Schema Versioning & Cache Tables (`CMP-GRAPH-STORAGE` in `src/eidos/core/index/graph_index.py`)
* Bump `ArchitecturalIndex.SCHEMA_VERSION` from `"2.1.0"` (set by `DLT-2026-034`) to `"2.2.0"` and add `"spec_validation_cache"` and `"test_binding_cache"` to `_MANAGED_TABLES` (`src/eidos/core/index/graph_index.py`).
* Create `test_binding_cache (file_path TEXT PRIMARY KEY, mtime_ns INTEGER NOT NULL, sha256 TEXT NOT NULL, has_fixture INTEGER NOT NULL DEFAULT 0, functions_json TEXT NOT NULL, bindings_json TEXT NOT NULL, file_tokens_json TEXT NOT NULL)` in `eidos/.cache/index.db`.
* Create `spec_validation_cache (file_path TEXT PRIMARY KEY, mtime_ns INTEGER NOT NULL, sha256 TEXT NOT NULL, schema_hash TEXT NOT NULL, doc_json TEXT NOT NULL, schema_errors_json TEXT NOT NULL)` in `eidos/.cache/index.db`.

=== 2. Incremental Test Binding & Function Cache (`CMP-DRIFT-DETECTOR` in `src/eidos/vcs/drift.py`)
* Discover polyglot test file paths and stat `(st_mtime_ns)` without eagerly reading file contents when `eidos/.cache/index.db` has a matching `(file_path, mtime_ns)` entry in `test_binding_cache`.
* On cache miss (`mtime_ns` mismatch or missing row), read the test file, compute `sha256`, extract `list_test_functions()`, `extract_test_bindings()`, `# eidos:fixture`-filtered function tokens, and file-level `INV-*`/`POL-*` tokens, and upsert the row into `test_binding_cache`.
* Prune deleted test files from `test_binding_cache` automatically.
* Both `_verify_single_invariant()` (including `file::func` and `file`-only bindings) and `detect_orphan_invariants()` (including `# eidos:fixture` / `// eidos:fixture` exclusions) operate directly on the cached structures without re-reading or AST-parsing unchanged test files.

=== 3. Incremental Spec Validation Cache (`CMP-SPEC-VALIDATOR` in `src/eidos/core/spec/validator.py`)
* Compute a deterministic `schema_hash` across loaded bundled schemas in `SpecValidator`.
* When `SpecValidator.validate_directory()` runs, check `spec_validation_cache` by `(rel_path, mtime_ns, schema_hash)`. On a hit, hydrate the `SpecDocument` (`file_path`, `doc_id`, `doc_type`, `schema_ref`, `frontmatter`, `errors`) and `schema_errors` without re-parsing YAML or running `Draft202012Validator`.
* Always execute dedicated `components[].ref` discovery and full in-memory cross-document reference validation (`_validate_cross_references()`, `_validate_semantic_references()`, `_validate_source_and_contract_paths()`) across the assembled catalog so cross-file link or source-path breakage is caught immediately.

== Coordination & Sequencing
* **Depends on `DLT-2026-040`**: Requires `_extract_mutation_target` to prefer `target_invariant_id` for `patch_invariant` and component-level digest verification.
* **Coordinates with `DLT-2026-034`**: Bumps `ArchitecturalIndex.SCHEMA_VERSION` (`2.1.0` -> `2.2.0`) and extends `_MANAGED_TABLES`.

== Verification Criteria

* A warm invocation of `eidos drift` when zero `.adoc` or test files have changed executes zero `ASTIndexer.list_test_functions()` / `extract_test_bindings()` calls and zero redundant `Draft202012Validator` runs.
* Modifying a test file (including files with `# eidos:fixture`), deleting a test file, or modifying a `.adoc` specification immediately invalidates its cache entry via `mtime_ns` / `sha256` and produces identical validation and invariant coverage results to a cold run.
* Modifying a bundled `.schema.yaml` invalidates `spec_validation_cache` via `schema_hash`.
* `eidos validate eidos && eidos drift --uncommitted` exits 0.
