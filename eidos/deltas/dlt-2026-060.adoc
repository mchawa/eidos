= SpecDelta: Unify YAML Frontmatter Delimiter Parsing and Adopt Typed Pydantic Domain Models Across Core Engines
:toc: left

== Problem Statement

`CNT-EIDOS-CORE` and `CNT-EIDOS-VCS` currently suffer from two parser and data-model fragilities:

1. **Three Divergent Frontmatter Regexes**:
   * `src/eidos/core/spec/parser.py` (line 10) uses `re.compile(r"^---\s*$", re.MULTILINE)`.
   * `src/eidos/vcs/structural.py` (line 54) uses `re.compile(r"\A---[ \t]*\n(.*?)\n---[ \t]*(?:\n|\Z)", re.DOTALL)`.
   * `src/eidos/core/lifecycle/catalog.py` (line 83) uses `re.compile(r"^---\s*\n(.*?)\n---\s*(?:\n|$)(.*)", re.DOTALL)`.
   * If a YAML block scalar (`|` or `>`) inside frontmatter contains an indented `---` (or if an AsciiDoc body contains a `---` thematic break), `parser.py`, `structural.py`, and `catalog.py` split the document differently.
2. **Underutilized Pydantic Domain Models (`CMP-DOMAIN-MODELS`)**:
   * `src/eidos/core/spec/models.py` defines `FrontmatterModel`, `DecisionModel`, and `InvariantModel`, and `SpecDocument.as_model()` exposes them.
   * However, downstream engines (`validator.py`, `delta_engine.py`, `sync.py`, `drift.py`, `generator.py`) ignore `as_model()` and manipulate raw `dict[str, Any]` with hundreds of defensive `isinstance(..., dict)` checks.

== Proposed Specification Changes

1. **Single Canonical Frontmatter Parser (`CMP-SPEC-PARSER` in `src/eidos/core/spec/parser.py`)**:
   * Implement a single `split_frontmatter_and_body(content: str)` and `dump_spec_document(frontmatter: dict[str, Any], body: str)` in `parser.py` that requires the opening `---` delimiter at the start of the document (`\A`) and only closes frontmatter on an unindented column-0 `---` line.
   * Reuse `split_frontmatter_and_body` in `src/eidos/vcs/structural.py` and `src/eidos/core/lifecycle/catalog.py`.
2. **Typed Pydantic Domain Models (`CMP-DOMAIN-MODELS` in `src/eidos/core/spec/models.py`)**:
   * Expand `FrontmatterModel` subclasses / typed accessors for `ContainerSpec`, `ComponentSpec`, `CapabilitySpec`, `ContractSpec`, `PolicySpec`, and `DeltaSpec` so core engines can consume normalized, strongly typed fields via `doc.as_model()`.
