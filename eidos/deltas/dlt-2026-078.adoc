= SpecDelta: Knowledge Graph Container & Inline-Component Invariant Indexing, AST Symbol FTS5 Projection, and Anchored Graph Traversal
:toc: left

== Problem Statement

Line-by-line inspection of `CNT-EIDOS-INDEX` (`src/eidos/core/index/sync.py`, `src/eidos/core/index/query.py`, `src/eidos/core/index/context.py`) and `eidos/explorations/exp-2026-006.adoc` identified three indexing and retrieval gaps:

1. **Container & Inline-Component `invariants:` Are Never Indexed in SQLite (`src/eidos/core/index/sync.py`, lines 682-698 & 1081-1156; `src/eidos/core/index/context.py`, lines 567-593)**:
   * In `sync_index()` and `rebuild_spec_edges()`, `invariants` are extracted for `product/capability`, `product/policy`, and promoted `tech/component` specs, **but never for `tech/container`** (neither top-level `fm.get("invariants", [])` nor inline `comp_entry.get("invariants", [])`).
   * As a result, any invariant declared on a `CNT-*` container or inline `CMP-*` component is omitted from `entities` (`type = 'invariant'`), `specs_fts`, `edges` (`asserts` / `bound_to`), and `symbol_mappings` (`test_binding`).
   * Similarly, in `build_tiered_context_slice()` (`src/eidos/core/index/context.py`, lines 567-593), when a child `INV-*` is matched directly (`direct_inv_ids`), `context.py` promotes `capability_id` and `policy_id` into `matched_capabilities` / `matched_policies`, **but never promotes `component_id` or `container_id` into `matched_components`**.
2. **Primary AST `code_symbols` Are Never Projected into `specs_fts.symbols` (`src/eidos/core/index/sync.py`, lines 1230-1245 & 1340-1342; noted in `eidos/explorations/exp-2026-006.adoc`, lines 82 & 384)**:
   * `specs_fts.symbols` currently only indexes inline component names from YAML frontmatter (`[m.get("name", "") for m in fm.get("components", [])]`), **not** the persisted AST `code_symbols` (`class`, `function`, `interface`, `struct`, `enum`) or `tech/component` `interfaces.provides` signatures owned by each container/component.
   * Consequently, querying `eidos context --task` or `eidos index search` by a class or function name that does not appear verbatim in spec prose fails to match the owning container/component via `specs_fts.symbols`.
3. **Unanchored SQLite `LIKE` Suffix & Cycle Checks + Missing `source_path` in `check_index_dirty` (`src/eidos/core/index/sync.py`, lines 475 & 1392-1426; `src/eidos/core/index/query.py`, line 166)**:
   * `sync.py` lines 1398 & 1420 use `OR rel_path LIKE '%' || edges.target_id` without a `/` boundary, allowing a bare filename like `system.adoc` or `domain.adoc` to match the wrong file (`eidos/design/systems/core/system.adoc` before `eidos/system.adoc`).
   * `sync.py` line 475 (`check_index_dirty`) queries `WHERE kind IN ('package_path', 'test_binding')` and omits `'source_path'`, so standalone `source_path` files outside `src/` aren't dirty-checked until already in `indexed_files`.
   * `query.py` line 166 (`execute_k_hop_traversal`) checks `AND gw.path NOT LIKE '%' || next_id || '%'` without `->` delimiter boundaries, so if `CNT-EIDOS-CORE-2` is already in `gw.path`, it falsely blocks visiting `CNT-EIDOS-CORE`.

== Proposed Specification Changes

1. **Index Top-Level Container & Inline Component Invariants and Promote Owning Components (`src/eidos/core/index/sync.py`, `src/eidos/core/index/context.py`)**:
   * In `sync_index()` and `rebuild_spec_edges()`, extract both top-level `tech/container` `invariants` and inline `components[].invariants` into `entities` (`type = 'invariant'`, storing `container_id` and `component_id` in `data_json`), `specs_fts`, `edges` (`asserts` from both the container and inline component ID, plus `bound_to`), and `symbol_mappings` (`test_binding`).
   * In `build_tiered_context_slice()`, when a directly matched invariant (`direct_inv_ids`) carries `component_id` or `container_id`, promote its owning component/container into `matched_components` so it is retained as a primary anchor alongside `matched_capabilities` and `matched_policies`.
2. **Project Primary AST `code_symbols` & Component API Signatures into `specs_fts.symbols` (`src/eidos/core/index/sync.py`)**:
   * Include `interfaces.provides` signature identifiers in `tech/component` `specs_fts.symbols`, and after code indexing / ownership reconciliation in `sync_index()`, refresh `specs_fts.symbols` for each owning container/component with its persisted primary AST `code_symbols` (`class`, `function`, `interface`, `struct`, `enum`) and their de-compounded sub-tokens (`compound_identifier_subtokens`).
3. **Anchor SQLite `LIKE` Path & Cycle Checks and Include `source_path` in `check_index_dirty` (`src/eidos/core/index/sync.py`, `src/eidos/core/index/query.py`)**:
   * Anchor `rebuild_spec_edges` path resolution to `OR rel_path LIKE '%/' || edges.target_id` with `ORDER BY length(rel_path) ASC`.
   * Include `'source_path'` in `check_index_dirty()` (`WHERE kind IN ('package_path', 'source_path', 'test_binding')`).
   * Anchor `execute_k_hop_traversal()` cycle prevention with `'->' || gw.path || '->' NOT LIKE '%->' || next_id || '->%'`.
