= SpecDelta: Enforce Canonical Contract Protocol Enum with Conditional Custom Protocol
:toc: left

== Problem Statement
`assets/schemas/v1/tech/contract.schema.yaml` currently validates `protocol` only as `#/$defs/non_empty_string` (`pattern: \S`). Because any non-empty string passes schema validation, typos or ad-hoc spellings (such as `grpc`, `rest`, `http`, `open_api`, or `proto3`) pass `eidos validate` silently while bypassing `ContractParityValidator` and `CMP-HTTP-TOPOLOGY-LINKER`. Meanwhile, maintaining redundant runtime aliases (`rest_openapi`, `http_json`, `grpc_proto`) creates unnecessary ambiguity in specs, docs, and portal rendering.

== Proposed Specification Changes
* **`CNT-EIDOS-CORE` (`assets/schemas/v1/tech/contract.schema.yaml`, `eidos/architecture/containers/core.adoc`)**:
  - Restrict `protocol` to a strict canonical 10-value enum: `openapi`, `rest_http`, `protobuf`, `graphql`, `asyncapi`, `json_schema`, `json_rpc_stdio`, `python_protocol`, `cli_args`, and `other`.
  - Add optional `custom_protocol` (`#/$defs/non_empty_string`) governed by Draft 2020-12 `if/then/else`: required when `protocol == "other"`, forbidden whenever `protocol` is any standard enum value.
  - Record `DEC-CORE-CANONICAL-CONTRACT-PROTOCOL-ENUM` (`graduated_from: DLT-2026-151-ENFORCE-CANONICAL-CONTRACT-PROTOCOL-9342`, rejecting open free-text `protocol` strings, inline `other:<name>` compound strings, and redundant runtime alias sprawl).
* **`CMP-DOMAIN-MODELS`, `CMP-CONTRACT-PARITY-VALIDATOR`, `CMP-SPEC-VALIDATOR`, `CMP-HTTP-TOPOLOGY-LINKER`**: Add `FrontmatterModel.custom_protocol`, remove redundant `rest_openapi`/`http_json`/`grpc_proto` alias keys so runtime dispatch matches the canonical schema enum 1:1, and treat `protocol: other` as explicitly custom (no parity check).
* **`CTR-EIDOS-PORTAL`, `CMP-PORTAL-GENERATOR`, `CMP-PORTAL-ASSETS`**: Migrate `CTR-EIDOS-PORTAL` from `http_json` to `rest_http`, add `"REST HTTP"` display formatting, and render `custom_protocol` when `protocol == "other"` across Mermaid diagrams and React views.
* **`CNT-EIDOS-PLUGIN`, `CMP-DOCS-CORE-CONCEPTS`, `CMP-DOCS-USER-GUIDES`, `CAP-PROD-001`**: Sync `eidos-spec/SKILL.md`, `docs/concepts/schema-glossary.md`, `docs/concepts/how-eidos-works.md`, `docs/concepts/architectural-index.md`, `docs/guides/cli.md`, and `INV-CONTRACT-PROTOCOL-SCHEMA-SYNC`.
