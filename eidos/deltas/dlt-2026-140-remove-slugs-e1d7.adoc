= SpecDelta: Remove Slugs, Raw IDs, and Technical Jargon Across the Living Web Portal UI
:toc: left
:icons: font
:sectnums:

== Problem Statement

Auditing the Living Web Portal frontend (`src/eidos/portal/frontend/src/`) and backend payload/diagram synthesizers (`src/eidos/portal/generator.py` and `src/eidos/portal/mermaid.py`) reveals pervasive raw slugs, internal identifiers, literal Markdown backticks, raw repository paths, leaking native tooltips/placeholders, and internal framework jargon across every visible screen:

1. **Raw Entity ID Slugs as Primary UI Headlines, Badges, Tooltips & Dropdown Labels**:
   * Cards, list rows, modal subtitles, dropdown `<option>` items, filter pills, native `title="..."` tooltips, and command palette results lead with raw prefixed IDs (`SYS-EIDOS-001`, `DOM-EXPERIENCE-PORTAL`, `CAP-EXP-001`, `POL-001-GIT-SOURCE-OF-TRUTH`, `PER-SOFTWARE-ENGINEER`, `INV-PORTAL-LIVE-DRIFT-SSE`, `DEC-PORTAL-HASH-ROUTING`, `CNT-EIDOS-PORTAL`, `CMP-PORTAL-ASSETS`, `CTR-EIDOS-PORTAL`, `DS-CORE`, `CLT-WEB-PORTAL`, `SCR-PORTAL-HOME`, `UIC-PORTAL-SHELL`, `FLOW-PORTAL-EXPLORATION`, `DLT-2026-132-HARDEN-WEB-D1D8`, `EXP-2026-006`) instead of human titles.
   * `BusinessView.tsx` prints the internal screen ID `SCR-PORTAL-BUSINESS` verbatim in the page banner.
   * `DesignView.tsx` strips filenames to uppercase or kebab-case slugs (`PORTAL-HOME`, `living-web-portal`) for client screens/capabilities, prints `DS-CORE` / `DS-BASE` in tabs and typography previews, and uses `Surface Dark BG` / `Surface Light BG` abbreviations.
   * `App.tsx` renders the raw route key (`activeTab`) in uppercase monospace (`HOME`, `BUSINESS`, `DELTAS`, `CATALOG`) in the sticky top header breadcrumb instead of the human view name.
   * `generator.py` sets every synthesized invariant's `title` to its raw `INV-*` ID and sets `source_type` to raw slug strings such as `policy (POL-001-GIT-SOURCE-OF-TRUTH)`.
2. **Raw Schema Type Slugs, `snake_case`/`kebab-case` Enum Tokens & CSS Colon Prefixes**:
   * `CatalogView.tsx` displays raw schema slugs (`product/capability`, `tech/container`, `design/ui-component`, `delta/mutation`) in the type filter `<select>`, branch summary cells, and every row badge, alongside all-caps `VALID`/`INVALID` and ASCII tree characters (`├──`, `└──`).
   * `ArchitectureView.tsx` displays raw `container_type` (`web_app`, `cli_app`) and `protocol` (`http_json`, `cli_args`, `python_protocol`) values directly in badges.
   * `DesignView.tsx` renders raw `category` (`data_display`, `data-display`), raw variant slugs (`focused-prose`, `high-contrast-dark`), raw `snake_case` layout slot keys (`hero_archetype_banner`, `hero_stat_grid`), raw `flow_type` (`client_internal`, `cross_client`), and CSS pseudo-class colon prefixes (`:loading`, `:populated`, `:mobile_drawer_open`, `:section_active`).
   * `BusinessView.tsx` displays raw `archetype` (`human_architect`, `ai_agent`), `severity` (`blocking`), and `category` values, while `DeltasView.tsx` displays raw `in_review` and `enabler` values.
3. **Literal Backticked Prefix Noise, Tooltips, Placeholders & Unnecessary Technical Jargon**:
   * JSX text strings across `BusinessView.tsx`, `ArchitectureView.tsx`, `DesignView.tsx`, `DeltasView.tsx`, and `ExplorationsView.tsx` contain literal backtick characters rendered verbatim in the browser: `` (`DOM-*`) ``, `` (`CAP-*`) ``, `` (`POL-*`) ``, `` (`PER-*`) ``, `` (`INV-*`) ``, `` (`CTR-*`) ``, `` (`CNT-*`) ``, `` (`DEC-*`) ``, `` (`DLT-*`) ``, `` (`EXP-*`) ``, `` (`DS-*`) ``, `` (`CLT-*`) ``, `` (`UIC-*`) ``, `` (`SCR-*`) ``, `` (`FLOW-*`) ``, `` (`tokens.json`) ``, `` (`tokens.spacing`) ``, `` (`tokens.border.radius`) ``, `` (`tokens.typography.font_family`) ``, and `` (`mermaid: stateDiagram-v2`) ``.
   * Internal engineering and methodology jargon clutters headlines, descriptions, tooltips, placeholders, and error/loading banners across all views: `DDD Strategic Layer`, `Domain-Driven Design (DDD) Bounded Contexts`, `Arc42/C4`, `C4 Level 1/2/3`, `Whitebox`, `1–2 Hop Graph BFS`, `W3C DTCG`, `Recursive W3C Token Tree Explorer`, `JTBD`, `POL-002 Traceability`, `POL-002 Verified`, `SSE Live Stream`, `Schema Conformance`, `Multi-Level Hierarchy`, `Zero ADR Policy`, `Direct Mode` / `Planned Mode (SpecDeltas)`, `Target VCS Branch`, `git checkout ...`, raw JSON `expect:` dumps, `Synthesizing Living Specifications...`, `Mermaid rendering error:`, `AsciiDoc rendering failed.`, `Search specifications (CMD+K)`, `Search specifications, C4 components, invariants (CMD+K)...`, `Search specifications by ID, title, or path...`, and `Filter by ID, title, branch, intent...`.
4. **Raw Filesystem Paths & Pytest Bindings in User-Facing Cards, Tooltips & Readers**:
   * `SpecReader.tsx`, `CatalogView.tsx`, `BusinessView.tsx`, `DeltasView.tsx`, `ExplorationsView.tsx`, `ArchitectureView.tsx`, `DesignView.tsx`, and `HomeView.tsx` surface raw `.adoc` paths (`eidos/domains/experience-portal/capabilities/living-web-portal.adoc`), empty-state directory paths (`eidos/design/systems/`, `tokens.json`), raw `source_path` arrays, raw `pytest` test bindings (`tests/test_portal.py::test_...` both visibly and in `title` tooltips), and an `"Inspect Raw YAML / JSON Frontmatter"` raw JSON dump toggle.
5. **Raw Slugs Inside Generated Mermaid Diagrams (`src/eidos/portal/mermaid.py`)**:
   * C4 Level 1–3, Screen State, and Flow Mermaid diagrams emitted by `src/eidos/portal/mermaid.py` embed raw `SYS-*`, `CNT-*`, `CMP-*`, `CTR-*`, `CLT-*` IDs, raw `web_app`/`cli_app` container types, raw Python/TS file paths, raw `snake_case` state names (`mobile_drawer_open`), and raw `.adoc` filename stems (`[portal-home]`) directly inside visible SVG node labels.

== Proposed Specification Changes

=== 1. Centralized Human-First Presentation Layer & React Context (`CMP-PORTAL-ASSETS`, `DEC-PORTAL-HUMAN-FIRST-PRESENTATION`)
Introduce `src/eidos/portal/frontend/src/lib/presentation.ts` as the single source of truth for human-readable UI formatting and entity-title resolution:

* **`EntityLabelProvider` & `useEntityLabels()` Context**: Mounted once in `App.tsx` around the shell and command palette so every view, modal, `SpecReader`, `AsciiDocRenderer`, and `CommandDialog` resolves entity titles automatically without prop-drilling, while keeping `renderAsciiDoc()` in `src/eidos/portal/frontend/src/lib/asciidoc.ts` pure (preserving `asciidoc.test.ts` unchanged).
* **`buildEntityLabelIndex(data: PortalData)` & `resolveEntityTitle(ref, index)`**: Indexes every spec, domain, capability, policy, persona, invariant, decision, container, internal component, contract, design system, client, screen, UI component, flow, delta, and exploration by canonical ID and repo-relative `.adoc` path. Resolves any cross-reference to its clean human title (never printing raw IDs or `.adoc` filenames); if an unindexed slug is encountered, strips known entity prefixes (`SYS-`, `DOM-`, `CAP-`, `POL-`, `PER-`, `INV-`, `DEC-`, `CNT-`, `CMP-`, `CTR-`, `DS-`, `CLT-`, `SCR-`, `UIC-`, `FLOW-`, `DLT-`, `EXP-`) and formats to Title Case.
* **Curated Enum & Token Formatters**:
  * `formatTabLabel(tab)`: `home` → `Overview`, `business` → `Business & Domains`, `architecture` → `Architecture`, `deltas` → `Changes`, `explorations` → `Explorations`, `catalog` → `Catalog`, `design` → `Design Systems`.
  * `formatSpecType(type)`: maps all 16 schema types to clean nouns (`product/system` → `System Overview`, `product/domain` → `Domain`, `product/capability` → `Capability`, `product/policy` → `Policy`, `product/persona` → `Persona`, `product/exploration` → `Exploration`, `tech/architecture` → `Architecture`, `tech/container` → `Container`, `tech/component` → `Component`, `tech/contract` → `Interface Contract`, `design/system` → `Design System`, `design/client` → `Client App`, `design/screen` → `Screen`, `design/ui-component` → `UI Component`, `design/flow` → `User Flow`, `delta/mutation` → `Change Proposal`).
  * `formatContainerType(raw)`: `web_app` → `Web App`, `cli_app` → `CLI App`, `frontend_spa` → `Web App`, `mobile_app` → `Mobile App`, `desktop_app` → `Desktop App`, `library` → `Library`, `service` → `Service`, `database` → `Database`, `plugin` → `Plugin`, `worker` → `Background Worker` (fallback: `humanizeToken`).
  * `formatProtocol(raw)`: `http_json` → `HTTP JSON`, `cli_args` → `CLI`, `python_protocol` → `Python API`, `openapi` → `OpenAPI`, `graphql` → `GraphQL`, `protobuf` → `Protobuf`, `json_schema` → `JSON Schema`.
  * `formatStatus(raw)`: `proposed` → `Proposed`, `in_review` → `In Review`, `approved` → `Approved`, `applied` → `Applied`, `rejected` → `Rejected`, `archived` → `Archived`, `in_progress` → `In Progress`, `adopted` → `Adopted`, `discarded` → `Discarded`, `active` → `Active`, `draft` → `Draft`, `planned` → `Planned`, `deprecated` → `Deprecated`, `retired` → `Retired`.
  * `formatDeltaKind(raw)`: `feature` → `Feature`, `enabler` → `Improvement`, `bug` → `Bug Fix`.
  * `formatFlowType(raw)`: `client_internal` → `Single-Client Flow`, `cross_client` → `Cross-Client Flow`, `omnichannel` → `Cross-Client Flow`.
  * `formatSeverity(raw)`: `blocking` → `Mandatory`, `warning` → `Warning`, `advisory` → `Advisory`.
  * `humanizeToken(raw)`: converts `snake_case`, `kebab-case`, and dotted keys into Title Case while preserving well-known acronyms (`UI`, `API`, `CLI`, `HTTP`, `JSON`, `SQL`, `AI`, `KPI`).
  * `humanizeInvariantTitle(inv)`: derives a concise readable title from an invariant's explicit title or humanized slug (never returning a raw `INV-*` ID).
* **Invisible Internal ID Retention**: Canonical IDs remain strictly internal in `/api/data`, `window.location.hash` (`#/<tab>/<id>`), DOM navigation hooks (`data-c4-entity`, `data-spec-ref`), stable component-ID-derived Mermaid node IDs, and hidden `searchText` strings in `CommandDialog` and view search filters so bookmarking, click navigation, and typing an ID into search continue working seamlessly.
