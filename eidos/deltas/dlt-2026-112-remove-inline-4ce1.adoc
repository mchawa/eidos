= SpecDelta: Remove Inline Components and SpecDelta Mutation Parent
:toc: left

== Problem Statement
Eidos previously supported a dual-mode C4 Level 3 component representation: components (`CMP-*`) could either be embedded inline inside a parent container's `components:` YAML frontmatter array (`tech/container`) or promoted to standalone `tech/component` files under `eidos/architecture/components/<slug>.adoc` via `eidos spec component promote` / `eidos spec component inline`.

Supporting both inline and standalone components introduced widespread dual-path complexity across the entire architecture:

1. **Schema & Model Duplication**: `assets/schemas/v1/common/defs.yaml` maintained `#/$defs/inline_component` shared between `container.schema.yaml` (`components[]`) and `component.schema.yaml`, while `FrontmatterModel` carried `InlineComponentModel` alongside top-level component fields.
2. **SpecDelta `mutations[].parent` Indirection**: Because inline components (and invariants) lacked standalone document identity or required container disambiguation, `delta.schema.yaml` and `DeltaMutationModel` carried an extra `parent` field (`mutations[].parent`), requiring `_check_structural_subtarget_precondition`, `_find_inline_component_dict`, and dual `(target, parent)` loops across `SpecValidator`, `DeltaEngine`, `AuditEngine`, `IncrementalSyncEngine`, `GraphTraversalEngine`, and `DriftDetector`.
3. **Graph Index & Query Dual-Pathing**: `IncrementalSyncEngine` (`sync.py`) had to synthesize virtual `tech/component` entity rows and `symbol_mappings` (`kind = 'component_id'`, `kind = 'module_name'`) from container frontmatters, while `query.py` (`_resolve_inline_component_node`, `execute_fts_query`, `execute_k_hop_traversal`, `execute_incoming_references`) and `context.py` (`_cap_binds_matched_inline_comp`) maintained separate branches for inline vs. standalone components.
4. **Obsolete Promotion/Inlining Plumbing**: `src/eidos/cli/component_commands.py` (`CMP-CLI-COMPONENT-COMMANDS`) and `promote_component` / `inline_component` / `_mutate_frontmatter_components` in `scaffolder.py` and `catalog.py` existed solely to shuttle components back and forth between container YAML frontmatters and `eidos/architecture/components/`.

== Proposed Specification Changes

=== 1. Standalone-Only C4 Level 3 Components (`tech/component`)
* **Living Catalog Migration First (`eidos/architecture/`)**:
  - Before removing the promotion machinery and inline schema definitions, promote all 40 active `CMP-*` components across `CNT-EIDOS-CORE`, `CNT-EIDOS-CLI`, `CNT-EIDOS-INDEX`, `CNT-EIDOS-PORTAL`, `CNT-EIDOS-PLUGIN`, `CNT-EIDOS-VCS`, and `CNT-EIDOS-DOCS` into standalone `eidos/architecture/components/<slug>.adoc` specifications with `container: CNT-*`, keeping narrative component responsibility solely in the `== Responsibility` AsciiDoc body section (`DEC-SCHEMA-PROSE-IN-BODY-AND-AST-EDGES`).
  - Remove `CMP-CLI-COMPONENT-COMMANDS` (`src/eidos/cli/component_commands.py`), remove `components:` from all 7 container frontmatters, and remove the duplicated `== Arc42 Section 5.2 / C4 Level 3: Internal Building Blocks` tables from all 7 container specifications.
* **Schemas (`assets/schemas/v1/`)**:
  - Remove `#/$defs/inline_component` from `assets/schemas/v1/common/defs.yaml`.
  - Remove the `components` property from `assets/schemas/v1/tech/container.schema.yaml` and `assets/schemas/v1/tech/container.template.adoc`.
  - Make `assets/schemas/v1/tech/component.schema.yaml` self-contained with explicit `properties` (`type`, `id`, `title`, `container`, `status`, `version`, `domain`, `source_path`, `invariants`, `decisions`) and `additionalProperties: false` (moving `responsibility` out of YAML frontmatter into the `== Responsibility` AsciiDoc body section).
* **Catalog, Index Ownership Precedence & Schema Cleanup**:
  - Simplify `_build_spec_catalog_with_invariants` (`catalog.py`), `query_spec_catalog_in_db` (`query.py`), and `ArchitecturalIndex.get_spec_catalog` (`graph_index.py`) from a 3-tuple `(specs_by_id, container_components, invariant_map)` to a 2-tuple `(specs_by_id, invariant_map)`.
  - In `_CodeOwnershipResolver` (`sync.py`), evaluate standalone `tech/component` (`CMP-*`) `owned_path` claims before `tech/container` (`CNT-*`) fallback so source files bind to their most specific `CMP-*` owner first.
  - Drop the redundant `component_id` column from `code_symbols` in `storage.py` and `query.py` alongside bumping `SCHEMA_VERSION` to `"2.17.0"`.
* **CLI Surface (`CTR-EIDOS-CLI`, `CMP-CLI-SPEC-COMMANDS`)**:
  - Delete `src/eidos/cli/component_commands.py`, unmount `eidos spec component` (`promote` / `inline`) from `spec_app` in `src/eidos/cli/spec_commands.py`, and update `tests/fixtures/cli_command_tree.json`.
  - Authoring a component uses the standard `eidos spec create component <CMP-ID> --title "<Title>"` and `eidos spec delete <CMP-ID>` commands.

=== 2. Removal of `mutations[].parent` from SpecDelta (`delta/mutation`)
* **Schema & Models**:
  - Remove `parent` from `mutations.items.properties` in `assets/schemas/v1/delta/delta.schema.yaml` and `assets/schemas/v1/delta/delta.template.adoc`.
  - Remove `parent: str | None = None` from `DeltaMutationModel` in `src/eidos/core/spec/models.py`.
  - Strip legacy `parent:` entries from existing SpecDelta files under `eidos/deltas/` and `eidos/deltas/archive/` so the entire repository validates cleanly under `additionalProperties: false`.
* **Validator, DeltaEngine, AuditEngine, Index & Drift**:
  - Remove `mutations.parent` cross-reference checks and the `operation == "add" and target.startswith("INV-") requires parent` rule in `SpecValidator` (`src/eidos/core/spec/validator.py`).
  - Remove `parent` normalization, `_find_inline_component_dict`, and `_check_structural_subtarget_precondition` from `src/eidos/core/lifecycle/delta_engine.py`.
  - Remove `parent` extraction from `AuditEngine._extract_targets_and_tokens` (`src/eidos/core/lifecycle/audit.py`), `rebuild_spec_edges` (`src/eidos/core/index/sync.py`), `compute_delta_impact_in_db` (`src/eidos/core/index/query.py`), and `detect_drift` (`src/eidos/vcs/drift.py`).

== Implementation Plan

1. **Promote Existing Inline Components & Clean SpecDeltas (`eidos/architecture/`, `eidos/deltas/`)**:
   - Promote all 40 active `CMP-*` inline components across all 7 `CNT-*` containers to standalone `eidos/architecture/components/<slug>.adoc` specifications (while existing promotion tooling is still intact), delete `CMP-CLI-COMPONENT-COMMANDS`, and remove `components:` from all 7 `CNT-*` container frontmatters.
   - Strip legacy `parent:` fields from existing SpecDelta files in `eidos/deltas/` and `eidos/deltas/archive/`.
2. **Schemas & Templates (`assets/schemas/v1/`)**:
   - Remove `inline_component` from `assets/schemas/v1/common/defs.yaml`.
   - Remove `components` from `assets/schemas/v1/tech/container.schema.yaml` and `assets/schemas/v1/tech/container.template.adoc`.
   - Define standalone component properties directly in `assets/schemas/v1/tech/component.schema.yaml`.
