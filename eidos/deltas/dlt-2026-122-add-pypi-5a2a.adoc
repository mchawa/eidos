= SpecDelta: Add PyPI CLI Update Check to eidos doctor
:toc: left
:icons: font
:sectnums:

== Problem Statement

`eidos doctor` (`src/eidos/cli/doctor_hook_commands.py`) currently verifies five local workspace and installation dimensions:

1. **CLI Binary on `PATH`** (`checks.cli_binary`)
2. **Git Repository** (`checks.git_repository`)
3. **Living Specifications** (`checks.living_specs`)
4. **SQLite Knowledge Graph** (`checks.knowledge_graph_index`)
5. **Agent Plugin Status** (`checks.agent_plugin` — comparing installed `.agents/plugins/eidos` manifest version against the locally bundled `eidos` package version)

However, `eidos doctor` only checks whether the project's installed agent plugin matches the *currently installed* `eidos-ai` CLI package; it never checks whether the installed `eidos-ai` CLI package itself is outdated relative to the latest published release on PyPI (`https://pypi.org/pypi/eidos-ai/json`). As a result, developers running an older global `uv tool` or `pip` installation of `eidos-ai` are not informed when a newer release of Eidos is available.

== Proposed Specification Changes

1. **PyPI CLI Version Check Helper (`CMP-PLUGIN-INSTALLER`, `src/eidos/plugin/version.py`)**:
   * Define `PYPI_PACKAGE_JSON_URL = "https://pypi.org/pypi/eidos-ai/json"`.
   * Introduce `check_cli_update_status(current_version: str | None = None, pypi_url: str = PYPI_PACKAGE_JSON_URL, timeout: float = 2.0) -> dict[str, Any]` in `src/eidos/plugin/version.py`:
     - Resolves `installed_raw = (current_version or getattr(eidos, "__version__", "0.2.0")).strip()` and normalizes it via `normalize_to_semver(installed_raw)`.
     - Validates `pypi_url.startswith(("https://", "http://"))` (rejecting non-HTTP schemes like `file://`), queries `pypi_url` using Python stdlib `urllib.request.urlopen` (`urllib.request.Request(pypi_url, headers={"Accept": "application/json", "User-Agent": f"eidos-ai/{installed_raw}"})`, `timeout=timeout`), and parses the JSON response via `orjson.loads` to extract `data["info"]["version"]`.
     - Compares normalized `installed_semver` and `latest_semver` using `compare_semver(installed_semver, latest_semver)`:
       * `cmp < 0`: `status = "update_available"`, `update_available = True`, `upgrade_command = "uv tool upgrade eidos-ai"`, `status_text = f"Update available: v{installed_raw} -> v{latest_version} (Run 'uv tool upgrade eidos-ai' or 'pip install -U eidos-ai')"`.
       * `cmp == 0`: `status = "up_to_date"`, `update_available = False`, `upgrade_command = None`, `status_text = f"Up to date (v{installed_raw})"`.
       * `cmp > 0`: `status = "newer"`, `update_available = False`, `upgrade_command = None`, `status_text = f"Ahead of latest PyPI release (v{installed_raw} > v{latest_version})"`.
     - Gracefully catches `(urllib.error.URLError, TimeoutError, OSError, ValueError, KeyError, orjson.JSONDecodeError)` (and skips live network I/O when `EIDOS_NO_UPDATE_CHECK=1` is set or during unmocked `PYTEST_CURRENT_TEST` runs) and returns `status = "offline"`, `latest_version = None`, `update_available = False`, `upgrade_command = None`, `ok = True`, `status_text = f"Unable to reach PyPI (v{installed_raw} installed)"`.

2. **Non-Blocking Diagnostic Integration in `eidos doctor` (`CMP-CLI-DOCTOR-HOOKS`, `src/eidos/cli/doctor_hook_commands.py`)**:
   * Call `cli_update = check_cli_update_status()` in `doctor_cmd`.
   * Populate `checks["cli_update"]` in the `--json` payload:
+
[source,json]
----
{
  "ok": true,
  "status": "update_available",
  "installed_version": "0.20.0",
  "latest_version": "0.20.1",
  "update_available": true,
  "upgrade_command": "uv tool upgrade eidos-ai"
}
----
   * Render a `"CLI Update Check"` row in the Rich terminal table (`Eidos Environment & Workspace Doctor`):
     - `status in ("up_to_date", "newer")`: Status `[bold green]PASS[/bold green]`, Details `cli_update["status_text"]`.
     - `status == "update_available"`: Status `[bold yellow]WARN[/bold yellow]`, Details `cli_update["status_text"]`.
     - `status == "offline"`: Status `[dim]SKIPPED[/dim]`, Details `cli_update["status_text"]`.
   * Preserve non-blocking advisory behavior: `checks["cli_update"]["ok"]` is always `True` and `overall_ok` is not gated on `cli_update`, ensuring `eidos doctor` exits with code `0` when all workspace health checks pass—even when a newer PyPI release exists or when running in an offline/air-gapped CI environment.

3. **Architecture, Contract, Documentation & Capability Governance (`CNT-EIDOS-CLI`, `CTR-EIDOS-CLI`, `CMP-DOCS-USER-GUIDES`, `CNT-EIDOS-DOCS`, `CAP-AGENT-001`)**:
   * Record `DEC-CLI-DOCTOR-UPDATE-CHECK` in `CNT-EIDOS-CLI` (`eidos/architecture/containers/cli.adoc`) documenting the stdlib `urllib.request` PyPI query, 2-second timeout, and non-blocking advisory `WARN`/`SKIPPED` design.
   * Update `CTR-EIDOS-CLI` (`eidos/architecture/contracts/cli.adoc`, version `1.1.0`) and `docs/guides/cli.md` (`CMP-DOCS-USER-GUIDES`, `CNT-EIDOS-DOCS`) to document `checks.cli_update` and the PyPI update notification in `eidos doctor`.
   * Bump `CAP-AGENT-001` (`eidos/domains/agent-intelligence/capabilities/agent-adapter.adoc`) to `1.9.0`, add `CMP-CLI-DOCTOR-HOOKS` and `CMP-PLUGIN-INSTALLER` to `technical.components`, and bind `INV-DOCTOR-UPDATE-CHECK` to `tests/test_plugin.py::test_cli_doctor_update_check`.
