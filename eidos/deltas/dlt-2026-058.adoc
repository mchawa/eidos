= SpecDelta: FTS5 Stop-Word Filtering, Incremental Spec Edge Sync, and Progressive Context Budget Compression
:toc: left

== Problem Statement

The embedded SQLite knowledge graph and tiered context generator (`CNT-EIDOS-INDEX`: `src/eidos/core/index/query.py`, `src/eidos/core/index/sync.py`, `src/eidos/core/index/context.py`) have three retrieval and synchronization bottlenecks:

1. **FTS5 Stop-Word Query Explosion (`build_fts_match_query`, `query.py` lines 68-81)**:
   * `build_fts_match_query` splits the user's natural-language `--task` string and joins every token with `OR` using prefix wildcards (`"term"*`) without filtering English stop words (`the`, `in`, `and`, `for`, `to`, `of`, `with`).
   * A prompt like `"Fix the drift error in the index and update tests"` produces `"fix"* OR "the"* OR "drift"* OR "error"* OR "in"* OR "and"* OR "update"* OR "tests"*`, matching virtually every document in the database and diluting BM25 ranking.
2. **Global Spec Edge Wipe on Single-Spec Edit (`rebuild_spec_edges`, `sync.py` lines 508-518)**:
   * Whenever even a single `.adoc` file changes (`spec_updates`), `sync_index` calls `rebuild_spec_edges`, which deletes all specification edges globally and re-parses `frontmatter_json` for every entity in SQLite.
3. **Repeated Full Serialization & Blind `.pop()` in Token Budgeting (`_enforce_token_budget`, `context.py` lines 225-271)**:
   * `_enforce_token_budget` checks `_exceeds_budget` in a `while` loop that re-serializes both `self.to_markdown()` and `self.to_json(indent=2)` on every iteration while popping entire `invariants` and `policies` before compressing verbose prose fields on surviving entities.

*(Note: Polyglot test file discovery and AST-verified `has_test_coverage` reconciliation in `sync_index` were already resolved directly in `src/eidos/core/index/sync.py`.)*

== Proposed Specification Changes

1. **Stop-Word Filtering & Two-Phase FTS5 Retrieval in `CMP-FTS-QUERY-ENGINE` (`src/eidos/core/index/query.py`)**:
   * Filter common English stop words (`_FTS_STOP_WORDS`) and single-character tokens in `build_fts_match_query` (falling back to unfiltered tokens only if every token in the query is a stop word).
   * Boost exact entity ID matches (`CNT-*`, `CMP-*`, `CAP-*`, `INV-*`, `CTR-*`, `POL-*`, `DOM-*`, `DEC-*`) and phrase/AND matches before falling back to `OR` prefix wildcards.
2. **Scoped Incremental Edge Updates in `CMP-INCREMENTAL-SYNC-ENGINE` (`src/eidos/core/index/sync.py`)**:
   * Update `rebuild_spec_edges` to accept `updated_doc_ids: set[str] | None = None`. On incremental single-spec edits where no entity ID was deleted or renamed, delete and rebuild outgoing spec edges only for `source_id IN updated_doc_ids` (plus any previously unresolved target edges).
3. **Progressive Field Compression & Incremental Token Accounting in `CMP-TIERED-CONTEXT-COMPRESSOR` (`src/eidos/core/index/context.py`)**:
   * In `_enforce_token_budget`, first compress verbose multi-sentence `description` / `rationale` / `details` fields on non-primary entities down to compact 1-line summaries before dropping `invariants` or `policies`, and compute token deltas incrementally before a single final serialization check.
