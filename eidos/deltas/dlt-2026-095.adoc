= SpecDelta: Remove Stateful delta_baselines Table and Memoize Git Baseline Resolution
:toc: left

== Problem Statement
1. **Stateful Exception in Derived Cache (`delta_baselines`)**: Every table in `eidos/.cache/index.db` (`src/eidos/core/index/storage.py`) is purely derived from the repository files on disk except `delta_baselines`, which forced `ensure_cache_schema` to maintain a special-case exemption (`if table != "delta_baselines"`) during schema version rebuilds and violated the principle that `.cache/index.db` is disposable local state (`POL-001`).
2. **Redundant Full-Catalog I/O on `eidos delta create`**: `_snapshot_delta_baselines` walks the entire living specification catalog, reads and SHA-256 hashes every spec file on disk, and writes 200–400 rows into SQLite on every `create_delta` invocation, even though `create_delta` already records `vcs.base_commit` in the SpecDelta frontmatter.
3. **Repeated Subprocess & Parse Overhead in `_resolve_git_baseline_sha`**: During `verify_delta_mutations`, `_resolve_git_baseline_sha` runs `git log --diff-filter=A` even when `vcs.base_commit` is already present in frontmatter, and spawns repeated `git show <rev>:<rel_target>` subprocesses when multiple inline `CMP-*` or `INV-*` mutations target the same container or capability specification.

== Proposed Specification Changes
* **`CMP-GRAPH-STORAGE` (`CNT-EIDOS-INDEX`)**:
  - Bump `SCHEMA_VERSION` from `"2.6.0"` to `"2.7.0"`.
  - Remove `"delta_baselines"` from `_MANAGED_TABLES` and `_CACHE_SCHEMA_DDL`.
  - Remove the `if table != "delta_baselines"` retention special-case from `ensure_cache_schema` and drop any legacy `delta_baselines` table during version migration.
* **`CMP-DELTA-ENGINE` (`CNT-EIDOS-CORE`)**:
  - Remove `_snapshot_delta_baselines` (and its call in `create_delta`), `_check_or_record_baseline_sha`, and SQLite `delta_baselines` queries in `_lookup_existing_baseline_sha`.
  - Optimize `_resolve_git_baseline_sha` to prioritize `vcs.base_commit` before invoking `git log --diff-filter=A` and memoize resolved candidate revisions and `(rev, rel_target)` Git blob contents across a verification pass.
* **`CAP-PROD-002` & `INV-DELTA-VERIFY-MODIFICATION-EVIDENCE` (`DOM-SPEC-ENGINE`)**:
  - Update the invariant rule and capability prose to reflect stateless Git-native baseline verification (`vcs.base_commit` / Git history via `_resolve_git_baseline_sha`) alongside declarative `expect` post-conditions.
