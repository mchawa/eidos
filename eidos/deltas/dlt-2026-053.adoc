= SpecDelta: Strict Base Git Reference Validation and Merge-Base Diff Resolution Without Silent Fallbacks
:toc: left

== Problem Statement
`get_git_diff_files` and `_get_file_versions` (`_git_show_text`) in `src/eidos/vcs/diff.py` and `src/eidos/vcs/drift.py` (`lines 149-186, 1045-1062`) have three Git diff resolution flaws that undermine CI gating:

1. **Silent Fallback to `--uncommitted` on Invalid or Missing `--base`**:
   - When `--base <ref>` is explicitly supplied (e.g., `eidos drift --base origin/main` in CI) and `git rev-parse --verify` fails (due to a shallow clone without `origin/main` or a misspelled ref), `get_git_diff_files` (`drift.py:168, 186`) silently falls back to `get_git_diff_files(repo_root, uncommitted=True)`.
   - On a clean CI runner checkout, `uncommitted=True` sees zero modified files and exits `0` ("Verification Passed!").
2. **2-Dot Diff Fallback on Empty 3-Dot Diff (`drift.py:171-182`)**:
   - `git diff --name-only <base>...<head>` returns `returncode == 0` with empty stdout when `<head>` has zero changes since branching from `<base>`.
   - Because `if lines:` (`line 175`) treats empty stdout as a failure, execution falls through to `git diff --name-only <base> <head>` (2-dot diff), which includes all upstream commits merged into `<base>` after the branch was created—causing false-positive drift failures.
3. **Mismatched Base Tip vs. Merge-Base File Contents (`drift.py:1061`)**:
   - While the file list is computed via 3-dot merge-base diff (`base...HEAD`), `_get_file_versions` (`_git_show_text`) reads the old file content from the tip of `base` (`git show base:path`) rather than the merge-base SHA.

== Proposed Specification & Engine Changes
1. **Fail-Closed `--base` Resolution**:
   - When `base_ref` is explicitly provided by the caller, verify it via `git rev-parse --verify` and resolve `merge_base = git merge-base <base_ref> <head_ref>`; raise an explicit error (and exit non-zero in CLI) if either fails rather than falling back to `uncommitted=True`.
2. **Preserve Valid Empty 3-Dot Diffs**:
   - When `git diff --name-only <merge_base> <head_ref>` succeeds with `returncode == 0`, return `lines` directly (even when empty `[]`) without falling back to a 2-dot diff against `<base_ref>`.
3. **Consistent Merge-Base Content Comparison**:
   - Pass the resolved `merge_base` SHA to `_get_file_versions` (`_git_show_text`) so old file versions match the exact commit used to compute the diff file list.
