= SpecDelta: Polyglot AST/Diff Parity, Unified SQLite Baselines & Git Enumeration, Weighted Context Slicing, and Lossless YAML Mutations
:toc: left

== Problem Statement

This SpecDelta addresses four foundational engine issues (#6, #7, #8, and #9):

1. **Issue #6 — Polyglot Code Extension Mismatch (`diff.py` vs. `ast_indexer.py`)**:
   `analyze_git_diff` (`src/eidos/vcs/diff.py`) classifies `.c`, `.cpp`, `.h`, `.cs`, `.rb`, `.php`, `.swift`, `.vue`, and `.svelte` as structural code files, whereas `LANGUAGE_MAP` (`src/eidos/core/index/ast_indexer.py`) only supports Python, TS/JS, Rust, Go, Java, and Kotlin. Because `_has_structural_ast_change` returns `True` whenever `ext not in LANGUAGE_MAP`, comment-only or function-body-local edits in C/C++, C#, Ruby, PHP, Swift, Vue, or Svelte unconditionally trigger structural drift.

2. **Issue #7 — Unmanaged `delta_baselines`, Full-Repo `os.walk`, and Uncached Catalog Scans**:
   * `_snapshot_delta_baselines` and `_check_or_record_baseline_sha` (`delta_engine.py`) open raw `sqlite3.connect(db_path)` connections without `open_cache_connection` (skipping WAL pragmas and `busy_timeout`), and `delta_baselines` is omitted from `_MANAGED_TABLES` in `storage.py`.
   * `_load_or_update_test_binding_cache` (`invariants.py`) and `_scan_and_classify_references` (`audit.py`) execute full `os.walk(repo_root)` filesystem traversals instead of using `get_tracked_files(repo_root)`, risking severe latency spikes on repositories with large gitignored directories not in the hardcoded exclusion set.
   * `_build_spec_catalog_with_invariants` (`catalog.py`) performs an uncached `eidos_dir.rglob("*.adoc")` + YAML parse on every call.

3. **Issue #8 — Context Slicing Hub Explosion, FTS `OR`-Dilution, and Token Underestimation**:
   * `execute_k_hop_traversal` (`query.py`) traverses all edges bidirectionally at depth >= 2, so reaching a hub `DOM-*` or `CNT-*` node at hop 1 pulls every sibling entity in that domain/container into the neighborhood at hop 2.
   * `build_fts_match_query` (`query.py`) joins all query terms with `OR`, diluting precision on multi-sentence `--task` prompts.
   * `_estimate_tokens` (`context.py`) uses `len(text) // 4`, under-counting tokens on YAML/JSON/paths/code signatures by ~25–35%.

4. **Issue #9 — Destructive `yaml.safe_dump` on Invariant Frontmatter Mutations (`catalog.py` & `delta_engine.py`)**:
   While `_set_frontmatter_scalar` and `_mutate_frontmatter_components` preserve YAML comments, `add_invariant`, `modify_invariant`, and `remove_invariant` in `delta_engine.py` call `_render_spec` (`yaml.safe_dump`), wiping all YAML comments and blank lines in the target spec's frontmatter.

== Proposed Specification Changes

1. **Polyglot Signature & Comment-Stripped Diff Parity (#6)**:
   * Extend `LANGUAGE_MAP` / `FallbackIndexer` in `src/eidos/core/index/ast_indexer.py` with public declaration extractors for `.c`, `.cpp`, `.h`, `.hpp`, `.cs`, `.rb`, `.php`, `.swift`, `.vue`, and `.svelte`, and ensure `_has_structural_ast_change` in `src/eidos/vcs/diff.py` compares extracted public signatures (or comment-stripped declaration headers) rather than unconditionally returning `True`.

2. **Unified SQLite Baselines, Git-Tracked File Enumeration, and Catalog Caching (#7)**:
   * Add `delta_baselines` to `_MANAGED_TABLES` and `ensure_cache_schema` in `src/eidos/core/index/storage.py`, and route `delta_engine.py` baseline queries through `open_cache_connection`.
   * Route file discovery in `_load_or_update_test_binding_cache` (`src/eidos/vcs/invariants.py`) and `_scan_and_classify_references` (`src/eidos/core/lifecycle/audit.py`) through `get_tracked_files(repo_root)` when inside a Git repository, falling back to `os.walk` only for non-Git directories.
   * Cache `_build_spec_catalog_with_invariants` in `src/eidos/core/lifecycle/catalog.py` keyed by `(eidos_dir, mtime_snapshot)`.

3. **Edge-Scoped Traversal, Two-Tier FTS Precision, and Calibrated Token Estimation (#8)**:
   * In `execute_k_hop_traversal` (`src/eidos/core/index/query.py`), prevent hop-2 sibling fan-out through organizational hub nodes (`product/domain`, `design/system`) when traversing from a child entity.
   * In `execute_fts_query` / `build_fts_match_query` (`src/eidos/core/index/query.py`), score multi-term matches using a two-tier strategy (boosting conjunction/phrase overlap above single-token `OR` hits).
   * In `_estimate_tokens` (`src/eidos/core/index/context.py`), weight structural punctuation/code/YAML tokens (`~3` chars/token) vs prose tokens (`~4` chars/token).

4. **Comment-Preserving Invariant Frontmatter Mutations (#9)**:
   * Add a comment-preserving `_mutate_frontmatter_invariants` helper in `src/eidos/core/lifecycle/catalog.py` (analogous to `_mutate_frontmatter_components`) and use it for `add_invariant`, `modify_invariant` / `patch_invariant`, and `remove_invariant` in `src/eidos/core/lifecycle/delta_engine.py` so YAML comments in target specs are never destroyed.
