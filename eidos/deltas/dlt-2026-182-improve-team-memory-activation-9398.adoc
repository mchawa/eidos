= SpecDelta: Improve Team Memory Activation, Capture Ergonomics, Guardrails Guidance, and Advisory Drift/Doctor Visibility
:toc: left

== Problem Statement

Although Eidos ships a full Git-native team memory stack (`agent/memory`, `eidos/memory/`, `eidos memory`, `eidos context` secondary attachment, and `SCR-PORTAL-MEMORY`), dogfooding reveals severe underutilization (only 1 memory file in Eidos's own repository):

1. **Narrow Capture Triggers & Unloaded Skill Cold Start**: Root `AGENTS.md` (`assets/plugin_reference/agents-md/block.md`) only triggers capture *"when corrected on a repo workflow/gotcha"*, missing self-discovered debugging, test, CI, and toolchain traps. Meanwhile `eidos/SKILL.md` omits any memory check from its Stage 2 pre-completion review, leaving `eidos-memory/SKILL.md` unloaded unless the agent already thinks of memory.
2. **Actionable Guidance Hidden at Default Tier**: `CMP-TIERED-CONTEXT-COMPRESSOR` (`context_memories.py` and `context_models.py`) currently strips `guidance` unless `--tier deep` is requested, so default `guardrails` slices surface only the 1-line `summary` and omit concrete commands or workarounds.
3. **High Capture Friction & Missing Update Command**: `eidos memory add` requires both `--title` and `--summary` plus manual `--entity` ID lookup; passing `--file` does not auto-infer owning `CMP-*`/`CNT-*` entities from `index.db`, there is no `--from-diff` shortcut to anchor uncommitted changes, and there is no `eidos memory update` subcommand to evolve an existing note when overlap warnings appear.
4. **Silent Daily Checkpoints**: Neither `eidos drift` nor `eidos doctor` surfaces non-blocking memory signals, so stale or diff-affected memories remain invisible during routine verification unless a developer explicitly runs `eidos memory audit`.

== Proposed Specification Changes

=== 1. Low-Friction Capture, Auto-Anchoring & In-Place Update (`CMP-MEMORY-ENGINE`, `CMP-CLI-MEMORY-COMMANDS`, `CTR-EIDOS-CLI` 2.1.0, `CAP-LIVING-SPEC-ENGINE` 1.24.0)
* **`add_memory` & `eidos memory add`**:
  ** Make `--summary` (`-s`) optional (default `None`); when omitted, deterministically derive `summary` from the first non-empty sentence/line of `--guidance` (or `--title` when `--guidance` is empty), cleanly truncated on word boundaries to `<= 220` chars.
  ** Add `infer_memory_entities_for_paths(eidos_dir, paths)` in `CMP-MEMORY-ENGINE` using the synced SQLite knowledge graph (`index.db`, `CMP-*`/`CNT-*` `source_path` ownership) and run it automatically when `auto_entities=True` (CLI `--auto-entities/--no-auto-entities`, default `True`), merging inferred IDs with any explicit `--entity` flags without duplicating entries.
  ** Add `--from-diff` on `eidos memory add` in `CMP-CLI-MEMORY-COMMANDS` (invoking `CMP-GIT-DIFF-INSPECTOR` `get_git_diff_files(..., uncommitted=True)` + `classify_changed_files`, keeping `CNT-EIDOS-CORE` acyclic from `CNT-EIDOS-VCS` per `ARCH-EIDOS.import_boundaries`), anchoring all modified non-memory workspace files (`code_files`, `test_files`, `spec_files`, `other_files`) and auto-inferring their owning entities.
* **`update_memory` & `eidos memory update <id_or_path>`**:
  ** Add the 9th `eidos memory` subcommand supporting partial updates to `--title`, `--category`, `--summary`, `--guidance`, `--why`, `--entity`, `--file`, `--replace-targets`, `--auto-entities/--no-auto-entities`, `--expires`, `--clear-expires`, and `--status` (`active` or `draft`).
  ** Reject `archived`/`promoted` targets and personal `category: user` with exit code `1`, sanitize AsciiDoc prose (`INV-ASCIIDOC-ZERO-WARNING-HYGIENE`), validate via `SpecValidator` before writing, re-stamp `verified_at` and `verified_commit`, run self-excluded overlap checks (`exclude_id`), and sync `index.db`.
* **Decision Record (`DEC-MEMORY-CAPTURE-ERGONOMICS-AND-ADVISORY-SURFACING`)**: Record rationale and rejected alternatives in `CMP-MEMORY-ENGINE.decisions` (including why `--from-diff` lives in `CMP-CLI-MEMORY-COMMANDS` rather than coupling `CNT-EIDOS-CORE` to `CNT-EIDOS-VCS`, and why `affected_memories` / `checks.team_memories` stay strictly outside `--fail-on-warnings`).

=== 2. Actionable `guidance` in Default `guardrails` Context Tier (`CMP-TIERED-CONTEXT-COMPRESSOR`, `CAP-AGENT-ADAPTER` 1.22.0)
* Extract `guidance` via `extract_memory_sections` in `attach_context_memories` for `tier in ("guardrails", "deep")` while keeping `why` exclusive to `deep`.
* Render clipped `guidance` (`<= 220` chars on `guardrails`, `<= 300` chars on `deep` under `_compact_prose`) in `TieredContextSlice._project_memory` and `to_markdown()` when `not self._compact_memories`.
* Stage 0 memory-first pruning (`_compact_memories = True`) drops `guidance` first before compressing or evicting any architectural `INV-*`, `DEC-*`, `POL-*`, or `CTR-*`, preserving `TIER_TOKEN_BUDGETS` (`guardrails <= 1000` tokens) with `0%` architectural eviction.

=== 3. Strictly Non-Blocking Advisory Memory Visibility in `eidos drift` & `eidos doctor` (`CMP-DRIFT-DETECTOR`, `CMP-CLI-DRIFT-COMMANDS`, `CMP-CLI-DOCTOR-HOOKS`, `CAP-DRIFT-DETECTION` 1.19.0, `CAP-AGENT-ADAPTER` 1.22.0)
* **`detect_drift` & `eidos drift` (`INV-DRIFT-AFFECTED-MEMORIES-ADVISORY`)**:
  ** Add `find_affected_memories(...)` in `src/eidos/vcs/drift.py` matching diff-changed non-memory files (`code_files`, `test_files`, `spec_files`, `other_files`) via `match_path_pattern` and `touched_components` against active non-archived `agent/memory` entries (evaluated inside `eval_root` on `--base`/`--head` commit-range runs), annotated with cached freshness (`fresh`, `stale`, `expired`, `unverifiable`) via `resolve_memory_freshness_batch`.
  ** Emit `DriftCheckResult.affected_memories` in `eidos drift --json` and as a concise advisory panel/list in Rich output (highlighting `stale`/`expired`/`unverifiable` entries with `eidos memory verify <ID>` / `eidos memory archive <ID>` hints).
  ** Strictly non-blocking: `affected_memories` never modifies `is_clean`, `drift_detected`, exit code `0`, or `--fail-on-warnings` (preserving `INV-AGENT-MEMORY-SCHEMA-ISOLATION` and `INV-DRIFT-MEMORY-FILE-ISOLATION`).
* **`eidos doctor` (`INV-DOCTOR-TEAM-MEMORY-ADVISORY`)**:
  ** Add `_check_team_memories(eidos_dir, specs_exist)` emitting `checks.team_memories` (`ok: true`, `status: "clean" | "empty" | "needs_review"`, `total_active`, `fresh`, `stale`, `expired`, `unverifiable`, `detail`) and a `Team Memories` row in the Rich doctor table, strictly non-blocking (`overall_ok` and exit code `0` unaffected).

=== 4. Agent Activation Triggers Within Existing Word Ceilings (`CNT-EIDOS-PLUGIN`, `CAP-AGENT-ADAPTER` 1.22.0)
* **`assets/plugin_reference/agents-md/block.md`** (enforced ceiling `<= 250` template / `<= 320` rendered words across all 9 targets): Broaden the team memory bullet from *"When corrected on a repo workflow/gotcha"* to *"When corrected or after hitting a non-obvious build/test/CI/tooling gotcha, save shared team memory via `eidos memory add` and note the `MEM-*` file in your reply (never personal prefs)."*
* **`assets/plugin_reference/skills/eidos/SKILL.md`** (enforced ceiling `<= 2,050` body words, currently `2,041`): Add a concise Stage 2 memory capture/reconciliation check (tightening ~10 redundant words elsewhere in Stage 2 so body stays `<= 2,050` with zero ceiling increase).
* **`assets/plugin_reference/skills/eidos-memory/SKILL.md`** (enforced ceiling `<= 450` body words, currently `357`): Document self-discovered gotcha capture, optional `--summary`, `--from-diff` and automatic `--entity` anchoring, and `eidos memory update <ID>`.
