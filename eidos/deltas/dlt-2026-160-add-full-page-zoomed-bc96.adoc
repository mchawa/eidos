= SpecDelta: Add Full-Page Zoomed C4 Diagram Mode and Component Connection Highlighting
:toc: left

== Problem Statement
While the Architecture view (`SCR-PORTAL-ARCHITECTURE`, `src/eidos/portal/frontend/src/components/views/ArchitectureView.tsx`) renders interactive C4 Level 1–3 diagrams and a node-only Blast Radius panel, two usability bottlenecks hinder real-world architectural analysis:

1. **No True Full-Page Zoomed-In View**: The current expand toggle (`isExpanded`) only stretches the inline card from `h-[580px]` to `h-[800px]` within the page column, and `autoFitDiagram()` clamps zoom to `<= 1.0` (`Math.min(1.0, optimalScale)`). On medium-to-large C4 Level 2 Container or Level 3 Component diagrams, nodes shrink to `35%–55%` scale with tiny, hard-to-read labels and no way to open the diagram full-page at a comfortable zoomed-in scale. (Note: `DLT-2026-120-SCALABLE-PORTAL-9B81` remains a broad, multi-view `proposed` overhaul; this SpecDelta delivers a focused, immediately shippable full-page zoomed C4 stage plus SVG connection highlighting.)
2. **No Component + Connections Highlighting on the Diagram Canvas**: `applyBlastRadiusToSvg()` (`ArchitectureView.tsx:168-272`) only styles `.node` boxes; it never highlights or dims Mermaid v12 SVG edges (`.edgePaths path[data-edge="true"]` / `.flowchart-link`) or edge labels (`.edgeLabels .edgeLabel`). On dense diagrams with dozens of crisscrossing arrows, tracing which incoming and outgoing connections belong to a specific component (`CMP-*`) or container (`CNT-*`) remains visually noisy—and clicking a node on the canvas immediately drills down or opens the inspector instead of offering an in-canvas connection focus mode.

== Proposed Specification Changes

=== 1. Full-Page Zoomed-In C4 Diagram Stage (`SCR-PORTAL-ARCHITECTURE`, `CMP-PORTAL-ASSETS`, `CNT-EIDOS-PORTAL`)
* **Enlarge Button (`#btnC4FullPage`)**: Add an explicit **"Full Page"** button (with `Maximize` icon, accessible `aria-label`, and `aria-expanded` state) in both the top C4 toolbar and the bottom-right viewport overlay bar beside `"Fit to View"`.
* **In-Place Full-Viewport Overlay (`state: full_page_c4`)**:
  * Promotes the live `#c4DiagramContainer` / `#c4ActiveDiagram` wrapper in-place into a fixed full-page stage (`fixed inset-0 sm:inset-2 z-[45]` with translucent backdrop, `role="dialog"`, `aria-modal="true"`, `aria-label="Full-Page C4 Architecture Diagram"`, and body scroll lock), preserving the rendered SVG and all active highlight attributes with zero unmount/re-render flicker.
  * Layered explicitly at `z-[45]`—strictly above `NavigationRail` (`z-40`, `NavigationRail.tsx:86`) and sticky top `header` (`z-30`, `App.tsx:740`), and strictly below `Sheet` (`z-50`, `sheet.tsx:68`) and `CommandDialog` (`z-50`)—with no transform-creating ancestor trapping `position: fixed`, so clicking a node to inspect it opens `#c4InspectorDrawer` cleanly **above** the full-page diagram.
  * Dismisses cleanly via an **"Exit Full Page"** (`#btnC4ExitFullPage`) button or `Escape` key (only when no `Sheet` inspector is open on top; when a `Sheet` is open, `Escape` closes the `Sheet` first).
* **Zoomed-In Initial Scaling & Extended Zoom Range**:
  * On entering Full Page mode, re-measure the full-viewport canvas after layout settles and automatically open at a **readable zoomed-in scale** (`Math.min(1.5, Math.max(optimalScale, 1.0))`, centered on the highlighted node's SVG bounding box if a component is highlighted, or centered at `(0, 0)` otherwise), ensuring node titles and descriptions are immediately legible rather than zoomed out to 40%.
  * Expand interactive button and native wheel zoom bounds (`[isFullPage]` dependency on the wheel listener effect) in Full Page mode to `0.25x`–`4.0x` (`25%`–`400%`) while keeping **"Fit All"** (`optimalScale`), **"100%"**, drag-to-pan, and wheel zoom controls directly accessible in the full-page header.
  * Retain the full C4 Level Switcher (`#btnC4Level1`–`3`), breadcrumbs, Level 3 container dropdown (`#c4ContainerSelect`), tier legend, and Component Connection Highlight controls inside the full-page top bar.

=== 2. Highlight a Specific Component & Its Connections (`SCR-PORTAL-ARCHITECTURE`, `CMP-PORTAL-ASSETS`)
* **Unified Pure SVG Connection Highlighting Engine (`src/eidos/portal/frontend/src/lib/c4Highlight.ts`)**:
  * Parse directed connections (`-->`, `==>`, `-.->`) and declared node IDs from the active Mermaid source (`currentDiagramSource`).
  * Resolve Mermaid v12 SVG nodes (`g.node`) by matching `el.getAttribute("data-id")` or stripping Mermaid's `flowchart-<nodeId>-<n>` prefix against `knownNodeIds` (with `data-c4-entity` as a secondary mapping), ensuring **all** visible nodes across Levels 1, 2, and 3—including `CNT_*`, `mod_CMP_*`, `peer_CNT_*`, `ctr_CTR_*`, `PER_*`, and `EXT_*`—are covered uniformly.
  * Resolve Mermaid v12 SVG edge elements (`path[data-edge="true"]` / `.edgePaths path.flowchart-link` with `data-id="L_<src>_<dst>_<idx>"` or `id`) and matching `.edgeLabels .edgeLabel` elements against the exact set of known diagram node IDs—safely handling underscores inside entity slugs without naive `split("_")`.
  * Support directional filtering: `all` (incoming + outgoing), `incoming` (used by), and `outgoing` (depends on).
  * Enforce mutual exclusion between component-connection focus (`highlightedEntityId`) and Blast Radius simulation (`blastTargetId`), routing both through the same SVG style-snapshot/restoration pipeline so `data-orig-*` attributes are never corrupted:
    * Selected node: `data-c4-highlight="selected"` (`.c4-node-selected`, prominent primary ring + glow, `opacity: 1`).
    * Connected neighbor nodes: `data-c4-highlight="incoming" | "outgoing" | "connected"` (`.c4-node-connected`, distinct accent border, `opacity: 1`).
    * Connected edges & edge labels: `data-c4-edge-state="incoming" | "outgoing"` (`.c4-edge-incoming`, `.c4-edge-outgoing`, thickened `3px` high-contrast stroke + drop-shadow keeping Mermaid arrowhead markers crisp, and `.c4-edge-label-connected` label).
    * Unrelated nodes, unrelated edges, and unrelated edge labels: `data-c4-highlight="dimmed"` / `data-c4-edge-state="dimmed"` (`opacity: 0.14`–`0.18`), isolating the selected component's exact connection graph.
  * Also highlight connecting edges between impacted hops when `blastTargetId` is active via the same shared edge-matching helper.
* **Intuitive User Controls (`state: connection_highlighted`)**:
  * **Highlight Component Selector (`#c4HighlightSelect`)**: Available in both inline and full-page toolbars, populated with human-readable titles (`INV-PORTAL-HUMAN-READABLE-UI`) for the entities present in the active C4 level (Containers at L2; Internal Components `CMP-*`, Related Containers, and Contracts at L3; System/Actors/External Systems at L1), paired with an `All / Incoming / Outgoing` direction toggle and **"Clear"** button.
  * **Direct Canvas Focus Mode**: Add a **"Focus Connections"** toggle button (`#btnC4FocusMode`, `aria-pressed`) in the toolbar (plus `Shift`/`Alt`+click shortcut on any node) so clicking any node on the canvas highlights that component and its connections directly instead of drilling down—clicking the same node again clears focus.
  * **Connection Summary Pill & Inspector Integration**: When a node is highlighted, show a compact human-readable pill (`<Title> • X incoming • Y outgoing`, plus quick **"Inspect"** and **"Clear"** actions) in the diagram viewport; also add a **"Highlight on Diagram"** action inside `#c4InspectorDrawer` (for both containers and internal components) to close the drawer and highlight that entity and its connections on the canvas.

== Implementation Plan
1. **Pure Unified Connection-Highlight Module (`CMP-PORTAL-ASSETS`)**:
   * Create `src/eidos/portal/frontend/src/lib/c4Highlight.ts` implementing:
     * `parseMermaidEdges(source: string)`: parses directed edges (`-->`, `==>`, `-.->`) and known node IDs from the active Mermaid diagram source.
     * `resolveSvgNodeId(nodeEl: Element, knownNodeIds: Set<string>)`: resolves the Mermaid node ID from `data-id` or `flowchart-<nodeId>-<n>` without breaking on underscores.
     * `matchSvgEdgeEndpoints(edgeEl: Element, knownNodeIds: Set<string>, parsedEdges: ParsedMermaidEdge[], edgeIndex: number)`: resolves `(sourceNodeId, targetNodeId)` deterministically from Mermaid v12 `data-id` / `id` (`L_<src>_<dst>_<n>`) matched against `knownNodeIds`, falling back to parsed edge order.
     * `restoreC4SvgStyles(svgRoot: Element)` and `applyC4ConnectionHighlight(svgRoot: Element, options: { selectedNodeId: string | null; direction: "all" | "incoming" | "outgoing"; parsedEdges: ParsedMermaidEdge[]; knownNodeIds: Set<string> })`: restores prior inline styles cleanly before applying highlight/dim attributes to nodes, edges, and `.edgeLabel` elements, and returns `{ incomingCount, outgoingCount, connectedNodeIds }`.
     * `computeFullPageZoom(svgSize: { width: number; height: number }, viewportSize: { width: number; height: number })`: computes a readable zoomed-in entry scale (`>= 1.0`, capped at `1.5`, falling back cleanly for invalid dimensions) and optional pan-to-node centering helper.
