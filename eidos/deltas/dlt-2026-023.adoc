= SpecDelta: Continuous Code-Aware AST Indexing and Status Telemetry
:toc: left

== Problem Statement

The Eidos Architectural Knowledge Graph indexer embeds deep polyglot AST symbol mapping (`ast-grep-py` / Python `ast`) and granular test-function invariant traceability (`(test_fn) -[asserts]-> (INV-*)`).

However, two significant gaps limit its reliability and developer experience:
1. **Spec-Only Dirty Checking**: `ArchitecturalIndex.is_dirty()` currently only scans `.adoc` files under `eidos/`. When a developer or AI agent edits source code under `src/` or tests under `tests/`, `is_dirty()` returns `False` (`SYNCED (Clean)`), leaving AST symbol mappings stale in `.eidos/cache/index.db` until an `.adoc` spec is modified or `--force` is passed.
2. **Parser Engine Opacity & Hidden Metrics**: The `eidos index status` CLI command and `get_index_status()` API only expose an aggregate counter (`AST Symbol Mappings: 388`). Crucial metrics—active parser engine (`ast-grep` vs `python-ast`), symbol breakdown by syntax kind (classes, functions, methods, test bindings), and test-to-invariant assertion counts—remain invisible, and `--json` is not supported.

== Architecture & Behavioral Mutations

=== 1. Continuous Code-Aware Dirty Checking (`src/eidos/core/graph_index.py`)
Extend `is_dirty()`:
1. Continue scanning `.adoc` files in `eidos/`.
2. Discover tracked source code files from container and component manifests (`package_path`, `source_path`, and `tests/`).
3. Compare file `stat.st_mtime` with timestamps stored in `indexed_files`.
4. If any source code file or test file has modified `mtime`, flag `is_dirty() = True` in `< 5ms`.
5. When `_ensure_synced()` runs (which guards all reading APIs), dirty code files are re-parsed via `extract_symbols()` and `extract_test_bindings()`, keeping the SQLite index fresh automatically.

=== 2. `ArchitecturalIndex.get_index_status()` Payload
Return an `ast` telemetry payload:
```python
"ast": {
    "engine": "ast-grep (Native AST)" | "python-ast (Standard Library Fallback)",
    "engine_class": "AstGrepIndexer" | "PythonAstIndexer",
    "ast_grep_available": True | False,
    "total_symbols": int,
    "classes": int,
    "functions": int,
    "methods": int,
    "test_bindings": int,
    "symbols_by_kind": dict[str, int],
    "test_invariant_assertions": int,  # Count of (test_fn)-[asserts]->(INV-*)
    "tested_invariants": int,          # Count of distinct target invariants asserted
}
```

=== 3. CLI `eidos index status` (`src/eidos/cli/main.py`)
1. **Header Panel**: Add `AST Engine`, `AST Symbols` breakdown, and `Invariant Traceability`.
2. **Tabular Breakdown**: Render `Living Specifications by Type` alongside `AST Code Symbols & Traceability`.
3. **`--json` Output**: Expose `--json` option to print the complete dictionary as formatted JSON for tool callers.

=== 4. Agent Hook Integration (`.agents/plugins/eidos/scripts/check_drift.py`)
In `check_drift.py` (`PostInvocation` hook), run incremental index sync (`idx.sync()`) when dirty to ensure the index is always fresh for the agent.

=== 5. Contract & Capability Invariants
1. Update `CTR-EIDOS-CLI` in `eidos/architecture/contracts/cli.adoc`.
2. Register `INV-INDEX-STATUS-AST-TELEMETRY` and `INV-INDEX-CODE-DIRTY-SYNC` in `CAP-AGENT-002` (`eidos/domains/agent-intelligence/capabilities/cap-agent-002.adoc`).
3. Add automated test coverage in `tests/test_context.py` and `tests/test_graph_index.py`.
