== 4. Solution Strategy
* **Git as the OS**: All states (PRDs, ADR-free architectures, task graphs, test bindings) reside in Git.
* **Progressive Onboarding (`eidos init --lite`)**: Supports a compact 3-file starter profile (`system.adoc`, `architecture/system-architecture.adoc`, and `POL-001`) that expands seamlessly as the project grows.
* **SpecDelta Diff Engine**: Evolutionary changes are composable semantic mutations (`add`, `modify`, `remove`, `deprecate`) stored flat in `eidos/deltas/`.
* **Multi-Design Systems & W3C Tokens**: Product capabilities bridge business JTBD with technical code packages and W3C tokenized multi-brand design systems.
* **Interactive Hierarchical C4 Explorer**: Living Web Portal provides dynamic, clickable drill-down from C4 Level 1 System Context to Level 2 Container Topologies and Level 3 Component Whiteboxes with breadcrumbs and slide-over component inspection, packaged via deterministic gzipped assets (`assets/portal/bundle.html.gz`) and a Hatch custom build hook.
* **Embedded SQLite Knowledge Graph & FTS5 Retrieval**: High-speed, zero-dependency caching layer (`eidos/.cache/index.db`) decomposed into focused internal modules (`storage.py`, `sync.py`, `query.py`, `context.py`, `ast_indexer.py`) with sub-2ms dirty checking.
* **Recursive CTE Blast-Radius & Impact Analysis**: Architectural blast radius and k-hop neighborhood traversal executed natively in SQLite via Common Table Expressions (CTEs).
* **Tiered Context Compression Model**: Three-tier context extraction (`anchor`, `guardrails`, `deep`) reducing prompt token payloads by 60-80% for AI coding agents.
* **Token-Budgeted Context Slicing**: Slices bounded C4 topologies, active invariants, and governing policies dynamically for AI agent contexts.
* **Polyglot Invariant Verification**: Continuous drift detection decomposed across `diff.py`, `invariants.py`, and `report.py` validating automated test bindings across Python, TypeScript, Go, Rust, Java, and Kotlin.

== 5. Building Block View (C4 Architecture Hierarchy)

=== 5.1 C4 Level Mapping Guide
Eidos enforces a strict, first-principles mapping to the canonical C4 architecture model:

[cols="1,1,2,2", options="header"]
|===
| C4 Level | C4 Term | Eidos Specification Entity | Architectural Boundary
| **Level 1** | **System Context** | Root System Spec (`SYS-*`) & Architecture (`ARCH-*`) | System boundaries, users/personas, and external platforms
| **Level 2** | **Container** | Container Manifests (`CNT-*`, `type: tech/container`) | **Process / Deployable / Package boundary** (CLI app, library, daemon, SPA, docs)
| **Level 3** | **Component** | In-Process Modules (`CMP-*`, centralized in `eidos/architecture/components/<comp>.adoc` with `container: CNT-*`) | **In-Process / Memory boundary** (internal modules, services, parsers, engines)
| **Level 4** | **Code** | Source Code & Schemas (`source_path`) | Exact classes, functions, and data structures (`src/eidos/**/*.py`)
|===

=== 5.2 Monorepo Container Topology (C4 Level 2)
Eidos is distributed as a monorepo consisting of the following primary Level 2 containers, structured into four canonical architectural tiers:

[cols="1,2,2,2,2", options="header"]
|===
| Container ID | Name | Architectural Tier | Type | Source Path
| `CNT-EIDOS-CLI` | Eidos Command-Line Interface | Tier 1: Presentation & Interface | CLI Application | `src/eidos/cli`
| `CNT-EIDOS-PORTAL` | Eidos Living Web Portal & Static Generator | Tier 1: Presentation & Interface | Web Application | `src/eidos/portal`, `assets/portal`
| `CNT-EIDOS-DOCS` | Eidos User Documentation System | Tier 1: Presentation & Interface | Web Application | `docs`
| `CNT-EIDOS-PLUGIN` | Eidos Agent Plugin & Extension Manager | Tier 2: Extensibility & Agent Integration | Library | `src/eidos/plugin`, `assets/plugin_reference`
| `CNT-EIDOS-CORE` | Eidos Living Spec & Design Core Engine | Tier 3: Core Domain & Spec Engine | Library | `src/eidos/core`, `assets/schemas`
| `CNT-EIDOS-VCS` | Eidos Git Drift & Lifecycle Engine | Tier 3: Core Domain & Spec Engine | Library | `src/eidos/vcs`
| `CNT-EIDOS-INDEX` | Eidos Architectural Knowledge Graph & Retrieval Index | Tier 4: Knowledge Graph & Persistence | Library | `src/eidos/core/index`
|===

The C4 Level 2 Container Diagram explicitly renders the inter-container dependency connections:
* `CNT-EIDOS-CLI` invokes Core Engine commands (`CNT-EIDOS-CORE`), runs drift detection (`CNT-EIDOS-VCS`), queries the knowledge index (`CNT-EIDOS-INDEX`), validates plugins (`CNT-EIDOS-PLUGIN`), and hosts/builds the Living Portal (`CNT-EIDOS-PORTAL`).
* `CNT-EIDOS-VCS` inspects Git diffs, AST symbols, and 1-hop graph neighborhoods via `CNT-EIDOS-CORE` and `CNT-EIDOS-INDEX`.
* `CNT-EIDOS-PORTAL` validates and synthesizes living specifications (`CNT-EIDOS-CORE`) and retrieves graph metrics (`CNT-EIDOS-INDEX`).
* `CNT-EIDOS-DOCS` embeds and links the Living Portal (`CTR-EIDOS-PORTAL`).
* `CNT-EIDOS-PLUGIN` resolves schemas and plugin reference assets (`CNT-EIDOS-CORE`).
* `CNT-EIDOS-INDEX` consumes AST models and frontmatter definitions (`CNT-EIDOS-CORE`).

=== 5.3 Level 3 Component Whitebox View & Interface Governance
Internal component building blocks reside centrally in `eidos/architecture/components/<component>.adoc` (see link:../explorations/EXP-2026-004.adoc[EXP-2026-004]), linked bottom-up via `container: CNT-*` in the standalone component manifest, and point to code via `source_path`. Eidos specifications **never touch or reside within source code directories** (`src/`, `packages/`).

Furthermore, interface ownership strictly distinguishes between deployment boundaries and in-memory linkage:
* **Containers (`CNT-*`)** define **Boundary Protocol Contracts (`CTR-*`)**: Cross-process, network, or CLI protocols (CLI args, REST OpenAPI, gRPC).
* **Components (`CMP-*`)** resolve **In-Process Dependencies via AST**: Cross-component (`consumes_api`) and cross-container (`depends_on`) edges are automatically derived from source file imports and `source_path` ownership mappings during index synchronization.

Container manifests interactively explorable in the Living Web Portal's Hierarchical C4 Explorer:

* **Interface Contracts**:
  - link:contracts/cli.adoc[`CTR-EIDOS-CLI` (Command-Line Interface Contract)]
