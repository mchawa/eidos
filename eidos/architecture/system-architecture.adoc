== 4. Solution Strategy
* **Git as the OS**: All states (PRDs, ADR-free architectures, task graphs, test bindings) reside in Git.
* **SpecDelta Diff Engine**: Evolutionary changes are semantic mutations (`add`, `modify`, `remove`, `patch`) stored flat with gitignored symlink status views.
* **Multi-Design Systems & W3C Tokens**: Product capabilities bridge business JTBD with technical code packages and W3C tokenized multi-brand design systems.
* **Arc42 & C4 Hierarchical Zoom**: High-level system context down to C4 Level 3 internal package components.

== 7. Deployment View (Infrastructure & Delivery)
* **Local Workstation**: Developers run the CLI directly (`uv run eidos`) and IDEs connect via stdio MCP.
* **CI/CD Automation**: GitHub Actions or GitLab CI runners execute validation gates on every PR.

== 8. Cross-Cutting Concepts
* **Interface Contracts**:
  - link:contracts/cli.adoc[`CTR-EIDOS-CLI` (Command-Line Interface Contract)]
  - link:contracts/mcp.adoc[`CTR-EIDOS-MCP` (Model Context Protocol stdio Contract)]
* **Design System Standard**: W3C Design Tokens Community Group (`tokens.json`) with multi-brand inheritance.
* **Lifecycle Isolation**: Self-contained `eidos/.gitignore` isolating generated status symlink views (`deltas/by-status/`).
* **Error Diagnostics**: Standardized exit codes and formatted terminal tables using Rich.
* **Data Storage**: Entirely Git filesystem backed with YAML frontmatter + AsciiDoc.
