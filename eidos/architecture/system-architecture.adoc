== Architectural Overview

Eidos is architected as a lightweight, Git-native execution and validation engine. It enforces zero external database dependencies: all state, domain models, technical architectures, and task mutations are persisted directly inside the version-controlled Git repository.

== C4 Model Level 1: System Context

[mermaid]
----
flowchart TD
    User["Product Lead / Engineer"] -->|CLI commands / Git commits| Git["Git Repository (Local / Remote)"]
    Agent["Autonomous Coding Agent (agy, claude, codex)"] -->|Reads Specs / Submits PRs| Git
    Git -->|Webhook Events| CI["CI / CD Pipeline (GitHub / GitLab)"]
    CI -->|Runs 'eidos validate'| EidosEngine["Eidos Engine"]
    EidosEngine -->|Pass / Fail Gate| CI
----

== C4 Model Level 2: Container / Package Topology

Eidos is delivered as a monorepo consisting of:
1. **Core Package (`src/eidos`)**: The Python orchestration engine, schema validator, and CLI tool.
2. **Specification Tree (`eidos/`)**: The living business and technical specifications.
3. **Test Harness (`tests/`)**: Automated test suites verifying invariant compliance.
