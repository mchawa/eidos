= Component: Eidos User Documentation System (C4 Level 3 Whitebox)
:toc: left

== Architectural Boundary
This container represents the public documentation site under `docs/` and its build pipeline configured by `zensical.toml`. It publishes comprehensive guides, conceptual frameworks, schema glossaries, and CLI references to GitHub Pages (`https://mchawa.github.io/eidos/`), while embedding the Living Architecture Portal (`site/portal/`).

== Arc42 Section 5.2 / C4 Level 3: Internal Building Blocks

[cols="1,2,2", options="header"]
|===
| Internal Module | Responsibility | Source Path
| **GettingStartedGuides** | Installation, environment setup, and 5-minute quickstart onboarding | `docs/getting-started/`
| **CoreConceptsGuides** | Explanations of Living Specs, SpecDeltas, Invariants, Explorations, Design Systems, and Schemas | `docs/concepts/`
| **UserGuides** | CLI reference, AI Agent Plugin guides (Antigravity, Claude, Cursor), and Portal operations | `docs/guides/`
| **SiteConfiguration** | Zensical theme styling, search indexing, and navigation topology | `zensical.toml`
|===

== Operational Invariants & Quality Attributes
* **Continuous Documentation Sync (`INV-DOCS-SYNCHRONIZATION`, `POL-003`)**: User documentation in `docs/` must remain in 100% synchronization with schemas and CLI commands, verified by `tests/test_docs_sync.py`.
* **Strict Validation (`--strict`)**: Documentation must build with zero broken cross-references or missing asset warnings.
* **Portal Co-Hosting**: The static Living Architecture Portal is compiled directly into `site/portal/` as part of the unified deployment artifact.
* **Offline-Ready Search**: Emits client-side `search.json` for high-speed offline query resolution without backend server requirements.
