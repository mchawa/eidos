= Component: DriftDetector
:toc: left

== Responsibility
Analyzes Git diffs and working-tree changes with -c core.quotePath=false and gitignore- and STANDARD_EXCLUDED_DIRS-aware file enumeration (get_git_diff_files, delegating get_tracked_files and is_polyglot_test_file to ProjectResolver in project.py, _has_structural_ast_change across all 20 polyglot code_extensions including .hpp and .kts, and orjson-parsed design token manifest comparison in _has_design_token_change) via direct canonical calls (`detect_drift`) without runtime sys.modules, inspect.signature, or `check_pr_drift` shims, scopes synthetic diff detection strictly to synthetic_diff_mock so file-mode changes do not trigger false drift, validates explicit and shallow-clone (.git/shallow) base Git references fail-closed without silent fallbacks while advancing main/master and origin/main/origin/master to HEAD~1 when equal to HEAD, resolves deterministic merge-base commit SHAs for 3-dot diffs and baseline file content extraction via a single batched `git cat-file --batch` pipe (`batch_read_git_blobs` and `_get_files_versions_batch` pre-fetching changed code, spec, and delta versions in `detect_drift`), batches linguist-generated/vendored gitattributes filtering, dynamically classifies specification files against configured specification directories (eidos_dir), filters SpecDeltas by active lifecycle status (skipping unchanged status: applied deltas and reading head_ref content on commit ranges) via get_cached_spec_document and typed FrontmatterModel and populates Planned Mode declared_delta_targets and declared_delta_paths from composable mutations[].target via direct attribute access (resolving .adoc file paths), pairs moved/renamed files by content and public symbols without VCS rename heuristics, evaluates structural AST symbol and design token/props modifications (traversing extends, design_system, tokens.manifest, and cross_client clients in _collect_design_subgraph without unschematized owned_path or tokens_path lookups), expands 1-hop neighborhood targets in _collect_1hop_spec_targets across parent CNT-* containers of standalone components, flags unowned structural code files in Direct and Planned modes unless claimed by a container/component or covered by a substantive system-level spec update, enforces substantive spec diffs (parsed via canonical split_frontmatter_and_body, rejecting deleted spec files) on all structural code and design changes, excludes global POL-* and PER-* neighbors from 1-hop component satisfaction neighborhoods, verifies static invariant test bindings (combining model.invariants and model.technical.invariants, enforcing strict class-qualified 'Class::method' matching without cross-class fallback while allowing unqualified 'method' bindings to match class methods, and unified 'INVARIANT_PATTERN' matching) and orphan invariants (scoping function-level docstring/comment eidos:fixture exemptions via _has_function_level_fixture and line-level eidos:fixture comments inside function bodies while preserving top-level test function orphans when a test class defines the same method name) across domains, policies, top-level tech/container specs, and architecture components in a single AST pass via shared `extract_test_file_cache_payload` and flat `{func: [tokens]}` `functions_json` and `file_tokens_json` in `test_binding_cache` (serialized with orjson, omitting empty functions and without any `has_fixture` column or `fixture_invs` sub-objects, reusing warm rows populated by `sync_index`) and shared 'load_test_binding_cache', 'save_test_binding_cache', 'load_spec_validation_cache', and 'get_cached_spec_document' helpers in storage.py (zero inline CREATE TABLE DDL) and 'SCHEMA_VERSION' in 'eidos/.cache/index.db', reconciles 1-hop contract/capability neighbors via get_k_hop_neighborhood(cid, max_depth=1), exposes DriftCheckResult properties (validation_passed, validation_errors, uncovered_invariants, code_files) and generate_remediation_prompt (always rendering validation_errors, uncovered_invariants, and orphan_invariants alongside code drift), and detects spec-to-code and design drift across component-scoped 1-hop knowledge graph neighborhoods with strict path-boundary matching; structural additions (new files or public symbols) are covered only by substantive, comment- and whitespace-normalized spec diffs (new unclaimed files and non-owner 1-hop coverage of new public symbols require symbol/file anchoring via inspector.is_anchored).
