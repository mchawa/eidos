= Component: SpecCommands
:toc: left

== Responsibility
Implements `eidos validate` and the `eidos spec` subcommand group (`list`, `show`, `schema`, `create`, `delete`, `discover`) for inspecting, validating, discovering, scaffolding, and deleting living catalog specifications across all 15 non-delta specification types.

== Key Responsibilities & Collaborators
* **Root Validation (`eidos validate`)**: Resolves `--path` through `resolve_cli_eidos_dir(path)` (`CMP-CLI-APP`), resolves `--fail-on-warnings/--no-fail-on-warnings` against `drift.fail_on_warnings` in optional `eidos/eidos.yaml` via `resolve_param_from_config` (explicit CLI flags always override config/env), invokes `CMP-SPEC-VALIDATOR` (`SpecValidator.validate_directory`), and renders Rich validation tables (including yellow advisory `warnings` when present) or compact `orjson` JSON reports (`--json`, listing only failing documents in `documents` alongside `schema_errors`, `broken_references`, non-blocking `warnings`, and `warning_count` while preserving exit code `0` when `is_clean` is `True` unless effective `fail_on_warnings` escalates non-empty warnings to exit code `1`).
* **Living Catalog Management & Brownfield Discovery (`eidos spec`)**: Routes `--path` discovery across `list`, `show`, `create` (guiding users toward non-numbered semantic living-spec IDs and exposing `--client` / `-c`, required when creating a `screen` specification), `delete`, and `discover` (`eidos spec discover [--path PATH] [--json]` delegating to `discover_repository_blueprint` in `CMP-LIFECYCLE-SCAFFOLDER` to emit deterministic candidate containers, contracts, test roots, and unmapped source_path gaps) while enforcing a strict disjoint boundary from `eidos delta`.

== Public Surface
* `register(app: typer.Typer) -> None`, `spec_app: typer.Typer`
* `validate(target_path: Path | None, fail_on_warnings: bool = False, json_output: bool = False) -> None`
* `spec_list_cmd(...)`, `spec_show_cmd(...)`, `spec_schema_cmd(...)`, `spec_create_cmd(...)`, `spec_delete_cmd(...)`, `spec_discover_cmd(...)`

== Design Constraints & Operational Notes
* **Disjoint Delta Rejection**: Rejects `delta/mutation` (`DLT-*`) in `eidos spec list --type delta`, `show` (directing callers specifically to `eidos delta show <ID>`), `create`, and `delete`, keeping `eidos spec` and `eidos delta` cleanly separated.
