= Component: MemoryCommands
:toc: left

== Responsibility
Implements the 9-subcommand `eidos memory` CLI group (`add`, `update`, `list`, `search`, `show`, `verify`, `archive`, `audit`, `promote`) as a thin Typer presentation adapter over `CMP-MEMORY-ENGINE` (with `--from-diff` uncommitted file collection via `CMP-GIT-DIFF-INSPECTOR`) with Rich tables/panels and machine-readable `--json` outputs (`CTR-EIDOS-CLI`, `INV-MEMORY-CLI-AND-SKILL-PARITY`).

== Key Responsibilities & Collaborators
* **Team Memory CRUD & Lifecycle Presentation**: Routes workspace resolution through `require_cli_eidos_dir` (`CMP-CLI-APP`, auto-routing `--file`, `--from-diff`, and path-shaped `show`/`update`/`verify`/`archive`/`promote` targets to their owning monorepo sub-project with sub-project-relative path normalization and failing closed with `discovered_subprojects` hints when spanning multiple sub-projects or invoked at a rootless monorepo) and delegates memory creation (`add`, with optional `--summary`, `--auto-entities/--no-auto-entities` default `true`, and `--from-diff` resolving existing non-memory uncommitted files via `CMP-GIT-DIFF-INSPECTOR`), in-place updating (`update`, supporting partial frontmatter/body edits, `--replace-targets`, `--auto-entities/--no-auto-entities`, `--expires`/`--clear-expires`, and `--status`), filtered listing (`list`), BM25/Hybrid search (`search`), inspection (`show`), freshness re-verification (`verify`), archival (`archive`), non-blocking auditing (`audit`, always exit code `0`), and verified graduation (`promote`) to `CMP-MEMORY-ENGINE`.
* **Consistent CLI Ergonomics**: Uses `--file`/`-f` for target file paths/globs and `--entity`/`-e` for target Eidos entity IDs while reserving `--path`/`-p` for the governing `eidos/` specifications directory across every subcommand.

== Public Surface
* `memory_app: typer.Typer`
* `memory_add_cmd(...)`, `memory_update_cmd(...)`, `memory_list_cmd(...)`, `memory_search_cmd(...)`, `memory_show_cmd(...)`
* `memory_verify_cmd(...)`, `memory_archive_cmd(...)`, `memory_audit_cmd(...)`, `memory_promote_cmd(...)`

== Design Constraints & Operational Notes
* **Strictly Non-Blocking Audit Exit Code**: `eidos memory audit` always returns exit code `0` even when stale, expired, duplicate, or overlapping memories exist so memory staleness never blocks CI pipelines.
