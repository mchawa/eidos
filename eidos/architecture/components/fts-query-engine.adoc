= Component: FTSQueryEngine
:toc: left

== Responsibility
Executes column-weighted SQLite FTS5 BM25 lexical search (`execute_fts_query`), reverse symbol lookup (`find_symbol_in_db`), and token-budgeted structural repository map generation (`generate_repo_map_from_db`) over the indexed knowledge graph from its dedicated disjoint module (`fts_query.py`).

== Key Responsibilities & Collaborators
* **Two-Tier Weighted FTS5 Search & Synonym Backfill (`DEC-INDEX-FTS-RETRIEVAL-HYGIENE`)**: Prioritizes high-precision multi-term `AND` queries before `OR` fallback using positional BM25 column weights `(0, 4, 2, 1, 2, 2)` (`title` > `jtbd_or_rule`/`keywords`/`symbols` > `body_text`), identifier de-compounding, deterministic architectural synonym expansion (`expand_architectural_synonyms`), and exact `CMP-*`/`DEC-*` entity ID boosting.
* **Gated Hybrid Reciprocal Rank Fusion & Epistemic Provenance (`DEC-INDEX-HYBRID-SEMANTIC-RRF`, `DEC-INDEX-HTTP-LINKING-AND-PROVENANCE`, `INV-SEMANTIC-COMPLETE-RRF-GATE`)**: When `is_semantic_index_complete(conn)` confirms `spec_embeddings` reflects a completed sync and `use_semantic=True`, `execute_fts_query` delegates dense cosine scanning (`tau_min = 0.50`) and Reciprocal Rank Fusion ($k_0 = 20, w_{\text{lex}} = 1.0, w_{\text{sem}} = 0.50$) to `CMP-SEMANTIC-EMBEDDING-ENGINE` (falling back 100% deterministically to FTS5 BM25 when absent or partially populated after an interrupted sync) and stamps every search hit with normalized epistemic `provenance` (`fts_bm25`, `semantic_rrf`, or `hybrid_rrf`) and `confidence` (`observed` for lexical `fts_bm25`, `inferred` for `semantic_rrf` / `hybrid_rrf`).
* **Reverse Symbol (Including Methods & Tests) & Repo Map Resolution**: Resolves AST symbol names (`find_symbol_in_db`, `resolve_symbol_locations_in_db`) across governed source symbols, class `method` symbols, `http_endpoint`/`http_request` route symbols, and automated test symbols (`is_test = 1`, excluding `'import'` and `'namespace'` metadata rows and excluding `'http_endpoint'`/`'http_request'` from synthetic `Class.method` unions) with normalized `provenance` (`declared_spec`, `ast_symbol`, `inferred_ownership`) and `confidence` (`observed`, `derived`, `inferred`), and formats token-budgeted structural outlines (`generate_repo_map_from_db`, filtering `is_test = 0` and excluding HTTP route/request rows to preserve `INV-INDEX-AI-REPO-MAP-BUDGET`) from persisted primary `code_symbols` rows without re-parsing source files.

== Public Surface
* `execute_fts_query(conn: sqlite3.Connection, text: str, limit: int = 10, include_types: tuple[str, ...] | list[str] | None = None, exclude_types: tuple[str, ...] | list[str] = (), use_semantic: bool = True, eidos_dir: Path | None = None) -> list[dict[str, Any]]`
* `build_fts_match_query(text: str, operator: str = "OR", expand_synonyms: bool = False) -> str`, `expand_architectural_synonyms(text: str) -> str`
* `find_symbol_in_db(conn: sqlite3.Connection, query: str, limit: int = 20) -> list[dict[str, Any]]`
* `generate_repo_map_from_db(conn: sqlite3.Connection, max_tokens: int = 1500) -> dict[str, Any]`

== Design Constraints & Operational Notes
* **SQL-Scoped Type Filtering**: Applies `include_types` (`PRIMARY_TASK_SLICE_ENTITY_TYPES` and `SECONDARY_TASK_SLICE_ENTITY_TYPES` including `product/persona`, `design/client`, `design/ui-component`, `design/screen`, and `design/flow`) and `exclude_types` filters inside SQL *before* `LIMIT` so historical SpecDeltas and explorations never crowd out active architecture, persona, or design entities during `eidos context --task`.
