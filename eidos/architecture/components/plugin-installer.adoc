= Component: PluginInstaller
:toc: left

== Responsibility
Installs, updates, and safely uninstalls the Eidos Agent Plugin and its 4 workflow skills (`eidos`, `eidos-spec`, `eidos-plan`, `eidos-ops`) across 8 AI coding harnesses via a declarative `TargetAdapter` registry and SHA-256 `.eidos-manifest.json` tracking, and projects one canonical, marker-delimited Eidos block into the repository's root `AGENTS.md`.

== Key Responsibilities & Collaborators
* **Declarative Multi-Harness Projection (`installer.py`)**: Resolves `project_dir` to the enclosing Git monorepo root via `find_git_root` across `install_plugin`, `uninstall_plugin`, and `update_plugin` so `.agents/plugins/eidos`, harness skill projections, and `AGENTS.md` / `CLAUDE.md` are always installed at the main Git root and never duplicated inside a sub-project. Projects `assets/plugin_reference/` (resolved via `CMP-ASSET-LOCATOR`) across `project` (`.agents/plugins/eidos`), GitHub Copilot (`.github/plugin/`, `.github/skills/`, `.github/copilot/settings.json`), Claude Code (`.claude/skills/` and `.claude/settings.json` `hooks.Stop` registration), Cursor (`.cursor/skills/`), Cline, OpenCode, OpenAI Codex (`.codex/`), and Aider (`.aider/skills/`) targets, merging `hooks.json` and `.claude/settings.json` non-destructively. Each `TargetAdapter` resolves its installed skills directory via `TargetAdapter.skills_dir()`.
* **Canonical `AGENTS.md` Managed Block (`managed_block.py`, `DEC-PLUGIN-AGENTS-MD-MANAGED-BLOCK`)**: Every target calls `project_agents_md_block`, which renders `assets/plugin_reference/agents-md/block.md` (`render_agents_md_block`) and writes it through `upsert_managed_block` between `<!-- eidos:begin agents-md ... -->` / `<!-- eidos:end agents-md -->` markers.
** The begin marker carries a `sha256:` of the LF-normalized inner content and a sorted `targets=<target>:<skills-dir>` list (pruning any previously uninstalled target whose skills directory is gone and deduplicating shared paths in the rendered block). Installing several harnesses therefore yields one deterministic block that lists every installed skill location, independent of install order. In-repository custom `--dest` installs participate as `custom:<dest>/skills`.
** Text outside the markers is never modified: blocks are spliced into the original bytes (line endings and UTF-8 BOM preserved, atomic writes), and markers inside Markdown fenced code blocks are ignored.
** Hand-edited blocks are reported as `modified` and left untouched unless the user runs an explicit `eidos plugin install --force`. `update_plugin` always passes `force_blocks=False`.
** Malformed markers are reported as `malformed` without writing, and a standalone `<!-- eidos:<name> off -->` line opts a block out silently.
* **Harness Bridges via `AGENTS.md`**: GitHub Copilot, Cursor, OpenAI Codex, Antigravity, Cline, and OpenCode load root `AGENTS.md` natively, so no per-harness rule files are written.
** Claude Code gets a one-line `claude-import` block (`@AGENTS.md`) in root `CLAUDE.md` via `project_claude_import_block`, skipped when the user's `CLAUDE.md` already imports `@AGENTS.md`.
** Aider gets `AGENTS.md` added to `.aider.conf.yml` `read:` via `_update_project_aider_conf`.
* **Manifest-Tracked Uninstall & Version Synchronization (`version.py`)**: Records installed file paths and SHA-256 digests in `.eidos-manifest.json`. Shared user files (`SHARED_USER_FILES`: `AGENTS.md`, `CLAUDE.md`, `.aider.conf.yml`, `settings.json`) are never recorded in or unlinked from a manifest. Uninstall removes only Eidos-managed files and leaves `AGENTS.md` / `CLAUDE.md` blocks and the Aider `read:` entry in place by design. The component resolves both `plugin.json` and `.eidos-manifest.json` at the enclosing Git root (`find_git_root`) in `_resolve_installed_plugin_manifest` and `check_plugin_version_status`, normalizes package versions to SemVer 2.0.0 (`normalize_to_semver`, `get_bundled_plugin_version`), and checks PyPI (`PYPI_PACKAGE_JSON_URL`) for newer `eidos-ai` CLI releases (`check_cli_update_status`).

== Design Constraints & Operational Notes
* **Symlink & User-File Safety**: Rejects symlink traversal outside the repository (`_check_not_symlink`, and the managed-block writer's own symlink guard) and refuses to overwrite modified user-owned files when `force=False`. A symlinked `AGENTS.md` or `CLAUDE.md` is never written through: the block is reported as `skipped` in the install message without aborting the install, and a `CLAUDE.md` symlinked to `AGENTS.md` needs no import block because Claude Code already loads the `AGENTS.md` block through it.
* **Managed-Block Safety (`INV-PLUGIN-MANAGED-BLOCK-SAFETY`)**: On install and update, Eidos only creates or replaces text between its own named markers in shared instruction files. An unchanged block (same rendered content and targets) is never rewritten.
* **No Backward Compatibility for Legacy Bridges**: Per-harness rule files and instruction blocks written by releases before `DLT-2026-121` are neither migrated nor removed; fresh-install correctness is the only compatibility requirement.
