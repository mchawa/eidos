= Component: TieredContextCompressor
:toc: left

== Responsibility
Extracts rank-ordered, token-budgeted architectural subgraph slices (`ArchitecturalContextSlice`) across `anchor` (`<=300` tokens), `guardrails` (`<=1000` tokens), and `deep` (`<=2500` tokens) tiers in both Markdown and `orjson` JSON formats for AI coding agents.

== Key Responsibilities & Collaborators
* **Multi-Entry Context Slicing**: Resolves context queries by file path (`--file`), entity ID (`--component`), or natural-language task (`--task`) using `CMP-FTS-QUERY-ENGINE` and `CMP-GRAPH-TRAVERSAL-ENGINE`, expanding matched containers, standalone components, capabilities, contracts, invariants, and policies.
* **Calibrated Token Budgeting & Two-Stage Eviction**: Estimates tokens using structure-aware calibration (`~3.0` chars/token for code/YAML/JSON vs. `~4.0` chars/token for prose) and applies progressive prose compression on invariant rules and `DEC-*` rationale *before* evicting 1-hop neighbors or tail matches.

== Public Surface
* `ArchitecturalContextSlice`, `TieredContextSlice`
* `build_tiered_context_slice(index: ArchitecturalIndex, files: list[str] | None, component: str | None, task: str | None, tier: str = "guardrails", use_semantic: bool = True) -> ArchitecturalContextSlice`
* `get_context_slice(...) -> ArchitecturalContextSlice`
* `collect_component_decisions(comp: dict) -> list[dict]`, `format_decisions_markdown(...) -> list[str]`

== Design Constraints & Operational Notes
* **Honest Empty Slices**: Returns an empty `ArchitecturalContextSlice` when an explicit query matches zero entities rather than injecting unrelated alphabetical fallback specs.
* **Direct-Over-1-Hop Container Prioritization & Hybrid Provenance (`DEC-INDEX-HYBRID-SEMANTIC-RRF`)**: Separates directly matched containers/components (`direct_cnt_ids`) from 1-hop domain/design-system expansions (`expanded_cnt_ids`) so 1-hop expansions never crowd out direct FTS/Hybrid container hits or survive `_enforce_token_budget` ahead of direct matches, and records `"Hybrid task match"` / `"Semantic task match"` provenance in `matched_reasons`.
