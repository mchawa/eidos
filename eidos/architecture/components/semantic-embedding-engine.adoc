= Component: SemanticEmbeddingEngine
:toc: left

== Responsibility
Encapsulates the opt-in local Harrier-OSS-v1-0.6B ONNX semantic embedding engine (`eidos-ai[semantic]`), content-addressed `spec_embeddings` persistence, sub-millisecond SQLite `BLOB` + NumPy BLAS cosine similarity scanning, and zero-regression gated Hybrid Reciprocal Rank Fusion (`DEC-INDEX-HYBRID-SEMANTIC-RRF`).

== Key Responsibilities & Collaborators
* **Pinned SHA-256 Verified Downloads, Config Mirror URL, Shared Git-Root Cache & Dead GQA Output Pruning (`DEC-INDEX-FLOCK-WAL-AND-PINNED-ONNX`)**: Resolves the Harrier model cache directory via `resolve_semantic_model_dir(eidos_dir)` to `<git_root>/eidos/.cache/models/harrier-oss-v1-0.6b` when inside a Git repository, resolves optional `context.semantic.variant` and strictly HTTP(S)-only `context.semantic.model_mirror_url` from `<eidos_dir>/eidos.yaml` inside `setup_semantic_model` (rejecting `file://`, non-HTTP schemes, and embedded credentials), pins `HARRIER_HF_REVISION` to an immutable 40-character HuggingFace commit SHA, unconditionally enforces `Content-Length` byte counts and pinned per-artifact SHA-256 digests (`HARRIER_ARTIFACT_MANIFEST`) across both default HuggingFace and custom mirror downloads before atomic promotion, checks all 3 required `fp32` files (including `model.onnx_data_1`) in `_detect_installed_variant`, enforces `direction="right"` padding (`HARRIER_DOC_MAX_LENGTH = 4096`), prunes unconsumed `present_k_dummy`/`present_v_dummy` outputs, and sets `enable_cpu_mem_arena = False`.
* **Canonical Asymmetric Prompt Formatting, Atomic Worker Locking & Dynamic Batching**: Formats queries with Harrier's `sts_query` instruction prefix, encodes living specification passages over spec-only fields (`content_sha256`), batches documents under `HARRIER_MAX_BATCH_TOKENS = 2048`, acquires `semantic_sync.lock` atomically via non-blocking `flock` / exclusive lockfile creation in `_trigger_auto_semantic_refresh` so concurrent CLI invocations never spawn duplicate background ONNX worker processes, and serializes foreground ONNX `sync_spec_embeddings` runs on `semantic_sync.lock` with a fresh `spec_embeddings` SHA-256 re-check before encoding.
* **Sub-Millisecond BLAS Scan, Completeness Tracking & Gated Hybrid RRF (`INV-SEMANTIC-COMPLETE-RRF-GATE`)**: Tracks semantic sync completeness via the existing SQLite `metadata` table (`semantic_sync_complete` flipped to `"0"` before batch encoding and `"1"` only after all batches and orphan pruning commit), exposes `is_semantic_index_complete(conn)` (also surfaced as `is_complete` in `get_semantic_index_status`), scans `spec_embeddings` (`4,096`-byte `float32` `BLOB` rows) via `np.frombuffer` + BLAS matrix-vector multiplication (`~0.22 ms` for `111` specs), and fuses lexical FTS5 BM25 ranks with semantic ranks via `fuse_hybrid_rrf` ($k_0 = 20, w_{\text{lex}} = 1.0, w_{\text{sem}} = 0.50, \tau_{\min} = 0.50$).

== Design Constraints & Operational Notes
* **100% Deterministic Fallback (`POL-ZERO-AI-CALL-DEPENDENCY`, `INV-AGENT-HYBRID-SEMANTIC-FALLBACK`)**: When `onnxruntime`/`tokenizers` are not installed or `spec_embeddings` is empty, all retrieval operations bypass `SemanticEmbeddingEngine` in `< 0.01 ms` and fall back deterministically to FTS5 BM25.
* **Cross-Component `EMBEDDING_SCHEMA_VERSION` Bump Contract (`DEC-INDEX-PRESERVE-EMBEDDINGS-ON-SCHEMA-MIGRATION`, `INV-INDEX-EMBEDDINGS-SCHEMA-PRESERVATION`)**: Because `CMP-GRAPH-STORAGE` preserves `spec_embeddings` across unrelated `SCHEMA_VERSION` bumps whenever `EMBEDDING_SCHEMA_VERSION` in `src/eidos/core/index/storage.py` matches, any change to `HARRIER_MODEL_ID`, `HARRIER_HF_REVISION`, `HARRIER_EMBEDDING_DIM`, `HARRIER_DOC_MAX_LENGTH`, `HARRIER_STS_INSTRUCTION`, vector normalization/dtype, or `format_spec_embedding_document()` MUST bump `EMBEDDING_SCHEMA_VERSION` in `storage.py` so incompatible embeddings are dropped and rebuilt cleanly.
