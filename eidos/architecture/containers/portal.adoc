= Container: Eidos Living Web Portal (C4 Level 2 Container)
:toc: left

== Architectural Boundary
This container represents the graphical web interface under `src/eidos/portal/` and packaged bundle assets under `assets/portal/`. It enables non-IDE stakeholders (product managers, architects, designers, and compliance officers) to visually navigate the living architecture, inspect C4 topologies, simulate architectural blast radius directly on C4 SVG nodes (`INV-PORTAL-STATIC-SCALABILITY`), monitor SpecDelta lifecycles and real-time workspace drift, and explore multi-design system tokens via hash-based deep linking (`DEC-PORTAL-HASH-ROUTING`).

== Internal Structure & Key Mechanisms
* **Dual Deployment Modes & Loopback Isolation (`CTR-EIDOS-PORTAL`, `DEC-PORTAL-STRICT-SANITIZATION-AND-SSE-CHUNKING`)**: Operates either as a same-origin isolated HTTP + Server-Sent Events preview server (`eidos portal serve`, validating `Host` headers and streaming live `eidos/` + `src/` + `tests/` drift/version updates over `/api/events` alongside `/api/data`, `/api/version`, `/api/drift`, and `/api/validate`) or as a zero-backend static site export (`eidos portal build`, emitting chunked `./assets/*` + `./specs/<id>.json` by default or a standalone `index.html` with `--single-file`).
* **Strict XSS Sanitization & Payload Chunking (`DEC-PORTAL-PAYLOAD-DEDUP-AND-CLIENT-BFS`, `DEC-PORTAL-STRICT-SANITIZATION-AND-SSE-CHUNKING`)**: Configures Mermaid with `securityLevel: "strict"` and DOM-delegated C4 drill-down listeners, enforces DOMPurify `SANITIZE_DOM: true` and `idprefix: "spec-"` on AsciiDoc bodies, restricts `tokens.manifest` inside `repo_root`, and lazy-loads per-spec `./specs/<id>.json` body chunks on SpecReader open while retaining pre-computed `data.edges` and `data.validation` for instant client-side Blast Radius simulation.

== Air-Gapped Bundle (`INV-PORTAL-AIR-GAPPED-BUNDLE`)
Both the single-file bundle served by `eidos portal serve` (and `eidos portal build --single-file`) and the default chunked static export (`eidos portal build`, emitting local `./assets/*` and `./specs/<id>.json`) load zero scripts, stylesheets, fonts, or other subresources from remote origins, so C4 diagrams and the specification reader work in air-gapped environments (and over `file://` with `--single-file`):

* **Mermaid.js** is imported from npm at the version pinned in `package.json` / `pnpm-lock.yaml` (lazy `import()` folded inline by the single-file build; the ELK layout engine is not shipped, `dagre` is the portal layout).
* **Asciidoctor.js** (`@asciidoctor/core`, `safe: 'secure'`) renders specification AsciiDoc bodies directly in the browser; `include::` is unsupported in the browser.
* **Fonts**: Geist and Geist Mono latin `woff2` subsets from `@fontsource`; the `Inter` / `JetBrains Mono` stacks in `tokens.json` fall through to system fonts.
* **Build & Packaging**: `cd src/eidos/portal/frontend && pnpm build:assets` runs the Vite build and `scripts/build_assets.py`, which writes deterministic gzip-compressed `assets/portal/bundle.html.gz` (marked `linguist-generated=true` in `.gitattributes`) and `assets/portal/favicon.svg`, and refuses bundles with remote references, more than one `</head>`, or more than 5 MiB. CI enforces bundle parity via `python3 scripts/build_assets.py --check`, and `hatch_build.py` synchronizes assets during `uv build`. Node.js is a build-time dependency only (`INV-PORTAL-ZERO-NODE-DEP`).

== Quality Attributes & Operational Policies
* **Zero Runtime Node.js Dependency (`INV-PORTAL-ZERO-NODE-DEP`)**: End users run `eidos portal serve` and `eidos portal build` using only Python and the pre-compiled `assets/portal/bundle.html.gz` asset.
* **Air-Gapped & Offline Integrity (`INV-PORTAL-AIR-GAPPED-BUNDLE`)**: Zero external CDN, font, or telemetry requests at runtime.
