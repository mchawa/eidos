= Container: Architectural Knowledge Graph & Retrieval Index (C4 Level 2 Container)
:toc: left

== Architectural Boundary
This container represents the embedded relational, lexical, and optional semantic indexing engine under `src/eidos/core/index/`. `ArchitecturalIndex` in `graph_index.py` acts as a thin facade delegating persistence, schema versioning, incremental sync, FTS5/CTE graph queries, optional ONNX semantic embedding fusion, and tiered context slicing to focused submodules (`storage.py`, `sync.py`, `query.py`, `context.py`, `semantic.py`, and `ast_indexer.py`). It persists and manages the local SQLite knowledge graph (`eidos/.cache/index.db`) via per-thread `threading.local()` connections and advisory lockfile coordination (`index.db.lock`), providing sub-millisecond catalog lookups, incremental zero-drift synchronization, AST-derived component and container dependency graphs, FTS5 BM25 + optional Harrier Hybrid RRF search, recursive CTE blast-radius traversal, and tiered context slicing for AI coding agents and CLI commands.

== Internal Structure & Key Mechanisms
* **Embedded SQLite WAL + FTS5 Knowledge Graph (`DEC-INDEX-SQLITE-WAL`, `DEC-INDEX-FLOCK-WAL-AND-PINNED-ONNX`)**: Persists living specification entities (`entities`), typed directed relationships (`edges`, rebuilt in bounded batches without hitting `SQLITE_MAX_EXPR_DEPTH`), governed file digests (`indexed_files`), ownership rules (`symbol_mappings`), polyglot AST symbols (`code_symbols`, including class `method` entries and `is_test = 1` automated test symbols), weighted lexical search (`specs_fts`), inverted token index (`file_tokens_fts`), validation/test caches (`spec_validation_cache`, `test_binding_cache`), and content-addressed dense embeddings (`spec_embeddings`) in a local SQLite WAL database (`SCHEMA_VERSION` `2.19.0`) without `PRAGMA mmap_size`.
* **Incremental Synchronization & Polyglot AST Extraction (`DEC-INDEX-CPP-MACRO-NORMALIZATION`)**: Performs single-pass `os.scandir` mtime and SHA-256 dirty checks (debounced via `_last_synced_check`) across `eidos/`, governed `source_path` trees, and test suites, extracting polyglot symbols, interface/trait member signatures, overload-disambiguated symbol keys, Rust/C# trait/interface public items, and cross-file imports across 17 languages via `ast-grep-py` (`SgRoot`).
* **Two-Tier Retrieval, Pinned ONNX Verification & Tiered Context Slicing (`DEC-INDEX-FTS-RETRIEVAL-HYGIENE`, `DEC-INDEX-HYBRID-SEMANTIC-RRF`, `DEC-INDEX-FLOCK-WAL-AND-PINNED-ONNX`)**: Combines column-weighted FTS5 BM25 ranking, `{a,b}` brace-glob file resolution, and optional gated Harrier-OSS-v1-0.6B ONNX Hybrid RRF (pinned to an immutable HuggingFace commit SHA with `Content-Length` + SHA-256 artifact verification, 3-file `fp32` validation, and atomic `semantic_sync.lock` background worker locking) with calibrated token-budget compression (`anchor` <=300, `guardrails` <=1000, `deep` <=2500 tokens).

== Quality Attributes & Operational Policies
* **Sub-10ms Query & Sync Latency (`INV-AGENT-GRAPH-INDEX-FRESHNESS`)**: Warm dirty checks and incremental single-file syncs complete in <5ms; recursive CTE blast-radius, FTS5 queries, and `spec_embeddings` BLAS cosine scans (`0.22ms`) execute in sub-millisecond to <4ms latency.
* **Stateless Derived Cache (`DEC-INDEX-STATELESS-DERIVED-CACHE`, `POL-001`)**: `eidos/.cache/index.db` contains zero unrecoverable state and automatically drops and rebuilds whenever `SCHEMA_VERSION` changes.
* **Offline Determinism & Opt-In Local Semantic Indexing (`POL-004`, `INV-AGENT-HYBRID-SEMANTIC-FALLBACK`)**: Core CLI workflows use stdlib `sqlite3` and deterministic AST/BM25 algorithms with zero required model weights, while optional `eidos-ai[semantic]` runs 100% locally on CPU with zero remote API calls and 100% deterministic fallback to FTS5 BM25.
