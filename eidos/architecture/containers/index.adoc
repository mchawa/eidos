= Container: Architectural Knowledge Graph & Retrieval Index (C4 Level 2 Container)
:toc: left

== Architectural Boundary
This container represents the embedded relational, lexical, and optional semantic indexing engine under `src/eidos/core/index/`. `ArchitecturalIndex` in `graph_index.py` acts as a thin facade delegating to 9 disjoint C4 Level 3 components (`DEC-ARCH-MODULAR-COMPONENT-COHESION`): `CMP-GRAPH-STORAGE` (`storage.py`, `graph_index.py`), `CMP-INCREMENTAL-SYNC-ENGINE` (`sync.py`, `code_graph.py`, `spec_edges.py`), `CMP-FTS-QUERY-ENGINE` (`fts_query.py`), `CMP-GRAPH-TRAVERSAL-ENGINE` (`traversal.py`), `CMP-TIERED-CONTEXT-COMPRESSOR` (`context.py`, `context_globs.py`, `context_models.py`), `CMP-SEMANTIC-EMBEDDING-ENGINE` (`semantic.py`), `CMP-AST-SYMBOL-INDEXER` (`ast_indexer.py`, `ast_preprocess.py`, `ast_imports.py`), `CMP-HTTP-TOPOLOGY-LINKER` (`ast_http.py`, `http_linker.py`), and `CMP-AST-DIFF-CLASSIFIER` (`ast_diff.py`), while retaining a thin container-owned `query.py` compatibility shim. It persists and manages the local SQLite knowledge graph (`eidos/.cache/index.db`) via per-thread `threading.local()` connections, re-entrant advisory lockfile coordination (`index.db.lock`), and `BEGIN IMMEDIATE` write transactions (`DEC-INDEX-SERIALIZED-SYNC-AND-CSHARP-NAMESPACES`), providing sub-millisecond catalog lookups, incremental zero-drift synchronization, AST/namespace/ProjectReference and static client-to-endpoint HTTP (`ast_http`) dependency graphs, explicit epistemic `provenance` and 3-tier certainty (`observed`, `derived`, `inferred`), FTS5 BM25 + optional Harrier Hybrid RRF search, recursive CTE blast-radius traversal, and tiered context slicing for AI coding agents and CLI commands.

== Internal Structure & Key Mechanisms
* **Embedded SQLite WAL + FTS5 Knowledge Graph (`DEC-INDEX-SQLITE-WAL`, `DEC-INDEX-FLOCK-WAL-AND-PINNED-ONNX`, `DEC-INDEX-HTTP-LINKING-AND-PROVENANCE`, `DEC-INDEX-PERSISTENT-PUBLIC-SURFACE-CACHE`)**: Persists living specification entities (`entities`), typed directed relationships (`edges` with `provenance` and `file:line` `evidence`), per-call-site cross-boundary couplings (`code_couplings`), governed file digests (`indexed_files`), ownership rules (`symbol_mappings`), polyglot AST symbols (`code_symbols`, including `http_endpoint`, `http_request`, class `method` entries, and `is_test = 1` automated test symbols), weighted lexical search (`specs_fts`), inverted token index (`file_tokens_fts`), validation/test/public-surface/Mermaid caches (`spec_validation_cache`, `test_binding_cache`, `public_surface_cache`, `mermaid_validation_cache`), and content-addressed dense embeddings (`spec_embeddings`) in a 14-table local SQLite WAL database (`SCHEMA_VERSION` `2.22.0`) without `PRAGMA mmap_size`.
* **Incremental Synchronization, Static HTTP Auto-Linking & Polyglot AST Extraction (`DEC-INDEX-CPP-MACRO-NORMALIZATION`, `DEC-INDEX-HTTP-LINKING-AND-PROVENANCE`)**: Performs single-pass `os.scandir` mtime and SHA-256 dirty checks (debounced via `_last_synced_check`) across `eidos/`, governed `source_path` trees, and test suites, extracting polyglot symbols, interface/trait member signatures, overload-disambiguated symbol keys, Rust/C# trait/interface public items, server HTTP routes (`http_endpoint`), client HTTP calls (`http_request`, matched non-test-only against endpoints and OpenAPI/`rest_http` `CTR-*` contracts as `ast_http` edges), and cross-file imports across 17 languages via `ast-grep-py` (`SgRoot`).
* **Two-Tier Retrieval, Pinned ONNX Verification & Tiered Context Slicing (`DEC-INDEX-FTS-RETRIEVAL-HYGIENE`, `DEC-INDEX-HYBRID-SEMANTIC-RRF`, `DEC-INDEX-FLOCK-WAL-AND-PINNED-ONNX`)**: Combines column-weighted FTS5 BM25 ranking, `{a,b}` brace-glob file resolution, and optional gated Harrier-OSS-v1-0.6B ONNX Hybrid RRF (pinned to an immutable HuggingFace commit SHA with `Content-Length` + SHA-256 artifact verification, 3-file `fp32` validation, and atomic `semantic_sync.lock` background worker locking) with calibrated token-budget compression (`anchor` <=300, `guardrails` <=1000, `deep` <=2500 tokens).

== Quality Attributes & Operational Policies
* **Sub-10ms Query & Sync Latency & Strict-Freshness Lock Diagnostics (`INV-AGENT-GRAPH-INDEX-FRESHNESS`, `INV-INDEX-FRESHNESS-AND-LOCK-DIAGNOSTICS`)**: Warm dirty checks and incremental single-file syncs complete in <5ms; recursive CTE blast-radius, FTS5 queries, and `spec_embeddings` BLAS cosine scans (`0.22ms`) execute in sub-millisecond to <4ms latency. Opportunistic cache reads/writes never stall on `index.db.lock`, while freshness-critical waits emit `sys.stderr` holder-PID notices before waiting cleanly for the active writer to commit.
* **Stateless Derived Cache (`DEC-INDEX-STATELESS-DERIVED-CACHE`, `POL-001`)**: `eidos/.cache/index.db` contains zero unrecoverable state and automatically drops and rebuilds whenever `SCHEMA_VERSION` changes.
* **Offline Determinism & Opt-In Local Semantic Indexing (`POL-004`, `INV-AGENT-HYBRID-SEMANTIC-FALLBACK`)**: Core CLI workflows use stdlib `sqlite3` and deterministic AST/BM25 algorithms with zero required model weights, while optional `eidos-ai[semantic]` runs 100% locally on CPU with zero remote API calls and 100% deterministic fallback to FTS5 BM25.
