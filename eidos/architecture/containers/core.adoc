= Container: Eidos Living Specification Core Engine (C4 Level 2 Container)
:toc: left

== Architectural Boundary
This container represents the foundational library under `src/eidos/core/` (`spec/`, `lifecycle/`, and `workspace/` subpackages) and bundled schemas and AsciiDoc prose templates under `assets/schemas/`. It owns all specification parsing, JSON Schema validation, zero-config project and monorepo sub-project path resolution, minimal blueprint scaffolding across all 15 living specification types, W3C token management, SpecDelta lifecycle state machines, and reference checking. It explicitly excludes SQLite persistence and lexical/AST indexing (delegated to `CNT-EIDOS-INDEX`), Git diff and drift evaluation (delegated to `CNT-EIDOS-VCS`), CLI presentation (`CNT-EIDOS-CLI`), and web portal rendering (`CNT-EIDOS-PORTAL`).

== Internal Structure & Key Mechanisms
`CNT-EIDOS-CORE` is structured into three internal subpackages plus the packaged `assets/schemas/v1/` schema bundle:

* **Specification Parsing & Validation (`src/eidos/core/spec/`, `DEC-CORE-NON-EMPTY-SCHEMA-STRINGS-AND-DELTA-SHOW`, `DEC-CORE-STRICT-DELTA-AND-SURFACE-VERIFICATION`)**: Parses AsciiDoc documents with YAML frontmatter via Rust-backed `fastyaml-rs` (tolerating trailing `---` document end markers and surfacing `UnicodeDecodeError` cleanly), resolves entity types parent-directory-first, and validates all 16 v1 document types against JSON Schema Draft 2020-12 (`minLength: 1` / non-whitespace `non_empty_string`, `minItems: 1` `code_paths`, and `"cli"` client platform), recursive `x-eidos-ref` cross-references, bidirectional multi-protocol `CTR-*` contract parity (`cli_args` imported sub-apps, `openapi`, `protobuf` messages/enums, `graphql`, `python_protocol`), per-class `== Public Surface` AST parity, repository-contained `tokens.manifest` files, and active `file::symbol` `INV-*` test bindings.
* **Specification & SpecDelta Lifecycle (`src/eidos/core/lifecycle/`, `DEC-CORE-STRICT-DELTA-AND-SURFACE-VERIFICATION`)**: Orchestrates greenfield repository initialization (`init_repository`), live catalog-aware blueprint generation without nonexistent placeholder IDs, quote-safe YAML scalar updates, ambiguity-checked ID lookups, cross-branch collision-free SpecDelta IDs, non-empty `mutations` verification across `add`/`modify`/`deprecate`/`remove` (with CRLF-normalized and shallow-clone-safe baselines), lossless multi-line exploration archiving, tombstone pattern auditing, and dynamic `SYS-*` Keep a Changelog compilation.
* **Workspace & Asset Resolution (`src/eidos/core/workspace/`)**: Resolves repository roots (`eidos/`), enclosing `.git` worktree roots (`find_git_root`), cached `.gitignore`-aware monorepo sub-project boundaries (`discover_nested_subproject_roots`), `{a,b}` brace-glob `source_path` ownership rules, Git-tracked file preservation inside excluded directory names, repo-relative `.agents` filtering, and bundled schema/template assets.

== Quality Attributes & Operational Policies
* **Stateless Git-Native Execution (`POL-001`)**: Operates statelessly over the Git working tree and commit graph; `eidos/.cache/index.db` is strictly an ephemeral, disposable acceleration cache.
* **Deterministic Validation & Serialization**: Schema validation, reference resolution, and `orjson` report serialization produce deterministic ordering and exit codes with zero external network or AI API calls (`POL-004`).
* **Zero Legacy Shims**: Enforces `additionalProperties: false` across all 16 v1 schemas and derives schema paths 1:1 from `type`.
