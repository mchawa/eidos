= Container: Eidos Living Specification Core Engine (C4 Level 2 Container)
:toc: left

== Architectural Boundary
This container represents the foundational library under `src/eidos/core/` (`spec/`, `lifecycle/`, and `workspace/` subpackages) and bundled schemas and AsciiDoc prose templates under `assets/schemas/`. It owns all specification parsing, JSON Schema validation, zero-config project and monorepo sub-project path resolution, minimal blueprint scaffolding across all 15 living specification types, W3C token management, SpecDelta lifecycle state machines, and reference checking. It explicitly excludes SQLite persistence and lexical/AST indexing (delegated to `CNT-EIDOS-INDEX`), Git diff and drift evaluation (delegated to `CNT-EIDOS-VCS`), CLI presentation (`CNT-EIDOS-CLI`), and web portal rendering (`CNT-EIDOS-PORTAL`).

== Internal Structure & Key Mechanisms
`CNT-EIDOS-CORE` is structured into three internal subpackages plus the packaged `assets/schemas/v1/` schema bundle:

* **Specification Parsing, Validation & Architectural Conformance (`src/eidos/core/spec/`, `DEC-CORE-NON-EMPTY-SCHEMA-STRINGS-AND-DELTA-SHOW`, `DEC-CORE-STRICT-DELTA-AND-SURFACE-VERIFICATION`, `DEC-CORE-SCOPED-PUBLIC-SURFACE-AND-LRU-CACHE`, `DEC-CORE-DECLARATIVE-IMPORT-BOUNDARIES`, `DEC-CORE-MODERN-REST-PARITY-ONLY`, `DEC-CORE-CANONICAL-CONTRACT-PROTOCOL-ENUM`, `DEC-ARCH-MODULAR-COMPONENT-COHESION`)**: Parses AsciiDoc documents with YAML frontmatter via Rust-backed `fastyaml-rs`, validates all 16 v1 document types against JSON Schema Draft 2020-12 (including the strict canonical 10-value `tech/contract` `protocol` enum `openapi`, `rest_http`, `protobuf`, `graphql`, `asyncapi`, `json_schema`, `json_rpc_stdio`, `python_protocol`, `cli_args`, and `other` with conditionally required `custom_protocol`, plus directory and glob `specification_file` targets for `rest_http`), client-scoped `design/screen` placement and `CLT-*.screens` ownership (`INV-DESIGN-SCREEN-CLIENT-OWNERSHIP`), and W3C DTCG `tokens.manifest` containment (`CMP-SPEC-VALIDATOR`: `validator.py`, `design_validation.py`), verifies bidirectional multi-protocol `CTR-*` contract parity across `cli_args`, `python_protocol`, `openapi`, modern `rest_http` (ASP.NET Core controllers/Minimal APIs plus polyglot REST frameworks with opt-in `[Authorize]`/`[AllowAnonymous]` checks, intentionally excluding legacy SOAP/WCF and Web API 2), `protobuf`, `graphql`, and `json_schema` (`CMP-CONTRACT-PARITY-VALIDATOR`: `contract_parity.py`, `cli_contract_parity.py`), and enforces scoped `== Public Surface` AST parity, non-blocking `ValidationReport.warnings` (over-scoped `CMP-*.source_path` entries, 2-tier lazy prose symbol drift via `DEC-CORE-ADVISORY-VALIDATION-WARNINGS`, active-to-`deprecated`/`retired` `x-eidos-ref` dependency warnings, and undeclared `CNT-*.tier` warnings against configured `ARCH-*.import_boundaries.tier_rules` via `INV-LIFECYCLE-AND-TIER-GUARDRAIL-WARNINGS`), plus executable `import_boundaries` / `ratchet_baseline` evaluation (`CMP-ARCHITECTURE-BOUNDARY-VALIDATOR`: `surface_validator.py`, `boundary_validator.py`).
* **Specification & SpecDelta Lifecycle (`src/eidos/core/lifecycle/`, `DEC-CORE-STRICT-DELTA-AND-SURFACE-VERIFICATION`)**: Orchestrates greenfield repository initialization (`init_repository`), live catalog-aware blueprint generation, quote-safe YAML scalar updates, ambiguity-checked ID lookups, cross-branch collision-free SpecDelta CRUD (`delta_engine.py`), stateless Git-baseline and declarative `expect:` post-condition verification (`delta_verifier.py`), lossless two-tier SpecDelta and Exploration archiving (`archiver.py`), tombstone pattern auditing, and dynamic `SYS-*` Keep a Changelog compilation.
* **Workspace & Asset Resolution (`src/eidos/core/workspace/`)**: Resolves repository roots (`eidos/`), enclosing `.git` worktree roots (`find_git_root`), cached `.gitignore`-aware monorepo sub-project boundaries (`discover_nested_subproject_roots`), `{a,b}` brace-glob `source_path` ownership rules, Git-tracked file preservation inside excluded directory names, repo-relative `.agents` filtering, and bundled schema/template assets.

== Quality Attributes & Operational Policies
* **Stateless Git-Native Execution (`POL-001`)**: Operates statelessly over the Git working tree and commit graph; `eidos/.cache/index.db` is strictly an ephemeral, disposable acceleration cache.
* **Deterministic Validation & Serialization**: Schema validation, reference resolution, and `orjson` report serialization produce deterministic ordering and exit codes with zero external network or AI API calls (`POL-004`).
* **Zero Legacy Shims**: Enforces `additionalProperties: false` across all 16 v1 schemas and derives schema paths 1:1 from `type`.
