= Contract: Eidos CLI Interface
:toc: left

== Optional Repository Configuration (`eidos/eidos.yaml`) & Precedence
All configurable commands optionally read `<eidos_dir>/eidos.yaml` (`eidos/eidos.yaml` or `<subproject>/eidos/eidos.yaml`) and documented `EIDOS_*` environment variables under strict deterministic precedence: `CLI flags > EIDOS_* env vars > eidos/eidos.yaml > built-in defaults`. Explicit CLI options (including boolean negation flags) always win over environment variables and `eidos/eidos.yaml`; invalid config files or invalid `EIDOS_*` values fail closed with exit code `1`.

== Monorepo Root Auto-Routing & Multi-Subproject Governance
When invoked from a Git monorepo root containing nested sub-project `eidos/` directories (both sub-projects-only layouts and root + sub-projects layouts) without an explicit `--path`:
* **Path-Hint & Diff Auto-Routing**: `eidos context -f <path>` (including planned non-existent subdirectories), `eidos index blast-radius <path>`, `eidos memory add -f <path>`, and path-shaped `eidos spec` / `eidos delta` / `eidos memory` targets auto-route to the owning sub-project with sub-project-relative path normalization (failing closed with `discovered_subprojects` when `--file` spans multiple sub-projects). `eidos context --uncommitted/--base` and `eidos memory add --from-diff` auto-route when exactly one project has changes and fail closed listing `discovered_subprojects` when multiple projects are dirty.
* **Fail-Closed Ambiguity Guards & Root Hints**: Commands requiring a single `eidos/` catalog (`eidos index`, `eidos spec`, `eidos delta`, `eidos memory`) fail closed with exit code `1` and `discovered_subprojects` hints at rootless monorepos (preventing empty `<git_root>/eidos/.cache/index.db` creation), and root `eidos index search`/`find-symbol`/`repo-map` queries in hybrid monorepos surface `nested_subprojects`.
* **Multi-Subproject `drift`, `validate`, and `hook`**: `eidos drift` auto-routes to the dirty sub-project or aggregates all dirty (or rootless) projects under `monorepo_projects` (preventing false-green root runs), `eidos validate` aggregates discovered projects under `monorepo_projects`, and `eidos hook` baselines and evaluates all modified root and nested sub-projects (ignoring cache-only `eidos/` directories).

== Command Specifications

=== `eidos --version` & `eidos --path`
Displays current Eidos engine version (e.g. `eidos 0.32.0`) or sets a global target project / `eidos/` path before any subcommand.
* **Options**:
  - `--version`, `-V`: Show Eidos engine version and exit.
  - `--path`, `-p`: Global path to target project or `eidos` specifications directory (propagated to every subcommand including `validate`, `drift`, `context`, `index`, `spec`, `delta`, `memory`, `config`, `portal`, `plugin`, `doctor`, `hook`, and `init`; overridden whenever the subcommand receives its own `--path`, `--project-dir`, or positional `PATH`).
* **Exit Code**: 0

=== `eidos info`
Displays current engine version, loaded v1 schemas, and available agent plugin targets.
* **Exit Code**: 0

=== `eidos config`
Scaffolds, inspects, and views the offline schema for optional repository configuration (`eidos/eidos.yaml`) under Setup & Workspace.
* **Sub-commands**:
  - `init [--force] [--path <path>] [--json]`: Scaffolds a commented, schema-validated starter `<eidos_dir>/eidos.yaml` into an initialized workspace (refusing to overwrite an existing file with exit code `1` unless `--force` is passed).
  - `show [--path <path>] [--json]`: Displays the active config file path (or `absent`), every effective resolved setting (`EIDOS_*` env > `eidos/eidos.yaml` > built-in defaults), and per-key `default` / `file` / `env` source attribution, failing closed with exit code `1` on invalid config or env values.
  - `schema [--json]`: Introspects `assets/schemas/config/eidos-config.v1.schema.yaml` offline, listing all seven sections, allowed keys, types/enums, built-in defaults, and mapped `EIDOS_*` environment variables.
* **Exit Codes**:
  - `0`: Operation succeeded.
  - `1`: Existing `eidos/eidos.yaml` without `--force`, missing `eidos/` directory, or invalid `eidos/eidos.yaml` / `EIDOS_*` environment value.

=== `eidos validate [PATH] [--fail-on-warnings/--no-fail-on-warnings] [--json]`
Validates all specification documents under `PATH` (defaults to `./eidos`) against the bundled JSON/YAML schemas—plus automatic fail-closed validation of optional `<eidos_dir>/eidos.yaml` (`schema_errors["eidos/eidos.yaml"]`) and configurable `drift.checks` severities—and verifies cross-references, embedded Mermaid (`[mermaid]` / `[source,mermaid]`) diagram syntax (in-process QuickJS `mermaid.parse()` backed by `mermaid_validation_cache`), `== Public Surface` AST symbols, active `test_binding` coverage, and contract parity.
* **Arguments**: `PATH` (Optional directory path)
* **Options**:
  - `--fail-on-warnings/--no-fail-on-warnings`: Escalate non-empty advisory `warnings` to exit code `1` (resolves default from `drift.fail_on_warnings` in `eidos/eidos.yaml` or `EIDOS_DRIFT_FAIL_ON_WARNINGS`; built-in default `False`).
  - `--json`: Output a compact machine-readable JSON validation report (`is_clean`, `total_docs`, `valid_docs`, `broken_references`, non-blocking advisory `warnings`, `warning_count`, repo-relative `schema_errors`, and any invalid `documents`).
* **Exit Codes**:
  - `0`: All specifications (and optional `eidos/eidos.yaml`) are valid (advisory `warnings` do not fail exit code `0` unless effective `fail_on_warnings` is enabled).
  - `1`: One or more validation errors, invalid `eidos/eidos.yaml`, broken cross-references, or warnings under `--fail-on-warnings` found.

=== `eidos context [--file PATH] [--component ID] [--task PROMPT] [--uncommitted] [--base REF] [--head REF] [--tier TIER] [--semantic/--no-semantic] [--json] [--path PATH]`
Extracts a compact, token-efficient architectural subgraph context slice (C4 components, bound contracts, domain capabilities, active invariants, governing policies, structured epistemic `provenance_tags` on `guardrails` and `deep` tiers, and optional secondary budgeted team operational `memories` (`MEM-*`) with computed freshness and clipped `guidance` on `guardrails`/`deep` when active memories match).
* **Options**:
  - `--file, -f`: Target source file path(s), comma-separated paths, or quoted glob patterns including `{a,b}` brace globs (e.g. `'apps/*/Dockerfile'`, `'src/**/*.{ts,tsx}'`).
  - `--component, -c`: Target component identifier (e.g. `CMP-EIDOS-CLI`).
  - `--task, -t`: Free-text task description or prompt.
  - `--uncommitted, -u`: Slice deduplicated architectural context for all uncommitted working-tree and staged Git changes.
  - `--base, -b`: Slice deduplicated architectural context for files changed relative to a base Git reference (e.g. `origin/main`).
  - `--head`: Head Git reference when slicing with `--base` (default: `HEAD`).
  - `--tier, -T`: Context tier budget: `anchor` (~140 tokens), `guardrails` (default, ~260-890 tokens), or `deep` (~500-1500 tokens), configurable via `context.default_tier` / `EIDOS_CONTEXT_TIER`.
  - `--semantic/--no-semantic`: Enable or disable opt-in Hybrid RRF semantic fusion when `spec_embeddings` are available (defaults to `context.semantic.enabled` / `EIDOS_SEMANTIC_ENABLED`; built-in default `--semantic`).
  - `--json`: Output context slice as machine-readable JSON instead of Markdown.
  - `--path, -p`: Path to specifications directory (default: `./eidos`).
* **Exit Codes**:
  - `0`: Slice successfully extracted (including clean empty-diff responses).
  - `1`: Missing specifications directory, invalid `eidos/eidos.yaml`, or invalid `--base` Git reference.

=== `eidos index`
Manages the embedded SQLite architectural knowledge graph and FTS5 hybrid search index (`eidos/.cache/index.db`).
* **Sub-commands**:
  - `status [--path <path>] [--json]`: Displays index health, `SCHEMA_VERSION` (`2.23.0`), `edge_counts_by_provenance`, AST parser engine telemetry (`ast-grep` vs `python-ast`), symbol breakdown by syntax kind, test invariant assertion metrics, cache file size, and continuous code-aware dirty status. Supports `--json` for programmatic agent consumption.
  - `sync [--path <path>] [--force] [--semantic/--no-semantic] [--json]`: Synchronizes or rebuilds the knowledge graph index, resolving semantic embedding refresh default from `context.semantic.enabled` in `eidos/eidos.yaml` with explicit `--semantic/--no-semantic` override, or emitting machine-readable JSON telemetry (`--json`).
  - `search <query> [--limit <n>] [--semantic/--no-semantic] [--path <path>] [--json]`: Performs BM25 full-text search with optional Harrier Hybrid RRF fusion across titles, requirements, and invariants, tagging each match with epistemic `provenance` (`fts_bm25`, `semantic_rrf`, `hybrid_rrf`) and `confidence` (`observed` for `fts_bm25`, `inferred` for `semantic_rrf` / `hybrid_rrf`).
  - `blast-radius <symbol_or_path> [--depth <n>] [--min-confidence <level>] [--path <path>] [--json]`: Computes the transitive dependency and governance blast radius for a canonical entity ID, AST code symbol, specification file path, or source file path, filtering traversal edges by `--min-confidence` (`inferred` default, `derived`, or `observed`) and reporting `query`, `resolved_entities`, `entity_id`, `min_confidence`, and `neighbors` (with `provenance`, `confidence`, `via_rel_type`, and `evidence`) in `--json` output.
  - `repo-map [--max-tokens <tokens>] [--json] [--path <path>]`: Generates a token-budgeted structural repo map outline (classes, functions, methods, routes; default max tokens resolved from `context.repo_map_max_tokens`) for AI coding agents in Markdown or JSON (`--json`).
  - `find-symbol <query> [--limit <n>] [--json] [--path <path>]`: Locates code symbols (including class methods, `http_endpoint` / `http_request` symbols, and automated test symbols) across polyglot AST source files and links them to associated living component specifications. Each `--json` match carries `provenance`, `confidence`, `file_path` (the owning *specification* path), and a `location` object (`file`, `line_start`, `line_end`, `signature`, `parent_symbol`) pointing at the source definition, or `null` for non-AST matches.
  - `semantic [action] [--model <variant>] [--force] [--path <path>] [--json]`: Manages and inspects the optional SHA-256 verified Harrier-OSS-v1-0.6B ONNX semantic embedding index (`status`, `setup`, or `sync`, resolving `--model` from `context.semantic.variant` and mirror base URL from `context.semantic.model_mirror_url`).
  - `health [--path <path>] [--json]`: Displays a deterministic architecture governance health scorecard quantifying source file ownership coverage (and unowned files), active `CNT-*`/`CMP-*` `== Public Surface` coverage, verified `CTR-*` `specification_file` coverage, active `CAP-*` bound-invariant coverage, validation warning counts, and `ratchet_baseline` import debt in Rich table or `--json` format.

=== `eidos memory`
Manages Git-native team operational memories (`type: agent/memory`, `MEM-*`) stored under `eidos/memory/` and `eidos/memory/archive/`.
* **Sub-commands**:
  - `add --title <title> [--summary <summary>] [--category <feedback|project|reference>] [--guidance <text>] [--why <text>] [--entity <id>] [--file <path_or_glob>] [--auto-entities/--no-auto-entities] [--from-diff] [--expires <YYYY-MM-DD|none>] [--status <active|draft>] [--semantic/--no-semantic] [--path <path>] [--json]`: Creates a collision-resistant, AsciiDoc-sanitized, schema-validated `MEM-*` file (auto-deriving `summary` from `--guidance` or `--title` within 220 chars when omitted, auto-inferring owning `CMP-*`/`CNT-*` entities from `--file` / `--from-diff` paths when `--auto-entities` is enabled, and anchoring non-memory uncommitted files under `--from-diff`) stamped with `verified_at` and current Git `verified_commit`, applying `memory.default_expiry_days` when configured (unless `--expires none` opts out), and emitting non-blocking duplicate and spec-overlap hints.
  - `update <id_or_path> [--title <title>] [--category <feedback|project|reference>] [--summary <summary>] [--guidance <text>] [--why <text>] [--entity <id>] [--file <path_or_glob>] [--replace-targets] [--auto-entities/--no-auto-entities] [--expires <YYYY-MM-DD>] [--clear-expires] [--status <active|draft>] [--semantic/--no-semantic] [--path <path>] [--json]`: Updates an active or draft `MEM-*` entry in place (preserving untouched body sections losslessly, rejecting archived/promoted entries and personal `category: user` with exit code `1`), re-stamps `verified_at` and `verified_commit`, validates schema conformance before writing, and emits self-excluded overlap warnings.
  - `list [--category <cat>] [--status <status>] [--entity <id>] [--include-archived] [--path <path>] [--json]`: Lists team operational memories with computed freshness status (`fresh`, `stale`, `expired`, `unverifiable`) in Rich tabular or `--json` format.
  - `search <query> [--limit <n>] [--semantic/--no-semantic] [--path <path>] [--json]`: Searches active team memories via FTS5 BM25 and optional Harrier Hybrid RRF fusion.
  - `show <id_or_path> [--path <path>] [--json]`: Displays full frontmatter metadata, computed freshness diagnostics, and sanitized AsciiDoc body of an active or archived memory.
  - `verify <id_or_path> [--expires <YYYY-MM-DD>] [--clear-expires] [--path <path>] [--json]`: Re-stamps `verified_at` and `verified_commit` on a memory after verifying it against live code.
  - `archive <id_or_path> [--reason <text>] [--path <path>] [--json]`: Transitions a memory to `status: archived` and moves it into `eidos/memory/archive/`.
  - `audit [--check-overlaps/--no-check-overlaps] [--semantic/--no-semantic] [--path <path>] [--json]`: Runs a strictly non-blocking (exit code `0`) audit reporting freshness totals, stale/expired/unverifiable entries, duplicate pairs, and formal spec overlaps.
  - `promote <id_or_path> --to <decision|invariant|policy> --spec-id <spec_id> [--archive/--no-archive] [--path <path>] [--json]`: Verifies that `<spec_id>` exists in the living catalog (standalone `POL-*`, child `INV-*`, or embedded `DEC-*`), sets `status: promoted` and `promoted_to: <spec_id>`, and moves the memory to `eidos/memory/archive/` by default.

=== `eidos portal`
Manages the interactive Living Web Portal and documentation site export.
* **Sub-commands**:
  - `serve [--path PATH] [--host HOST] [--port PORT] [--open/--no-open]`: Launches the local interactive Eidos Living Web Portal HTTP + SSE (`/api/events`) server (resolving `--host`, `--port`, and `--open/--no-open` defaults from `portal.serve.*` in `eidos/eidos.yaml`).
  - `build [--path PATH] [--out OUT_DIR] [--single-file/--no-single-file]`: Exports the Living Web Portal as a self-contained static site using externalized local `./assets/*` and per-entity `./specs/<id>.json` body chunks by default, or inlines all JS, CSS, and spec bodies into a single standalone `index.html` when `--single-file` (or `portal.build.single_file: true`) is active (resolving `--out` and `--single-file/--no-single-file` from `portal.build.*` in `eidos/eidos.yaml`).
* **Exit Codes**:
  - `0`: Operation completed successfully.
  - `1`: Specifications directory not found or invalid `eidos/eidos.yaml`.

=== `eidos plugin`
Manages, validates, installs, updates, and uninstalls Eidos Agent Skills and lifecycle hooks across supported AI agent environments (Antigravity, Claude Code, Cursor, Aider, Cline, Kilo Code, OpenCode, OpenAI Codex, and GitHub Copilot, plus `all`).
* **Sub-commands**:
  - `install [TARGET] [--project-dir <path>] [--force/--no-force] [--launcher <launcher>] [--hooks/--no-hooks]`: Installs the 5 Eidos Agent Skills across `.agents/skills/` (Antigravity, Cursor, GitHub Copilot, OpenAI Codex, Cline, Kilo Code, OpenCode), `.claude/skills/` (Claude Code project-native skills), and `.aider/skills/` (Aider), projects the canonical root `AGENTS.md` block (plus `CLAUDE.md` `@AGENTS.md` import for Claude Code and comment-preserving `.aider.conf.yml` `read:` entry for Aider), falls back to `plugin.targets` in `eidos/eidos.yaml` when `[TARGET]` is omitted (exiting with code `2` when neither `[TARGET]` nor `plugin.targets` is configured), resolves `--launcher` from `plugin.launcher`, and when `--hooks` (or `plugin.hooks.install: true` without `--no-hooks`) is active wires each hook-capable target's native `Stop` / `PreToolUse` (`attempt_completion`) lifecycle hook (`.agents/hooks.json`, `.claude/settings.json`, `.cursor/hooks.json`, `.clinerules/hooks/PreToolUse`, `.github/hooks/hooks.json`, `.codex/hooks.json`).
  - `uninstall <TARGET> [--project-dir <path>]`: Uninstalls and cleans up the plugin, managed `AGENTS.md` / `CLAUDE.md` / `.aider.conf.yml` target entries, and tool hook configurations from project scope (`<TARGET>` remains strictly required for safety).
  - `version [--project-dir <path>]`: Displays and compares bundled vs installed plugin version and reports SemVer sync status (`up_to_date`, `outdated`, or `modified` when non-force installs skipped edited skills).
  - `update [TARGET] [--project-dir <path>] [--launcher <launcher>]`: Updates project-scoped plugin to the latest bundled version and syncs configurations, falling back to `plugin.targets` in `eidos/eidos.yaml` when `[TARGET]` is omitted (exiting with code `2` when neither `[TARGET]` nor `plugin.targets` is configured) and preserving each target's recorded `hooks` setting in `.eidos-manifest.json`.
  - `validate [PATH]`: Validates an Agent Skills package against `agentskills.io` frontmatter and SemVer 2.0.0 rules.
  - `info [PATH]`: Displays Agent Skills package metadata, skills, and lifecycle hooks.

=== `eidos spec`
Manages the living specification catalog (15 declarative specification & discovery blueprint types, excluding `delta/mutation` and `agent/memory`) and dynamic v1 schema introspection across all 17 bundled schemas: listing, authoring, inspecting, and deleting specifications.
* **Sub-commands**:
  - `list [--path <path>] [--type <type>] [--status <status>] [--include-archived] [--json]`: Lists all living specifications across the 15 living specification types (excluding SpecDeltas and excluding `archive/` subdirectories by default unless `--include-archived` is passed) in tabular or JSON format. Rejects `--type delta` with an error directing the caller to `eidos delta list`.
  - `show <id_or_path> [--path <path>]`: Displays detailed frontmatter metadata and preview of a living specification document (rejecting `delta/mutation` targets and directing the caller to `eidos delta show`).
  - `create <type> <id> --title <title> [--client <client>] [--design-system <ds>] [--path <path>]`: Scaffolds a minimal, schema-valid draft blueprint (`status: draft`, or `status: proposed` for `exploration`) across all 15 living specification types (`system`, `architecture`, `domain`, `capability`, `policy`, `persona`, `exploration`, `container`, `component`, `contract`, `design-system`, `ui-component`, `screen`, `client`, `flow`), requiring `--client` (`-c`) for `screen` blueprints (`eidos/design/clients/<client>/screens/<screen>.adoc`), accepting optional `--design-system` (`-d`) for `ui-component` and `client` blueprints (auto-resolving the first `DS-*` when omitted), auto-resolving parent references from existing catalog specs for other types (or omitting optional references), and rejecting `delta/mutation` (directing to `eidos delta create`) and `agent/memory` (directing to `eidos memory add`).
  - `delete <id_or_path> [--path <path>] [--force]`: Safely deletes a living specification document with cross-reference safety checks (rejecting `delta/mutation` targets and directing to `eidos delta delete`).
  - `schema [type] [--json]`: Dynamically loads and inspects bundled v1 YAML frontmatter schemas from `assets/schemas/v1/` across all 17 specification types, displaying required/optional keys, nested constraints, and schema-synthesized YAML frontmatter templates in Rich tabular or `--json` format.
  - `discover [--path <path>] [--json]`: Deterministically scans a polyglot repository's workspace manifests (`.csproj`/`.fsproj`, `pyproject.toml`, `package.json`, `go.mod`, `Cargo.toml`, `pom.xml`, `build.gradle`), schema-first interface schemas (OpenAPI, AsyncAPI, Protobuf, GraphQL, OpenRPC), code-first modern REST controller/router roots (`rest_http` with `route_count`, honoring `DEC-CORE-MODERN-REST-PARITY-ONLY`), and test directories to propose `CNT-*` containers, `CTR-*` contracts, `already_mapped` ownership status, and unmapped `source_path` gaps in Rich tabular or `--json` format.

=== `eidos delta`
Orchestrates SpecDeltas (`DLT-*`) throughout their semantic mutation lifecycle using flat storage (`eidos/deltas/` and `eidos/deltas/archive/`).
* **Sub-commands**:
  - `list [--path <path>] [--status <status>] [--include-archived] [--json]`: Lists SpecDeltas from flat `eidos/deltas/` (or including `eidos/deltas/archive/` when `--include-archived` is passed) with optional status filter (`proposed`, `in_review`, `approved`, `applied`, `rejected`, or `active`) and `--json` output.
  - `show <delta_id> [--path <path>] [--json]`: Displays frontmatter metadata, composable `mutations`, archival state, and AsciiDoc body of an active (`eidos/deltas/`) or archived (`eidos/deltas/archive/`) SpecDelta in Rich terminal or `--json` format (rejecting living specifications and directing to `eidos spec show`).
  - `status [id] [new_status] [--path <path>] [--json]`: Displays lifecycle status dashboard across the 5 canonical `delta_status` states (`proposed`, `in_review`, `approved`, `applied`, `rejected`) or transitions a specific SpecDelta's status when `id` and `new_status` are given.
  - `create [id] --title <title> [--kind <kind>] [--slug] [--path <path>]`: Scaffolds a new SpecDelta blueprint in flat storage `eidos/deltas/<id>.adoc` with status `proposed`, auto-detecting `vcs.branch` and `vcs.base_commit` from Git `HEAD` (`id` defaults to `auto`, `--slug` / `-s` appends a title-derived slug suffix, `--kind`: `feature, enabler, bug`; defaults to `feature`).
  - `verify <id_or_path> [--path <path>] [--json]`: Verifies that a SpecDelta declares at least one mutation and that all declared semantic mutations and `expect:` post-conditions exist in the living specifications catalog.
  - `conflicts [--path <path>] [--blast-radius/--no-blast-radius] [--strict] [--json]`: Detects direct `mutations[].target` collisions (flagging incompatible `remove`/`deprecate` vs. `modify` pairs as `high` severity) and optional 1-hop graph blast-radius overlaps across open non-terminal SpecDeltas (`proposed`, `in_review`, `approved`), exiting with code `1` under `--strict` when direct target conflicts exist.
  - `audit <id_or_path> [--path <path>] [--strict] [--json]`: Performs reverse-dependency blast-radius audit on entities removed or deprecated by the SpecDelta, classifying references into approved (historical, negative tests, cleanup routines, tombstones) vs. unacknowledged active leaks.
  - `apply <id_or_path> [--verify/--no-verify] [--path <path>] [--json]`: Verifies declared non-empty mutations against the living specification catalog by default (`--verify`, or bypass via `--no-verify`), validates the updated SpecDelta, and updates frontmatter status to `applied`.
  - `archive [--keep-recent <n>] [--explorations/--no-explorations] [--dry-run] [--json] [--path <path>]`: Partitions and slims older terminal SpecDeltas (`applied`/`rejected`) and Explorations (`adopted`/`discarded`) beyond the most recent `--keep-recent` (resolved from `lifecycle.archive.keep_recent`, default `15`, and `--explorations/--no-explorations` from `lifecycle.archive.include_explorations`, default `true`) into `eidos/deltas/archive/` and `eidos/explorations/archive/`, stripping verification `expect` scaffolding while retaining full multi-line exploration findings and schema-valid `.adoc` artifacts.
  - `delete <id_or_path> [--path <path>] [--force]`: Deletes a SpecDelta (`DLT-*`) file (rejecting non-delta living specifications and directing to `eidos spec delete`).
  - `changelog [--output <path>] [--unreleased/--no-unreleased] [--docs/--no-docs] [--stdout] [--path <path>]`: Compiles an auditable, Keep a Changelog compliant release history partitioned by Git release tags and frontmatter-verified applied SpecDeltas (`DLT-*`).

=== `eidos drift [--base REF] [--head REF] [--path PATH] [--uncommitted] [--strict/--no-strict] [--fail-on-warnings/--no-fail-on-warnings] [--warn-only/--no-warn-only] [--json]`
Detects spec-to-code drift, schema validity (including `<eidos_dir>/eidos.yaml` and `drift.checks` severities), executable `import_boundaries` and `ratchet_baseline` compliance, onboarding governance integrity, planned-mode SpecDelta mutation validity, and static invariant test coverage (including `design/` `UIC-*` invariants) across both Planned Mode and Direct Mode.
* **Options**:
  - `--base, -b`: Base git reference to compare against (defaults to `drift.base_ref` / `EIDOS_DRIFT_BASE_REF` when configured, ahead of `origin/main` or `main`).
  - `--head`: Head git reference (defaults to `HEAD`; commit-range checks without `--uncommitted` evaluate specs, `eidos/eidos.yaml`, `code_couplings`, and invariants isolated to the `--head` Git tree).
  - `--path, -p`: Path to the specifications directory (default: `eidos`).
  - `--uncommitted, -u`: Analyze uncommitted working tree and staged changes instead of branch diff.
  - `--strict/--no-strict`: Enforce strict drift detection on behavioral (`body_only_code_files`) modifications, requiring a substantive 1-hop specification update, an active SpecDelta target, or a modified bound test file (resolves default from `drift.strict` / `EIDOS_DRIFT_STRICT`).
  - `--json`: Output raw JSON verification result, including `structural_code_files`, `body_only_code_files`, `trivially_covered_files`, `boundary_violations`, `ratchet_shrink_candidates`, non-blocking `validation_warnings`, diff-scoped `ready_to_apply_deltas`, advisory `untouched_consumers`, and strictly non-blocking diff-scoped `affected_memories`.
  - `--fail-on-warnings/--no-fail-on-warnings`: Exit with code `1` when advisory `validation_warnings` or `ready_to_apply_deltas` are non-empty unless effective `warn_only` is set (resolves default from `drift.fail_on_warnings` / `EIDOS_DRIFT_FAIL_ON_WARNINGS`); `ratchet_shrink_candidates`, `untouched_consumers`, and `affected_memories` remain strictly non-blocking review advisories.
  - `--warn-only/--no-warn-only`: Do not exit with code 1 on drift (resolves default from `drift.warn_only` / `EIDOS_DRIFT_WARN_ONLY`).
* **Exit Codes**:
  - `0`: Specifications and code are synchronized, all schemas valid, invariant tests green (advisory `ratchet_shrink_candidates`, `untouched_consumers`, `affected_memories`, `validation_warnings`, and `ready_to_apply_deltas` do not fail exit code `0`, though `validation_warnings` and `ready_to_apply_deltas` escalate when effective `fail_on_warnings` is enabled).
  - `1`: Spec-to-code drift detected, shallow-clone history insufficient, specification or `eidos/eidos.yaml` validation errors, or non-empty `validation_warnings` / `ready_to_apply_deltas` under `--fail-on-warnings` (without `--warn-only`).

=== `eidos init [PATH]`
Bootstraps a repository with an Eidos living specification directory skeleton, a root `eidos/system.adoc`, `.gitkeep` files for empty directories, a self-contained `eidos/.gitignore`, and immediate schema validation. Note: `eidos init` initializes Eidos specifications cleanly without creating `eidos/eidos.yaml` by default (preserving any pre-existing `eidos/eidos.yaml` untouched; optional config can be scaffolded separately via `eidos config init` and plugins via `eidos plugin install`).
* **Arguments**: `PATH` (Optional directory path, defaults to `.`)
* **Options**:
  - `--title <title>`: Human-readable display title.
  - `--force`: Overwrite existing files if present (preserving an existing authored `system.adoc` when `--title` is omitted).
  - `--ci <provider>`: Optional turnkey CI workflow template to scaffold (`github` -> `.github/workflows/eidos-drift.yml`, or `gitlab` -> `.gitlab-ci.eidos.yml`), non-destructively preserving an existing workflow file unless `--force` is passed.
* **Exit Codes**:
  - `0`: Initialization and immediate validation successful.
  - `1`: Directory already initialized without `--force`, or validation failed.

=== `eidos doctor [--path PATH] [--json]`
Runs a comprehensive workspace health and configuration diagnostic across optional `eidos/eidos.yaml` (`checks.repo_config`), the CLI binary, non-blocking PyPI release currency (`checks.cli_update`, honoring `plugin.updates_check`), root `AGENTS.md` managed-block integrity (`checks.agents_md`), non-blocking open SpecDelta verification readiness (`checks.open_deltas`), non-blocking team operational memory health (`checks.team_memories`), living specifications, knowledge graph index, and agent plugin installations (including per-target hook health `hooks_ok`, `hooks_status`, `target_hooks`, `hook_errors`, and non-blocking advisories for missing concrete `plugin.targets`).
* **Options**:
  - `--path, -p`: Path to eidos specifications directory (defaults to `./eidos`).
  - `--json`: Output diagnostic report in JSON format (including `checks.repo_config`, `checks.cli_update`, `checks.agents_md`, `checks.open_deltas`, `checks.team_memories`, and `checks.agent_plugin` with `hooks_ok`, `hooks_status`, `target_hooks`, `hook_errors`, `configured_targets`, and `missing_configured_targets`).
* **Exit Codes**:
  - `0`: All critical workspace diagnostic checks passed (`checks.repo_config` `absent` or `valid`, available PyPI CLI updates, missing configured `plugin.targets` advisories, already-verified `ready_to_apply` open SpecDeltas, and `checks.team_memories` staleness/expiry advisories remain non-blocking, and plugins installed without `--hooks` pass with `hooks_status: "disabled"`).
  - `1`: One or more critical workspace diagnostics failed (including invalid `eidos/eidos.yaml` in `checks.repo_config`, wiped root `AGENTS.md` managed blocks, or missing/corrupted installed hooks).

=== `eidos hook [--path PATH]`
Executes the session-baseline-aware CLI-native agent lifecycle `Stop` / `PreToolUse` (`attempt_completion`) / `SessionStart` hook across the 6 hook-capable AI coding harnesses (honoring `plugin.hooks.{enabled,strict,fail_on_warnings,baseline_ttl_seconds}` from `eidos/eidos.yaml`), capturing working-tree baselines on session start, short-circuiting zero-edit Q&A turns on pre-existing dirty worktrees, honoring both `stop_hook_active` and `stopHookActive` retry flags, and emitting a client-aware 1-turn capped continuation payload (`decision: "continue"` for Antigravity, `followup_message` for Cursor, `cancel: true` on `.clinerules/hooks/PreToolUse` `attempt_completion` for Cline, and `decision: "block"` for Claude Code, GitHub Copilot, and OpenAI Codex on the first stop turn, or a clean allow response on retry).
* **Options**:
  - `--path, -p`: Path to repository root or `eidos` directory.
* **Exit Codes**:
  - `0`: Hook evaluation completed (JSON decision emitted to stdout).

== Command Groups (Rich Help Panels)

Every operation has a single canonical command path without top-level shortcuts or intra-group duplicate aliases. Commands are semantically organized into six functional panels in CLI help output (`eidos --help`):
1. **Setup & Workspace**: `info`, `doctor`, `init`, `config`
2. **Governance & Verification**: `validate`, `drift`
3. **Knowledge Graph & AI Context**: `context`, `index`, `memory`
4. **Living Catalog & Mutations**: `spec`, `delta`
5. **Living Web Portal**: `portal`
6. **Agent Ecosystem & Plugins**: `plugin`, `hook`
