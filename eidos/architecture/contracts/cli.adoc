= Contract: Eidos CLI Interface
:toc: left

== Command Specifications

=== `eidos --version`
Displays current Eidos engine version (e.g. `eidos 0.8.0`).
* **Options**: `--version`, `-V`
* **Exit Code**: 0

=== `eidos info`
Displays current engine version, loaded v1 schemas, and available agent plugin targets.
* **Exit Code**: 0

=== `eidos validate [PATH]`
Validates all specification documents under `PATH` (defaults to `./eidos`) against the bundled JSON/YAML schemas and verifies cross-references.
* **Arguments**: `PATH` (Optional directory path)
* **Exit Codes**:
  - `0`: All specifications are valid.
  - `1`: One or more validation errors or broken cross-references found.

=== `eidos context [--file PATH] [--component ID] [--task PROMPT] [--tier TIER] [--json] [--path PATH]`
Extracts a compact, token-efficient architectural subgraph context slice (C4 components, bound contracts, domain capabilities, active invariants, and governing policies).
* **Options**:
  - `--file, -f`: Target source code file path(s).
  - `--component, -c`: Target component identifier (e.g. `CMP-EIDOS-CLI`).
  - `--task, -t`: Free-text task description or prompt.
  - `--tier, -T`: Context tier budget: `anchor` (~140 tokens), `guardrails` (default, ~260-890 tokens), or `deep` (~500-1500 tokens).
  - `--json`: Output context slice as machine-readable JSON instead of Markdown.
  - `--path, -p`: Path to specifications directory (default: `./eidos`).
* **Exit Codes**:
  - `0`: Slice successfully extracted.

=== `eidos index`
Manages the embedded SQLite architectural knowledge graph and FTS5 hybrid search index (`eidos/.cache/index.db`).
* **Sub-commands**:
  - `status [--path <path>] [--json]`: Displays index health, AST parser engine telemetry (`ast-grep` vs `python-ast`), symbol breakdown by syntax kind, test invariant assertion metrics, cache file size, and continuous code-aware dirty status. Supports `--json` for programmatic agent consumption.
  - `sync [--path <path>] [--force]`: Synchronizes or rebuilds the knowledge graph index.
  - `search <query> [--limit <n>] [--path <path>] [--json]`: Performs BM25 full-text search across titles, requirements, and invariants.
  - `blast-radius <symbol_or_path> [--depth <n>] [--path <path>] [--json]`: Computes the transitive dependency and governance blast radius for a symbol or spec path.
  - `repo-map [--max-tokens <tokens>] [--json] [--path <path>]`: Generates a token-budgeted structural repo map outline (classes, functions, methods, routes) for AI coding agents in Markdown or JSON (`--json`).
  - `find-symbol <query> [--limit <n>] [--json] [--path <path>]`: Locates code symbols across polyglot AST source files and links them to associated living component specifications. Each `--json` match carries `file_path` (the owning *specification* path) and a `location` object (`file`, `line_start`, `line_end`, `signature`, `parent_symbol`) pointing at the source definition, or `null` for non-AST matches such as paths and component references. The text table shows a `Location` (`file:line`) column.

=== `eidos portal`
Manages the interactive Living Web Portal and documentation site export.
* **Sub-commands**:
  - `serve [--path PATH] [--host HOST] [--port PORT] [--open]`: Launches the local interactive Eidos Living Web Portal HTTP server.
  - `build [--path PATH] [--out OUT_DIR]`: Exports the Living Web Portal as a self-contained static site.
* **Exit Codes**:
  - `0`: Operation completed successfully.
  - `1`: Specifications directory not found.

=== `eidos plugin`
Manages, validates, installs, updates, and uninstalls Eidos Agent Plugins across supported AI agent environments (Antigravity, Claude Code, Cursor, Aider, Cline, OpenCode, OpenAI Codex, and GitHub Copilot).
* **Sub-commands**:
  - `install [TARGET] [--project-dir <path>] [--dest <path>] [--force] [--launcher <launcher>]`: Installs the plugin into `.agents/plugins/eidos` (strict `agent-plugins.org` v1.0.0), `.claude/plugins/eidos/` & `.claude/skills/` (Claude Code 6-Layer Plugin Architecture), `.github/plugin/` & `.github/skills/` (Copilot Agent Plugins 1.0), `.cursor/skills/`, `.cline/skills/`, `.opencode/skills/`, `.codex/skills/`, `.aider/skills/`, and configures client settings and Agent Skills.
  - `uninstall [TARGET] [--project-dir <path>] [--dest <path>]`: Uninstalls and cleans up the plugin and tool configurations from project scope.
  - `version [--project-dir <path>] [--dest <path>]`: Displays and compares bundled vs installed plugin version and reports SemVer sync status.
  - `update [TARGET] [--project-dir <path>] [--dest <path>] [--launcher <launcher>]`: Updates project-scoped plugin to the latest bundled version and syncs configurations.
  - `validate [PATH]`: Validates an Agent Plugin against canonical JSON schemas and SemVer 2.0.0 rules.
  - `info [PATH]`: Displays plugin metadata, skills, hooks, and extensions.

=== `eidos spec`
Manages the living specification catalog (15 declarative specification & discovery blueprint types, excluding `delta/mutation`) and dynamic v1 schema introspection across all 16 bundled schemas: listing, authoring, inspecting, and deleting specifications.
* **Sub-commands**:
  - `list [--path <path>] [--type <type>] [--status <status>] [--include-archived] [--json]`: Lists all living specifications across the 15 living specification types (excluding SpecDeltas and excluding `archive/` subdirectories by default unless `--include-archived` is passed) in tabular or JSON format. Rejects `--type delta` with an error directing the caller to `eidos delta list`.
  - `show <id_or_path> [--path <path>]`: Displays detailed frontmatter metadata and preview of a living specification document (rejecting `delta/mutation` targets and directing the caller to `eidos delta status` / `eidos delta verify`).
  - `create <type> <id> --title <title> [--path <path>]`: Scaffolds a minimal, schema-valid draft blueprint (`status: draft`, or `status: proposed` for `exploration`) across all 15 living specification types (`system`, `architecture`, `domain`, `capability`, `policy`, `persona`, `exploration`, `container`, `component`, `contract`, `design-system`, `ui-component`, `screen`, `client`, `flow`), auto-resolving required parent references from the catalog or canonical fallbacks (`DOM-CORE`, `CNT-CORE`, `DS-CORE`, `PER-USER`) and rejecting `delta/mutation` (directing to `eidos delta create`).
  - `delete <id_or_path> [--path <path>] [--force]`: Safely deletes a living specification document with cross-reference safety checks (rejecting `delta/mutation` targets and directing to `eidos delta delete`).
  - `schema [type] [--json]`: Dynamically loads and inspects bundled v1 YAML frontmatter schemas from `assets/schemas/v1/` across all 16 specification types (omit `[type]` to list all 16 schemas, or pass a short alias or canonical type like `capability` / `product/capability`), displaying required/optional keys, nested object/array item constraints, and schema-synthesized YAML frontmatter templates in Rich tabular or `--json` format.

=== `eidos delta`
Orchestrates SpecDeltas (`DLT-*`) throughout their semantic mutation lifecycle using flat storage (`eidos/deltas/` and `eidos/deltas/archive/`).
* **Sub-commands**:
  - `list [--path <path>] [--status <status>] [--include-archived] [--json]`: Lists SpecDeltas from flat `eidos/deltas/` (or including `eidos/deltas/archive/` when `--include-archived` is passed) with optional status filter (`proposed`, `in_review`, `approved`, `applied`, `rejected`, or `active`) and `--json` output.
  - `status [id] [new_status] [--path <path>] [--json]`: Displays lifecycle status dashboard across the 5 canonical `delta_status` states (`proposed`, `in_review`, `approved`, `applied`, `rejected`) or transitions a specific SpecDelta's status when `id` and `new_status` are given.
  - `create [id] --title <title> [--kind <kind>] [--slug] [--path <path>]`: Scaffolds a new SpecDelta blueprint in flat storage `eidos/deltas/<id>.adoc` with status `proposed`, auto-detecting `vcs.branch` and `vcs.base_commit` from Git `HEAD` (`id` defaults to `auto`, `--slug` / `-s` appends a title-derived slug suffix, `--kind`: `feature, enabler, bug`; defaults to `feature`).
  - `verify <id_or_path> [--path <path>] [--json]`: Verifies that all semantic mutations declared in a SpecDelta exist in the living specifications catalog.
  - `audit <id_or_path> [--path <path>] [--strict] [--json]`: Performs reverse-dependency blast-radius audit on entities removed or deprecated by the SpecDelta, classifying references into approved (historical, negative tests, cleanup routines, tombstones) vs. unacknowledged active leaks.
  - `apply <id_or_path> [--verify/--no-verify] [--json]`: Verifies declared mutations against the living specification catalog by default (`--verify`, or bypass via `--no-verify`), validates the updated SpecDelta, and updates frontmatter status to `applied`.
  - `archive [--keep-recent <n>] [--explorations/--no-explorations] [--dry-run] [--json] [--path <path>]`: Partitions and slims older terminal SpecDeltas (`applied`/`rejected`) and Explorations (`adopted`/`discarded`) beyond the most recent `--keep-recent` (default `15`) into `eidos/deltas/archive/` and `eidos/explorations/archive/`, stripping verification `expect` scaffolding while retaining schema-valid `.adoc` artifacts.
  - `delete <id_or_path> [--path <path>] [--force]`: Deletes a SpecDelta (`DLT-*`) file (rejecting non-delta living specifications and directing to `eidos spec delete`).
  - `changelog [--output <path>] [--unreleased/--no-unreleased] [--docs/--no-docs] [--path <path>]`: Compiles an auditable, Keep a Changelog compliant release history partitioned by Git release tags and applied SpecDeltas (`DLT-*`).

=== `eidos drift [--base REF] [--head REF] [--uncommitted] [--markdown FILE] [--json]`
Detects spec-to-code drift, schema validity, and invariant test coverage across both Planned Mode and Direct Mode.
* **Options**:
  - `--base, -b`: Base git reference to compare against (defaults to `origin/main` or `main`).
  - `--head`: Head git reference (defaults to `HEAD`).
  - `--uncommitted, -u`: Analyze uncommitted working tree and staged changes instead of branch diff.
  - `--markdown, -m`: Path to write the markdown summary comment (e.g. for CI/CD reports).
  - `--json`: Output raw JSON verification result, including `trivially_covered_files` (a list of `{file, owner, additions, spec_files, rule}` where `rule` is `trivial_spec_diff` or `missing_anchor`): structural additions whose only spec coverage was a whitespace/comment-only or unanchored edit; these files count as drift.
  - `--warn-only`: Do not exit with code 1 on drift.
* **Exit Codes**:
  - `0`: Specifications and code are synchronized, all schemas valid, invariant tests green.
  - `1`: Spec-to-code drift detected or specification validation errors.

=== `eidos init [PATH]`
Bootstraps a repository with an Eidos living specification directory skeleton, a root `eidos/system.adoc` (populated with `product/system` frontmatter when `--title` is provided, or an empty placeholder otherwise), `.gitkeep` files for empty directories, a self-contained `eidos/.gitignore`, and immediate schema validation. Note: `eidos init` initializes Eidos specifications and does not install plugins (plugins can be installed separately via `eidos plugin install`).
* **Arguments**: `PATH` (Optional directory path, defaults to `.`)
* **Options**:
  - `--title <title>`: Human-readable display title.
  - `--force`: Overwrite existing files if present (preserving an existing authored `system.adoc` when `--title` is omitted).
* **Exit Codes**:
  - `0`: Initialization and immediate validation successful.
  - `1`: Directory already initialized without `--force`, or validation failed.

=== `eidos doctor [--path PATH] [--json]`
Runs a comprehensive workspace health and configuration diagnostic across living specifications, knowledge graph index, agent plugin installations, and git hooks.
* **Options**:
  - `--path, -p`: Path to eidos specifications directory (defaults to `./eidos`).
  - `--json`: Output diagnostic report in JSON format.
* **Exit Codes**:
  - `0`: All diagnostic checks passed.
  - `1`: One or more critical workspace diagnostics failed.

=== `eidos hook [--path PATH]`
Executes the stateless CLI-native agent lifecycle `Stop` hook across supported AI coding harnesses, verifying specification schemas, invariant test bindings, and spec-to-code drift and emitting a JSON decision (`allow` with optional `systemMessage` warning).
* **Options**:
  - `--path, -p`: Path to repository root or `eidos` directory.
* **Exit Codes**:
  - `0`: Hook evaluation completed (JSON decision emitted to stdout).

== Command Groups (Rich Help Panels)

Every operation has a single canonical command path without top-level shortcuts or intra-group duplicate aliases. Commands are semantically organized into six functional panels in CLI help output (`eidos --help`):
1. **Setup & Workspace**: `info`, `doctor`, `init`
2. **Governance & Verification**: `validate`, `drift`
3. **Knowledge Graph & AI Context**: `context`, `index`
4. **Living Catalog & Mutations**: `spec`, `delta`
5. **Living Web Portal**: `portal`
6. **Agent Ecosystem & Plugins**: `plugin`, `hook`
