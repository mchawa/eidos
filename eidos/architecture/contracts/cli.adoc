= Contract: Eidos CLI Interface
:toc: left

== Command Specifications

=== `eidos info`
Displays current engine version, loaded v1 schemas, supported VCS platforms, and available agent harnesses.
* **Exit Code**: 0

=== `eidos validate [PATH]`
Validates all specification documents under `PATH` (defaults to `./eidos`) against the bundled JSON/YAML schemas.
* **Arguments**: `PATH` (Optional directory path)
* **Exit Codes**:
  - `0`: All specifications are valid.
  - `1`: One or more validation errors or broken cross-references found.

=== `eidos components [PATH]`
Scans and displays all monorepo containers, C4 components, internal modules, dependencies, and package paths.
* **Arguments**: `PATH` (Optional directory path, defaults to `eidos/architecture`)
* **Exit Codes**:
  - `0`: Scan complete.

=== `eidos mcp`
Launches the stdio Model Context Protocol (MCP) server for AI agent clients.
* **Protocol**: JSON-RPC 2.0 stdio
* **Exit Codes**:
  - `0`: Clean termination.

=== `eidos plugin`
Manages, validates, installs, updates, and removes Eidos Agent Plugins conforming to `agent-plugins.org` v1.0.0.
* **Sub-commands**:
  - `install [--target <target>] [--project-dir <path>] [--dest <path>]`: Installs the plugin into `.agents/plugins/eidos` and local workspace MCP configurations.
  - `uninstall / remove [--target <target>] [--project-dir <path>] [--dest <path>]`: Uninstalls and cleans up the plugin from project scope.
  - `version [--project-dir <path>] [--dest <path>]`: Displays and compares bundled vs installed plugin version and reports SemVer sync status.
  - `update / upgrade [--target <target>] [--project-dir <path>] [--dest <path>]`: Updates project-scoped plugin to the latest bundled version and syncs MCP configs.
  - `validate [PATH]`: Validates an Agent Plugin against canonical JSON schemas and SemVer 2.0.0 rules.
  - `info [PATH]`: Displays plugin metadata, skills, MCP servers, and extensions.

=== `eidos spec`
Manages the living specification catalog: listing, authoring, inspecting, and deleting specification documents.
* **Sub-commands**:
  - `list [--path <path>] [--type <type>] [--status <status>]`: Lists all living specifications in tabular format.
  - `show <id_or_path> [--path <path>]`: Displays detailed frontmatter metadata and preview of a specification document.
  - `create <type> <id> --title <title> [options]`: Scaffolds a new specification document (capability, domain, policy, contract, component, persona, delta, exploration) with schema validation.
  - `delete <id_or_path> [--force]`: Safely deletes a specification document with cross-reference safety checks.

=== `eidos delta`
Orchestrates SpecDeltas throughout their semantic mutation lifecycle.
* **Sub-commands**:
  - `list [--path <path>] [--status <status>]`: Lists active and applied SpecDeltas.
  - `create <id> --title <title> [--kind <kind>] [--motivation <text>]`: Scaffolds a new active SpecDelta in `eidos/deltas/active/<id>.adoc`.
  - `apply <id_or_path>`: Reconciles an active delta, updates its status to `applied`, and moves it to `eidos/deltas/applied/`.
  - `delete <id_or_path> [--force]`: Deletes an active or applied SpecDelta.

=== Convenience Shortcuts
* `eidos create <type> <id> --title <title>`: Direct shortcut to `eidos spec create`.
* `eidos delete <id_or_path> [--force]`: Direct shortcut to `eidos spec delete`.
* `eidos list [--type <type>] [--status <status>]`: Direct shortcut to `eidos spec list`.
